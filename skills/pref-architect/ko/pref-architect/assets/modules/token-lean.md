# token-lean

같은 결과물을 더 적은 토큰으로 완성하는 절차다. 줄이는 대상은 작업 과정의 낭비다. 결과물의 내용은 줄이지 않는다.

## 판별 질문

컨텍스트에 싣거나 출력하는 모든 텍스트는 아래 질문을 통과해야 한다. 통과하지 못하면 싣지 않거나 출력하지 않는다.

- (입력) 이 텍스트가 컨텍스트에 없으면 결과물 품질이 실제로 떨어지는가
- (출력) 사용자가 이 텍스트를 실제로 읽고 쓰는가
- (턴) 이 턴이 없으면 작업을 진행할 수 없는가

대화가 길어지면 매 턴의 입력에 지난 대화 전체가 들어간다. 그래서 한 번의 불필요한 로드와 출력은 이후 모든 턴에서 다시 비용을 만든다.

## 입력 줄이기

### 파일 로드

- 파일 전체를 읽기 전에 구조(줄 수, 목차, 헤더, 열 이름)부터 확인한다.
- 구조를 확인한 뒤 작업에 필요한 범위만 읽는다.
- 파일 전체 읽기는 파일이 작거나 전체가 실제로 필요할 때만 한다.
- 같은 파일을 반복해서 읽지 않는다. 처음 읽을 때 필요한 정보를 확보한다.
- 읽을 범위를 잘못 잡으면 다시 읽느라 더 많이 쓴다. 경계가 불확실하면 여유 있게 읽는다.

### 대량 파싱

- 파일이 많거나 원문이 크면 코드로 파싱, 필터, 집계를 하고 결과만 컨텍스트에 싣는다.
- 모델이 원문 전체를 직접 훑는 처리를 피한다.
- 파싱 결과가 맞는지는 표본 1-2건과 집계 수치로 확인한다.

### 검색과 페이지 가져오기

- 검색 횟수는 답에 필요한 최소로 줄인다.
- 검색 결과 요약만으로 답할 수 있으면 원문 전체를 가져오지 않는다.
- 원문이 필요하면 필요한 부분만 쓴다.
- 같은 자료를 반복해서 가져오지 않는다.

### 도구 출력

- 코드를 실행할 때 표준 출력은 검증에 필요한 최소로 줄인다.
- 큰 데이터는 전체를 출력하지 않고 표본, 집계, 형태 정보로 확인한다.
- 로그와 경고는 작업에 필요한 수준만 표시한다.

## 출력 줄이기

- 사용자 입력, 업로드 파일 내용, 이전 응답을 다시 서술하지 않는다. 원문 인용은 논거에 필요한 최소로 줄인다.
- 파일로 만든 결과물은 경로와 요지만 응답에 쓴다. 파일 본문 전체를 응답에 다시 출력하지 않는다. 결과물이 제대로 만들어졌는지는 구조 요약이나 핵심 수치로 알린다.
- 기존 결과물을 고칠 때는 바뀐 곳만 보여 준다. 파일은 전체를 다시 쓰지 않고 부분 편집을 우선한다.
- 착수 보고와 진행 설명은 사용자의 결정에 필요한 항목만 짧게 쓴다.
- 중간 추론과 작업 기록은 짧게 한다. 언어는 write-standard나 code-standard의 (추론 언어) 설정을 따르고 설정이 없으면 영어로 한다. 최종 결과만 사용자의 언어로 쓴다.
- 같은 정보를 반복 요약하지 않는다.
- 기본은 품질을 유지하는 절약이다. 결과물의 내용과 근거는 그대로 둔다. 사용자가 "요지만", "짧게"처럼 분량을 줄여 달라고 한 경우에만 핵심 결론과 최소 근거 위주로 줄인다.

## 턴 줄이기

- 확인할 질문은 한 턴에 모아서 묻는다.
- 합리적인 기본값이 있는 사항은 묻지 않고 적용한 기본값을 밝힌 뒤 진행한다.
- 중간 산출물을 파일로 남겨 세션을 넘기거나 다시 시작할 때 설명을 반복하지 않게 한다.
- 대화 기록이 매우 길어진 세션에서 새 대형 작업이 시작되면 산출물 파일을 기준으로 새 세션으로 옮기자고 제안한다.

## 시행착오 줄이기

- 코드를 실행하기 전에 경로, 의존성, 입력 형식을 확인하여 실패 후 재실행 반복을 줄인다.
- 대량 반복 작업은 소량으로 먼저 시험하여 방식을 정한 뒤 전체를 코드 반복문으로 처리한다.
- 검증은 실패할 수 있는 지점을 좁혀서 하고 결함이 나온 지점만 다시 실행한다.
- 같은 오류가 반복되면 시도를 멈추고 원인을 진단한 뒤 다시 시작한다.

## 실행 환경별 적용

- 코드를 실행할 수 있는 환경에서는 이 모듈의 모든 규칙을 적용한다.
- 코드를 실행할 수 없는 환경에서는 파일 부분 로드, 출력 줄이기, 턴 줄이기 규칙만 적용하고 대량 처리는 나누어 하자고 제안한다.

## 줄이지 않는 항목

토큰 절약을 이유로 아래 항목을 생략하지 않는다.

- 정량 데이터의 출처와 산출 근거
- 결과물이 제대로 만들어졌는지 확인하는 검증
- 사용자가 요청한 결과물 본문의 내용과 분량
- 오류가 났을 때 원인과 대응의 보고
- 법률, 안전처럼 민감한 사항의 확인 절차
- staged-work가 함께 불러와졌을 때의 단계 계획과 검증 기록

## 산출 전 점검

- 컨텍스트에 실은 텍스트가 입력 질문을 통과하는가
- 응답에 쓴 텍스트가 출력 질문을 통과하는가
- 파일 본문이나 원문 전체를 다시 출력하지 않았는가
- 수정 응답이 바뀐 곳만 담고 있는가
- 확인 질문을 한 턴에 모았는가
- 줄이지 않는 항목을 생략하지 않았는가

## 예외

- 사용자가 전체 출력, 전체 로드, 자세한 과정 설명을 명시적으로 요청하면 해당 규칙을 적용하지 않는다.
- 인용 원문을 정확히 옮겨야 하는 경우 그 부분은 재서술 금지 규칙에서 제외한다.
- 디버깅을 위해 사용자가 전체 로그를 요청하면 도구 출력 제한을 적용하지 않는다.
