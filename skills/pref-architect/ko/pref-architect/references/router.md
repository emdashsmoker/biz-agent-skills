# 상시 지침 작성법

상시 지침은 모든 대화의 앞부분에 들어간다. 그래서 짧을수록 좋고 가장 중요한 규칙이 맨 앞에 와야 한다. 지시가 많을수록 준수율이 떨어지고 앞쪽 지시가 더 잘 지켜진다는 연구 결과가 이 원칙의 근거다.

## 들어갈 내용

상시 지침에는 아래 내용만 순서대로 둔다.

1. 모듈 로드 규칙
2. 공통 작업 규칙(인터뷰 F1-F7에서 켠 규칙)
3. 모든 출력에 적용할 짧은 선호(인터뷰 F8, 있을 때만)

작업 종류에 따라 달라지는 규칙은 상시 지침에 두지 않고 해당 모듈에 둔다. 예를 들어 차트 색 규칙은 code-standard에 들어가고 출처 표기 형식은 write-standard에 들어간다.

## 작성 원칙

- 규칙마다 이유를 한 구절 붙인다. 이유가 있으면 모델이 새 상황에도 규칙의 목적에 맞게 판단한다.
- 대문자 강조, "절대", "예외 없음" 같은 과한 표현을 쓰지 않는다. 최근 모델은 강한 표현에 과하게 반응하여 관계없는 작업에도 규칙을 적용할 수 있다.
- 하지 말아야 할 일보다 해야 할 일을 적는다.
- 모듈 이름은 실제 설치할 폴더 이름과 글자 하나까지 같게 쓴다.
- 짧은 질문에도 모듈 로드 규칙을 적용한다고 적는다. 모델은 질문이 짧으면 스킬 로드를 생략하는 경향이 있다.

모델이 모듈 로드를 계속 건너뛴다고 사용자가 알려 오면 로드 규칙을 한 번 더 앞쪽으로 옮기고 "응답의 첫 동작은 모듈 로드"라는 문장을 추가한다. 그래도 건너뛰면 사용자와 상의하여 표현의 강도를 높인다.

## 서식

아래 서식을 사용자의 출력 언어로 옮겨 쓴다. 대괄호 부분은 인터뷰 답으로 바꾸고 설치하지 않는 모듈의 줄은 지운다.

```
# 모듈 로드

응답을 시작하기 전에 해당하는 표준 모듈을 먼저 불러온다. 표준 모듈에 글과 코드의 작성 기준이 들어 있어서 불러오지 않으면 결과물이 기준을 벗어난다. 질문이 짧거나 단순해도 같게 적용한다.

- 코드, 차트, UI, 데이터 시각화, 파일 작업이 들어간 요청에는 code-standard를 불러온다.
- 그 밖의 모든 요청(글쓰기, 조사, 일상적인 검색 등)에는 write-standard를 불러온다.
- 두 영역에 걸친 요청에는 둘 다 불러온다.

표준 모듈을 불러온 뒤 작업 규모를 판단한다.

- 여러 단계, 여러 파일, 여러 출처에 걸친 복잡한 작업이면 staged-work를 추가로 불러온다.
- 대량 파싱, 대량 조사, 대량 도구 호출, 긴 산출물, 반복 파일 작업처럼 토큰을 많이 쓰는 작업이면 token-lean을 추가로 불러온다.

불러온 모듈의 규칙은 끝까지 따른다. 사용자가 다른 스킬을 지정해도 표준 모듈은 함께 불러온다. 사용자가 특정 모듈을 쓰지 말라고 명시한 경우에만 그 모듈을 생략한다.

# 공통 작업 규칙

- [F1-F7에서 켠 규칙을 이유와 함께 한 줄씩]

# 기타 선호

- [F8 답, 없으면 이 절을 지운다]
```

설치하는 표준 모듈이 하나뿐이면 "두 영역에 걸친 요청" 줄을 지우고 남은 모듈을 모든 요청에 불러오도록 고친다. 표준 모듈을 하나도 설치하지 않으면 staged-work와 token-lean의 로드 조건만 남긴다.

## 환경별 배치

| 대상 환경 | 상시 지침 위치 | 모듈 설치 위치 | 참고 |
|---|---|---|---|
| claude.ai (웹, 데스크톱, 모바일) | 설정의 유저 프리퍼런스 입력 칸 | 설정의 스킬 메뉴에서 .skill이나 zip 업로드 | 프리퍼런스는 계정 전체 대화에 적용된다 |
| Claude Code | 모든 프로젝트용은 `~/.claude/CLAUDE.md`, 한 프로젝트용은 프로젝트 루트의 `CLAUDE.md` | 모든 프로젝트용은 `~/.claude/skills/모듈이름/`, 한 프로젝트용은 `.claude/skills/모듈이름/` | CLAUDE.md는 200줄 이하가 권장된다 |
| AGENTS.md를 읽는 도구(Codex, Cursor 등) | 저장소 루트의 `AGENTS.md` | Codex와 Cursor는 `~/.agents/skills/모듈이름/`이나 저장소의 `.agents/skills/모듈이름/` | 도구마다 추가 경로가 있으므로 해당 도구 문서를 확인한다 |

이 표의 경로는 2026년 기준 각 도구의 공식 문서에 적힌 값이다. 도구가 바뀌면 경로도 바뀔 수 있으므로 사용자에게 안내할 때 해당 도구의 최신 문서를 확인하라고 한 줄로 덧붙인다.

## 환경별 주의점

- Claude Code의 `@경로` 가져오기는 가져온 파일을 세션 시작 시 모두 컨텍스트에 싣는다. 모듈을 `@경로`로 CLAUDE.md에 붙이면 매번 전부 읽히므로 모듈로 나눈 효과가 사라진다. 모듈은 스킬 폴더에 설치한다.
- Claude Code는 같은 위치에 CLAUDE.md가 있으면 기본 설정에서 AGENTS.md를 읽지 않는다. 두 파일을 함께 쓰는 사용자에게는 CLAUDE.md 첫 줄에 `@AGENTS.md`를 적고 공통 내용은 AGENTS.md 한 곳에만 두도록 안내한다.
- AGENTS.md는 저장소에 커밋되어 다른 사람과 공유되는 경우가 많다. 개인 선호는 사용자 전역 위치에 두고 AGENTS.md에는 팀이 합의한 규칙만 두도록 안내한다.

## 스킬을 쓸 수 없는 환경

대상 환경이 스킬을 지원하지 않으면 아래 순서로 대체한다.

1. 환경이 파일 단위 규칙을 지원하면(예: 특정 파일을 열 때만 읽히는 규칙 파일) 모듈 본문을 그 기능에 옮기고 상시 지침에서는 로드 규칙을 삭제한다.
2. 모델이 파일을 읽을 수 있는 환경이면 모듈을 일반 md 파일로 두고 로드 규칙의 "불러온다"를 "해당 파일을 읽는다"로 바꾼다. 파일 경로를 로드 규칙에 적는다.
3. 두 방법 모두 안 되면 사용자가 가장 자주 쓰는 모듈 하나에서 가장 자주 쓰는 규칙만 골라 상시 지침에 추가한다. 나머지 모듈은 필요할 때 대화에 붙여 넣어 쓰도록 안내한다.
