# 자료 정리 (digest)

여러 형태의 입력 자료를 텍스트로 바꾼 뒤 읽는 사람이 바로 쓸 수 있는 글로 정리한다. 변환은 `scripts/extract.py`가 맡고 정리는 모델이 맡는다. 변환 결과를 파일로 먼저 저장한 뒤 그 파일을 읽고 쓰는 순서를 지킨다. 원본을 바로 읽으면 시간 정보, 서식 태그, 중복 줄 같은 잡음이 정리 품질을 떨어뜨리기 때문이다.

## 용어

| 용어 | 뜻 |
|---|---|
| 입력 자료 | 사용자가 제출한 파일, 웹 주소, 대화창에 붙여넣은 글 |
| 변환본 | 입력 자료의 내용을 바꾸지 않고 마크다운 텍스트로 옮긴 파일 |
| 번역본 | 입력 자료 전체를 다른 언어로 옮긴 글 |
| 정리본 | 입력 자료를 재구성한 글. 회의록, 브리핑, 보고서가 여기에 속한다 |
| 사용자 언어 | 사용자가 대화에서 쓰는 언어 |

## 작업 순서

1. 입력 자료를 확인한다. 자료 없이 요청만 왔다면 받을 수 있는 자료 종류와 산출물 유형을 짧게 안내하고 자료를 요청한다. 회의록 요청이면 정리 기준(발언자, 주제, 시간)도 함께 안내한다.
2. 산출물 유형을 정한다. 기준은 "산출물 유형" 절을 따른다.
3. 필요한 패키지를 설치한다. 설치는 다른 작업보다 먼저 한다.
4. 붙여넣은 글을 제외한 모든 입력 자료를 스크립트로 변환한다.
5. 변환 결과 파일을 읽는다. 문서, 자막, 음성의 원본 파일은 읽지 않는다.
6. 산출물 유형별 형식에 맞춰 작성한다.
7. "산출 전 점검" 절의 항목을 확인한 뒤 전달한다. 정리본과 번역본은 대화 응답으로 출력하고 사용자가 파일을 원하면 마크다운 파일로 저장해 전달한다. 변환본은 파일로 전달한다.

자료와 함께 요청이 오면 안내 없이 바로 2번부터 진행한다. 한 번 사용한 뒤에는 사용자가 그만두라고 하기 전까지 같은 대화에서 들어오는 입력 자료도 이 순서로 처리한다.

## 산출물 유형

사용자가 유형, 형식, 분량을 지정하면 지정을 따른다. 지정이 없으면 아래 표를 위에서부터 차례로 확인하고 처음 맞는 유형을 고른다.

| 순서 | 조건 | 산출물 |
|---|---|---|
| 1 | 변환, 추출, 마크다운으로 바꾸기처럼 형식 변경만 요청 | 변환본 |
| 2 | 번역 요청 | 번역본 |
| 3 | 사용자가 회의 자료라고 밝혔거나 입력 자료가 여러 참석자의 안건 논의 기록 | 회의록 |
| 4 | 입력 자료가 1건 | 브리핑 |
| 5 | 입력 자료가 2건 이상 | 보고서 |

요약 요청은 3번부터 5번에 따라 정리본으로 처리한다. "세 줄로 요약"처럼 분량을 정한 요청은 고른 유형의 기본 형식보다 사용자가 정한 분량을 먼저 따른다.

## 설치

필요한 입력 종류의 패키지만 설치한다.

| 입력 종류 | 패키지 |
|---|---|
| 웹 주소 | httpx, trafilatura |
| PDF, DOCX, PPTX, XLSX 등 문서 | markitdown[pdf,docx,pptx,xlsx,xls], pdfplumber |
| HWPX | python-hwpx, beautifulsoup4, lxml |
| HWP | pyhwp, olefile |
| 음성, 영상 | faster-whisper |
| 자막 | 없음 |

```bash
pip install httpx trafilatura "markitdown[pdf,docx,pptx,xlsx,xls]" pdfplumber python-hwpx beautifulsoup4 lxml olefile faster-whisper
pip install pyhwp
```

- 개인 컴퓨터에서는 프로젝트 전용 가상 환경(venv, conda 등)을 만들어 그 안에 설치한다. 시스템 파이썬에 직접 설치하면 다른 프로그램이 쓰는 패키지와 충돌할 수 있다.
- 일회용 격리 환경(클라우드 샌드박스 등)에서 `externally-managed-environment` 오류가 나면 `--break-system-packages` 옵션을 붙여 다시 설치한다.
- pyhwp 설치가 `install_layout` 관련 빌드 오류로 실패하면 `SETUPTOOLS_USE_DISTUTILS=stdlib pip install pyhwp`로 다시 시도한다. 그래도 실패하면 pyhwp 없이 진행한다. HWP 파일은 olefile 대체 경로로 처리된다.
- ffmpeg는 선택 사항이다. 설치되어 있으면 음성 디코딩에 우선 쓰고 없으면 faster-whisper에 포함된 디코더를 쓴다.
- Whisper 모델은 첫 전사 때 Hugging Face에서 자동으로 내려받는다. 네트워크가 막힌 환경에서는 전사를 진행할 수 없으므로 사용자에게 그 사실을 알린다.
- 스크립트가 `missing_dependency` 오류를 내면 결과에 적힌 `install` 명령을 실행한 뒤 다시 시도한다.

## 입력 변환

### 입력 종류별 처리

| 입력 | 확장자 | 처리 방법 | 결과 파일 |
|---|---|---|---|
| 웹 페이지 | http, https 주소 | trafilatura로 본문과 메타데이터 추출, 실패하면 단순 HTML 추출 | `web_(주소 해시).md` |
| 웹 주소의 파일 | 아래 확장자 | 내려받은 뒤 파일과 같은 방법으로 처리 | 파일 종류별 결과 |
| PDF | .pdf | markitdown으로 본문 추출, pdfplumber로 표 추출 | `(이름)_parsed.md`, 표가 있으면 `(이름)_tables.md` |
| HWPX | .hwpx | python-hwpx export_markdown, 실패하면 TextExtractor, 다시 실패하면 XML 직접 파싱 | `(이름)_parsed.md` |
| HWP | .hwp | pyhwp(hwp5txt), 실패하면 olefile 레코드 파싱 | `(이름)_parsed.md` |
| 그 밖의 문서 | .docx .pptx .xlsx .xls .csv .json .xml .html .htm .txt .md .epub .zip | markitdown | `(이름)_parsed.md` |
| 이미지 | .jpg .jpeg .png | markitdown(EXIF 메타데이터만 추출) | `(이름)_parsed.md` |
| 자막 | .srt .vtt | 시간 정보, 서식 태그, 연속 중복 줄 제거 | `(이름)_captions.md` |
| 음성, 영상 | .ogg .opus .m4a .aac .mp3 .wav .flac .wma .webm .amr .mp4 .mkv .avi .mov | faster-whisper 로컬 전사 | `(이름)_transcript.md` |
| 구형 문서 | .doc .ppt | 추출 엔진 없음 | 없음 |

PDF 본문 추출은 표의 칸 구조를 보존하지 못한다. 표 내용은 `_tables.md`를 기준으로 읽는다. 이미지의 그림 내용은 스크립트가 추출하지 못한다. 모델이 이미지를 직접 볼 수 있는 환경이면 이미지를 직접 읽는다. HWP 대체 파서 고지: "본 제품은 한컴의 HWP 문서 파일(.hwp) 공개 문서를 참고하여 개발하였습니다."

### 스크립트 사용법

명령 예시의 `scripts/extract.py`는 이 스킬 폴더 기준 경로다. 결과 파일은 `DIGEST_WORK_DIR` 환경변수가 가리키는 폴더에 저장되며 기본값은 현재 폴더 아래 `digest_work`다. 스크립트는 입력 1건마다 1번 실행한다.

```bash
python scripts/extract.py report.pdf
python scripts/extract.py "https://example.com/news/123" --max-chars 50000
python scripts/extract.py meeting.m4a --model small --language ko
python scripts/extract.py lecture.vtt --start 00:10:00 --end 00:25:00
python scripts/extract.py report.pdf --chunk --chunk-size 2000
python scripts/extract.py "https://example.com/files/plan.hwpx" --download
python scripts/extract.py --bundle
python scripts/extract.py --clean
```

| 옵션 | 기본값 | 용도 |
|---|---|---|
| `--out-dir` | `digest_work` | 결과 저장 폴더 |
| `--max-chars` | 0(제한 없음) | 결과 본문의 최대 글자 수. 넘는 부분은 잘리고 잘림 표시가 붙는다 |
| `--timeout` | 15 | 웹 요청 제한 시간(초) |
| `--download` | 꺼짐 | 웹 주소의 원본 파일을 `downloads` 폴더에 보관 |
| `--chunk`, `--chunk-size` | 꺼짐, 2000 | 문서를 제목 단위로 나눈 청크 파일 생성 |
| `--start`, `--end` | 전체 | 자막과 음성의 처리 구간(예: 00:10:00) |
| `--timestamps` | 꺼짐 | 자막과 전사 결과의 각 줄 앞에 시각 표기 |
| `--model` | tiny | Whisper 모델 크기 |
| `--language` | 자동 감지 | 음성 언어 코드(예: ko, en) |
| `--beam-size` | 5 | 전사 빔 서치 크기 |
| `--bundle` | 꺼짐 | `downloads` 폴더의 파일을 ZIP 1개로 묶음 |
| `--clean` | 꺼짐 | `downloads` 폴더의 파일 삭제 |
| `DIGEST_ACCEPT_LANGUAGE` 환경변수 | 한국어 우선 | 웹 요청 시 선호 언어 |

### 결과 확인

스크립트는 결과 요약을 JSON으로 출력한다. `output_path`(또는 `chunk_paths`, `tables_path`)의 파일을 읽고 `truncated`가 true이면 사용자에게 뒷부분이 반영되지 않았다고 알린다. `warnings`와 `error` 값은 아래처럼 처리한다.

| 값 | 뜻 | 대응 |
|---|---|---|
| `missing_dependency` | 패키지 미설치 | `install` 명령 실행 후 재시도 |
| `encrypted` | 암호가 걸린 파일 | 암호를 해제한 파일을 요청 |
| `text_empty` | 텍스트가 거의 없음(스캔 문서 등) | 광학 문자 인식(OCR)이 필요하다고 알림 |
| `hwp_table_placeholder` | pyhwp는 표 내용을 자리표시자로 바꿈 | 표 내용이 필요하면 HWPX로 저장한 파일을 요청 |
| `hwp_olefile_fallback` | 대체 파서 사용, 깨진 문자가 섞일 수 있음 | 깨진 문자가 보이면 HWPX로 저장한 파일을 요청 |
| `unsupported_extract` | 추출할 수 없는 형식 | 지원 형식을 안내하고 docx, pptx 등으로 저장한 파일을 요청 |
| `unsupported_content_type` | 웹 주소가 웹 페이지도 지원 파일도 아님 | 접근할 수 없다고 알림 |
| `failed` | 요청이나 변환 실패(`status_code`, `detail` 참고) | 다른 주소를 시도하거나 파일 제출을 요청 |

### 웹 주소

- 스크립트로 먼저 수신한다. 실행 환경의 네트워크 제한으로 스크립트가 주소에 닿지 못하면 실행 환경이 제공하는 웹 읽기 도구를 쓴다. 그런 도구도 없으면 사용자에게 파일이나 본문 텍스트를 요청한다.
- 이 스킬에는 검색 기능이 없다. 주소는 사용자가 주거나 별도 웹 검색 결과에서 얻는다.
- 로그인이나 구독이 필요한 페이지는 공개된 부분만 추출된다. 본문이 빠져 있으면 사용자에게 본문 제출을 요청한다.
- 문서 파일 주소는 텍스트만 추출하고 원본은 보관하지 않는다. 사용자가 파일 보관을 요청했거나 웹 검색 결과의 문서를 모으는 작업일 때만 `--download`를 쓴다.
- 내려받은 파일이 3개 이상이면 `--bundle`로 묶어서 전달하고 2개 이하면 파일을 하나씩 전달한다. 같은 대화에서 두 번째 다운로드 작업을 시작하기 전에는 `--clean`으로 이전 파일을 지운다.

### 음성과 영상

- 입력 파일을 16kHz 모노로 디코딩한 뒤 CPU에서 int8 방식으로 전사한다. 결과는 구간마다 한 줄로 저장하며 시각 정보는 붙이지 않는다. 시간 기준 회의록을 쓰거나 사용자가 시각을 요청하면 `--timestamps`를 붙인다.
- 사용자가 특정 구간만 요청하면 `--start`, `--end`로 그 구간만 처리한다. 언어를 알면 `--language`로 지정한다.
- 모델은 tiny를 기본으로 쓴다. 사용자가 품질 개선을 요청하면 small 이상을 쓴다. 메모리가 부족한 환경이나 60분 이상의 긴 녹음에는 tiny나 base를 쓴다.

| 모델 | 매개변수 수 | 상대 속도(large 기준) |
|---|---|---|
| tiny | 약 3,900만 | 약 10배 |
| base | 약 7,400만 | 약 7배 |
| small | 약 2억 4,400만 | 약 4배 |
| medium | 약 7억 6,900만 | 약 2배 |
| large-v3 | 약 15억 5,000만 | 1배 |

모델이 클수록 정확도는 오르고 속도는 떨어지며 메모리를 더 쓴다. 인식 품질은 언어에 따라 크게 다르다. tiny는 오인식이 많아 교정 부담이 크다.

> OpenAI(2022), Whisper 모델 크기별 매개변수와 상대 속도(https://github.com/openai/whisper)

### 자막 파일

- 자막 파일을 스크립트로 정제한 뒤 정제된 `_captions.md`만 읽는다. 자동 생성 자막은 같은 문장이 여러 구간에 걸쳐 반복되는 경우가 있어 스크립트가 직전 줄과 같은 줄을 지운다.
- 사용자가 특정 시간대만 요청하면 `--start`, `--end`로 그 구간만 추출한다.

### 동영상 플랫폼 주소

사용자가 동영상 공유 서비스의 영상 페이지 주소만 주면 사용자 동의 없이 영상이나 자막을 자동 도구로 내려받지 않는다. 플랫폼 약관이 자동 수집과 다운로드를 제한하는 경우가 있기 때문이다. 사용자에게 아래 자료 중 하나를 요청한다.

- 사용자가 약관이 허용하는 방법으로 확보한 자막 파일(.srt, .vtt)
- 플랫폼이 제공하는 스크립트 보기 기능에서 복사한 텍스트
- 사용자가 가진 음성 또는 영상 파일

자막 확보 방법은 사용자가 직접 물어볼 때만 안내한다. 사용자가 방법을 물으면 아래 순서로 답한다.

1. 사용자가 준 주소로 플랫폼을 확인한다.
2. 그 플랫폼에서 자막을 얻는 방법을 모델이 아는 지식으로 정리한다. 플랫폼 자체 기능 및 외부 방법을 모두 살핀다.
3. 실행 환경에 웹 검색 도구가 있으면 2번 내용을 최신 정보로 확인한다. 플랫폼 기능, 약관, 외부 방법의 작동 여부가 자주 바뀌기 때문이다. 검색 도구가 없으면 안내 내용이 최신이 아닐 수 있다고 알린다.
4. 확인한 방법 가운데 가장 유용한 방법을 사용자가 직접 따라 할 수 있는 단계로 안내한다. 유용성은 사용자 환경에서 실행할 수 있는지, 필요한 언어의 자막을 얻을 수 있는지, 단계가 적은지로 판단한다.
5. 안내한 방법에 따르는 리스크를 충분히 알린다.
6. 그 방법을 실행할지 사용자에게 묻는다. 사용자가 원하면 실행 환경에서 실행한다. 실행할 수 없는 환경이면 사용자가 직접 실행하도록 안내한다.
7. 자막을 확보하면 작업 순서 2번부터 이어간다. 처음 요청한 산출물이 있으면 그 요청을 따른다.

### 읽기 분량 상한

한 작업에서 읽는 변환 결과가 모델의 컨텍스트 창을 넘지 않도록 자료당 글자 수 상한을 `--max-chars`로 정한다. 자료 수는 한 작업에서 읽는 입력 자료의 개수다. 사용자가 상한을 따로 정하면 그 값을 쓴다.

| 자료 수 | 자료당 상한(컨텍스트 창 100만 토큰 기준) |
|---|---|
| 1-2개 | 제한 없음 |
| 3-5개 | 100,000자 |
| 6-10개 | 50,000자 |
| 11-20개 | 25,000자 |
| 21개 이상 | 15,000자 |

- 표의 기준은 전체 읽기 분량을 500,000자로 잡은 값이다.
- 컨텍스트 창이 100만 토큰보다 작으면 표의 상한에 (컨텍스트 창 토큰 수 ÷ 1,000,000)을 곱한다. 이때 "제한 없음"은 (컨텍스트 창 토큰 수 × 0.5 ÷ 자료 수)로 바꾼다.
- 컨텍스트 창 크기를 모르면 200,000 토큰으로 계산한다.
- 상한 계산은 코드로 한다.
- 변환본 작업은 결과를 파일로만 전달하므로 상한을 적용하지 않는다.

## 정리 공통 원칙

아래 원칙은 회의록, 브리핑, 보고서에 모두 적용한다.

- 입력 자료에 있는 내용만 쓴다. 자료에 없는 주장, 평가, 수치, 계획을 더하지 않는다.
- 음성 전사, 자동 생성 자막, 자동 생성 녹취록은 오인식을 교정한다. 교정 대상은 발음이 비슷한 단어의 오인식, 잘못된 띄어쓰기, 반복 구간, 앞뒤와 이어지지 않는 문장이다.
- 교정은 앞뒤 문장이나 자료 안의 다른 언급으로 올바른 표기가 하나로 좁혀질 때만 한다. 하나로 좁혀지지 않으면 원래 표기를 그대로 둔다. 고유명사와 전문 용어에도 같은 기준을 쓴다.
- 정리본은 사용자 언어로 쓴다. 입력 자료가 외국어여도 같다.
- 수치를 더하거나 나누는 계산은 코드로 한다.

## 회의록

정리 기준은 발언자, 주제, 시간 가운데 하나다. 사용자가 기준을 정하지 않으면 주제 기준을 쓴다. 녹음 파일이 오면 전사를 마친 뒤 교정한 전사문을 녹취록으로 보고 같은 방법으로 정리한다.

```markdown
# 회의 목적
- **(주제명) 회의에서 다룬 목적**

# 회의 내용
- **(1단계 소제목) 주장**
    + (2단계 소제목) 주장의 근거

# 향후 계획
- **(실행자) 결과물을 받을 사람, 결과물, 기한**
```

| 기준 | 1단계 소제목 | 2단계 소제목 | 묶는 방법 |
|---|---|---|---|
| 발언자 | 발언자 이름 | 주제 | 발언자별로 묶는다. 이름은 녹취록 표기를 그대로 쓴다. 발언자마다 주장 묶음은 한 번만 쓰고 여러 곳에 나눠 쓰지 않는다 |
| 주제 | 주제 | 키워드 | 비슷한 주장을 한 주제로 묶는다. 주제끼리 겹치지 않고 빠진 논의가 없게 나눈다 |
| 시간 | 주제 | 키워드 | 논의가 진행된 시간 순서로 쓴다. 시각 정보가 없으면 발언 순서를 따른다. 흐름을 보존하기 위해 발언자별로 묶지 않는다 |

- 회의 목적과 향후 계획은 각각 3-5줄로 쓴다. 녹취록에 나온 항목이 그보다 적으면 나온 만큼만 쓴다.
- 1단계 줄은 굵게 표시하고 들여쓰지 않는다. 2단계 줄은 들여쓴다.
- 모든 1단계 주장에는 녹취록에 있는 근거를 2단계로 붙인다.

## 브리핑

입력 자료 1건의 흐름을 보존하면서 정리한다. 영상 자막, 음성, 기사, 문서에 모두 같은 형식을 쓴다.

```markdown
# 개요
- (제목) 자료 제목
- (항목명) 확인된 기본 정보

# 요약
3-5줄 요약

# 내용
## 자료 흐름에 따른 소주제
- 내용

# 시사점
3-5줄 시사점
```

| 자료 | 개요 항목 |
|---|---|
| 영상 자막, 영상 파일 | 제목, 게시자, 게시일, 길이, 조회수, 출처 주소 |
| 음성 파일 | 파일명, 길이, 감지 언어 |
| 웹 기사 | 제목, 매체, 작성자, 게시일, 출처 주소 |
| 문서 | 제목, 발행 주체, 발행일, 출처 |

- 개요에는 변환 결과의 메타데이터나 사용자 설명으로 확인된 항목만 쓴다. 확인되지 않은 항목은 줄째 생략한다.
- 내용은 자료에 나온 순서대로 쓴다. 영상과 음성은 시간 순서를 따른다. 모든 주제를 빠짐없이 담고 분량은 제한하지 않는다.
- 시사점에는 자료 내용에서 나오는 의미와 추가로 확인할 점을 쓴다. 자료에 근거가 없는 전망이나 평가는 쓰지 않는다.

## 보고서

입력 자료 2건 이상을 주제 중심으로 종합한다.

- 현황이나 동향을 공유하는 보고서는 왜, 무엇, 어떻게 순서로 구성한다. 문제 해결이나 의사결정을 요청하는 보고서는 상황, 문제, 질문, 답 순서로 구성한다.
- 헤더 제목만 읽어도 아래 내용을 알 수 있게 짓는다.
- 자료끼리 내용이 다르면 각 자료의 내용을 출처와 함께 나란히 쓴다.
- 결론을 이끄는 주요 수치는 3개 이하로 고른다. 수치가 많으면 독자가 무엇을 기준으로 판단할지 흐려진다.
- 표는 요약이 필요한 곳에 3개 이하로 쓰고 주장 바로 뒤에 둔다. 표를 연달아 두지 않는다.
- 문장마다 어느 자료에서 왔는지 추적할 수 있게 출처를 단다.

## 번역본

번역 목표 언어는 사용자가 지정한 언어다. 지정이 없으면 사용자 언어로 번역한다. 원문이 이미 사용자 언어로 쓰였고 목표 언어가 정해지지 않았으면 목표 언어를 물어본다. 글의 성격에 따라 아래 방식 가운데 하나를 쓴다.

| 방식 | 대상 | 규칙 |
|---|---|---|
| 일반 번역 | 뉴스 보도, 공문, 매뉴얼, 논문, 회의록처럼 사실 전달이 중심인 글 | 원문 전체를 왜곡과 누락 없이 옮긴다. 마크다운과 불릿은 원문이 쓴 곳에만 쓴다 |
| 에세이 번역 | 에세이, 칼럼, 사설, 기고처럼 저자의 주장이 중심인 글 | 요약하지 않고 전체를 옮긴다. 본문은 존댓말(목표 언어의 정중한 문체)로 쓴다. 불릿은 저자가 구조화를 의도한 곳에만 쓴다. 맨 앞에 개요와 10줄 이내의 요약을 두며 이 부분은 존댓말을 쓰지 않는다 |

- 저자가 구조화를 의도한 곳은 콜론(:) 뒤에 항목을 나열하는 부분에서 자주 나타난다. 문장 흐름으로 이어지는 문단은 불릿으로 바꾸지 않는다.
- 번역본은 원문의 문체를 따르므로 "작성 문체" 절을 적용하지 않는다. 에세이 번역의 개요와 요약에는 적용한다.

## 변환본

- 스크립트를 `--max-chars` 없이 실행하고 결과 파일을 실행 환경의 파일 전달 방법으로 전달한다. 대화 응답에는 파일 목록과 글자 수만 적는다.
- PDF는 표가 있을 때만 `_tables.md`를 함께 전달한다.
- 사용자가 청크나 분할을 요청하면 `--chunk`를 쓴다. 기준 크기는 사용자가 정하지 않으면 2,000자다.

## 작성 문체

아래 규칙은 정리본 전체와 에세이 번역의 개요, 요약에 적용한다. 한국어가 아닌 언어로 쓸 때는 같은 원칙을 그 언어의 간결한 개조식 표현으로 적용한다.

- 개조식으로 쓰고 명사형으로 끝맺는다(예: "예산 감액 합의", "추가 검토 필요", "하반기 회복 전망"). 존댓말을 쓰지 않는다.
- 한 문장에는 한 메시지만 담는다. 한 문장 안에 행위 주체, 대상, 방법 가운데 하나가 두 번 나오면 문장을 나눈다.
- "그리고", "그러나", "-으며" 같은 연결어로 문장을 잇지 않는다. 쉼표는 같은 종류의 항목을 3개 이상 나열할 때만 쓴다.
- 대등한 명사 2개는 "와", "과" 대신 "및"으로 잇는다(예: "예산과 인력 확보"는 "예산 및 인력 확보"). 두 명사 사이의 관계(사이, 간, 격차, 차이, 일치, 불일치, 연계, 연동, 정렬, 비교, 구분, 분리, 협력)나 동작의 상대를 나타내는 "와", "과"는 그대로 둔다(예: "현행과 기준의 격차", "유관기관과 공유"). BSC의 "학습과 성장" 같은 관용 명칭의 "와", "과"도 그대로 둔다.
- 문장 앞 소제목은 괄호로 감싼다(예: "(예산 조정) 2분기 예산 감액 합의"). 콜론이나 하이픈으로 소제목을 붙이지 않는다. 소제목 이름은 내용을 드러내게 짓고 "설명", "근거"처럼 내용이 드러나지 않는 이름은 쓰지 않는다.
- 헤더 하나에는 주제 하나만 둔다. "A 및 B"처럼 두 주제를 묶은 헤더를 쓰지 않는다. 한 글 안에서는 키워드형이나 문장형 가운데 한 가지로 헤더 형식을 맞춘다.
- 하위 불릿(+)은 같은 수준의 항목이 2개 이상일 때만 쓴다. 1개뿐이면 상위 문장에 합친다.
- "A가 아니라 B" 같은 대비 구문, em dash 기호, 물결표(범위는 "-"로 표기), "3대 과제"처럼 개수를 미리 알리는 표현을 쓰지 않는다.
- "매우", "상당히" 같은 강조 부사와 "획기적", "혁신적" 같은 과장된 평가어를 쓰지 않는다.
- "본 보고서는", "요청하신 대로", "정리하면"처럼 글 자체나 작성 과정을 설명하는 문장을 쓰지 않는다.
- "에 있어서", "을 통하여", "하는 것이 필요" 같은 번역투 표현을 쓰지 않는다.
- 수치에는 출처를 붙인다. 출처는 `>` 블록에 "기관명 혹은 저자명(연도), 자료명(링크)" 형식으로 쓰고 출처가 여럿이면 블록을 나눈다.

## 산출 전 점검

- 산출물 유형이 요청과 "산출물 유형" 절의 기준에 맞는가
- 변환 결과 파일을 읽고 작성했는가
- 입력 자료의 주제가 빠짐없이 반영되었는가
- 입력 자료에 없는 주장, 평가, 수치, 계획이 들어가지 않았는가
- 교정한 표기가 교정 기준을 충족하는가
- 개요에 확인되지 않은 항목이 들어가지 않았는가
- 잘린 자료가 있다면 사용자에게 알렸는가
- 회의록의 주장마다 근거가 붙어 있는가
- 번역본에 누락된 문단이 없는가
- 작성 문체 규칙을 지켰는가
