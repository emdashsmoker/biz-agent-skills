## 사내 초거대AI 전사 확대 필요성

**핵심 메시지**
6주 시범 운영에서 품질팀의 문서 업무 시간이 61~76% 줄었고, 사내 서버 운영으로 보안 사고 없이 쓸 수 있다는 점도 확인했습니다. 다른 부서에서 먼저 사용을 요청하고 있어 확대를 추진할 시점입니다.

### 1. 시범 운영 개요

| 항목 | 내용 |
|---|---|
| 기간 | 2026. 11. 2.(월) ~ 12. 11.(금), 6주 |
| 참여 | 품질팀 3명 |
| 운영 방식 | 사내 서버 설치(온프레미스) |
| 적용 업무 | 과거 품질 문서 검색, 불량 원인 분석 보고서 초안 작성 |

### 2. 확대가 필요한 근거

**① 업무 시간이 크게 줄었다**

| 업무 | 도입 전 | 도입 후 | 건당 절감 | 절감률 |
|---|---|---|---|---|
| 과거 품질 문서 검색 | 25분 | 6분 | 19분 | 76% |
| 불량 원인 분석 보고서 초안 | 3시간 | 1시간 10분 | 1시간 50분 | 약 61% |

- 단순 검색 업무와 분석·작성 업무, 성격이 다른 두 업무에서 모두 효과가 나타남
- 문서를 찾고 쓰는 일은 설계, 기획 등 다른 부서에도 공통이므로 같은 효과를 기대할 수 있음

**② 현업이 계속 쓰고 싶어 한다**
- 참여자 3명 전원이 계속 사용 희망
- 시범으로 끝나지 않고 실제 업무에 정착할 수 있다는 신호

**③ 보안 우려를 해소했다**
- 모델을 사내 서버에 설치해 데이터가 외부로 나가지 않는 구조
- 6주간 보안 사고 0건
- 경영진이 가장 먼저 물을 질문에 대한 답이므로 앞부분에서 강조 권장

**④ 다른 부서의 자발적 수요가 있다**
- 설계팀과 기획팀이 먼저 사용을 요청
- 위에서 지시한 도입이 아니라 현업이 원하는 도입이므로 확대 시 정착이 빠를 가능성이 높음

### 3. 확대 추진 방식(제안)

- **1단계:** 사용을 요청한 설계팀, 기획팀에 우선 적용하고 시범 운영과 같은 방식으로 업무별 소요 시간 측정
- **2단계:** 1단계 결과를 확인한 뒤 전사로 확대하고 서버 용량, 사용 지침, 교육 체계 정비

요청 부서부터 넓혀 가면 "표본이 작다"는 지적에 대응하면서도 확대 속도를 늦추지 않을 수 있습니다.

### 4. 회의에서 나올 만한 질문

| 예상 질문 | 답변 방향 |
|---|---|
| 3명, 6주로 판단하기 충분한가? | 표본이 작은 점은 인정하고, 요청 부서 적용으로 추가 검증하겠다고 답변 |
| 절감 효과를 금액으로 환산하면? | 처리 건수 × 건당 절감 시간 × 인건비로 산출(건수 데이터 필요) |
| AI가 쓴 초안을 믿을 수 있나? | 초안은 AI가 쓰고 최종 판단과 검토는 담당자가 하는 구조임을 설명 |
| 확대하려면 비용이 얼마나 드나? | 서버 증설, 운영 인력, 교육 비용 산정 필요 |

### 5. 보고 전에 채워 두면 좋은 숫자

지금 자료만으로도 근거는 충분하지만, 아래 숫자가 있으면 설득력이 훨씬 커집니다.

- **6주간 처리 건수**(문서 검색 몇 건, 보고서 초안 몇 건): 있으면 "6주간 품질팀 3명이 총 OO시간 절약"처럼 한 문장으로 말할 수 있음
- **초안 작성 시간에 검토 시간이 포함됐는지 여부**: "1시간 10분"의 기준을 미리 확인
- **서버 구축·운영 비용**: 투자 대비 효과를 묻는 질문에 대비
