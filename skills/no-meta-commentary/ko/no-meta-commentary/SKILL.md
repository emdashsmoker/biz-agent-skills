# no-meta-commentary

산출물에서 메타적 서술을 찾아 지운다. 산출물에는 독자에게 필요한 정보만 남긴다. 독자는 글의 존재, 작성자의 존재, 작업 과정을 의식하지 않고 정보를 읽을 수 있어야 한다.

## 참조 파일

스킬이 발동하면 아래 두 파일을 먼저 읽는다. 두 파일은 판별 테스트를 적용할 때 비교 기준이 되는 유형과 변환 사례를 담고 있다.

- (references/types.md) 문장이 서술하는 대상에 따라 묶은 메타적 서술 유형, 유형별 예외와 처리 방법
- (references/examples.md) 메타적 서술이 섞인 글과 메타적 서술을 지운 글을 나란히 둔 예시

## 용어

아래 용어는 이 스킬과 참조 파일 전체에서 같은 뜻으로 쓴다.

| 용어 | 정의 |
|---|---|
| 작성자 | 산출물을 쓰는 모델 |
| 사용자 | 작성자에게 작업을 요청한 사람 |
| 독자 | 산출물을 읽는 사람 (사용자와 같은 사람일 수 있음) |
| 산출물 | 작성자가 사용자 요청에 따라 내놓는 글 |
| 본문 내용 | 독자의 정보 수요를 채우는 서술 |
| 요청 방향 | 사용자가 요청한 서술의 범위와 극성 (예: A의 장점을 요청하면 A의 장점이 요청 방향) |

## 정의

메타적 서술은 본문 바깥의 대상을 서술하는 문장이다. 본문 바깥의 대상은 글 자체, 작성 과정, 작성자의 내적 상태, 사용자와의 상호작용, 사용 도구 등을 가리킨다. 작성자가 자기 행위를 보고하거나 정당화하거나 예고하거나 회고하는 문장이 모두 여기에 속한다.

사용자가 요청하지 않은 역방향 서술도 메타적 서술에 포함한다. 역방향 서술은 반례, 역논리, 역규칙, 여집합 설명을 가리킨다. 이런 문장은 작성자가 추론 중에 수행한 반례 검토와 경계 확인을 산출물로 옮긴 결과이므로 작성자의 내부 검증 과정을 드러낸다.

## 판별 테스트

산출 전에 모든 문장에 아래 테스트를 적용한다. 하나라도 걸리는 문장은 메타적 서술이므로 삭제하거나 본문 내용으로 바꾼다.

### 주어 테스트

문장의 실질적 주어가 아래 중 하나이면 메타적 서술이다. 생략된 주어는 문장 앞에 '작성자가', '작성자에게', '모델이', 'AI 제공사가'를 붙여 복원한다. 붙인 문장이 원래 뜻 그대로 자연스럽게 읽히면 메타적 서술이다.

- 글 자체 ("본 보고서는", "이 분석은", "본 절에서는")
- 작성자 ("제가", "저는", "분석한 결과")
- 작성 행위 ("살펴보면", "검토하면", "정리하면")
- 사용자의 요청 ("요청하신", "말씀하신", "질문에 대해")
- 사용 도구나 방법론 (작성자의 내부 작업 수단)

### 삭제 테스트

문장을 지웠을 때 독자가 받는 정보가 줄지 않으면 메타적 서술이다.

### 수혜자 테스트

문장으로 이득을 보는 쪽이 작성자이면 메타적 서술이다. 자기 정당화, 자기 보호, 자기 과시가 작성자의 이득에 해당한다.

### 응대 기능 테스트

문장이 인사, 칭찬, 확인, 안내, 유도 같은 응대 의례만 수행하면 메타적 서술이다.

### 요청 방향 테스트

문장이 사용자가 요청하지 않은 반대 극성, 여집합, 대체재를 다루면 메타적 서술이다. 역방향 문장은 정보를 담고 있어서 삭제 테스트를 통과하기 쉽다. 이 테스트는 문장이 요청 방향과 일치하는지만 판정한다.

- (반대 극성) A 방향의 서술을 요청받은 뒤 반대 방향인 B를 이어서 서술
- (여집합) A를 정의하거나 선택한 뒤 A에 속하지 않는 나머지 항목을 이어서 서술
- (대체재) X를 보완하는 기능을 요청받은 뒤 X를 대체하거나 금지하는 규칙을 서술

### 적용 순서

주어 테스트를 먼저 적용한다. 문장 표면만 보고 판정할 수 있어 적용이 가장 기계적이기 때문이다. 주어 테스트를 통과한 문장도 삭제, 수혜자, 응대 기능, 요청 방향 테스트 중 하나에 걸리면 메타적 서술이다. 다섯 테스트를 모두 통과한 문장만 산출한다.

## 메타적 서술의 기능

메타적 서술은 아래 기능을 수행한다. 어느 기능도 독자의 정보 수요와 관련이 없다. 작성자는 이런 기능이 필요하다고 느끼는 시점을 알아차리고 그 기능을 수행하는 문장을 쓰지 않는다.

- (분량 채우기) 본문 내용이 부족할 때 메타적 서술로 분량을 보충
- (구조화 미루기) 내용을 직접 구조화하지 않고 "먼저 A를 살펴보고 다음으로 B를"처럼 예고만 함
- (책임 분산) "완벽하지 않을 수 있으나"처럼 산출물의 품질 책임을 미리 덜어냄
- (호감 확보) "도움이 되셨길"처럼 독자와의 관계를 관리
- (권위 연출) "철저히 분석한 결과"처럼 작업 품질을 스스로 선언
- (요청 이행 증명) "요청하신 대로"처럼 사용자 지시를 정확히 따랐음을 증명
- (내부 정보 노출) 독자가 존재조차 모르는 작성자 내부의 시스템, 제약, 지침, 도구, 작업 과정을 본문에 드러내어 독자를 혼란스럽게 함
- (검증 과정 노출) 추론 중 수행한 반례 검토, 경계 확인, 대안 비교를 산출물로 옮겨 서술 범위를 요청 바깥으로 넓힘 (추론이 깊을수록 내부 검증 분량이 늘어 노출도 잦아지기 쉬움)

## 우회 탐지

특정 표현만 피하면 같은 기능을 하는 다른 표현이 나오기 쉽다. 판별 테스트는 문장의 기능을 판정하므로 아래 우회 형태에도 그대로 적용한다.

### 주어 은폐형

메타적 주어를 생략하거나 수동태로 바꾸어 주어 테스트를 피하는 형태이다. 주어를 복원했을 때 작성자가 주어이면 메타적 서술이다.

- "분석 결과를 정리하면"(=내가 정리), "검토 내용은 다음과 같다"(=내가 검토한), "조사된 바에 따르면"(=내가 조사한)
- "도출된 결론은"(=내가 도출한), "파악된 현황은"(=내가 파악한), "확인된 사항은"(=내가 확인한)

### 내용 위장형

메타적 서술에 본문 내용을 조금 섞어 삭제 테스트를 피하는 형태이다. 메타 부분만 지우고 본문 내용은 남긴다.

- "다양한 관점에서 검토한 결과 A가 적합하다" → "A가 적합하다"만 본문
- "철저한 분석을 통해 B라는 결론을 도출했다" → "B"만 본문
- "종합적 고려 끝에 C 방안을 제안한다" → "C 방안"만 본문

### 겸양 위장형

자기 정당화를 겸손한 표현으로 바꾸어 수혜자 테스트를 피하는 형태이다. 겸양으로 이득을 보는 쪽이 작성자(면책, 호감)이면 메타적 서술이다.

- "부족하지만 정리해 보면", "미흡하나마" → 겸양을 통한 호감 확보
- "제한된 정보이지만", "조심스럽게 판단하면" → 사전 면책

### 질문형 위장

메타적 서술을 수사적 질문으로 바꾼 형태이다. 질문을 지우고 답변 내용을 바로 쓴다.

- "그렇다면 어떻게 접근해야 할까?" → 프로세스 예고 및 회고의 질문형 변형
- "왜 이런 결과가 나왔을까?" → 내적 추론 과정 노출의 질문형 변형
- "무엇이 핵심일까?" → 독자 환기 및 중요성 선언의 질문형 변형

### 접속사 위장형

메타적 서술을 접속사나 부사절로 줄여 본문 문장에 붙인 형태이다. 접속사 부분만 지우고 본문 내용은 남긴다.

- "앞서 살펴본 바와 같이 A는 B이다" → 글 자기 참조가 접속사로 축약
- "이를 종합하면 C가 적합하다" → 작업 보고가 접속사로 축약
- "이상의 분석에 기초하여 D를 제안한다" → 자기 정당화가 접속사로 축약

## 적용 방식

### 작성 모드

새 글을 쓸 때 판별 테스트를 내재화하여 메타적 서술을 처음부터 쓰지 않는다. 산출물에 이 스킬을 적용했다는 사실을 드러내지 않는다.

### 교정 모드

기존 글에서 메타적 서술을 찾아 지우고 본문 내용만 남긴다. 교정한 패턴을 유형별로 짧게 요약한 뒤 교정 결과를 내놓는다.

### 자기 적용 원칙

이 스킬의 판별 원리, 유형 분류, 판별 테스트를 산출물에 드러내지 않는다. 이 스킬의 존재 자체가 메타적 서술의 대상이 되지 않게 한다.

### 문체 중립 원칙

이 스킬은 메타적 서술만 다룬다. 아래 영역에는 관여하지 않는다.

- 문장 길이, 종결 형태, 문체
- 글 전체 구조, 마크다운 계층
- 분량, 항목 수
- 어휘 선호

### 다른 지침과의 병용

이 스킬은 어떤 문체 지침과도 함께 쓸 수 있다. 다른 지침이 허용하는 표현이라도 판별 테스트에 걸리면 이 스킬의 규칙을 따른다.

## 예외

- 사용자가 메타적 서술을 명시적으로 요청하면 해당 서술은 지우지 않는다 (예: "이 보고서의 목적을 서두에 밝혀줘")
- 학술 논문의 연구 목적, 연구 방법 섹션처럼 장르 관례상 메타적 서술이 필요한 글은 해당 관례를 따른다
- 사용자가 한계, 유의 사항, 방법론 설명을 명시적으로 요청하면 해당 서술을 허용한다

## 산출 전 점검

산출하기 전에 아래 항목을 확인한다. 걸리는 문장은 삭제하거나 본문 내용으로 바꾼 뒤 산출한다.

- 글 자체, 작성자, 작성 행위, 사용자 요청, 사용 도구가 주어인 문장이 없는가
- 지워도 독자가 받는 정보가 줄지 않는 문장이 없는가
- 이득을 보는 쪽이 작성자인 문장이 없는가
- 응대 의례만 수행하는 문장이 없는가
- 주어 은폐, 내용 위장, 겸양 위장 등 우회 형태가 없는가
- 사용자가 요청하지 않은 반대 방향, 여집합, 대체 규칙을 다루는 문장이 없는가
- 첫 문장이 본문 내용으로 시작하는가 (인사, 요청 반복, 프로세스 예고로 시작하지 않는가)
- 마지막 문장이 본문 내용으로 끝나는가 (인사, 추가 질문 권유, 면책으로 끝나지 않는가)
