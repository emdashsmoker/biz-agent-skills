# 메타적 서술 유형

아래 유형은 판별 테스트를 적용할 때 비교 기준으로 쓰는 예시이며 전체 목록이 아니다. 목록에 없는 문장도 판별 테스트에 걸리면 메타적 서술이다. 특정 표현만 피하면 같은 기능의 다른 표현이 나오기 쉬우므로 문장의 표면 형태보다 판별 테스트가 확인하는 기능을 따른다.

모든 유형의 처리 방법은 같다. 메타적 서술을 지우고 본문 내용으로 바로 들어간다. 유형별 예외와 처리 방법이 따로 적힌 경우에는 해당 내용을 함께 따른다.

유형은 문장이 서술하는 대상을 기준으로 묶는다.

## 글을 서술하는 문장

글의 목적, 범위, 구조, 위치, 형태를 서술하는 유형이다.

### 글 자기 참조

글 자체를 주어로 삼아 글의 목적, 범위, 구조, 위치를 선언하는 서술

- "본 보고서는 X를 분석한다", "이 글의 목적은", "본 절에서는 Z를 다룬다"
- "앞서 언급한 바와 같이", "위 내용을 종합하면", "아래에서 상세히 설명한다"

### 프로세스 예고 및 회고

작성 순서를 독자에게 안내하거나 완료된 작업을 회고하는 서술

- "먼저 A를 살펴보고 다음으로 B를 분석하겠다", "이상으로 A를 살펴보았다"
- "결론적으로 말하면", "요약하자면", "이제 본론으로 들어가면"

### 전환 수사

섹션 사이의 전환을 메타적 언급으로 처리하는 서술

- "이제 다음 주제로 넘어가면", "이와 관련하여", "추가적으로" (전환 목적으로만 사용)
- "이를 바탕으로" (실질적 연결 없이 전환 목적만), "한편" (내용상 대비 없이 전환 목적만)

### 반복 요약

본문에서 이미 서술한 내용을 다시 요약하거나 재진술하는 서술. 삭제 테스트를 통과하지 못한다.

- "다시 정리하면", "이상의 내용을 요약하면", "종합하면" (이미 서술한 내용의 재진술)
- "다시 한번 강조하면", "거듭 말씀드리면", "반복하지만"

### 산출물 형태 자기 설명

산출물의 형식, 구조, 배치를 독자에게 설명하는 서술

- "아래 표로 정리했습니다", "다음과 같이 분류할 수 있습니다"
- "시간순으로 정리하면 다음과 같습니다", "차트로 시각화하면"

### 범위 고백

작업 범위를 벗어났음을 고백하거나 범위 제한을 스스로 선언하는 서술

- "본래 범위를 벗어나지만", "부수적인 내용이지만", "참고로"
- "이번에는 A만 다루겠습니다", "B는 별도로 분석이 필요합니다" (사용자 미요청 시)

### 병렬 나열 후 총괄 선언

항목을 나열한 뒤 나열했다는 사실을 다시 총괄하여 선언하는 서술. 이미 나열한 항목의 존재를 재선언하므로 삭제 테스트를 통과하지 못한다.

- "이처럼 A, B, C 등 다양한 요인이 존재한다" (이미 A, B, C를 나열한 뒤)
- "이상과 같이 여러 측면에서 검토하였다"

### 동어 반복형 도입

본문의 첫 문장을 도입부에서 같은 말로 미리 예고하는 서술

- "핵심은 A이다. A에 대해 설명하면" → "A에 대해 설명하면" 부분이 메타적 서술
- "결론부터 말하면 B이다. B에 대해 구체적으로 보면" → 뒷부분 삭제

## 작성 과정을 서술하는 문장

작성자가 수행한 작업, 추론, 탐색, 선택, 수정을 서술하는 유형이다.

### 작업 자랑 및 완료 보고

작성자가 수행한 작업의 양, 질, 완료 여부를 보고하는 서술

- "철저히 분석한 결과", "다양한 관점에서 검토하여", "면밀히 검토한 결과"
- "분석을 완료했습니다", "정리가 완료되었습니다", "다각도에서 분석하면"

### 내적 추론 과정 노출

결론에 이르는 내적 사고 과정을 독자에게 보고하는 서술

- "여러 가능성을 검토한 결과", "다양한 각도에서 살펴본 결과", "숙고한 결과"
- "A와 B를 비교 검토하여 B가 적합하다고 판단", "여러 대안을 검토했으나"

### 방법론 및 내부 도구 자기 노출

작성에 쓴 사고 도구, 프레임워크, 내부 도구를 본문에 직접 인용하는 서술

- "웹 검색을 통해 확인한 결과", "Python 코드를 실행하여 계산한 결과"
- "MECE 원칙에 따라 분류하면", "피라미드 구조로 작성하면", "스킬을 적용하여"
- (예외) 사용자가 방법론이나 도구 사용 여부를 명시적으로 질문한 경우에 한해 허용

### 작업 순서 보고

과거 시제로 작업 절차를 나열하여 작업 과정을 보고하는 서술. 주어를 복원하면 모두 작성자이다.

- "우선 A를 확인했고 그다음 B를 검토했으며 마지막으로 C를 분석했습니다"
- "1단계로 데이터를 수집하고 2단계로 분석을 수행했습니다"

### 선택 근거 자기 보고

여러 대안 중 특정 방향을 고른 작성자의 내적 판단 과정을 보고하는 서술

- "여러 방법 중 A를 선택한 이유는", "B 대신 C를 채택한 것은"
- "이 방식을 택한 배경은" → A나 C가 적합한 근거를 직접 서술

### 정보 탐색 과정 보고

정보를 찾아본 과정 자체를 독자에게 보고하는 서술

- "조사해 본 결과", "찾아본 바에 따르면", "확인해 본 결과"
- "자료를 살펴보니", "검색 결과", "관련 문헌을 검토한 결과"

### 작업 의도 선언

작성자가 특정 서술 방식을 택한 의도를 독자에게 설명하는 서술

- "명확하게 전달하기 위해", "이해를 돕기 위해", "혼동을 방지하기 위해"
- "가독성을 위해 표로 정리하면", "비교를 용이하게 하기 위해"

### 자기 수정 보고

이전 서술의 오류를 발견하고 고치는 과정을 독자에게 보고하는 서술

- "정정하면", "앞서 말씀드린 내용을 수정하면", "다시 생각해보니"
- (처리) 수정한 내용만 바로 서술

### 작업 난관 보고

정보 부족, 자료 제한 등 작업 과정의 어려움을 독자에게 보고하는 서술

- "정확한 데이터를 찾기 어려웠으나", "자료가 제한적이지만"
- "공개된 정보가 많지 않아", "접근 가능한 자료의 범위 내에서"

### 비교 과정 노출

비교한 행위 자체를 보고하는 서술. 비교 결과는 본문 내용으로 바로 쓴다.

- "A와 B를 비교해 보면", "양자를 대조하면", "상호 비교 분석을 수행하면"

### 관점 전환 보고

작성자가 관점을 바꾸는 행위 자체를 독자에게 보고하는 서술

- "다른 각도에서 접근하면", "시각을 바꿔서 보면"
- "수요자 관점에서 재해석하면", "거시적으로 조망하면"

### 시도 선언

작업을 수행하겠다는 의사를 미리 선언하는 서술. 시도한 결과를 바로 제시한다.

- "시도해보겠습니다", "한번 해보면", "접근해보겠습니다", "작성해보겠습니다"

## 작성자를 서술하는 문장

작성자의 자기 평가, 태도, 감정, 내부 사정을 서술하는 유형이다.

### 자기 정당화

산출물의 품질, 정합성, 완전성을 작성자가 스스로 평가하고 선언하는 서술

- "체계적으로 분류하면", "누락 없이 전체를 포괄하는 분류", "균형 잡힌 시각에서"
- "객관적으로 판단하면", "공정하게 평가하면", "엄밀히 따지면"

### 지적에 대한 해명

사용자의 지적에 고친 내용 대신 작성자의 의도나 이전 발언을 변호하는 서술. 수혜자는 작성자(책임 축소)이다. 해명을 지우고 고친 내용을 쓴다.

- "그런 의도는 아니었습니다", "앞서 말씀드리려던 요지는"
- "그렇게 말한 적은 없습니다" 등

### 사전 면책 및 한계 자기 노출

사용자가 요청하지 않았는데도 산출물의 한계, 불완전성, 추가 검토 필요성을 스스로 선언하는 서술

- "완벽하지 않을 수 있으나", "더 자세한 분석이 필요할 수 있으나"
- "본 분석의 한계로는", "전문가의 추가 검토가 필요", "이 분석은 현 시점 기준이며 향후 변동 가능"
- (예외) 사용자가 한계를 명시적으로 요청하거나 정보 신뢰성에 실질적 영향을 미치는 중대한 불확실성이면 허용

### 감정 연출

작성자의 감정이나 평가적 태도를 부사로 주입하여 독자의 반응을 유도하는 서술. 수혜자는 작성자(서사 통제, 반응 유도)이다. 사실이 충분히 전달되면 독자가 스스로 판단한다.

- "안타깝게도", "다행히도", "흥미롭게도", "놀랍게도", "당연하게도"
- "우려스럽게도", "고무적인 것은"

### 난이도 및 복잡성 평가

주제의 난이도를 작성자가 평가하여 보고하는 서술. 내용을 쉽게 쓰면 난이도를 따로 평가할 필요가 없다.

- "이 문제는 상당히 복잡한데", "간단히 설명하면", "쉽게 말하면"
- "단순화하면", "복잡한 문제이지만 핵심만 추리면"

### 가정 과잉 선언

자명한 전제나 사용자가 이미 설정한 전제를 과도하게 명시적으로 선언하는 서술

- "A라고 가정하겠습니다" (자명한 전제), "B라는 전제 하에" (사용자가 이미 설정한 전제)
- (예외) 분석 결과에 실질적 영향을 미치는 비자명한 수치 가정("기준 환율을 1달러당 1,300원으로 가정" 등)은 본문 내용

### 출처 과잉 해설

출처 자체의 권위나 신뢰도를 작성자가 따로 해설하는 서술. 출처의 신뢰도는 독자가 출처명을 보고 판단한다.

- "신뢰할 수 있는 기관에서 발행한 보고서에 따르면"
- "권위 있는 학술지에 게재된 연구에 의하면", "공신력 있는 조사 결과"

### 조건부 유보 남발

결론에 조건절을 과도하게 붙여 명확성을 흐리는 서술. 사전 면책 및 한계 자기 노출이 문장 안으로 들어간 변형이다.

- "물론 A라는 전제 하에서이고 B도 고려해야 하며 C의 변수도 있지만 결론은 D이다"
- "단정할 수는 없으나", "속단하기 이르지만"

### 작성자 전용 정보 노출

독자가 존재조차 모르는 작성자 내부의 시스템, 제약, 지침, 도구, 내부 상태, 작업 과정 세부를 본문에 드러내는 서술. 공지 사실 재서술은 독자가 이미 아는 정보를 되풀이하는 유형이고 이 유형은 독자가 알 수도 없고 알 필요도 없는 정보를 드러내는 유형이다. 독자에게 정보 가치를 주지 못하고 혼란만 일으킨다.

- "학습 데이터 수집 시점 이후의 정보라서", "제 훈련 데이터에는 해당 정보가 포함되어 있지 않아"
- "컨텍스트 윈도우의 제한으로 인해", "토큰 수 제한으로 전체를 다루기 어려워"
- "시스템 프롬프트에 따라", "사용자 설정 지침에 의해"
- "3개의 검색 결과를 종합하면", "2개의 출처를 교차 검증한 결과" (내부 작업 과정의 수치 노출)
- "이 작업에는 여러 스킬이 적용되었습니다", "해당 스킬을 로드하여 처리"
- "JSON 상태 파일에 기록하여", "Python 스크립트로 계산한 뒤"
- "제가 직접 확인할 수는 없지만", "실시간 정보에 접근할 수 없어"
- "이 질문은 제 지식 범위 내에서", "제 역량으로는"
- (판별 기준) 독자가 해당 정보를 알게 되었을 때 독자의 의사결정이나 이해에 기여하는지 확인하며 기여하지 않으면 작성자 전용 정보
- (예외) 사용자가 내부 작업 방식, 제약, 도구 사용 여부를 명시적으로 질문한 경우에 한해 허용

### 응답 어조 메타

응답의 어조나 말투를 작성자가 스스로 해설하는 서술

- "솔직히 말씀드리면", "조심스럽게 말씀드리면", "단도직입적으로"
- "너무 딱딱했나요", "친근하게 표현하자면", "부드럽게 말씀드리면"

## 읽는 사람을 향한 문장

사용자의 요청을 되풀이하거나 독자의 상태, 기대, 행동, 관계를 다루는 유형이다.

### 사용자 요청 반복

사용자가 입력한 요청을 재서술하거나 요청의 존재를 언급하는 서술

- "요청하신 대로", "말씀하신 것처럼", "질문에 대해 답변드리면"
- "주신 자료를 검토한 결과", "업로드해 주신 파일을 확인한 결과", "지시하신 조건에 맞추어"

### 독자 환기 및 중요성 선언

독자의 주의를 인위적으로 환기하거나 중요성을 따로 선언하는 서술. 내용이 실제로 중요하면 독자가 내용에서 중요성을 판단한다. 중요성을 따로 선언하는 문장은 내용의 힘이 부족할 때 작성자가 보충하는 문장이다.

- "주목할 점은", "여기서 핵심은", "강조할 부분은", "중요한 것은"
- "특히 눈여겨볼 부분은", "간과해서는 안 될 점은", "반드시 알아야 할 점은"

### 인사 및 관계 관리

독자와의 관계를 만들거나 유지하려는 의례적 서술

- "도움이 되셨길 바랍니다", "추가 질문이 있으시면 말씀해 주세요"
- "좋은 질문입니다", "감사합니다" (의례적 사용)

### 능력 광고 및 조건부 제안

작성자의 추가 능력을 광고하거나 사용자가 요청하지 않은 추가 작업을 조건부로 제안하는 서술. 수혜자는 작성자(능력 과시, 관계 유지)이다.

- "필요하시면 더 자세히 설명드리겠습니다", "원하시면 추가 분석도 가능합니다"
- "표로 정리해 드릴 수도 있습니다", "더 구체적인 사례가 필요하시면"
- "원하시면 -해 드릴까요", 내용을 밝히지 않고 예고만 하는 "더 효과적인 방법이 하나 더 있습니다" 등

### 이행 수단 없는 후속 약속

작업 환경에서 이행 수단을 확인할 수 없는 후속 작업을 약속하는 서술. 수혜자는 작성자(미완료 은폐)이다. 이번 응답에서 수행한 결과와 수행하지 못한 내용을 쓴다.

- "몇 시간 뒤에 파일을 보내드리겠습니다", "지금 작성 중이니 완성되면 알려드리겠습니다" 등

### 독자 상태 추정

독자의 인지 상태, 감정 상태, 이해도를 작성자가 임의로 추정하여 서술

- "혼란스러우실 수 있지만", "이해하기 어려울 수 있으나", "생소하실 수 있는데"
- "이미 아시겠지만", "예상하셨겠지만", "궁금하셨을 텐데", "의아하실 수 있으나"
- "충분히 화가 나실 만합니다", "그렇게 느끼시는 것이 당연합니다" 등

### 독자 기대 관리

독자의 기대 수준을 작성자가 미리 조정하려는 서술. 수혜자는 작성자(실망 예방, 책임 분산)이다.

- "기대하신 것과 다를 수 있지만", "예상과 다른 결과일 수 있으나"
- "단순한 답이 아닐 수 있지만"

### 독자 행동 지시

독자에게 특정 행동을 지시하는 서술. 수혜자는 작성자(권위 연출, 지시적 관계 형성)이다.

- "참고하시기 바랍니다", "유의하시기 바랍니다", "고려해 보시기 바랍니다"
- "염두에 두시기 바랍니다", "확인해 보시기 바랍니다"

### 동의 및 승인 표현

사용자의 판단이나 질문을 작성자가 평가하거나 승인하는 서술. 수혜자는 작성자(호감 확보)이다.

- "좋은 접근입니다", "올바른 방향입니다", "적절한 판단입니다"
- "정확하게 짚으셨습니다", "맞습니다" (동의 표시만으로 사용)
- "핵심을 찌르셨습니다", "깊이 있는 질문입니다", "통찰력 있는 지적입니다" 등
- 근거를 확인할 수 없는 사용자 평가("상위 1% 수준입니다" 등), 반박이나 거절 앞에 붙인 동의("맞는 말씀입니다. 다만" 등)

### 사용자 의도 추측 보고

사용자의 의도를 추정한 과정 자체를 보고하는 서술. 의도는 내부에서 추정하고 결과만 제시한다.

- "아마도 X를 원하시는 것 같아", "X를 의도하시는 것으로 이해했습니다"
- "X를 궁금해하시는 것 같은데", "X를 알고 싶으신 거라면"
- 사용자의 발언을 다시 규정하는 "말씀하신 내용은 A가 아니라 B입니다", "결국 B를 원하시는 것입니다" 등 (사용자가 쓴 표현을 그대로 받아 답한다)

### 확인 및 재확인 의례

독자의 이해 여부나 만족 여부를 확인하는 의례적 서술. 응대 기능 테스트를 통과하지 못한다.

- "잘 보셨나요", "이해되시나요", "어떠신가요"
- "혹시 이 부분이 맞나요", "이렇게 해석해도 될까요", "맞게 이해한 건가요"

## 본문처럼 보이는 문장

본문 내용처럼 보이지만 독자에게 새 정보가 없거나 요청 범위를 벗어난 유형이다.

### 공지 사실 재서술

독자가 이미 아는 정보를 교과서 정의처럼 나열하여 분석을 대신하는 서술

- "AI란 인공지능의 약자로서" (AI 보고서의 독자 대상), "SWOT이란 강점, 약점, 기회, 위협을" (전략 보고서의 독자 대상)
- (판별 기준) 대상 독자가 해당 글을 읽는 상황에서 이미 가진 지식이면 공지 사실

### 구체성 없는 배경 선언

실질 정보 없이 배경만 선언하는 서술. 구체적 내용이 뒤따르면 선언 부분만 지운다.

- "현재 상황을 고려하면" (구체적 상황 미명시), "최근 트렌드를 감안하면" (구체적 트렌드 미명시)
- "글로벌 환경 변화 속에서", "시대적 요구에 부응하여"

### 대상 재정의형

분석 대상을 "X란 무엇인가"로 다시 정의하며 분석 진입을 늦추는 서술. 공지 사실 재서술과 결합하여 서두 분량을 채우는 경우가 많다.

- "디지털 전환이란 무엇인가?", "먼저 개념부터 정리하면"
- "정의를 명확히 하면" (대상 독자에게 자명한 개념)

### 요청하지 않은 역방향 서술

사용자가 요청한 서술의 반대 극성, 여집합, 대체재를 요청 없이 덧붙이는 서술. 반례, 역논리, 역규칙이 대표 형태이다. 수혜자는 작성자(완결성 과시, 서술 경계 방어)이다. 요청 방향 테스트를 통과하지 못한다.

- (보완 기능의 대체 전환) X를 보완하는 Y 기능의 추가 요청에 "Y를 기본으로 사용하고 X는 사용하지 않는다"를 덧붙임
- (반대 방향 대응 추가) A 방향의 서술을 요청받은 뒤 반대 방향인 B의 대응 방향을 이어서 서술
- (비해당 사유 나열) B, C, D, E와 구분되는 A의 정의를 작성한 직후 B, C, D, E가 A의 정의에 부합하지 않는 이유를 이어서 서술
- (미선택 요인 나열) SWOT 분석으로 SO 전략을 도출한 뒤 ST, WO, WT 전략의 요인을 이어서 서술
- (처리) 역방향 검토는 내부 검증에만 활용하고 산출물에는 요청 방향의 결과만 서술

### 요청하지 않은 단서와 반박

결론을 바꾸지 않는 단서나 사용자가 하지 않은 주장에 대한 반박을 요청 없이 덧붙이는 서술. 수혜자는 작성자(오류 책임 회피)이다. 요청 방향 테스트를 통과하지 못한다.

- (드문 예외의 단서) "다만 모든 경우에 해당하지는 않습니다" 등
- (내용 없는 정정 예고) "한 가지는 바로잡겠습니다", "하나만 짚고 가겠습니다" 등
- (극단화 반박) 사용자가 하지 않은 극단적 주장을 세운 뒤 반박하는 "그렇게 일반화하면 사실과 다릅니다" 등
- (처리) 결론이나 독자의 결정을 바꾸는 조건, 예외, 사실 오류의 정정은 본문 내용이므로 결론 아래에 한 번 서술
