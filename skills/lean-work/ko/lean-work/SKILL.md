# 린 워크

목적에 기여하는 요소만 남기고 남은 요소를 충분히 수행하거나 설명하는 작업 방식을 정의한다. 적용 대상은 작업 절차와 표현이다.

언어 모델의 산출물에는 떠올린 단계와 보유한 정보를 선별 없이 모두 내놓는 문제가 자주 나타난다. 작업 절차에서는 사용자의 시간, 예산, 인력을 넘어서는 과잉 절차가 나온다. 표현에서는 독자가 읽을 대상을 스스로 골라야 하는 백화점식 나열이 나온다. 이 스킬은 두 문제를 요소 선별이라는 같은 방법으로 다룬다.

## 용어 정의

아래 용어는 이 스킬 안에서 표에 적은 뜻으로만 쓴다.

| 용어 | 정의 |
|------|------|
| 목적 | 최종 산출물을 받은 독자가 내릴 판단이나 실행할 행동 |
| 독자 | 최종 산출물을 읽거나 실행하는 사람. 사용자가 지정하지 않으면 일반적인 성인 독자 |
| 범위 | 최종 산출물이 다루는 대상의 경계 |
| 최종 산출물 | 작업이 끝났을 때 독자가 받는 결과물. 작업 절차에서는 절차를 모두 수행한 뒤 나오는 결과물 |
| 요소 | 판별의 최소 대상. 작업 절차에서는 단계, 표현에서는 문장, 불릿, 표의 행, 차트 계열, 슬라이드 구성 항목 |
| 단계 | 입력을 받아 산출물 1개를 내는 작업 |
| 과잉 절차 | 판별 조건을 통과하지 못한 단계가 남아 있는 작업 절차 |
| 단위 | 독자가 한 번에 보고 소화하는 표현 구획. 슬라이드 1장, 차트나 다이어그램 1개, 문단 1개, 표 1개 |
| 메시지 | 한 단위를 본 독자가 기억해야 할 판단문 1개 |
| 판단문 | 주어와 서술을 갖추고 독자가 동의하거나 반박할 수 있는 문장 |
| 주제 라벨 | 판단 없이 대상만 가리키는 제목. 예를 들어 "시장 현황", "추진 배경", "주요 이슈" |
| 백화점식 나열 | 메시지 없이 관련 정보를 같은 비중으로 늘어놓은 표현 |
| 메시지 과적 | 한 단위에 독립 주장이 2개 이상 들어간 상태 |

## 작동 순서

1. (기준 확정) 목적, 독자, 범위를 정한다
2. (모드 선택) 산출물 종류에 맞는 모드를 고른다
3. (요소 판별) 모든 요소에 판별 조건을 적용한다
4. (모드 규칙 적용) 탈락한 요소를 처리하고 선택한 모드의 규칙으로 산출물을 만든다
5. (산출 전 점검) 점검 목록을 확인한 뒤 산출한다

## 기준 확정

요소 판별은 목적에 비추어 요소의 필요 여부를 가리는 작업이다. 목적, 독자, 범위가 정해져야 같은 요소에 같은 판별 결과가 나온다.

- 목적, 독자, 범위를 한 문장씩 정한다. 사용자가 이미 정한 항목은 그대로 쓴다.
- 요청과 주어진 자료에서 읽어낼 수 있는 항목은 추정하여 정한다. 추정에 따라 산출물이 달라지는 항목은 사용자에게 확인한다.
- 작업 절차를 다룰 때는 사용자가 밝힌 제약 조건(기한, 예산, 인력, 보유 자료, 사용 도구, 권한)을 함께 정리한다.
- 한 번 정한 기준과 용어는 산출물 끝까지 같은 뜻으로 쓴다.

## 모드 선택

| 모드 | 산출물 | 적용 규칙 |
|------|--------|-----------|
| 작업 절차 | 문제 해결, 기획, 분석, 조사, 코딩 등에서 사용자에게 제안하는 절차와 모델이 직접 수행하려고 세우는 계획 | 작업 절차 규칙 |
| 표현 | 답변, 문서, 슬라이드, 차트, 다이어그램, 표 | 표현 규칙 |

- 두 모드 모두 새로 만드는 작성과 기존 산출물을 고치는 교정을 지원한다. 교정은 교정 절차를 따른다.
- 작업을 수행한 뒤 결과 문서까지 내는 요청은 계획에 작업 절차 규칙을 적용하고 결과 문서에 표현 규칙을 적용한다.
- 작업 절차를 제안하는 답변의 문장에는 표현 규칙의 문장 선별을 함께 적용한다.
- 사용자나 다른 지침이 출력 구조(표 양식, 평가 등급, 정해진 워크플로우 등)를 지정하면 그 구조를 유지한다. 이때는 구조 안의 각 단계와 각 항목에 요소 판별을 적용한다.

## 요소 판별

요소는 적용 대상인 조건을 모두 통과해야 남는다. 통과 기준은 제3자가 같은 결과를 낼 수 있도록 확인할 수 있는 사실로 적는다.

| 조건 | 적용 대상 | 판별 질문 | 통과 기준 |
|------|-----------|-----------|-----------|
| 필수성 | 작업 단계 | 이 단계를 빼면 최종 산출물이 달라지는가 | 단계의 산출물이 쓰이는 뒤 단계나 최종 산출물의 위치를 지목할 수 있다 |
| 실행 가능성 | 작업 단계 | 사용자가 가진 자원과 제약 안에서 실행할 수 있는가 | 단계에 필요한 시간, 예산, 인력, 자료, 도구, 권한이 모두 사용자가 밝힌 범위 안에 있다 |
| 비례성 | 작업 단계 | 들이는 노력이 얻는 가치에 걸맞은가 | 단계의 노력이 그 산출물의 쓰임에 걸맞다. 최종 산출물의 결론을 바꿀 수 있는 근거를 만드는 단계에 큰 노력을 배정하고 보조 근거를 만드는 단계에 작은 노력을 배정한다 |
| 메시지 기여 | 표현 요소 | 이 요소를 지우면 메시지 전달이 약해지는가 | 요소가 메시지의 이유, 근거, 사례, 세부 내용 중 하나를 맡고 다른 요소와 내용이 겹치지 않는다 |
| 독자 관련성 | 표현 요소 | 독자가 아직 모르고 알아야 할 이유가 있는 정보인가 | 독자가 처음 접하는 정보이며 독자의 판단이나 행동에 쓰인다 |

- 작업 단계는 필수성, 실행 가능성, 비례성 순서로 판별한다. 필수성에서 탈락한 단계는 나머지 조건을 따질 필요가 없다.
- 실행 가능성의 결과가 제약 조건에 따라 달라지는데 그 조건이 불명확하면 사용자에게 확인한 뒤 진행한다.
- 사용자가 제약 조건을 밝혔다면 그 조건을 실행 가능성의 통과 기준으로 쓴다.

## 작업 절차 규칙

작업 절차는 목표 달성에 필요한 최소 단계로 구성한다.

### 단계 처리

탈락한 단계는 아래 순서로 처리한다. 삭제를 먼저 검토하면 삭제할 단계를 다듬는 데 드는 노력을 아낄 수 있다.

1. (삭제) 필수성을 통과하지 못한 단계는 삭제한다
2. (병합) 수행 내용은 필요하지만 다른 단계와 동시에 수행되거나 한 작업 안에서 끝나는 단계는 그 단계에 합쳐 하나로 쓴다
3. (축소) 필수성을 통과했으나 실행 가능성이나 비례성을 통과하지 못한 단계는 같은 쓰임의 산출물을 더 적은 자원으로 내는 방법으로 바꾼다

| 탈락한 단계 | 축소한 단계 |
|-------------|-------------|
| 이해관계자 전체 인터뷰 | 담당자 1명에게 해석이 갈리는 항목만 확인 |
| 전수 조사 | 표본 조사 |
| 신규 자료 수집 | 사용자가 보유한 자료 활용 |

축소할 방법이 없는 단계는 필요한 자원을 사용자에게 알리고 진행 여부를 확인한다.

### 단계 작성

- 사용자가 정한 문제, 목적, 방향은 그대로 받아들인다. 절차는 그 뒤의 작업부터 시작한다.
- 단계는 수행 행동으로 쓴다. 절차의 의의, 배경, 기대효과를 설명하는 문장은 생략한다. "다음과 같은 프로세스를 제안한다", "본 단계에서는 자료를 수집한다", "이를 통해 효율을 높일 수 있다"가 생략 대상이다.
- 법률, 규정, 안전에 걸린 단계는 판별 결과와 관계없이 유지한다. 이런 단계는 최종 산출물에 직접 기여하지 않아도 생략하면 제재나 사고로 이어진다.
- 모델이 직접 수행하는 작업의 계획에도 같은 조건을 적용한다. 요청받은 범위를 수행하고 요청에 없는 부가 작업(추가 파일, 추가 분석, 추가 기능)은 필수성을 통과할 때만 수행한다.
- 모듈 수와 단계 수는 판별을 통과한 단계에 맞춘다. 통과한 단계가 적으면 모듈 1개로 쓴다.

### 절차 재점검 신호

아래 신호가 1개 이상 보이면 해당 단계에 요소 판별을 다시 적용한다.

- 산출물이 뒤 단계의 입력이나 최종 산출물 어디에도 쓰이지 않는 단계가 있다
- 산출물 이름을 구체적으로 적을 수 없는 단계가 있다
- 사용자가 이미 정한 문제, 목적, 방향을 다시 정하는 단계가 있다
- 한 번의 작업으로 끝나는 일이 여러 단계로 나뉘어 있다
- 사용자가 밝히지 않은 자원(추가 인력, 추가 예산, 외부 기관의 협조, 유료 자료)을 전제로 한 단계가 있다
- 요청과 주어진 자료만으로 최종 산출물을 만들 수 있는데 추가 조사 단계(벤치마킹, 인터뷰, 설문, 워크숍)가 들어 있다
- 보조 근거를 만드는 단계가 절차에서 가장 큰 노력을 차지한다

### 출력 포맷

별도 지정이 없으면 아래 포맷으로 출력한다. 내용 칸에는 수행 행동만 쓴다.

```
## Module N. 모듈명
- (목적) 한 줄 서술

| Task | Input | 내용 | Output |
|------|-------|------|--------|
| N-1. Task명 | 입력 자료명 또는 목록 | 수행 행동 | 산출물명 또는 목록 |
| N-2. Task명 | 입력 자료명 또는 목록 | 수행 행동 | 산출물명 또는 목록 |
```

## 표현 규칙

모든 단위는 메시지를 1개 전달한다. 백화점식 나열은 읽을 대상을 고르는 부담을 독자에게 넘긴다. 메시지 과적은 단위가 전하려는 내용을 독자가 알 수 없게 만든다. 두 문제는 보유한 정보를 선별 없이 모두 배치할 때 생긴다.

### 메시지 확정

- 산출물을 단위 목록으로 나눈다.
- 단위마다 "이 단위를 본 독자가 기억해야 할 한 문장은 무엇인가"에 답한다.
- 답을 아래 두 시험으로 확인한다.

| 시험 | 질문 | 결과 |
|------|------|------|
| 판단문 시험 | 독자가 이 문장에 동의하거나 반박할 수 있는가 | 할 수 있으면 판단문이다. 대상만 가리켜 동의나 반박이 성립하지 않으면 주제 라벨이다 |
| 독립 주장 시험 | 두 주장 중 하나가 다른 하나의 이유, 근거, 사례, 세부 내용인가 | 그렇다면 메시지 1개와 그 지지 요소다. 어느 쪽도 다른 쪽을 뒷받침하지 않으면 독립 주장 2개다 |

- 답이 없거나 답이 주제 라벨이면 메시지가 없는 상태다. 판단문을 세우거나 단위를 삭제한다.
- 독립 주장이 2개 이상이면 메시지 과적이다. 슬라이드를 추가하거나 문단을 나누거나 차트를 분할하여 단위를 나눈다.
- "시장 현황"은 주제 라벨이고 "저가 제품 유입으로 국내 시장의 수익성 하락"은 판단문이다.
- "해외산 저가 제품의 유입으로 평균 판매 가격 하락"은 "국내 시장의 수익성 하락"의 근거이므로 두 문장은 메시지 1개를 이룬다. "국내 시장의 수익성 하락"과 "규제 특례 제도 시행으로 신규 서비스 허용"은 서로 뒷받침하지 않으므로 독립 주장 2개다.

### 메시지 위치

메시지는 단위의 머리에 둔다. 독자는 머리에서 읽은 메시지를 기준으로 나머지 요소를 해석한다.

| 단위 | 메시지를 담는 위치 |
|------|--------------------|
| 슬라이드 | 헤드메시지 문장 |
| 차트, 다이어그램 | 제목 |
| 표 | 표 제목 또는 표 바로 위의 문장 |
| 문단 | 첫 문장. 나머지 문장은 첫 문장을 뒷받침 |

- 문장형 헤더는 헤더가 메시지를 직접 담고 본문 첫 문장은 근거로 시작한다.
- 키워드형 헤더는 메시지의 대상을 예고하고 본문 첫 문장이 판단문을 담는다.
- 헤더가 예고한 대상과 첫 문장의 메시지가 다르면 헤더 이름을 바꾸거나 내용을 옮긴다.

### 구성요소 선별

메시지를 뒷받침하는 구성요소는 단위당 3-4개 이하를 기본으로 한다. 사람이 한 번에 기억에 담아 둘 수 있는 항목 수에는 한계가 있어서 항목이 늘수록 항목 하나에 돌아가는 주의가 줄어든다.

- 선별한 구성요소는 서로 겹치지 않고 메시지의 서로 다른 내용을 맡는다.
- 2개로 충분한 내용은 2개로 쓴다.
- 4분면 매트릭스나 5단계 프로세스처럼 개수가 정해진 프레임워크는 고유 개수를 유지한다.
- 5개 이상이 필요해 보이면 아래 순서로 처리한다.

1. 메시지가 섞였는지 독립 주장 시험으로 확인하고 메시지가 2개 이상이면 단위를 나눈다
2. 하위 항목을 상위 범주 3-4개로 모으고 세부 내용은 하위 수준으로 옮긴다
3. 메시지 기여 조건을 통과하지 못한 항목을 삭제한다

압축은 요소를 골라내는 방식으로 한다. 요소를 모두 남긴 채 문장만 줄이면 서술 밀도만 올라가고 독자가 처리할 항목 수는 그대로 남는다. 골라낸 뒤 남은 요소는 충분한 분량으로 설명한다. 삭제 후보는 아래 순서로 검토한다.

1. 메시지와 무관한 정보
2. 독자가 이미 아는 배경 설명
3. 같은 결론을 반복해서 뒷받침하는 근거
4. 독자의 판단에 쓰이지 않는 장식성 수치와 사례

탈락한 요소는 아래 기준으로 처리한다.

- 기본 처리는 삭제다. 작성에 들인 노력은 요소를 남길 이유가 되지 못한다.
- 독립된 메시지로 가치가 있으면 별도 단위로 분리한다.
- 참조 가치만 있으면 부록, 각주, 별첨으로 옮긴다.
- 본문에는 내용을 온전히 설명한 요소만 둔다. 이름만 언급하고 내용을 생략한 요소는 삭제, 분리, 이동 중 하나로 처리한다.

### 강조 배치

강조 지점은 단위당 1개로 정한다. 강조 지점이 여러 개이면 독자의 시선이 나뉘어 메시지가 약해진다.

- 단위 안의 요소는 메시지, 지지 요소, 세부 내용 순서로 비중을 달리하여 배치한다.
- 슬라이드와 디자인은 크기, 위치, 색으로 시선을 유도하고 나머지 요소는 작은 크기와 낮은 채도로 처리한다.
- 차트는 강조 계열 1개만 부각하고 비교 계열은 낮은 채도로 처리한다. 데이터 라벨은 메시지와 관련된 지점에 붙인다.
- 표는 메시지와 관련된 행이나 열 1개를 굵은 글씨나 색으로 구분한다.
- 모든 요소가 같은 비중이면 강조 지점이 없는 상태로 보고 다시 배치한다.

### 문장 선별

문장도 메시지 기여와 독자 관련성을 통과해야 남는다. 모든 문장은 독자에게 새 정보를 전달한다.

- 첫 문장은 답이나 메시지로 시작하고 마지막 문장은 본문 내용으로 끝낸다. "좋은 질문입니다" 같은 서론, "먼저 A를 설명하고 다음으로 B를 설명한다" 같은 예고, "도움이 되셨길 바랍니다" 같은 마무리 인사는 삭제 대상이다.
- 이미 전달한 내용의 반복 요약, 질문 범위를 벗어난 관련 지식, 요청받지 않은 대안과 추가 옵션은 삭제 대상이다.
- 답변 항목이 여러 개이면 3-4개 이하로 선별한다. 사용자가 전수 나열을 요청하면 모두 나열한다.
- 불확실성은 해당 내용이 처음 나오는 문장에서 1회 밝힌다.
- 불릿 1개에는 메시지 1개를 담는다. 불릿이 한국어 100자 안팎이나 영어 15단어 안팎을 넘으면 독립 주장 시험을 다시 적용한다. 메시지가 1개로 확인되면 길이를 그대로 둔다.

### 표현 재점검 신호

아래 신호가 1개 이상 보이면 단위를 다시 구성한다.

- 같은 수준에 나란히 놓인 항목이 5개 이상 있다
- 한 문단에 독립 주장을 담은 문장이 2개 이상 있다
- 제목이나 헤드가 주제 라벨에 머문다
- 모든 항목이 같은 시각 비중과 서술 분량으로 배치되어 강조 지점이 없다
- 원인과 결과, 현상과 대책, 사실과 의견처럼 성격이 다른 요소가 한 나열에 섞여 있다
- 헤더가 예고한 대상과 본문 첫 문장의 메시지가 다르다
- "이 단위에서 기억할 한 문장"에 답할 수 없다

## 교정 절차

기존 산출물을 고칠 때 적용한다.

1. 기존 산출물의 목적, 독자, 범위를 확인한다
2. (작업 절차) 단계마다 판별 조건을 적용하고 탈락한 단계를 삭제, 병합, 축소 순서로 처리한다
3. (표현) 단위별 메시지를 모두 추출하여 메시지가 없는 단위와 메시지 과적 단위를 찾는다. 메시지 과적 단위는 나누고 구성요소는 기준 이내로 선별한다
4. 남은 문장에 문장 선별을 적용한다
5. 교정 결과를 산출하고 처리한 단계나 단위마다 진단 요지를 짧게 덧붙인다

## 산출물 공통 규칙

- 산출물에는 독자에게 전달할 내용만 담는다. 이 스킬의 적용 사실, 규칙 이름, 점검 과정은 교정 절차의 진단 요지에서만 언급한다.
- 문체와 종결 형태, 어휘 선택, 거시 구조와 목차 구성, 마크다운 포맷은 사용자나 다른 지침을 따른다. 이 스킬은 단계와 요소의 선별, 메시지 배치, 강조 배치에 관여한다.

## 예시

아래 예시의 기관, 제품, 상황은 모두 가상이다.

### 작업 절차

(요청) 지난달 직원 설문 원자료 엑셀로 경영진 보고 자료를 만드는 절차를 요청. 기한은 이번 주이며 담당자는 1명

(before)

```
1. 보고 목적 재정의
2. 국내외 설문 분석 사례 벤치마킹
3. 분석 프레임워크 설계
4. 데이터 정제
5. 기술 통계 산출
6. 교차 분석
7. 이해관계자 인터뷰
8. 시사점 도출
9. 보고서 초안 작성
```

(처리) 보고 목적은 사용자가 이미 정했으므로 재정의 단계를 삭제했다. 벤치마킹과 프레임워크 설계는 산출물이 집계나 보고 자료에 쓰이지 않아 필수성에서 탈락하여 삭제했다. 기술 통계와 교차 분석은 한 번의 집계 작업에서 끝나므로 병합했다. 이해관계자 인터뷰는 결과 해석을 확인하는 데 쓰이지만 담당자 1명이 이번 주 안에 수행하기 어려워 설문 담당자 확인으로 축소했다. 시사점 도출은 메시지 선정 단계에 병합했다.

(after)

```
## Module 1. 설문 결과 집계
- (목적) 경영진의 결정이 필요한 설문 결과 확인

| Task | Input | 내용 | Output |
|------|-------|------|--------|
| 1-1. 데이터 정제 | 설문 원자료 엑셀 | 무응답과 중복 응답 제거 | 정제 데이터 |
| 1-2. 결과 집계 | 정제 데이터 | 문항별 응답 분포와 부서별 차이 집계 | 집계표 |

## Module 2. 보고 자료 작성
- (목적) 경영진이 한 번 읽고 결정할 수 있는 자료 작성

| Task | Input | 내용 | Output |
|------|-------|------|--------|
| 2-1. 메시지 선정 | 집계표 | 경영진의 결정이 필요한 결과 3-4개 선정, 해석이 갈리는 결과는 설문 담당자에게 확인 | 메시지 목록 |
| 2-2. 자료 작성 | 메시지 목록 | 메시지마다 슬라이드 1장 작성 | 보고 자료 |
```

(before)

```
(제목) 시장 현황
- 국내 시장 규모 정체
- 주요 사업자 다수 경쟁
- 해외산 저가 제품 유입 증가
- 규제 특례 제도 시행으로 신규 서비스 허용
- 소비자 인식 개선 필요
- 유통 구조 복잡
- 신기술 도입 지연
```

(진단) 제목이 주제 라벨이다. 같은 수준의 항목이 7개다. 수익성 하락, 제도 변화, 산업 구조 문제라는 독립 주장이 섞여 있고 강조 지점이 없다.

(after, 분리한 첫 슬라이드)

```
(헤드메시지) 저가 제품 유입과 다자 경쟁으로 국내 시장의 수익성 하락
- 다수 사업자가 정체된 시장에서 경쟁하면서 가격 인하 압박 심화
- 해외산 저가 제품의 유입 증가로 평균 판매 가격 하락
- 시장 규모가 정체되어 판매량 증가로 수익성 하락을 메우기 어려운 상황
```

(처리) 수익성 하락을 뒷받침하는 요소 3개만 남겼다. 규제 특례 제도는 기회 요인을 다루는 다음 슬라이드로 분리했다. 소비자 인식, 유통 구조, 신기술 지연은 이 메시지에 기여하지 않아 삭제하거나 별첨으로 옮겼다.

### 문단

(before)

```

출시가 늦어지는 동안 경쟁 구도가 불리해지고 있다. 경쟁사는 유사 제품을
먼저 출시하여 초기 수요를 가져갔다. 마케팅 예산도 당사보다 크게 운영한다.

대응의 첫 순서는 조달처 다변화다. 부품 수급이 안정되어야 출시 일정 단축과

```


## 예외

- 사용자가 "더 자세히", "구체적으로", "상세 프로세스", "전체 단계"를 요청하면 요청한 범위에서는 최소 단계 기준과 개수 기준을 해제한다.
- 사용자가 전수 나열이나 상세 목록을 요청하면 요청한 범위에서는 개수 기준을 해제한다.
- 법령, 규정, 점검표처럼 빠짐없는 목록이 목적인 산출물은 개수 기준을 해제하고 강조 배치 규칙만 적용한다.
- 개수가 정해진 프레임워크와 표준 양식은 고유 개수를 유지한다.
- 인용문, 원문 전재, 코드 본문은 적용 대상에서 제외한다. 코드 앞뒤의 설명 문장에는 적용한다.

## 산출 전 점검

- (공통) 목적, 독자, 범위가 정해져 있고 기준과 용어가 산출물 끝까지 같은 뜻으로 쓰였는가
- (공통) 산출물에 이 스킬의 적용 사실이나 규칙 이름이 드러나지 않는가
- (작업 절차) 모든 단계의 산출물이 뒤 단계의 입력이나 최종 산출물에 쓰이는가
- (작업 절차) 모든 단계가 사용자가 밝힌 제약 조건 안에서 실행되는가
- (작업 절차) 탈락한 단계를 삭제, 병합, 축소 순서로 처리했는가
- (작업 절차) 사용자가 정한 문제, 목적, 방향이 그대로 쓰였는가
- (작업 절차) 법률, 규정, 안전에 걸린 단계가 남아 있는가
- (작업 절차) 절차 재점검 신호에 해당하는 단계가 없는가
- (표현) 모든 단위의 메시지가 판단문 시험을 통과하고 단위마다 메시지가 1개인가
- (표현) 메시지가 단위의 머리에 있는가
- (표현) 단위당 구성요소가 3-4개 이하인가 (프레임워크 고유 개수와 예외 항목은 제외)
- (표현) 요소를 골라내는 방식으로 압축했고 남은 요소를 충분히 설명했는가
- (표현) 탈락한 요소를 삭제, 분리, 이동 중 하나로 처리했는가
- (표현) 단위마다 강조 지점이 1개인가
- (표현) 첫 문장이 답이나 메시지로 시작하고 마지막 문장이 본문 내용으로 끝나는가
- (표현) 표현 재점검 신호에 해당하는 단위가 없는가
