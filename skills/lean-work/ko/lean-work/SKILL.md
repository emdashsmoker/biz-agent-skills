# 린 워크

독자의 목적에 기여하지 않는 요소를 걸러내고 남은 요소를 충분히 설명하는 작업 방식을 정의한다. 요소를 거르기 전에 목적, 독자, 범위를 먼저 정한다. 무엇이 필요한지는 이 기준이 서야 판단할 수 있다.

적용 대상은 작업 절차와 표현이다. 작업 절차는 목표 달성에 필요한 최소 단계로 구성한다. 표현은 슬라이드, 차트, 문단 같은 단위마다 메시지를 1개씩 전달하도록 구성한다. 두 대상 모두 같은 판별 조건으로 요소를 가리고 제거, 결합, 재배열, 단순화 순서로 처리한다.

## 용어 정의

아래 용어는 이 스킬 안에서 표에 적은 뜻으로만 쓴다.

| 용어 | 정의 |
|------|------|
| 목적 | 산출물을 받은 독자가 내리거나 실행할 판단과 행동 |
| 독자 | 산출물을 읽거나 실행하는 사람. 사용자가 지정하지 않으면 해당 분야의 배경지식이 없는 일반 성인 |
| 범위 | 산출물이 다루는 대상의 경계 |
| 요소 | 판별과 처리의 최소 대상. 작업 절차의 요소는 작업 단계이고 표현의 요소는 문장, 불릿, 표의 행, 차트 계열, 슬라이드 구성 항목 등의 표현 요소 |
| 단위 | 독자가 한 번에 보고 소화하는 표현 구획. 슬라이드 1장, 차트나 다이어그램 1개, 문단 1개, 표 1개 |
| 메시지 | 한 단위를 본 독자가 기억해야 할 판단문 1개. 주어와 서술을 갖춘 문장 |
| 주제 라벨 | 판단 없이 대상만 가리키는 제목. 예를 들어 "시장 현황", "추진 배경", "주요 이슈" |
| 백화점식 나열 | 메시지 없이 관련 정보를 같은 비중으로 늘어놓은 표현 |
| 메시지 과적 | 한 단위에 독립 주장이 2개 이상 들어 있는 상태 |
| ECRS | 작업 연구(work study)에서 쓰는 개선 순서. 제거(Eliminate), 결합(Combine), 재배열(Rearrange), 단순화(Simplify)의 머리글자 |

## 작동 순서

1. (기준 확정) 목적, 독자, 범위를 정하고 전제를 검증한다
2. (모드 선택) 산출물 종류에 맞는 모드를 고른다
3. (판별과 처리) 선택한 모드의 절차 안에서 모든 요소를 판별하고 ECRS 순서로 처리한다
4. (산출 전 점검) 점검 목록을 확인한 뒤 산출한다

## 기준 확정

판단 기준이 흔들리면 남길 요소와 지울 요소도 함께 흔들린다. 요소를 거르기 전에 아래 항목을 확정한다.

- 왜 필요한지, 무엇을 만드는지, 어떻게 만드는지를 먼저 답한다.
- 목적, 독자, 범위를 한 문장씩 정한다. 사용자가 이미 정한 항목은 다시 정의하지 않는다.
- 한 번 정한 정의와 판단 기준은 산출물 끝까지 같은 뜻으로 쓴다. 같은 대상을 여러 이름으로 부르지 않는다.
- 사용자 요청에 담긴 전제와 모델 자신의 지식을 모두 검증 대상으로 둔다. 상식, 권위, 유명한 프레임워크, 유행어, 마케팅 용어는 그 자체로 근거가 되지 못한다.
- 문제가 주어지면 원인을 거슬러 올라가 사용자가 조치할 수 있는 가장 깊은 원인을 찾는다. 개선안은 그 원인에서 도출한다.
- 결론은 배경지식이 없는 제3자가 근거를 따라가며 납득할 수 있어야 한다. 말장난이나 뜻이 비어 있는 표현으로 설명을 대신하지 않는다.
- 검증의 깊이는 그 판단이 결론에 미치는 영향에 맞춘다. 결론을 바꾸지 못하는 세부 사항은 깊이 따지지 않는다.

## 모드 선택

| 모드 | 산출물 | 따르는 절차 |
|------|--------|-------------|
| 작업 설계 | 문제 해결, 기획, 분석, 조사, 코딩 등의 작업 절차 | 작업 설계 절차 |
| 표현 | 답변, 문서, 슬라이드, 차트, 다이어그램 | 표현 절차 |

- 두 모드는 새로 쓰는 작성과 기존 산출물을 고치는 교정으로 나뉜다. 교정은 교정 절차를 따른다.
- 한 요청이 작업 절차와 표현을 모두 요구하면 작업 설계 절차로 절차를 정한 뒤 그 절차의 산출물에 표현 절차를 적용한다.
- 사용자나 다른 지침이 출력 구조(표 양식, 평가 등급, 정해진 워크플로우 등)를 지정하면 그 구조를 유지한다. 이때는 구조 안의 각 항목과 각 단계에 요소 판별과 ECRS 처리를 적용한다.

## 요소 판별

모든 요소는 아래 조건을 통과해야 그대로 남는다. 조건마다 적용 대상이 다르다.

| 조건 | 판별 질문 | 적용 대상 |
|------|-----------|-----------|
| 필수성 | 이 요소를 지우면 메시지 전달이나 산출물 품질이 낮아지는가 | 모든 요소 |
| 독자 관련성 | 독자가 아직 모르는 정보이며 독자가 알아야 할 이유가 있는가 | 표현 요소 |
| 실행 가능성 | 사용자가 가진 자원과 제약 안에서 실행할 수 있는가 | 작업 단계 |
| 비례성 | 투입하는 노력이 얻는 가치보다 작은가 | 작업 단계 |

- 실행 가능성을 판단할 제약 조건(기한, 예산, 인력, 보유 자료와 도구)이 불명확하면 사용자에게 확인한 뒤 진행한다. 사용자가 밝힌 제약 조건은 실행 가능성의 판단 기준으로 쓴다.
- 법률, 규정, 안전처럼 민감도가 높은 단계는 판별 결과와 관계없이 유지한다. 이런 단계는 생략했을 때의 손실이 절감하는 노력보다 크다.

## ECRS 처리

판별을 마친 요소는 아래 네 가지 질문을 표의 순서대로 거친다. 해당하지 않는 질문은 처리 없이 넘어간다.

| 순서 | 질문 | 작업 단계의 처리 | 표현 요소의 처리 |
|------|------|------------------|------------------|
| 1. 제거 (Eliminate) | 이 요소가 없어도 목적이 달성되는가 | 필수성을 통과하지 못한 단계를 삭제한다 | 메시지를 뒷받침하지 않는 요소와 독자가 이미 아는 요소를 삭제한다. 다른 단위나 부록에서 쓰일 요소는 재배열로 넘긴다 |
| 2. 결합 (Combine) | 다른 요소와 합쳐 한 번에 처리할 수 있는가 | 동시에 수행되거나 한 작업 안에서 끝나는 단계를 하나로 합친다 | 같은 범주의 항목을 상위 범주로 묶는다 |
| 3. 재배열 (Rearrange) | 순서나 위치를 바꾸면 재작업이나 독자의 탐색이 줄어드는가 | 뒤 단계의 내용을 정하는 단계를 앞으로 옮긴다 | 메시지를 단위의 머리로 옮기고 제거에서 넘어온 요소를 다른 단위나 부록으로 옮긴다 |
| 4. 단순화 (Simplify) | 더 단순한 수단이나 형태로 같은 결과를 얻을 수 있는가 | 사용자가 보유한 자료, 양식, 도구를 쓰는 방법으로 바꾼다 | 강조 지점을 1곳으로 정하고 나머지 요소의 시각 비중을 낮춘다 |

- (순서의 이유) 제거할 요소를 합치거나 다듬는 노력은 결과에 남지 않는다. 제거를 먼저 끝낸 뒤 남은 요소에 결합, 재배열, 단순화를 적용한다.
- (제거의 출발점) 제거 여부는 산출물을 직접 만드는 핵심 단계부터 검토한다. 핵심 단계가 제거되면 그 단계를 준비하거나 점검하는 부속 단계도 함께 제거된다.
- (노력이 큰 필수 단계) 필수성은 통과했으나 실행 가능성이나 비례성을 통과하지 못한 단계는 결합과 단순화로 노력을 줄인 뒤 다시 판별한다. 다시 판별해도 통과하지 못한 단계는 제거한다.
- (제거 전 확인) 제거하면 목표 달성이 어려워지는 단계는 제거하기 전에 사용자에게 확인한다.
- (남은 요소의 서술) 네 가지 처리를 마치고 남은 요소는 충분한 분량으로 다룬다. 네 가지 처리는 요소 수를 줄여 남은 요소에 독자의 주의를 모으려고 수행한다.

## 작업 설계 절차

작업 설계 모드는 목표 달성에 필요한 최소 단계만 제시한다. 모델은 사용자의 시간, 비용, 자원을 고려하지 않고 단계를 늘린 절차를 제안하기 쉬우므로 모든 단계에 요소 판별과 ECRS 처리를 적용한다.

1. 최종 산출물, 사용자가 가진 입력 자료, 제약 조건을 확인한다
2. 최종 산출물에 이르는 단계를 나열하고 단계마다 입력과 산출물을 적는다
3. 모든 단계에 요소 판별과 ECRS 처리를 적용한다
4. 남은 단계를 출력 포맷에 맞춰 쓴다

### 단계 처리 기준

- (제거) 사용자가 정한 문제 정의와 방향을 절차의 출발점으로 쓴다. 문제를 다시 정의하는 단계와 방향을 다시 탐색하는 단계는 제거한다.
- (결합) 동시에 수행되거나 한 작업 안에서 자연스럽게 끝나는 단계는 하나로 쓴다. 같은 입력 자료를 같은 방법으로 처리하는 단계도 하나로 쓴다.
- (재배열) 앞 단계의 산출물을 입력으로 쓰는 단계는 그 단계 뒤에 둔다.
- (재배열) 결과에 따라 뒤 단계의 범위나 방법이 달라지는 단계는 앞에 둔다. 이런 단계를 뒤에 두면 앞서 만든 산출물을 다시 만들게 된다.
- (재배열) 같은 목적을 가진 단계는 한 모듈에 모은다.
- (단순화) 사용자가 이미 가진 자료, 양식, 도구로 수행하는 방법을 먼저 고른다. 새로 만드는 방법은 보유 자원으로 목적을 달성하기 어려울 때 고른다.
- (단순화) 수행 범위와 정밀도는 목적이 요구하는 수준에 맞춘다.

### 서술 기준

- 절차에는 수행할 행동만 쓴다. 절차의 의의, 배경, 기대효과를 설명하는 문장은 제거 대상이다. "다음과 같은 프로세스를 제안한다", "본 단계에서는 자료를 수집한다", "이를 통해 효율을 높일 수 있다" 같은 문장이 여기에 해당한다.
- 모듈 수는 판별 조건을 통과하는 범위에서 정한다.
- 모델이 직접 수행하는 작업의 수행 계획에도 같은 판별과 처리를 적용한다. 출력 포맷은 사용자가 절차를 요청한 경우에 쓴다.

### 출력 포맷

별도 지정이 없으면 아래 포맷으로 출력한다. 내용 칸에는 수행 행동만 쓴다.

```
## Module N. 모듈명
- (목적) 한 줄 서술

| Task | Input | 내용 | Output |
|------|-------|------|--------|
| N-1. Task명 | 입력 자료명 또는 목록 | 수행 행동 | 산출물명 또는 목록 |
| N-2. Task명 | 입력 자료명 또는 목록 | 수행 행동 | 산출물명 또는 목록 |
```

## 표현 절차

표현 모드에서 모든 단위는 메시지를 정확히 1개 전달한다. 백화점식 나열은 무엇을 볼지 고르는 부담을 독자에게 넘긴다. 메시지 과적은 그 단위가 무엇을 말하는지 독자가 알 수 없게 만든다. 두 문제는 전달할 요소를 고르지 않고 가진 정보를 모두 배치할 때 생긴다.

1. 산출물을 단위 목록으로 나눈다
2. 단위마다 메시지를 판단문 1개로 확정한다
3. 단위 안의 요소에 요소 판별과 ECRS 처리를 적용한다
4. 백화점식 나열 신호를 점검한 뒤 산출한다

### 메시지 확정

- 단위마다 "이 단위를 본 독자가 기억해야 할 한 문장은 무엇인가"에 답한다.
- 답이 없으면 메시지가 없는 상태다. 판단문을 세우거나 단위를 삭제한다.
- 답에 독립 주장이 2개 이상 이어지면 메시지 과적이다. 슬라이드를 추가하거나 문단을 나누거나 차트를 분할하여 단위를 나눈다.
- 주제 라벨은 판단을 담지 않으므로 메시지로 인정하지 않는다. 메시지 예시는 "저가 제품 유입으로 국내 시장의 수익성 하락"처럼 주어와 서술을 갖춘 판단문이다.

### 메시지 위치

재배열의 첫 대상은 메시지다. 메시지는 단위의 머리에 둔다.

- 슬라이드는 헤드메시지 문장이 메시지를 담는다.
- 차트는 제목이 메시지를 담는다.
- 문단은 첫 문장이 메시지를 담는다. 나머지 문장은 첫 문장만 뒷받침한다.
- 문장형 헤더는 헤더가 메시지를 직접 담고 본문 첫 문장은 근거로 시작한다.
- 키워드형 헤더는 메시지의 대상을 예고하고 본문 첫 문장이 판단문을 담는다.
- 헤더가 예고한 대상과 첫 문장의 메시지가 다르면 헤더 이름을 바꾸거나 내용을 옮긴다.

### 구성요소 선별

메시지를 뒷받침하는 구성요소는 단위당 3-4개 이하를 기본값으로 한다. 사람이 한 번에 붙잡아 둘 수 있는 정보 묶음 수에는 한계가 있어서 항목이 늘수록 항목 하나에 돌아가는 주의가 줄어든다.

이 단위의 메시지를 뒷받침하지 않는 요소는 아래 세 가지 중 하나로 처리를 끝낸다. 본문에 이름만 남기고 내용을 생략하는 처리는 세 가지에 포함되지 않으므로 쓰지 않는다.

| 처리 | ECRS 순서 | 적용 조건 |
|------|-----------|-----------|
| 삭제 | 제거 | 기본 처리. 작성에 들인 노력은 요소를 남기는 이유가 되지 못함 |
| 분리 | 재배열 | 독립된 메시지로 가치가 있는 요소를 별도 단위로 옮김 |
| 이동 | 재배열 | 참조 가치만 있는 요소를 부록, 각주, 별첨으로 옮김 |

삭제 후보는 아래 순서로 검토한다.

1. 메시지와 무관한 정보
2. 독자가 이미 아는 배경 설명
3. 같은 결론을 반복해서 뒷받침하는 근거
4. 판단에 기여하지 않는 장식성 수치와 사례

남은 구성요소는 아래 기준으로 정리한다.

- (결합) 제거를 마친 뒤에도 항목이 5개 이상이면 메시지가 2개 이상 섞였는지 먼저 확인하고 섞였으면 단위를 나눈다. 메시지가 1개이면 하위 항목을 상위 범주 3-4개로 묶고 세부 내용은 하위 계층으로 옮긴다.
- (재배열) 원인과 결과, 현상과 대책, 사실과 의견처럼 성격이 다른 요소는 성격별로 나누어 배치한다.
- 선별한 구성요소는 서로 겹치지 않고 메시지의 서로 다른 부분을 맡는다.
- 구성요소 수는 메시지가 요구하는 만큼만 둔다. 2개로 충분한 내용은 2개로 끝낸다.
- 4분면 매트릭스나 5단계 프로세스처럼 개수가 정해진 프레임워크는 고유 개수를 유지한다.

압축은 요소 수를 줄이는 방식으로 한다. 요소를 모두 남긴 채 문장만 줄이면 서술 밀도만 올라가고 독자가 처리할 항목 수는 그대로 남는다.

### 강조 배치

표현 요소의 단순화는 독자가 먼저 볼 지점을 1곳으로 정하고 나머지 요소의 시각 부담을 줄이는 처리다.

- 단위 안의 요소는 메시지, 지지 요소, 세부 순서로 비중을 달리하여 배치한다.
- 강조 지점은 단위당 1곳으로 정한다.
- 슬라이드와 디자인은 크기, 위치, 색으로 시선을 유도하고 나머지 요소는 작은 크기와 낮은 채도로 처리한다.
- 차트는 강조 계열 1개만 부각하고 비교 계열은 낮은 채도로 처리한다. 데이터 라벨은 메시지와 관련된 지점에만 붙인다.
- 메시지 구별에 쓰이지 않는 색, 선, 장식은 줄인다.
- 모든 요소가 같은 비중이면 강조 지점이 없는 상태로 보고 다시 배치한다.

### 백화점식 나열 신호

아래 신호가 1개 이상 보이면 단위를 다시 구성한다.

- 같은 계층에 병렬 항목이 5개 이상 있다
- 한 문단에 독립 주장을 담은 문장이 2개 이상 있다
- 제목이나 헤드가 주제 라벨에 머문다
- 모든 항목이 같은 시각 비중과 서술 분량으로 배치되어 강조 지점이 없다
- 원인과 결과, 현상과 대책, 사실과 의견처럼 성격이 다른 요소가 한 나열에 섞여 있다
- 헤더가 예고한 대상과 본문 첫 문장의 메시지가 다르다
- "이 단위에서 기억할 한 문장"에 답할 수 없다

## 교정 절차

기존 산출물을 고칠 때 적용한다. 교정 결과에는 진단 요지를 짧게 덧붙여 사용자가 변경 이유를 확인하게 한다.

### 작업 절차의 교정

1. 기존 절차의 단계마다 입력과 산출물을 파악한다
2. 모든 단계에 요소 판별과 ECRS 처리를 적용한다
3. 교정한 절차를 산출하고 제거, 결합, 재배열, 단순화한 단계와 이유를 짧게 덧붙인다

### 표현의 교정

1. 단위별 메시지를 모두 추출하여 단위마다 메시지 개수를 진단한다
2. 메시지가 2개 이상인 단위는 나누고 메시지가 없는 단위는 판단문을 세우거나 삭제한다
3. 단위 안의 요소에 요소 판별과 ECRS 처리를 적용한다
4. 교정 결과를 산출하고 단위별 진단 요지를 짧게 덧붙인다

## 산출물 공통 규칙

- 산출물에 이 스킬의 적용 사실, 규칙 이름, 점검 과정을 드러내지 않는다. 교정 절차의 진단 요지는 예외로 한다.
- 문체와 종결 형태, 어휘 선택, 개별 문장의 길이, 거시 구조와 목차 구성, 마크다운 포맷은 사용자나 다른 지침을 따른다. 이 스킬은 작업 단계의 선별과 순서, 표현 요소의 선별, 메시지와 강조의 배치에 관여한다.

## 예시

아래 예시의 기관, 제품, 상황은 모두 가상이다. 처리 설명에는 해당하는 처리만 적었다.

### 작업 설계

(요청) 지난달 직원 설문 원자료 엑셀로 경영진 보고 자료를 만드는 절차를 짜 달라는 요청. 분기마다 쓰는 경영진 보고 양식이 있음

(before)

```
1. 보고 목적 재정의
2. 국내외 설문 분석 사례 벤치마킹
3. 분석 프레임워크 설계
4. 데이터 정제
5. 기술 통계 산출
6. 교차 분석
7. 이해관계자 인터뷰
8. 시사점 도출
9. 보고서 구성 신규 설계
10. 경영진 보고 양식 확인
11. 보고서 초안 작성
```

(처리)

- (제거) 보고 목적은 사용자가 이미 정했으므로 재정의 단계를 삭제했다. 벤치마킹, 프레임워크 설계, 인터뷰는 지워도 설문 결과 보고의 품질이 유지되므로 삭제했다.
- (결합) 기술 통계와 교차 분석은 한 번의 집계 작업에서 끝나므로 합쳤다.
- (재배열) 보고 양식 확인을 첫 단계로 옮겼다. 양식이 집계 항목을 정하므로 뒤에 두면 집계를 다시 하게 된다.
- (단순화) 보고서 구성을 새로 설계하는 단계는 기존 보고 양식을 쓰는 방법으로 바꿔 자료 작성 단계에 합쳤다. 전체 문항의 시사점 도출은 보고 목적에 비해 노력이 커서 경영진 판단이 필요한 결과 3-4개를 고르는 메시지 선정으로 범위를 좁혔다.

(after)

```
## Module 1. 설문 결과 집계
- (목적) 경영진 판단이 필요한 설문 결과 확인

| Task | Input | 내용 | Output |
|------|-------|------|--------|
| 1-1. 보고 양식 확인 | 분기 경영진 보고 양식 | 양식이 요구하는 집계 항목 확인 | 집계 항목 목록 |
| 1-2. 데이터 정제 | 설문 원자료 엑셀 | 무응답과 중복 응답 제거 | 정제 데이터 |
| 1-3. 결과 집계 | 정제 데이터, 집계 항목 목록 | 엑셀에서 문항별 응답 분포와 부서별 차이 집계 | 집계표 |

## Module 2. 보고 자료 작성
- (목적) 경영진이 한 번 읽고 결정할 수 있는 자료 작성

| Task | Input | 내용 | Output |
|------|-------|------|--------|
| 2-1. 메시지 선정 | 집계표 | 경영진 판단이 필요한 결과 3-4개 선정 | 메시지 목록 |
| 2-2. 자료 작성 | 메시지 목록, 분기 경영진 보고 양식 | 양식에 메시지마다 슬라이드 1장 작성 | 보고 자료 |
```

### 표현 (슬라이드)

(before)

```
(제목) 시장 현황
- 국내 시장 규모 정체
- 주요 사업자 다수 경쟁
- 해외산 저가 제품 유입 증가
- 규제 특례 제도 시행으로 신규 서비스 허용
- 소비자 인식 개선 필요
- 유통 구조 복잡
- 신기술 도입 지연
```

(진단) 제목이 주제 라벨이다. 병렬 항목이 7개다. 수익성 악화, 제도 변화, 산업 구조 문제라는 독립 메시지가 섞여 있고 강조 지점이 없다.

(after, 분리한 첫 슬라이드)

```
(헤드메시지) 저가 제품 유입과 다자 경쟁으로 국내 시장의 수익성 하락
- 다수 사업자가 정체된 시장에서 경쟁하면서 가격 인하 압박 심화
- 해외산 저가 제품의 유입 증가로 평균 판매 가격 하락
- 시장 규모가 정체되어 판매량 증가로 수익성 하락을 메우기 어려운 상황
```

(처리)

- (제거) 소비자 인식, 유통 구조, 신기술 지연은 수익성 하락을 뒷받침하지 않아 삭제했다.
- (재배열) 판단문을 헤드메시지로 올렸다. 규제 특례 제도는 기회 요인을 다루는 다음 슬라이드로 옮겼다.

### 표현 (문단)

(before)

```
신제품 출시가 지연되는 원인은 부품 수급 불안정이다. 협력사의 생산 능력도
부족하다. 한편 경쟁사는 유사 제품을 먼저 출시하여 시장을 확보하고 있고
마케팅 예산도 당사보다 크다. 따라서 출시 일정을 앞당기고 마케팅 예산을
늘리고 협력사를 다변화해야 한다.
```

(진단) 원인 진단, 경쟁 동향, 대응 방안이라는 독립 메시지 3개가 한 문단에 들어 있다. 첫 문장이 문단 전체를 대표하지 못한다.

(after)

```

협력사 한 곳에 몰려 있다. 그 협력사의 생산 능력은 당사 발주량에 못 미친다.

출시가 늦어지는 동안 경쟁 구도가 불리해지고 있다. 경쟁사는 유사 제품을
먼저 출시하여 초기 수요를 가져갔다. 마케팅 예산도 당사보다 크게 운영한다.

대응의 첫 순서는 조달처 다변화다. 부품 수급이 안정되어야 출시 일정 단축과
마케팅 증액이 효과를 낼 수 있다.
```

(처리)

- (재배열) 메시지마다 문단을 나누고 각 문단의 첫 문장에 메시지를 두었다. 나머지 문장은 첫 문장만 뒷받침한다.

### 표현 (차트)

(before)

```
(제목) 부문별 실적
- 전 부문 막대 12개를 같은 색으로 표시
- 모든 막대에 데이터 라벨 부착
```

(after)

```
(제목) 소재 부문이 전사 매출 증가분의 절반 이상을 차지
- 소재 부문 막대만 강조 색으로 표시하고 데이터 라벨 부착
- 매출 증가분이 큰 2개 부문은 낮은 채도로 표시
- 나머지 9개 부문은 기타 막대 1개로 합산
```

- (재배열) 판단문을 차트 제목으로 올렸다.
- (단순화) 강조 계열을 1개로 정하고 데이터 라벨을 메시지와 관련된 막대에만 남겼다.

## 예외

- 사용자가 "상세 프로세스", "전체 단계"를 요청하면 해당 절차에는 요소 판별과 ECRS 처리를 적용하지 않는다.
- 사용자가 전수 나열이나 상세 목록을 요청하면 해당 부분에는 개수 기준을 적용하지 않는다.
- 법령, 규정, 점검표처럼 빠짐없는 목록이 목적인 산출물은 개수 기준을 적용하지 않고 강조 배치 규칙만 적용한다.
- 개수가 정해진 프레임워크와 표준 양식은 고유 개수를 유지한다.
- 인용문, 원문 전재, 코드 본문은 적용 대상에서 제외한다.

## 산출 전 점검

- (공통) 목적, 독자, 범위가 정해져 있고 정의와 기준이 산출물 끝까지 같은 뜻으로 쓰였는가
- (공통) 사용자 전제와 모델 지식을 근거를 확인한 뒤 받아들였는가
- (공통) 문제의 개선안이 사용자가 조치할 수 있는 가장 깊은 원인에서 도출되었는가
- (공통) 모든 요소가 적용 대상인 판별 조건을 통과했는가
- (공통) 모든 요소에 제거, 결합, 재배열, 단순화를 이 순서로 물었는가
- (공통) 산출물에 이 스킬의 적용 사실이나 규칙 이름이 드러나지 않는가
- (작업 설계) 사용자가 정한 문제 정의와 방향이 절차의 출발점으로 쓰였는가
- (작업 설계) 한 작업으로 끝나는 일이 한 단계로 쓰였는가
- (작업 설계) 뒤 단계의 범위나 방법을 정하는 단계가 앞에 놓였는가
- (작업 설계) 사용자가 보유한 자료, 양식, 도구로 수행하는 방법을 먼저 골랐는가
- (작업 설계) 법률, 규정, 안전 단계가 유지되었는가
- (작업 설계) 절차에 수행할 행동만 쓰였는가
- (표현) 모든 단위가 판단문 형태의 메시지를 1개만 전달하는가
- (표현) 메시지가 단위의 머리에 있고 헤더와 첫 문장이 같은 대상을 가리키는가
- (표현) 단위당 구성요소가 3-4개 이하인가 (프레임워크 고유 개수와 예외 항목은 제외)
- (표현) 요소 수를 줄이는 방식으로 압축했는가
- (표현) 본문에서 뺀 요소를 삭제, 분리, 이동 중 하나로 처리했는가
- (표현) 성격이 다른 요소가 한 나열에 섞여 있지 않은가
- (표현) 단위마다 강조 지점이 1곳인가
