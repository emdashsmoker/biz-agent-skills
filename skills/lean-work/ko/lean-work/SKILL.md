# 린 워크

독자의 목적에 기여하는 요소를 선별하고 선별한 요소를 충분히 설명하는 작업 방식을 정의한다. 요소를 선별하기 전에 목적, 독자, 범위를 먼저 정한다. 이 세 가지가 정해져야 요소의 필요 여부를 판단할 수 있다.

적용 대상은 작업 절차와 표현이다. 작업 절차는 목표 달성에 필요한 최소 단계로 구성한다. 표현은 글의 소제목이나 문단, 슬라이드의 헤드라인이나 구성요소, 데이터 항목 등의 단위마다 메시지를 1개씩 전달하도록 구성한다. 두 대상 모두 같은 조건으로 요소를 판별하고 제거, 결합, 재배열, 단순화 순서로 정리한다.

## 용어 정의

아래 용어는 이 스킬 안에서 표에 적은 뜻으로만 사용한다.

| 용어 | 정의 |
|------|------|
| 목적 | 산출물을 받은 독자가 내리거나 실행할 판단과 행동 |
| 독자 | 산출물을 읽거나 실행하는 사람. 사용자가 지정하지 않으면 해당 분야의 배경지식이 없는 일반 성인 |
| 범위 | 산출물이 다루는 대상의 경계 |
| 요소 | 판별하고 정리하는 최소 대상. 작업 절차의 요소는 작업 단계이고 표현의 요소는 단위를 구성하는 문장, 불릿, 수치, 도형 등의 표현 요소 |
| 단위 | 독자가 한 번에 보고 이해하는 표현 구획. 글의 소제목이나 문단, 슬라이드의 헤드라인이나 구성요소, 차트나 표의 데이터 항목 등. 큰 단위 안에 있는 작은 단위는 큰 단위의 요소로 다룸 |
| 메시지 | 한 단위를 본 독자가 기억해야 할 판단문 1개. 주어와 서술을 갖춘 문장 |
| 주제 라벨 | 판단 없이 대상만 가리키는 제목. 예를 들어 "시장 현황", "추진 배경", "주요 이슈" |
| 백화점식 나열 | 메시지 없이 관련 정보를 같은 비중으로 나열한 표현 |
| 메시지 과적 | 한 단위에 독립 주장이 2개 이상 들어 있는 상태 |
| ECRS | 작업 연구(work study)에서 사용하는 개선 순서. 제거(Eliminate), 결합(Combine), 재배열(Rearrange), 단순화(Simplify)의 머리글자 |

## 작동 순서

1. (기준 확정) 목적, 독자, 범위를 정하고 전제를 검증한다
2. (모드 선택) 산출물 종류에 맞는 모드를 선택한다
3. (요소 정리) 선택한 모드의 절차에 따라 모든 요소를 판별하고 ECRS 순서로 정리한다
4. (산출 전 점검) 점검 목록을 확인한 뒤 산출한다

## 기준 확정

판단 기준이 바뀌면 유지할 요소와 삭제할 요소도 함께 바뀐다. 요소를 선별하기 전에 아래 항목을 내부에서 확정한다. 확정한 내용은 판단 기준으로 사용하고 산출물에는 적지 않는다.

- 작업이 필요한 이유, 만들 산출물, 만드는 방법을 먼저 정한다.
- 목적, 독자, 범위를 한 문장씩 정한다. 사용자가 이미 정한 항목은 그대로 사용한다.
- 한 번 정한 정의와 판단 기준은 산출물 끝까지 같은 뜻으로 사용한다. 같은 대상은 하나의 이름으로 부른다.
- 사용자 요청에 담긴 전제와 모델 자신의 지식을 모두 검증 대상으로 둔다. 상식, 권위, 유명한 프레임워크, 유행어, 마케팅 용어는 그 자체로 근거가 되지 못한다.
- 문제가 주어지면 원인을 거슬러 올라가 사용자가 조치할 수 있는 가장 깊은 원인을 찾는다. 개선안은 그 원인에서 도출한다.
- 결론은 배경지식이 없는 제3자가 근거를 따라가며 납득할 수 있게 설명한다. 설명에는 뜻이 분명한 표현을 사용한다.
- 검증의 깊이는 그 판단이 결론에 미치는 영향에 맞춘다. 결론을 바꾸지 못하는 세부 사항은 깊이 검증하지 않는다.

## 모드 선택

| 모드 | 산출물 | 따르는 절차 |
|------|--------|-------------|
| 작업 설계 | 문제 해결, 기획, 분석, 조사, 코딩 등의 작업 절차 | 작업 설계 절차 |
| 표현 | 답변, 문서, 슬라이드, 차트, 다이어그램 | 표현 절차 |

- 두 모드는 새로 쓰는 작성과 기존 산출물을 고치는 교정으로 나뉜다. 교정은 교정 절차를 따른다.
- 한 요청이 작업 절차와 표현을 모두 요구하면 작업 설계 절차로 절차를 정한 뒤 그 절차의 산출물에 표현 절차를 적용한다.
- 사용자나 다른 지침이 출력 구조(표 양식, 평가 등급, 정해진 워크플로우 등)를 지정하면 그 구조를 유지한다. 이때는 구조 안의 각 항목과 각 단계에 요소 판별과 ECRS를 적용한다.

## 요소 판별

모든 요소는 아래 조건을 충족해야 유지한다. 조건마다 적용 대상이 다르다.

| 조건 | 판별 질문 | 적용 대상 |
|------|-----------|-----------|
| 필수성 | 이 요소를 삭제하면 메시지 전달이나 산출물 품질이 낮아지는가 | 모든 요소 |
| 독자 관련성 | 독자가 아직 모르는 정보이며 독자가 알아야 할 이유가 있는가 | 표현 요소 |
| 실행 가능성 | 사용자가 가진 자원과 제약 안에서 실행할 수 있는가 | 작업 단계 |
| 비례성 | 투입하는 노력이 얻는 가치보다 작은가 | 작업 단계 |

- 사용자가 밝힌 제약 조건은 실행 가능성의 판단 기준으로 사용한다. 제약 조건이 불명확하면 사용자에게 확인한 뒤 진행한다.
- 법률, 규정, 안전처럼 민감도가 높은 단계는 판별 결과와 관계없이 유지한다. 이런 단계를 생략하면 절감한 노력보다 큰 손실이 생긴다.

## ECRS 적용

판별을 마친 요소에 아래 네 가지 질문을 표의 순서대로 적용한다. 답이 "아니오"인 질문은 조치 없이 다음 질문으로 넘어간다.

| 순서 | 질문 | 답이 "예"일 때의 조치 |
|------|------|------------------------|
| 1. 제거 (Eliminate) | 이 요소가 없어도 목적이 달성되는가 | 요소를 삭제한다 |
| 2. 결합 (Combine) | 다른 요소와 합쳐 한 번에 다룰 수 있는가 | 여러 요소를 하나로 합친다 |
| 3. 재배열 (Rearrange) | 순서나 위치를 바꾸면 재작업이나 독자의 탐색이 줄어드는가 | 요소의 순서나 위치를 바꾼다 |
| 4. 단순화 (Simplify) | 더 단순한 수단이나 형태로 같은 결과를 얻을 수 있는가 | 요소의 수단이나 형태를 바꾼다 |

- 제거를 가장 먼저 적용한다. 제거할 요소를 합치거나 다듬는 노력은 결과에 남지 않는다.
- 네 가지 조치를 마치고 남은 요소는 충분한 분량으로 다룬다. ECRS는 요소 수를 줄여 남은 요소에 독자의 주의가 모이게 한다.
- 작업 단계에 적용하는 세부 기준은 작업 설계 절차에, 표현 요소에 적용하는 세부 기준은 표현 절차에 있다.

## 작업 설계 절차

작업 설계 모드는 목표 달성에 필요한 최소 단계만 제시한다. 모델은 사용자의 시간, 비용, 자원을 고려하지 않고 단계를 늘린 절차를 제안하기 쉽다.

1. 최종 산출물, 사용자가 보유한 입력 자료, 제약 조건을 확인한다
2. 최종 산출물에 이르는 단계를 나열하고 단계마다 입력과 산출물을 정한다
3. 모든 단계를 판별하고 아래 표의 기준으로 ECRS를 적용한다
4. 남은 단계를 출력 포맷에 맞춰 작성한다

### 작업 단계의 ECRS 기준

| 순서 | 작업 단계에 적용하는 기준 |
|------|---------------------------|
| 제거 | 필수성을 충족하지 못한 단계를 삭제한다. 사용자가 이미 정한 문제 정의나 방향을 다시 정하는 단계도 삭제한다 |
| 결합 | 동시에 수행되거나 한 작업 안에서 끝나는 단계를 한 단계로 합친다. 같은 입력 자료를 같은 방법으로 다루는 단계도 한 단계로 합친다 |
| 재배열 | 앞 단계의 산출물을 입력으로 사용하는 단계는 그 단계 뒤에 둔다. 결과에 따라 뒤 단계의 범위나 방법이 달라지는 단계는 앞에 둔다. 같은 목적을 가진 단계는 한 모듈에 모은다 |
| 단순화 | 사용자가 보유한 자료, 양식, 도구로 수행하는 방법을 먼저 선택한다. 수행 범위와 정밀도는 목적이 요구하는 수준에 맞춘다 |

- 제거 여부는 산출물을 직접 만드는 단계부터 검토한다. 이 단계가 삭제되면 이 단계를 준비하거나 점검하는 단계도 함께 삭제된다.
- 뒤 단계의 범위나 방법을 정하는 단계를 뒤에 두면 앞서 만든 산출물을 다시 만들게 된다.
- 필수성은 충족하나 실행 가능성이나 비례성을 충족하지 못한 단계는 결합과 단순화로 노력을 줄인 뒤 다시 판별한다. 다시 판별해도 충족하지 못한 단계는 삭제한다.
- 모델이 직접 수행하는 작업의 수행 계획에도 같은 판별과 ECRS를 적용한다.

### 절차 작성 기준

- 절차에는 수행할 행동만 작성한다. 절차의 의의, 배경, 기대효과를 설명하는 문장은 삭제한다. "다음과 같은 프로세스를 제안한다", "본 단계에서는 자료를 수집한다", "이를 통해 효율을 높일 수 있다" 같은 문장이 삭제 대상이다.
- 모듈 수는 판별 조건을 충족하는 범위에서 정한다.
- 사용자가 절차를 요청했고 포맷을 따로 지정하지 않았으면 아래 포맷으로 출력한다. 내용 칸에는 수행 행동만 작성한다.

```
## Module N. 모듈명
- (목적) 한 줄 서술

| Task | Input | 내용 | Output |
|------|-------|------|--------|
| N-1. Task명 | 입력 자료명 또는 목록 | 수행 행동 | 산출물명 또는 목록 |
| N-2. Task명 | 입력 자료명 또는 목록 | 수행 행동 | 산출물명 또는 목록 |
```

## 표현 절차

표현 모드에서 모든 단위는 메시지를 정확히 1개 전달한다. 백화점식 나열은 볼 대상을 고르는 부담을 독자에게 넘긴다. 메시지 과적은 단위가 전달하려는 내용을 독자가 파악하기 어렵게 만든다. 두 문제는 전달할 요소를 선별하지 않고 보유한 정보를 모두 배치할 때 생긴다.

1. 산출물을 단위 목록으로 나눈다
2. 단위마다 메시지를 판단문 1개로 확정한다
3. 단위 안의 요소를 판별하고 아래 표의 기준으로 ECRS를 적용한다
4. 백화점식 나열 신호를 점검한 뒤 산출한다

### 메시지 확정

- 단위마다 "이 단위를 본 독자가 기억해야 할 한 문장은 무엇인가"에 답한다.
- 답이 없으면 메시지가 없는 상태다. 판단문을 정하거나 단위를 삭제한다.
- 답에 독립 주장이 2개 이상 이어지면 메시지 과적이다. 슬라이드 추가, 문단 분리, 차트 분할 등의 방법으로 단위를 나눈다.
- 주제 라벨은 판단을 담지 않으므로 메시지로 인정하지 않는다. 메시지 예시는 "저가 제품 유입으로 국내 시장의 수익성 하락"처럼 주어와 서술을 갖춘 판단문이다.

### 표현 요소의 ECRS 기준

| 순서 | 표현 요소에 적용하는 기준 |
|------|---------------------------|
| 제거 | 메시지를 뒷받침하지 않는 요소와 독자가 이미 아는 요소를 삭제한다. 다른 단위나 부록에서 사용할 요소는 재배열 대상으로 둔다 |
| 결합 | 제거 후에도 구성요소가 5개 이상이면 하위 항목을 상위 범주 3-4개로 합친다. 세부 내용은 하위 계층으로 옮긴다 |
| 재배열 | 메시지를 단위의 머리에 둔다. 독립된 메시지로 가치가 있는 요소는 별도 단위로 분리한다. 참조 가치만 있는 요소는 부록, 각주, 별첨으로 옮긴다 |
| 단순화 | 강조 지점을 단위당 1곳으로 정한다. 나머지 요소는 시각 비중을 낮춘다 |

### 구성요소 선별

메시지를 뒷받침하는 구성요소는 단위당 3-4개 이하를 기본으로 한다. 사람이 한 번에 기억하고 다룰 수 있는 정보의 수에는 한계가 있어서 항목이 늘수록 항목 하나에 돌아가는 주의가 줄어든다.

삭제 후보는 아래 순서로 검토한다. 작성에 들인 노력은 요소를 유지할 이유가 되지 못한다.

1. 메시지와 무관한 정보
2. 독자가 이미 아는 배경 설명
3. 같은 결론을 반복해서 뒷받침하는 근거
4. 판단에 기여하지 않는 장식성 수치와 사례

- 메시지를 뒷받침하지 않는 요소는 삭제, 별도 단위로 분리, 부록으로 이동 중 하나로 정리한다. 본문에 이름만 남기고 내용을 생략하는 방식은 사용하지 않는다.
- 제거 후에도 구성요소가 5개 이상이면 메시지가 2개 이상 섞였는지 먼저 확인한다. 섞였으면 단위를 나누고 메시지가 1개이면 상위 범주로 합친다.
- 선별한 구성요소는 서로 겹치지 않고 메시지의 서로 다른 부분을 맡는다.
- 구성요소 수는 메시지가 요구하는 만큼만 둔다. 2개로 충분한 내용은 2개로 끝낸다.
- 원인과 결과, 현상과 대책, 사실과 의견처럼 성격이 다른 요소는 성격별로 나누어 배치한다.
- 4분면 매트릭스나 5단계 프로세스처럼 개수가 정해진 프레임워크는 고유 개수를 유지한다.

압축은 요소 수를 줄이는 방식으로 한다. 요소를 모두 유지한 채 문장만 줄이면 서술 밀도만 올라가고 독자가 읽어야 할 항목 수는 그대로 남는다.

### 메시지 위치

메시지는 단위의 머리에 둔다.

- 슬라이드는 헤드메시지 문장이 메시지를 담는다.
- 차트는 제목이 메시지를 담는다.
- 문단은 첫 문장이 메시지를 담는다. 나머지 문장은 첫 문장만 뒷받침한다.
- 문장형 헤더는 헤더가 메시지를 직접 담고 본문 첫 문장은 근거로 시작한다.
- 키워드형 헤더는 메시지의 대상을 예고하고 본문 첫 문장이 판단문을 담는다.
- 헤더가 예고한 대상과 첫 문장의 메시지가 다르면 헤더 이름을 바꾸거나 내용을 옮긴다.
- 슬라이드의 구성요소, 데이터 항목 등 그 밖의 단위는 독자가 가장 먼저 읽는 자리에 메시지를 둔다.

### 강조 배치

- 단위 안의 요소는 메시지, 지지 요소, 세부 순서로 비중을 달리하여 배치한다.
- 강조 지점은 단위당 1곳으로 정한다.
- 슬라이드와 디자인은 크기, 위치, 색으로 시선을 유도하고 나머지 요소는 작은 크기와 낮은 채도로 표현한다.
- 차트는 강조 계열 1개만 부각하고 비교 계열은 낮은 채도로 표현한다. 데이터 라벨은 메시지와 관련된 지점에만 붙인다.
- 메시지 구별에 사용하지 않는 색, 선, 장식은 줄인다.
- 모든 요소가 같은 비중이면 강조 지점이 없는 상태로 보고 다시 배치한다.

### 백화점식 나열 신호

아래 신호가 1개 이상 보이면 단위를 다시 구성한다.

- 같은 계층에 나란히 놓인 항목이 5개 이상 있다
- 한 문단에 독립 주장을 담은 문장이 2개 이상 있다
- 제목이나 헤드가 주제 라벨이다
- 모든 항목이 같은 시각 비중과 서술 분량으로 배치되어 강조 지점이 없다
- 원인과 결과, 현상과 대책, 사실과 의견처럼 성격이 다른 요소가 한 나열에 섞여 있다
- 헤더가 예고한 대상과 본문 첫 문장의 메시지가 다르다
- "이 단위에서 기억할 한 문장"에 답할 수 없다

## 교정 절차

기존 산출물을 고칠 때 적용한다. 교정 결과에는 진단 요지를 짧게 덧붙여 사용자가 변경 이유를 확인하게 한다. 진단 요지에는 변경한 내용과 이유를 산출물의 내용으로 서술한다.

### 작업 절차의 교정

1. 기존 절차의 단계마다 입력과 산출물을 파악한다
2. 모든 단계를 판별하고 ECRS를 적용한다
3. 교정한 절차를 산출하고 변경한 단계와 이유를 짧게 덧붙인다

### 표현의 교정

1. 단위별 메시지를 모두 추출하여 단위마다 메시지 개수를 진단한다
2. 메시지가 2개 이상인 단위는 나누고 메시지가 없는 단위는 판단문을 정하거나 삭제한다
3. 단위 안의 요소를 판별하고 ECRS를 적용한다
4. 교정 결과를 산출하고 단위별 진단 요지를 짧게 덧붙인다

## 산출물 공통 규칙

산출물에는 정리를 마친 결과만 담는다. 독자는 결과를 사용하며 결과를 만든 과정은 독자의 판단에 필요하지 않다.

- 이 스킬의 내부 작업에서 나온 모든 내용은 산출물에 담지 않는다. 아래 표는 대표 사례이며 표에 없는 내부 작업 내용에도 같은 규칙을 적용한다.
- 이 스킬의 이름과 적용 사실, 이 스킬에서 정의하거나 사용한 모든 용어(ECRS, 요소 판별, 백화점식 나열, 메시지 과적 등)는 산출물에 사용하지 않는다. 사용자가 요청에서 먼저 사용한 용어는 사용할 수 있다.
- 메타적 표현은 산출물에 사용하지 않는다. 메타적 표현은 독자의 목적에 기여하지 않는 요소이므로 필요한 요소만 남긴다는 이 스킬의 목적과 취지에 정면으로 어긋난다. 메타적 표현은 글 자체, 작성 과정, 작성자의 판단과 작업 방식을 서술하는 표현이다. "핵심만 정리하면", "불필요한 단계는 제외했다", "메시지 하나로 압축했다", "간결하게 구성했다" 등의 문장이 해당한다.

| 내부 작업 | 산출물에 담지 않는 내용의 사례 |
|-----------|--------------------------------|
| 기준 확정 | 목적, 독자, 범위를 정한 문장, 전제를 검증한 과정 등 |
| 요소 판별 | 조건별 판별 결과, 판별 질문의 답 등 |
| ECRS 적용 | 삭제, 결합, 이동, 단순화한 요소의 목록과 이유 등 |
| 산출 전 점검 | 점검 항목, 점검 결과 등 |

- 본문에서 삭제한 요소는 산출물에서 언급하지 않는다. 삭제한 요소를 나열하면 독자가 읽을 항목이 다시 늘어난다.
- 교정 절차의 진단 요지는 사용자가 변경 이유를 확인하는 용도이므로 예외로 한다. 진단 요지는 기존 산출물을 고친 경우에만 붙인다.
- 사용자가 판단 과정이나 삭제한 요소를 요청하면 요청한 범위만 제공한다.
- 문체와 종결 형태, 어휘 선택, 개별 문장의 길이, 거시 구조와 목차 구성, 마크다운 포맷은 사용자나 다른 지침을 따른다. 이 스킬은 작업 단계의 선별과 순서, 표현 요소의 선별, 메시지와 강조의 배치에 관여한다.

### 작업 설계 예시

교정 전 절차는 아래와 같다.

```
1. 보고 목적 재정의
2. 국내외 설문 분석 사례 벤치마킹
3. 분석 프레임워크 설계
4. 데이터 정제
5. 기술 통계 산출
6. 교차 분석
7. 이해관계자 인터뷰
8. 시사점 도출
9. 보고서 구성 신규 설계
10. 경영진 보고 양식 확인
11. 보고서 초안 작성
```

| 순서 | 적용 내용 |
|------|-----------|
| 제거 | 보고 목적은 사용자가 이미 정했으므로 재정의 단계를 삭제했다. 벤치마킹, 프레임워크 설계, 인터뷰는 삭제해도 설문 결과 보고의 품질이 유지되므로 삭제했다 |
| 결합 | 기술 통계와 교차 분석은 한 번의 집계 작업에서 끝나므로 합쳤다 |
| 재배열 | 보고 양식 확인을 첫 단계로 옮겼다. 양식이 집계 항목을 정하므로 뒤에 두면 집계를 다시 하게 된다 |
| 단순화 | 보고서 구성을 새로 설계하는 단계는 기존 보고 양식을 사용하는 방법으로 바꿔 자료 작성 단계에 합쳤다. 전체 문항의 시사점 도출은 보고 목적에 비해 노력이 커서 경영진 판단이 필요한 결과 3-4개를 고르는 메시지 선정으로 범위를 좁혔다 |

교정 후 절차는 아래와 같다.

```
## Module 1. 설문 결과 집계

|------|-------|------|--------|
| 1-1. 보고 양식 확인 | 분기 경영진 보고 양식 | 양식이 요구하는 집계 항목 확인 | 집계 항목 목록 |
| 1-2. 데이터 정제 | 설문 원자료 엑셀 | 무응답과 중복 응답 제거 | 정제 데이터 |
| 1-3. 결과 집계 | 정제 데이터, 집계 항목 목록 | 엑셀에서 문항별 응답 분포와 부서별 차이 집계 | 집계표 |

## Module 2. 보고 자료 작성
- (목적) 경영진이 한 번 읽고 결정할 수 있는 자료 작성

|------|-------|------|--------|

| 2-2. 자료 작성 | 메시지 목록, 분기 경영진 보고 양식 | 양식에 메시지마다 슬라이드 1장 작성 | 보고 자료 |
```

### 슬라이드 예시

교정 전 슬라이드는 제목이 주제 라벨이고 같은 계층의 항목이 7개다. 수익성 악화, 제도 변화, 산업 구조 문제라는 독립 메시지가 섞여 있고 강조 지점이 없다.

```
(제목) 시장 현황
- 국내 시장 규모 정체
- 주요 사업자 다수 경쟁
- 해외산 저가 제품 유입 증가
- 규제 특례 제도 시행으로 신규 서비스 허용
- 소비자 인식 개선 필요
- 유통 구조 복잡
- 신기술 도입 지연
```

교정 후에는 슬라이드를 메시지별로 나눈다. 아래는 나눈 슬라이드 가운데 첫 장이다.

```
(헤드메시지) 저가 제품 유입과 다자 경쟁으로 국내 시장의 수익성 하락
- 다수 사업자가 정체된 시장에서 경쟁하면서 가격 인하 압박 심화
- 해외산 저가 제품의 유입 증가로 평균 판매 가격 하락
- 시장 규모가 정체되어 판매량 증가로 수익성 하락을 메우기 어려운 상황
```

| 순서 | 적용 내용 |
|------|-----------|
| 제거 | 소비자 인식, 유통 구조, 신기술 지연은 수익성 하락을 뒷받침하지 않아 삭제했다 |
| 재배열 | 판단문을 헤드메시지로 올렸다. 규제 특례 제도는 기회 요인을 다루는 다음 슬라이드로 옮겼다 |

### 문단 예시

교정 전 문단에는 원인 진단, 경쟁 동향, 대응 방안이라는 독립 메시지 3개가 들어 있다. 첫 문장이 문단 전체를 대표하지 못한다.

```
신제품 출시가 지연되는 원인은 부품 수급 불안정이다. 협력사의 생산 능력도
부족하다. 한편 경쟁사는 유사 제품을 먼저 출시하여 시장을 확보하고 있고
마케팅 예산도 당사보다 크다. 따라서 출시 일정을 앞당기고 마케팅 예산을
늘리고 협력사를 다변화해야 한다.
```

교정 후에는 메시지마다 문단을 나누고 각 문단의 첫 문장에 메시지를 둔다. 나머지 문장은 첫 문장만 뒷받침한다.

```
신제품 출시 지연의 원인은 부품 수급 불안정이다. 주력 부품의 조달처가
협력사 한 곳에 몰려 있다. 그 협력사의 생산 능력은 당사 발주량에 못 미친다.

출시가 늦어지는 동안 경쟁 구도가 불리해지고 있다. 경쟁사는 유사 제품을
먼저 출시하여 초기 수요를 가져갔다. 마케팅 예산도 당사보다 크게 운영한다.

대응의 첫 순서는 조달처 다변화다. 부품 수급이 안정되어야 출시 일정 단축과
마케팅 증액이 효과를 낼 수 있다.
```

### 차트 예시

교정 전 차트는 제목이 주제 라벨이다. 막대 12개가 같은 비중으로 놓여 독자가 볼 지점을 알 수 없다.

```
(제목) 부문별 실적
- 전 부문 막대 12개를 같은 색으로 표시
- 모든 막대에 데이터 라벨 부착
```

교정 후 차트는 아래와 같다.

```
(제목) 소재 부문이 전사 매출 증가분의 절반 이상을 차지
- 소재 부문 막대만 강조 색으로 표시하고 데이터 라벨 부착
- 매출 증가분이 큰 2개 부문은 낮은 채도로 표시
- 나머지 9개 부문은 기타 막대 1개로 합산
```

| 순서 | 적용 내용 |
|------|-----------|
| 결합 | 매출 증가분이 작은 9개 부문을 기타로 합쳐 막대를 12개에서 4개로 줄였다 |
| 재배열 | 판단문을 차트 제목으로 올렸다 |
| 단순화 | 강조 계열을 1개로 정하고 데이터 라벨을 메시지와 관련된 막대에만 남겼다 |

## 예외

- 사용자가 "상세 프로세스", "전체 단계"를 요청하면 해당 절차에는 요소 판별과 ECRS를 적용하지 않는다.
- 사용자가 전수 나열이나 상세 목록을 요청하면 해당 부분에는 개수 기준을 적용하지 않는다.
- 법령, 규정, 점검표처럼 빠짐없는 목록이 목적인 산출물은 개수 기준을 적용하지 않고 강조 배치 규칙만 적용한다.
- 개수가 정해진 프레임워크와 표준 양식은 고유 개수를 유지한다.
- 인용문, 원문 전재, 코드 본문은 적용 대상에서 제외한다.

## 산출 전 점검

### 공통 점검

- 목적, 독자, 범위가 정해져 있고 정의와 기준이 산출물 끝까지 같은 뜻으로 사용되었는가
- 사용자 전제와 모델 지식을 근거를 확인한 뒤 받아들였는가
- 문제의 개선안이 사용자가 조치할 수 있는 가장 깊은 원인에서 도출되었는가
- 모든 요소가 적용 대상인 판별 조건을 충족하는가
- 모든 요소에 제거, 결합, 재배열, 단순화를 이 순서로 적용했는가
- 산출물에 정리를 마친 결과만 담겼는가
- 산출물에 내부 작업 내용, 이 스킬의 이름과 용어, 메타적 표현이 없는가

### 작업 설계 점검

- 사용자가 정한 문제 정의와 방향을 그대로 따랐는가
- 한 작업으로 끝나는 일이 한 단계로 작성되었는가
- 뒤 단계의 범위나 방법을 정하는 단계가 앞에 놓였는가
- 사용자가 보유한 자료, 양식, 도구로 수행하는 방법을 먼저 선택했는가
- 법률, 규정, 안전 단계가 유지되었는가
- 절차에 수행할 행동만 작성되었는가

### 표현 점검

- 모든 단위가 판단문 형태의 메시지를 1개만 전달하는가
- 메시지가 단위의 머리에 있고 헤더와 첫 문장이 같은 대상을 가리키는가
- 단위당 구성요소가 3-4개 이하인가 (프레임워크 고유 개수와 예외 항목은 제외)
- 요소 수를 줄이는 방식으로 압축했는가
- 메시지를 뒷받침하지 않는 요소를 삭제, 분리, 이동 중 하나로 정리했는가
- 성격이 다른 요소를 성격별로 나누어 배치했는가
- 단위마다 강조 지점이 1곳인가
