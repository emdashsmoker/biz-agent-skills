# 사내 초거대AI 도입 검토

2026년 10월 | 경영진 회의 보고 | 작성: IT팀

---

## 1. 요약

- **결론**: 2027년 상반기에 품질팀과 설계팀을 대상으로 초거대AI를 시범 도입할 것을 권고함
- **이유**: AI를 쓰는 비용이 크게 내려갔고, 사내 서버에 직접 설치해 쓰는 공개형 AI의 성능이 상용 AI 수준에 근접함. 외부로 문서를 내보내지 않고도 도입할 수 있는 여건이 마련됨
- **방식**: 외부 AI 서비스가 아닌 사내 서버 설치형으로, ① 과거 문서 검색 ② 보고서 초안 작성 두 업무에 한정해 3개월간 시험 운영
- **오늘 결정 요청**: 시범 추진 방향 승인. 예산은 업체 견적을 비교해 12월 회의에서 확정

## 2. 왜 지금 검토하는가

| 변화 | 근거 | 당사에 주는 의미 |
|---|---|---|
| AI 이용 비용 급락 | ChatGPT 초기 버전(GPT-3.5) 수준 AI가 답 하나를 만드는 비용이 2022년 11월~2024년 10월에 280배 이상 하락 | 소규모 시범의 비용 부담이 크게 낮아짐 |
| 기업 활용 확산 | AI를 쓴다고 답한 기업 비율이 2023년 55%에서 2024년 78%로 증가 | AI 활용이 일부 선도기업만의 일이 아니게 됨 |
| 공개형 AI 성능 추격 | 일부 성능 시험에서 공개형 AI와 상용 AI의 격차가 1년 새 8%에서 1.7%로 축소 | 사내 서버에 설치해 외부 반출 없이 쓰는 AI도 실무에 쓸 만한 수준에 도달 |

※ 출처: Stanford HAI, AI Index Report 2025
※ 공개형 AI: 설계 정보(가중치)가 공개되어 누구나 내려받아 자기 서버에 설치할 수 있는 AI. 상용 AI는 개발사 서버에 접속해서만 쓸 수 있음

**자료 해석 시 유의점**

- 위 수치는 2024년까지의 세계 동향이며 국내 제조업만의 수치는 아님. 현재 가격과 성능은 업체 견적과 당사 문서를 쓴 시험으로 다시 확인할 예정
- 성능 격차 1.7%는 "일부" 성능 시험 결과임. 당사 업무에서도 같은 수준이 나오는지는 시범으로 검증해야 함
- 정부는 2023년 「초거대 AI 경쟁력 강화방안」으로 2023년 3,901억 원 투입을 시작해 2027년까지 학습용 데이터 200종과 한국어 말뭉치 130종을 구축하기로 함. 다만 컴퓨팅 자원 지원 대상은 중소·벤처기업, 대학, 연구소이고 5대 중점 분야(법률, 의료, 심리상담, 문화·예술, 학술·연구)에 제조는 없음. 중견기업인 당사가 직접 지원을 받기는 어려울 것으로 보며, 공개되는 한국어 데이터의 활용 가능성만 추가로 확인할 예정 (출처: 과학기술정보통신부, 2023)

## 3. 당사 여건

| 구분 | 현황 | 시사점 |
|---|---|---|
| 현업 수요 | 품질팀·설계팀이 과거 문서 검색과 보고서 초안 작성에 시간이 많이 든다고 호소 | 문서를 찾아 요약하고 초안을 쓰는 일은 AI가 잘하는 업무와 일치함 |
| 보안 규정 | 외부 생성형 AI 서비스에 업무 문서 입력 금지 | ChatGPT 같은 외부 서비스는 현 규정상 업무에 쓸 수 없음 |
| IT 인력 | IT팀 5명, AI 전담 인력 없음 | 자체 구축과 운영은 어려움. 외부 전문업체와 협력 필요 |

## 4. 도입 방식 비교

| 구분 | A. 도입 보류 | B. 외부 AI 서비스 이용 | **C. 사내 서버 설치형 (권고)** |
|---|---|---|---|
| 보안 규정 | 해당 없음 | 위배. 규정 개정 필요 | **부합. 문서가 사외로 나가지 않음** |
| 초기 비용 | 없음 | 낮음 | 중간 (서버, 구축비) |
| IT팀 부담 | 없음 | 낮음 | 높음. 외부 업체 위탁으로 보완 |
| 성능 | - | 최상위 | 일부 시험 기준 근접. 당사 업무로 검증 필요 |
| 핵심 위험 | 현업 비효율 지속, 경쟁사 대비 격차 확대 | 설계·품질 기술 정보 유출 | 구축 지연, 외부 업체 의존 |

- **B를 택하지 않는 이유**: 설계·품질 문서는 당사 핵심 기술 정보임. 기업용 상품이라도 문서가 사외 서버로 나가는 점은 같음. 규정을 풀어 얻는 편의보다 유출 위험이 더 큼
- **A를 택하지 않는 이유**: 현업 수요가 확인되었고 도입 비용 장벽이 낮아짐. 범위를 좁힌 시범은 실패해도 손실이 제한적이므로 기다리는 것보다 직접 확인하는 편이 유리함

## 5. 시범 도입안

**대상과 업무**

- 대상: 품질팀·설계팀 내 희망자
- 업무 ① 과거 문서 검색: 질문하면 관련 사내 문서를 찾아 요약하고 원문 위치를 함께 제시
- 업무 ② 보고서 초안 작성: 정해진 양식에 맞춰 초안을 만들고 담당자가 검토·수정

**추진 체계**: IT팀 총괄 1명, 품질팀·설계팀 현업 담당 각 1명, 외부 구축 업체

**일정**

| 시기 | 내용 |
|---|---|
| 2026년 11~12월 | 업체 2~3곳 견적 비교, 보안 검토, 대상 문서 선정, 현행 업무 소요 시간 측정 → 12월 회의에 예산 확정안 보고 |
| 2027년 1~2월 | 사내 서버 구축, 대상 문서 정리·입력 |
| 2027년 3~5월 | 시범 운영 (3개월) |
| 2027년 6월 | 성과 평가, 확대 여부 보고 |

**평가 기준**

- 소요 시간: 문서 검색과 초안 작성에 드는 시간이 착수 전 대비 얼마나 줄었는가
- 정확도: AI 답변이 근거 문서와 일치하는 비율 (현업 담당자가 검토)
- 사용 의향: 시범 참여자 중 계속 쓰겠다는 비율
- 판단 규칙: 세 기준 모두 목표 달성 시 전사 확대 검토, 일부 달성 시 보완 후 연장, 미달 시 중단. 기준별 목표치는 11~12월 측정 결과를 바탕으로 12월 회의에 제시

## 6. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| AI가 그럴듯한 오답을 냄 | 모든 답변에 근거 문서를 표시. 최종 문서는 담당자 검토를 필수로 함 |
| 기밀 문서 열람 범위가 넓어짐 | 기존 문서 열람 권한을 AI 검색에도 그대로 적용. 사용 기록 보관 |
| 과거 문서가 스캔본·종이 위주이면 검색 품질 저하 | 준비 단계에서 문서 상태를 점검하고 전산화된 문서부터 적용 |
| 외부 업체 의존 | 계약에 운영 교육과 기술 이전을 포함. IT팀 담당자를 처음부터 참여시킴 |
| 기대 성능 미달 | 범위를 두 업무로 한정해 손실을 제한. 6월 평가에서 중단 가능 |

## 7. 결정 요청 사항

1. 2027년 상반기 시범 도입 추진 방향 승인 (사내 서버 설치형, 품질팀·설계팀 대상)
2. IT팀·품질팀·설계팀 담당자 지정과 업체 견적 착수 승인
3. 시범 예산과 평가 목표치는 12월 회의에서 견적 비교 결과와 함께 최종 승인
