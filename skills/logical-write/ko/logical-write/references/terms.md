# 전문용어 처리

비전공 독자가 정의 없이 이해할 수 없는 어휘를 무단으로 쓰지 않는다. 목표는 독자가 멈추지 않고 읽는 글이다.

## 두 가지 실패

어휘 수준을 조절할 때는 양 끝의 실패가 모두 생긴다. 한쪽을 피하다 반대쪽으로 넘어가기 쉬우므로 두 방향을 함께 점검한다.

- (과잉 전문성) 독자가 모르는 용어를 정의 없이 쓰는 실패. 작성자가 그 분야에 익숙할수록 어떤 단어가 전문용어인지 알아차리지 못한다.
- (과잉 평이화) 쉽게 쓰려다 정보를 잃는 실패. 정밀한 용어를 두루뭉술한 포괄어로 바꿔 문장이 아무것도 말하지 않게 되는 모호한 추상화("통화 스와프 체결"을 "돈 관련 약속 체결"로 대체)와 어휘를 낮추면서 어조까지 낮춰 격식이 무너지는 유치한 문체(구어체 종결, 감탄, 독자에게 말 걸기, 본질을 왜곡하는 비유)가 있다.

## 기준 독자

- 전문용어 여부를 판별하는 기준 독자는 평균적인 비전공 성인이다.
- 초중고 교과 내용을 배웠으나 세부 내용은 대부분 기억하지 못하는 상태로 본다. 교과 과정을 완벽하게 기억하는 독자를 상정하지 않는다.
- 특정 분야의 학부 전공 지식, 업계 관행, 조직 내부 약어는 모른다고 본다.
- 설명 수준은 경험 많은 전문가가 그 분야 입문자에게 설명하는 수준으로 맞춘다.
- 기준 독자는 어휘 판별의 기준일 뿐이다. 독자가 비전문가라는 사실은 어조를 낮추거나 독자를 미성숙하게 대할 근거가 되지 않는다.
- 사용자가 독자를 따로 밝히면(예: "반도체 엔지니어 대상") 그 독자의 전제 지식으로 판별 기준을 조정한다.

## 판별

글에 들어가는 어휘는 산출 전에 두 질문을 거친다. 독자가 이 단어를 아는가. 이 단어를 꼭 써야 하는가.

### 질문 1. 독자가 정의 없이 이해하는가

- 기준 독자가 정의 없이 이해하면 일반어로 보고 그대로 쓴다.
- 단어를 아는 경로가 일상 생활이면 일반어, 특정 분야의 학습이나 종사나 전공이면 전문용어다.
- 일상어와 형태가 같지만 그 분야에서 다른 뜻으로 쓰이는 단어는 전문용어로 본다(통계의 "유의하다", 법률의 "선의", 금융의 "노출").
- 영문 약어와 축약어는 독자가 아는지와 관계없이 처음 한 번 전체 명칭을 함께 적는다.
- 작성자에게 익숙한 단어일수록 판별을 건너뛰기 쉬우므로 익숙한 단어부터 의심한다.

### 질문 2. 꼭 써야 하는가

질문 1에서 전문용어로 판별된 단어에만 적용한다.

- 글의 목적과 결론 전달에 기여하지 않으면 등장 자체를 없앤다. 정의를 붙여 살릴 가치보다 글에 있어야 하는지를 먼저 판단한다.
- 뜻을 잃지 않고 일반어로 바꿀 수 있으면 필수 용어가 아니므로 평이어로 바꾼다.
- 일반어로 바꾸면 뜻이 달라지거나 다른 대상과 구별되지 않으면 필수 용어다. 본문에 두고 설명 블록을 붙인다.

## 처리 순서

전문용어로 판별된 어휘는 아래 순서로 처리한다. 앞 단계가 가능하면 뒤 단계로 내려가지 않는다.

본문에 남기는 전문용어의 정의는 설명 블록이 맡는다. 본문 문장은 용어를 쓰기만 하고 정의하거나 풀어 설명하지 않는다. 본문과 설명 블록이 같은 정보를 두 번 쓰면 읽기 흐름이 끊기고 글이 용어집처럼 된다. 글의 목적이 그 개념의 설명이면 본문의 개념 서술이 곧 본문 내용이므로 본문이 정의를 맡고 설명 블록은 붙이지 않는다. 어느 경우든 같은 용어의 정의는 본문과 설명 블록 가운데 한 곳에서 한 번만 한다.

### 1단계. 등장 제거

글의 목적과 결론 전달에 기여하지 않는 용어는 바꾸거나 정의하기 전에 등장 자체를 없앤다.

### 2단계. 평이어 대체

뜻을 잃지 않고 일반어로 바꿀 수 있는 용어는 일반어로 바꾼다.

| 교정 전 | 교정 후 |
|---|---|
| 마이그레이션 | 이전 |
| 온보딩 | 신규 인력의 업무 적응 |
| 거버넌스 체계 정립 | 의사결정 책임과 절차 마련 |
| 페인포인트 | 불편 사항 |
| 시너지 창출 | 결합 효과 확보 |

### 3단계. 설명 블록

평이어로 바꾸면 뜻이 달라지거나 모호해지는 용어는 본문에 그대로 쓰고 처음 나온 항목 바로 뒤에 설명 블록을 둔다. 그 뒤에 다시 나오면 설명 없이 쓴다. 본문에 괄호 정의를 끼워 넣으면 문장이 읽기 어려워지므로 쓰지 않는다.

```markdown
> (전문용어명) 5W1H를 지킨 한 줄 단문 설명
```

- (위치) 용어가 처음 나온 항목 바로 뒤에 둔다. 글 끝 용어집이나 각주로 모으지 않는다.
- (여러 용어) 한 자리에 여러 용어가 나오면 용어별 블록 사이에 빈 줄을 둔다.
- (대상) 법령 용어, 기술 표준명, 제도명, 학술 개념처럼 정밀성이 뜻의 일부인 용어
- (설명 문장) 한 줄 단문으로 쓴다. 설명 안에 다른 전문용어를 쓰지 않는다. 설명에 정의 대상 단어를 다시 쓰지 않는다. "(양자내성암호) 양자 공격에 내성을 가진 암호"는 틀리고 "(양자내성암호) 연산 능력이 크게 향상된 미래 컴퓨터로도 풀기 어렵게 설계한 암호 방식"이 맞다.
- (약어) 영문 약어는 본문에서 처음 한 번 전체 명칭을 함께 적고 전체 명칭 자체가 전문용어이면 설명 블록을 더한다. 전체 명칭 병기는 표기이므로 중복 정의가 아니다. 본문에 "PIM(Processing-In-Memory)"이라 적고 바로 뒤에 "> (PIM) 데이터 저장 장치 안에서 연산까지 수행하는 반도체 구조"를 둔다.
- (중복 금지) 설명 블록을 붙인 용어를 본문에서 다시 풀어 쓰지 않는다. 본문에 "은행 간 초단기 자금에 적용되는 콜금리가 상승"이라고 쓰고 블록에서 다시 정의하면 중복이다. 본문에는 "콜금리가 상승"만 쓴다.

### 하지 않는 처리

- 설명 없는 무단 사용
- 설명 블록이 맡을 정의를 본문 문장에서 하는 처리
- 모호한 포괄어로 뜻을 잃게 바꾸는 처리
- 본문 문장 안에 긴 괄호 정의를 끼워 넣는 처리
- 설명을 글 끝 용어집이나 각주로 미루는 처리

## 정밀성 보존

- 풀어 쓴 문장이 원래 용어가 담던 정보를 모두 담는지 검증한다. 풀어 쓴 문장만 읽은 독자가 원래 용어의 대상을 다른 대상과 구별할 수 있어야 한다. 구별할 수 없으면 설명 블록 방식으로 바꾼다.
- 용어에 수치, 조건, 범위가 들어 있으면 풀어 쓸 때 빠뜨리지 않는다. "콜금리"를 "은행 금리"로 바꾸면 어떤 금리인지 구별할 수 없다. 본문에 "콜금리"를 두고 설명 블록을 붙인다.
- 인접 개념과의 경계가 용어의 존재 이유이면 경계 정보를 보존한다. "추경"을 "추가 예산"으로만 풀면 본예산 증액과 구별되지 않으므로 본문에 정식 명칭 "추가경정예산"을 쓰고 설명 블록을 붙인다.

## 어조 보존

쉬움의 대상은 어휘 선택과 개념 설명이다. 어조의 격식은 낮추지 않는다.

- 어휘를 낮추더라도 성인 대상 공식 문서 수준의 어조를 유지한다.
- 격식 없는 표현, 구어체, 감탄, 이모지, "여러분" 같은 독자 호명을 쓰지 않는다.
- "쉽게 말해", "간단히 말하면", "어렵게 들리겠지만"처럼 난이도를 해설하지 않는다. 내용 자체를 쉽게 쓰면 해설이 필요 없다.
- 비유는 개념의 구조를 정확히 보존할 때만 제한적으로 쓴다. 일부 속성만 전하면서 전체를 대표하는 인상을 주는 비유는 쓰지 않는다. 비유를 쓰더라도 비유만으로 설명을 끝내지 않고 실제 작동 내용을 함께 쓴다.
- 문장을 짧게 끊어 리듬으로 쉬움을 연출하지 않는다. 쉬움은 어휘와 논리에서 확보한다.

## 용어 밀도

- 한 문단에 새 설명 블록이 쌓여 본문보다 설명이 많아지면 문단 설계를 다시 검토한다. 용어를 정의로 해결하기 전에 그 용어가 글의 목적에 필요한지 먼저 판단한다. 결론에 기여하지 않는 용어는 정의하지 않고 등장 자체를 없앤다.
- 같은 개념을 가리키는 용어는 글 전체에서 하나로 통일한다. 한 글에서 "마이그레이션", "이전", "전환"을 섞어 쓰지 않는다.

## 교정할 때

- 원문의 사실 관계, 수치, 출처, 구조는 보존하고 어휘만 처리한다.
- 교정 대상 용어와 처리 방식을 간략히 요약한 뒤 교정 결과를 낸다.
- 결과물에는 용어를 바꾼 사실, 독자 수준 판단, 이 규칙의 존재를 쓰지 않는다. "전문용어를 최소화하여 작성하면" 같은 자기 적용 선언을 쓰지 않는다.

## 예시

### 평이어 대체만으로 해결되는 경우

```markdown
교정 전
- 온프레미스 레거시 시스템의 클라우드 마이그레이션 시 리프트앤시프트 방식은 TCO 관점에서 차선책
    + 리플랫포밍 또는 리아키텍팅을 통한 클라우드 네이티브 전환이 운영 효율 측면에서 우위

교정 후
- 사내 서버에서 운영해 온 기존 시스템을 구조 변경 없이 클라우드로 옮기는 방식은 장기 총비용 측면에서 불리
    + 시스템 구조를 클라우드 환경에 맞게 재설계하여 옮기는 방식이 운영 효율 측면에서 우위
    + 재설계 범위는 운영 비용 비중이 큰 기능부터 단계적으로 확대
```

### 설명 블록이 필요한 경우

```markdown
교정 전
- 중앙은행의 빅스텝 단행으로 콜금리 상승 및 RP 매각 확대

교정 후
- 중앙은행이 기준금리를 한 번에 0.50%p 인상
    + 콜금리가 인상 폭을 반영하여 상승
    + 환매조건부채권 매각 확대로 시중 자금 흡수 병행

> (콜금리) 은행 사이에서 하루 단위로 빌리는 초단기 자금에 적용하는 금리

> (환매조건부채권) 일정 기간이 지난 뒤 되사는 조건으로 판매하는 채권
```

"빅스텝"은 수치로 풀 수 있어 평이어로 바꾼다. "콜금리"와 "RP"는 풀어 쓰면 다른 금리나 채권과 구별되지 않으므로 본문에 두고 설명 블록을 붙인다. 약어 "RP"는 본문에서 정식 명칭으로 바꾼다.

### 모호한 추상화 교정

```markdown
교정 전
- 정부가 돈과 관련된 조치를 통해 시장에 영향을 주는 정책을 시행
    + 이 조치로 경제 상황이 나아질 것으로 기대

교정 후
- 정부가 추가경정예산을 편성하여 소상공인 손실 보상 재원 확보
    + 보상금 지급으로 소상공인의 단기 자금난 완화 기대
    + 지급 대상과 기준은 매출 감소 증빙 자료로 확정

> (추가경정예산) 연도 중에 본예산을 바꾸어 다시 편성하는 예산
```

### 유치한 문체 교정

```markdown
교정 전
블록체인은 쉽게 말해 모두가 같이 쓰는 일기장이에요! 누가 한 번 쓰면 절대 지울 수 없답니다. 어렵게 들리겠지만 사실 우리 동네 반상회 회의록이랑 비슷해요.

교정 후
- 블록체인은 거래 기록을 여러 참여자가 같은 사본으로 나누어 보관하는 장부 기술
    + 한 참여자가 기록을 위조하면 다른 참여자의 사본과 대조하는 과정에서 위조 사실이 드러나는 구조
    + 중앙 관리자 없이 기록의 신뢰를 확보하여 거래 당사자 사이의 직접 검증이 가능
```

## 점검 목록

- 기준 독자가 정의 없이 이해할 수 없는 단어를 무단으로 쓰지 않았는가
- 글의 목적과 결론에 기여하지 않는 전문용어가 없는가
- 일상어와 형태가 같지만 분야 안에서 뜻이 다른 단어를 무단으로 쓰지 않았는가
- 영문 약어에 전체 명칭을 함께 적었는가
- 평이어로 바꾸면서 원래 용어의 구별 정보를 잃지 않았는가
- 설명 블록이 용어가 처음 나온 항목 바로 뒤에 있는가
- 같은 용어의 정의를 본문과 설명 블록 가운데 한 곳에서 한 번만 했는가
- 설명 블록 안에 다른 전문용어나 정의 대상 단어가 없는가
- 본문 문장 안에 긴 괄호 정의가 없는가
- 같은 개념을 가리키는 용어가 글 안에서 통일되어 있는가
- 격식 없는 표현, 구어체, 감탄, 난이도 해설이 없는가
- 비유만으로 설명을 끝내지 않았는가

## 적용하지 않는 경우

- 사용자가 전문가 독자를 밝히면 그 독자의 전제 지식으로 판별 기준을 조정한다.
- 인용 원문, 법령 조문 원문, 코드 자체는 고치지 않고 앞뒤 설명 문장에만 적용한다.
- 기관명, 제품명, 정책명, 표준명 같은 고유명사는 대체하지 않는다. 독자 이해에 필요하면 설명 블록을 붙인다.
- 사용자가 특정 용어를 유지하라고 하면 그 용어는 처리하지 않는다.
