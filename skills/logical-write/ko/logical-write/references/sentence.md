# 문장 규칙

## 1문장 1메시지와 5W1H 단일성

한 문장에는 메시지 하나만 담는다. 이를 판정하는 기준이 5W1H 단일성이다. 한 문장 안에서 누가, 언제, 어디서, 무엇을, 왜, 어떻게는 각각 한 번만 나온다. 같은 요소가 두 번 나오면 그 문장은 두 메시지를 담은 복문이다.

- 문장마다 Why, What, How를 담는 구성을 권장한다. 각 요소는 한 번만 쓴다.
- 문장을 나눠도 각 문장에 필요한 5W1H 정보는 빠뜨리지 않는다.
- 문장을 나누는 근거는 5W1H 요소의 중복이다. 임의로 끊지 않는다.
- 단문 모드의 접속 표현 제한과 두 모드 공통의 쉼표, 세미콜론 제한은 한 문장에 같은 요소가 겹쳐 들어오는 길을 막는 수단이다.
- 조사를 빠뜨리거나 주어와 서술어가 맞지 않는 비문을 쓰지 않는다.

판정 절차는 다음과 같다.

1. 문장에서 5W1H 요소를 찾는다.
2. 같은 요소가 두 번 이상 나오는지 본다.
3. 두 번 이상이면 요소 경계에서 문장을 나눈다.
4. 나눈 문장마다 Why, What, How가 있는지 다시 본다.

```markdown
틀린 예 (What 2개, 결과 2개)
- 회사는 교육 예산을 확대하고 평가 제도를 개편하여 학습 환경을 개선하고 성과를 제고함

올바른 예
- 회사는 직무 교육 예산을 단계적으로 확대하여 학습 환경 개선 추진
- 회사는 교육 성과 평가 제도를 개편하여 교육 성과 제고 도모
```

```markdown
틀린 예 (How 2개)
- 연구소는 자율 과제 비중을 높이고 행정 서류를 통합하여 연구 몰입도를 높임

올바른 예
- 연구소는 자율 과제 비중을 단계적으로 높여 연구 몰입도 제고
- 연구소는 반복 제출 행정 서류를 통합하여 연구자 행정 부담 완화
```

## 공통 표기

두 문장 모드에 모두 적용한다.

| 대상 | 예 | 처리 |
|---|---|---|
| 연결용 쉼표 | 문장 연결, 삽입구, 부연에 쓴 쉼표 | 문장을 나누거나 명사형으로 재구성 |
| 나열 쉼표 | 같은 범주 3개 이상 나열 | 쉼표 유지 (예: 반도체, 디스플레이, 이차전지). 대등한 명사 2개 나열은 '와', '과' 대신 "A 및 B" (예: "예산과 인력 확보"는 "예산 및 인력 확보"). 비교 대상이나 협력 상대를 나타내는 '와', '과'는 유지. BSC의 '학습과 성장' 같은 관용 명칭도 유지 |
| 문장 안의 `+` 기호 | "예산 + 인력 확보" | `+`는 하위 항목 들여쓰기 전용. 문장 안에서는 "및"이나 문장 재구성 |
| 마침표 | 문장 중간이나 항목 끝의 마침표 | 삭제. 문장 중간이면 그 자리에서 항목을 나눔 |
| 세미콜론 | 문장 연결용 세미콜론 | 삭제 후 항목을 나눔 |
| 구분 기호 | /, \|, ·, →, ←, ↑, ↓, vs ("비용/편익") | 삭제하거나 문장으로 풀어 씀 |
| 연결 하이픈 | "비용-편익", "단기-중기" | 문장으로 풀어 씀 |
| 물결표 | 범위 표기의 물결표 | 하이픈(-)으로 대체 |
| 과도한 축약어 | 불필요한 영문 약어, 비공식 줄임말 | 풀어 씀 |
| 불필요한 외래어, 한자어 | 한국어로 바꿀 수 있는 외래어 | 한국어로 바꿈 |
| 존댓말 | -합니다, -입니다, -하세요 | 명사형 종결로 바꿈 |

연결용 쉼표는 지우기만 하면 안 된다. 쉼표만 지우면 문장은 복문 그대로 남는다. 문장을 나누거나 명사형으로 재구성하여 해소한다. 3개 이상 나열의 쉼표는 지우지 않는다. 쉼표 없이 명사를 띄어쓰기로만 늘어놓으면 뜻이 흐려진다.

```markdown
틀린 처리 (쉼표만 삭제하여 복문이 남음)
- 회사는 예산을 확대하였고 이에 따라 교육 환경이 개선됨

올바른 처리 (문장 분리와 명사형 재구성)
- 회사는 직무 교육 예산을 단계적으로 확대
- 예산 확대에 따른 교육 환경 개선 기대
```

```markdown
틀린 처리 (나열 쉼표 삭제)
- 공공 산업 연구 부문의 수요를 종합 분석

올바른 처리 (나열 쉼표 유지)
- 공공, 산업, 연구 부문의 수요를 종합 분석
```

## 단문 모드

- 접속 표현과 절을 잇는 어미를 쓰지 않는다. 대상은 그리고, 그러나, 그래서, 그렇기 때문에, 이는, -으며, -있으며, -이며, -고 등이다.
- 접속 표현이 필요해 보이면 문장을 나누거나 명사형으로 재구성한다.
- 두 사실을 한 문장에 잇지 않는다. 사실마다 문장을 나누고 문장 사이 관계는 항목 순서와 계위로 드러낸다.
- 한 문장 안의 수단이나 원인은 "-하여", "-으로"처럼 5W1H 요소 하나로 담는다. "예산을 단계적으로 확대하여 학습 환경 개선 추진"은 How 하나와 What 하나를 담은 단문이다.

```markdown
틀린 예
- 신청 절차가 복잡하여 이탈률이 높으며 상담 문의도 증가함

올바른 예
- 온라인 신청 절차의 단계 과다로 중도 이탈률 상승
- 절차 문의 증가로 상담 창구 대기 시간 증가
```

## 연결 모드

### 허용 범위

종속절은 핵심 메시지를 보강하는 역할에만 쓴다.

- (인과) 핵심 메시지의 원인이나 결과를 부연하는 절
- (조건) 핵심 메시지가 성립하는 조건을 밝히는 절
- (구체화) 핵심 메시지의 범위나 사례를 구체화하는 절
- (수단) 핵심 메시지를 이루는 방식을 설명하는 절

독립된 새 메시지를 종속절로 붙이지 않는다. 두 사실이 단순 병렬이면 별도 문장이나 별도 항목으로 나눈다.

### 쓸 수 있는 연결 표현

- (인과) 이에 따라, 따라서, 이를 통해, 이러한 한계를 극복하고자, 이러한 변화에 대응하여
- (부연) 특히, 더욱이, 또한, 동시에, 아울러
- (대비) 그러나, 반면, 한편, 이와 달리
- (시간) 최근, 향후, 이후, 이전, 기존에는
- (지시) 이러한, 이와 같은, 해당, 본
- (종속 어미) 대등(-으며, -이며, -하며), 양보(-으나, -지만, -함에도), 인과(-함으로써, -함에 따라, -기 때문에), 조건(-할 경우, -한다면, -할 때)

### 사용 제한

- 연결 표현은 앞뒤 사이에 실제 인과, 부연, 대비, 시간, 조건 관계가 있을 때만 쓴다. 의무적으로 끼워 넣지 않는다.
- 같은 연결 표현을 반복하지 않는다.
- 한 문장에 -며, -고, -면서, -으나 같은 연결 어미를 쌓지 않는다.
- 흐름은 연결 표현의 개수보다 항목 배치 순서와 인과 논리로 만든다. 흐름이 자연스러우면 연결 표현 없이 간결하게 끝맺어도 된다.
- 핵심 메시지에 이미 있는 5W1H 요소를 종속절이 다시 들여오지 않는다. 같은 요소가 두 번 필요하면 인과 사슬 하나로 합치거나 문장을 나눈다.

```markdown
틀린 예 (원인 2개가 병렬)
- 예산 제약과 인력 공백으로 도입 시점이 지연됨

올바른 예 (원인을 인과 사슬 하나로 합침)
- 예산 제약으로 인력 확보가 늦어지면서 도입 시점이 지연됨
```

```markdown
틀린 예 (다른 시점의 독립 메시지 2개가 병렬)
- 정책 부재로 부서별 임의 적용 사례가 누적되며 표준화 시점에 저항 발생

올바른 예 (핵심 메시지를 "조직 저항 유발"로 하나로 정하고 "사례 누적"은 중간 단계로 합침)
- 정책 부재로 부서별 임의 적용 사례가 누적되어 사후 표준화 시도에 대한 조직 저항 유발
```

```markdown
올바른 예 (핵심 메시지는 "의사결정이 어려워짐", 앞 절은 인과 보강)
- 기술 변화의 속도가 빨라지면서 기존의 선형적 관리 절차로는 제때 의사결정을 내리기 어려워짐
```

### 문장 골격과 비문

- 한 문장에는 핵심 메시지를 담는 주어와 서술어 골격을 하나만 둔다. 종속절은 이 골격을 보강한다.
- 절이 늘어나도 핵심 주어와 서술어의 관계가 흐려지지 않게 각 절의 수식 범위를 분명히 한다.
- 조사 탈락, 주어와 서술어의 호응 파괴, 수식 대상이 모호한 수식어를 쓰지 않는다.
- 소리 내어 읽었을 때 한 호흡에 핵심 주어와 서술어를 따라갈 수 있을 만큼 절의 개수와 문장 길이를 조절한다.
- 문장 길이 자체를 줄이라는 규칙은 없다. 절이 여러 개여도 골격이 분명하면 허용한다.

```markdown
틀린 예 (절이 연쇄되어 주어와 서술어가 흐려짐)
- 정책이 부재한 상태에서 부서별로 적용 사례가 누적되는 가운데 책임 경계도 비공식적으로 형성되면서 사후 정비를 어렵게 하는 구조로 이어지는 양상

올바른 예
- 정책 부재 상태에서 부서별 적용 사례가 누적되면서 사후 정비 부담이 가중됨
```

### 연결 모드에서 피하는 형태

- (끊어쓰기 강박) 모든 문장을 5음절 안팎으로 끊어 흐름을 단절
- (병렬 나열 강박) 인접 문장 사이 관계 없이 단순 나열만 반복
- (연결어 회피 강박) 필요한 연결 표현까지 모두 지워 문장 사이 인과를 단절
- (장황한 만연체) 독립 메시지 두 개 이상을 종속절로 묶어 핵심 메시지가 흐려짐
- (구어체 침투) 흐름을 살린다는 이유로 -합니다, -군요, -네요 같은 구어체를 씀

## 종결

- 모든 문장은 명사형으로 끝맺는다. 예: -임, -함, -됨, -필요, -전망, -예정, -확인, -기대, -수행
- 동사형 종결(-한다, -된다, -한다고 밝혔다)은 쓰지 않는다. "-한다고 밝혔다"는 "-한다고 밝힌 바 확인"처럼 명사형으로 바꾼다. 인용, 법령, 정의 원문을 그대로 옮길 때는 원문을 따른다.
- 존댓말 종결(-합니다, -입니다, -하세요)은 쓰지 않는다.
- 한 항목에 독립된 내용이 두 개 이상 있으면 항목을 나눈다.
- 명사형 종결은 자연스러운 한국어로 쓴다.

| 어색한 예 | 자연스러운 예 |
|---|---|
| 목차명에는 키워드 기반 재구성으로 반영 | 목차명은 키워드 기반으로 재구성 |
| 온전 세트 | 온전한 세트 |

- "구조", "우선", "결론", "훌륭", "-것", "-곳"처럼 문장 끝에 오면 어색한 명사, 받침 'ㅅ'으로 끝나는 명사로 문장을 끝맺지 않도록 주의한다.

### 관형형 잔존

명사형 종결 문체에서 "-할", "-을 할", "-시킬" 같은 관형형이나 조사 "-의"가 남아 문장이 어색해지는 경우다.

| 어색한 형태 | 자연스러운 형태 | 문제 |
|---|---|---|
| 목적 달성을 할 필요 | 목적 달성 필요 | "을 할" 삽입 |
| 목적을 달성할 필요 | 목적 달성 필요 | 관형형이 명사형 종결과 충돌 |
| 선행할 필요, 후행할 필요 | 선행 필요, 후행 필요 | "할" 잔존 |
| 접근할 필요, 정의할 필요 | 접근 필요, 정의 필요 | "할" 잔존 |
| 내장시킬 필요 | 내장 필요 | "시킬" 삽입 |
| 접근할 시사 | 접근 가능 또는 문장 재구성 | "할"과 "시사"의 부조화 |
| 작업의 부담 | 작업 부담 발생 | "의" 삽입. "작업 부담"만으로는 서술이 불완전하므로 "발생", "증가", "우려" 같은 서술 명사 보충 |

- (판별) 관형형 뒤에 "필요", "시사", "부담" 같은 명사가 오고 관형형을 지워도 뜻이 같으면 교정 대상이다.
- (처리) 관형형을 지우고 명사구로 바로 끝맺거나 조사를 재구성한다.
- (허용) 관형형이 대상을 한정하여 지우면 뜻이 달라지는 경우는 둔다. "검토할 사항"과 "검토 사항"은 차이가 작으므로 교정하고 "삭제할 파일"처럼 동사가 대상을 특정하면 둔다.
- 관형형 뒤에 '것'이 오는 "-할 것"은 아래 빈자리 명사 규칙으로 처리한다.

### 명사만 이어 붙인 문장

명사만 연속으로 늘어놓은 문장은 쓰지 않는다. 조사와 서술어를 살려 관계를 드러낸다.

| 틀린 예 | 올바른 예 |
|---|---|
| 디지털 산업 집적 지표 | 디지털 산업의 집적도 |
| 연구 기술 자원 역량 상태 | 연구 인프라 보유 여부 |

## 빈자리 명사

지시 대상의 이름을 정하지 않고 정보 없는 명사로 감싸 넘기는 표현이다. 대표적인 예가 의존명사 '것'이다. 작성자는 대상을 알면서도 이름을 붙이지 않고 독자는 앞뒤 문장에서 대상을 복원하는 부담을 진다.

'것'만 막으면 같은 구조가 '곳', '거', '셈', '부분'으로 옮겨 간다. 그래서 단어 목록보다 구조의 기능으로 판별한다. 정상 문법 용법도 많으므로 명사가 나왔다는 사실만으로 판단하지 않고 구체적인 명사나 서술 명사로 바꿀 수 있는지로 판단한다.

### 범위

아래 목록은 탐지의 출발점이다. 목록에 없는 명사도 같은 기능을 하면 같게 처리한다.

| 지칭 기능 | 명사 예 |
|---|---|
| 사물이나 사안 | 것, 점, 부분, 사항, 측면 |
| 장소 | 곳, 데 |
| 사태나 정도 | 바, 셈, 편, 터, 식 |

- '것'의 구어 축약형 '거', '겄', '게(것이)', '건(것은)', '걸(것을)'도 '것'과 같게 처리한다.
- 구어 축약형은 격식 문체까지 해치므로 보고서 문체에서 먼저 고친다.

### 탐지 유형

| 유형 | 교정 전 | 교정 후 | 문제 |
|---|---|---|---|
| 의사분열문 | "사업 지연을 초래한 것은 승인 절차의 중복", "개선이 시급한 곳은 승인 단계" | "승인 절차 중복으로 사업 지연 발생", "승인 단계 개선 시급" | 주어 자리를 비우고 정보를 문장 끝으로 미룸 |
| 동사 명사화 우회 | "데이터를 정비하는 것이 필요", "고객 이탈을 줄이는 것을 목표로 설정" | "데이터 정비 필요", "고객 이탈률 감소를 목표로 설정" | 한자어 명사나 명사형(-기, -음)이 있는데 "-하는 것"으로 우회 |
| 모호 지칭 | "현장에서 원하는 것을 반영", "이런 것들을 고려하면", "문제가 되는 부분을 개선" | "현장에서 요청한 야간 교대 알림 기능을 반영", "인력 부족과 예산 제약을 고려하면", "중복 입력 항목을 개선" | 지시 대상을 빈자리 명사로 압축하여 정보 생략 |
| 빈자리 명사 종결 | "현장 인력의 활용도가 낮은 것", "보완이 필요한 곳", "추가 검토할 거", "입력 절차가 중복되는 부분" | "현장 인력 활용도 저조", "야간 알림 기능 보완 필요", "추가 검토 필요", "입력 절차 중복" | 빈자리 명사로 문장을 봉합하여 명사형 종결처럼 위장 |
| 정도 얼버무림 종결 | "사실상 무산된 셈", "개선된 편" | "예산 미확보로 추진 중단", "전년 대비 처리 기간 단축" | 판단의 근거와 정도를 밝히지 않음 |
| 단정 강조 종결 | "결국 비용이 문제라는 것이다" | "비용 부담이 도입 지연의 주된 원인이다" | 주장을 "-것이다"로 한 번 더 감싸 단정의 무게만 더함 |
| 추정 회피 종결 | "수요가 회복되는 것으로 보임", "개선이 필요한 것 같다" | 근거가 있으면 "재고 소진 속도 회복으로 수요 회복 확인", 없으면 "수요 회복 여부 확인 필요" | 판단 주체와 근거를 함께 생략 |

"중요한 것은", "주목할 점은"처럼 강조용 의사분열문은 `expression.md`의 의미 없는 표현으로 처리한다.

### 판별 기준

- (치환 테스트) 빈자리 명사를 구체적인 명사로 바꿀 수 있고 바꾼 문장이 더 많은 정보를 전달하면 교정 대상이다.
- (명사화 테스트) "-하는 것"을 한자어 명사나 명사형(-기, -음)으로 바꿔도 뜻이 같으면 교정 대상이다.
- (종결 테스트) 문장 끝의 빈자리 명사를 지우고 "필요", "저조", "확인" 같은 서술 명사로 자연스럽게 끝맺을 수 있으면 교정 대상이다.
- (구조 우선) 명사가 목록에 있는지보다 "관형절과 정보 없는 명사"가 주어 자리를 비우거나 문장 끝을 봉합하는지를 먼저 본다.
- (밀도 점검) 한 문단이나 한 항목 묶음에 빈자리 명사가 종류와 관계없이 합산 3회 이상 나오면 명사마다 치환 테스트를 적용한다. 밀도는 점검을 시작하는 신호이며 밀도만으로 고치지 않는다.

### 허용 조건

다음 경우는 판별 기준에 해당해도 원문을 둔다.

| 허용 유형 | 예 | 이유 |
|---|---|---|
| 어휘로 굳은 표현 | 먹을 것, 탈것, 날것, 새것, 옛것 | 한 단어로 굳어 바꿀 명사가 없음 |
| 문법 기능 용법 | "-할 수 있다", "설치하는 데 소요", "보고한 바와 같이" | '수', '데', '바'가 가능, 용도, 전거를 나타내며 대상을 감추지 않음 |
| 실제 공간 지칭 | "주차 공간이 부족한 곳에 임시 주차장 설치" | '곳'이 문맥에서 특정되는 물리적 위치를 가리킴 |
| 지시 장르의 지시형 종결 | "제출 기한을 준수할 것", "첨부 서류를 확인할 것" | 규정, 공문, 점검표, 프롬프트의 관용 종결. 보고서 서술부의 "-할 것"은 해당하지 않음 |
| 근거가 있는 전망 | "금리 인하 기조 유지로 대출 수요가 늘어날 것으로 전망" | 전망의 근거가 문장 안에 있음 |
| 치환하면 뜻이 바뀌는 문장 | 구체적인 명사로 바꾸면 초점이나 뜻이 달라지는 문장 | 치환이 정보를 더하지 못하고 원문의 뜻을 훼손 |

### 처리 원칙

- 서술 명사 종결, 지시 대상 명명, 한자어 명사화 가운데 하나로 고친다.
- 빈자리 명사를 다른 빈자리 명사나 구어 축약형으로 바꾸는 치환은 교정으로 인정하지 않는다. "필요한 것"을 "필요한 곳", "필요한 거", "필요한 부분"으로 바꿔도 정보량은 그대로다.
- 작성 중 '것'을 피하려다 대체 명사가 떠오르면 그 자리를 문장 재구성 신호로 보고 서술 명사 종결이나 지시 대상 명명으로 바꾼다.
- 원문의 종결 문체를 유지한다. 명사형 종결 글은 명사형으로, 동사형 종결 글은 동사형으로 고친다.
- 교정 모드에서는 빈자리 명사의 지시 대상을 원문 문맥에서 복원한다. 복원할 수 없으면 임의로 채우지 않고 해당 위치를 사용자에게 확인한다.

```markdown
교정 전
- 민원 처리가 지연되는 곳은 부서 간 이관 단계
    + 담당 부서를 재지정하는 데 평균 이틀이 소요되는 부분
- 현재 체계는 사실상 이관을 방치하는 셈
    + 자동 배정 규칙을 도입할 거

교정 후
- 부서 간 이관 단계에서 민원 처리 지연 발생
    + 담당 부서 재지정 과정에서 평균 이틀 소요
    + 재지정 기준이 문서로 정해지지 않아 담당자 판단에 의존
- 현행 체계에서 이관 민원의 후속 관리 미흡
    + 민원 유형별 자동 배정 규칙 도입 필요
    + 이관 후 처리 기한 경과 시 담당 부서에 알림 발송
```

## 문장 리듬

- 한 문장이 지나치게 짧거나 길지 않게 쓴다. 단문이어도 5W1H 정보는 충분히 담는다.
- 한 항목에 딸린 하위 항목 수가 지나치게 적거나 많지 않게 조절한다.
- 같은 단어, 주어, 서술어, 종결이 인접 문장에서 반복되지 않게 한다.
- 소리 내어 읽었을 때 리듬이 어색한 곳을 고친다.
