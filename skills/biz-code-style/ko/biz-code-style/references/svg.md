# SVG 도해

SVG를 직접 작성해 다이어그램, 도해, 개념도, 구조도, 일러스트, 차트를 그린다. 컨설팅과 기획 장표 삽입을 기준으로 적었으며 장표가 아닌 용도에도 같은 절차와 규칙을 적용한다. 색, 글꼴, 피할 패턴의 공통 규칙은 visual.md를 따르고 이 파일은 SVG에서 필요한 세부 규칙을 다룬다.

도해 형태는 요청마다 메시지의 관계구조에서 새로 도출하며 이전 산출물의 형태를 재사용하지 않는다. 단순 막대 차트부터 처음 정의하는 개념 도해까지 요청 범위가 넓어서 고정 형태를 미리 정할 수 없기 때문이다. 판단의 근거는 다음과 같다.

- 형태는 메시지에서 나온다. 메시지 없는 형태는 장식이다.
- 수치는 지각 정확도가 높은 인코딩 채널에, 범주는 그보다 낮은 채널에 배정한다.
- 요소를 지워도 메시지가 남으면 그 요소는 지운다.

## 작도 절차

코드를 작성하기 전에 1-3단계의 결정을 3-5행으로 먼저 적는다. 이 기록이 없으면 형태가 관습으로 수렴해 AI 상투 형태가 나온다.

### 1단계 메시지 확정

- 도해가 증명할 서술문 1개를 정한다. "조직 구조" 같은 명사구는 메시지가 되지 못한다. "권한이 3개 계층에 분산되어 의사결정이 지연"처럼 판단을 담은 문장이 메시지다.
- 메시지가 2개 이상이면 도해를 나눈다. 도해 1개에 메시지 2개를 함께 넣지 않는다.
- 정한 메시지 문장은 도해 안에 넣지 않는다. 메시지는 형태를 고르는 기준값이다.

### 2단계 관계구조 판별

메시지가 주장하는 관계를 아래 표에서 1개 고른다. 무엇이 데이터인지가 판별 기준이다.

| 계열 | 구조 | 단서 어휘 | 기하 형태 |
|------|------|-----------|-----------|
| 정량 | 구성비 | 비율, 점유율, 구성 | 100% 누적 막대, 원 분할 |
| 정량 | 항목 비교 | 크다, 순위, 격차 | 수평 막대, 점 플롯 |
| 정량 | 시계열 | 추이, 변화, 성장 | 수직 막대, 꺾은선 |
| 정량 | 도수분포 | 구간, 빈도, 분포 | 히스토그램, 계단 |
| 정량 | 상관 | 상관, 동반, 산포 | 산점도, 버블 |
| 관계 | 순차 | 절차, 단계, 흐름 | 좌우 정렬 블록과 단일 방향 표시(셰브론) |
| 관계 | 위계 | 상위, 하위, 분해 | 상하 트리, 들여쓰기 블록 |
| 관계 | 포함 | 소속, 범위, 경계 | 중첩 사각형이나 원 |
| 관계 | 연결 | 의존, 연동, 참조 | 노드와 간선 |
| 관계 | 대응 | 매핑, 대비, 연계 | 좌우 2열과 대응선 |
| 관계 | 순환 | 반복, 피드백, 되돌아옴 | 닫힌 경로 |
| 관계 | 중첩 | 공통, 교집합, 겹침 | 반투명 도형 교차 |
| 상태 | 변환 | 전환, 개선, 목표 | 같은 좌표계의 패널 2개 |
| 상태 | 간극 | 차이, 미달, 필요량 | 기준선과 차이 막대 |

- 구조를 먼저 정한 뒤 형태를 세부 조정한다. 형태를 먼저 떠올리고 구조를 거꾸로 끼워 맞추지 않는다.
- 관계 종류가 3개를 넘으면 도해 1개로 표현할 수 없으므로 도해를 나눈다.

### 3단계 인코딩 채널 배정

- 수치는 지각 정확도가 높은 채널부터 쓴다. 정확도 순서는 공통 축 위의 위치, 정렬되지 않은 축 위의 위치, 길이, 기울기와 각도, 면적, 부피, 명도와 채도 순이다.
- 정량값은 위치와 길이에 배정한다. 정량값을 색이나 면적만으로 표현하지 않는다.
- 원의 면적과 색 농도는 값을 읽는 오차가 크므로 순위 판단이 필요한 값에 쓰지 않는다.
- 범주는 그룹 위치와 질감에 배정한다. 범주를 길이로 표현하지 않는다.
- 단일 색 계열 안에서 범주를 구분해야 하면 명도 단계를 최대 4개까지 쓰고, 넘으면 해칭 무늬로 넘어간다.

### 4단계 캔버스와 그리드

| 용도 | viewBox |
|------|---------|
| 장표 본문 16:9 | `0 0 1600 900` |
| 장표 본문 4:3 | `0 0 1600 1200` |
| 보고서 삽입 가로 띠 | `0 0 1600 520` |
| 개념 도해 정사각형 | `0 0 1200 1200` |
| A4 가로 전면 | `0 0 1600 1131` |

- 캔버스 높이는 먼저 정하지 않는다. 내용 높이를 산정한 뒤 거꾸로 계산한다. 도해 안에 제목을 넣지 않으므로 표준 비율을 먼저 잡으면 위쪽 여백이 지나치게 커지고 무게가 아래로 쏠린다.
- 폭 1600 기준으로 좌우 여백 80, 12열 각 98, 열 사이 간격 24를 쓴다(80 × 2 + 98 × 12 + 24 × 11 = 1600).
- 위아래 여백은 짧은 변의 5% 이상으로 한다.
- 컨테이너가 테두리 역할을 할 때는 내용 요소가 컨테이너 높이의 70% 이상을 차지하게 한다. 비율이 낮으면 컨테이너가 빈 공간으로 읽혀 계층 인식이 무너진다.
- 간격은 8, 16, 24, 40, 64 중에서 고른다. 임의의 수치를 쓰지 않는다.
- 같은 계층 요소는 좌표를 정확히 맞춘다. 1px 차이도 정렬 불일치로 보인다.
- 그리드는 배치의 근거로 쓴다. 12열을 모두 채우는 균등 배치는 피한다.

### 5단계 텍스트

SVG에는 자동 줄바꿈이 없어 글자 폭을 잘못 추정하면 글자가 넘친다.

- 추정 폭 = 글자 크기 × (문자별 계수의 합)
- 문자별 계수는 한글 음절 1.00, 라틴 대문자 0.70, 라틴 소문자 0.55, 숫자 0.62, 문장 부호 0.50, 공백 0.30이다.
- 계수는 NanumGothic Bold의 문자 종류별 평균 advance width(em 단위)를 올림한 값이다. 다른 글꼴을 쓰면 같은 방법으로 다시 계산한다.
- 컨테이너 최소 폭 = 추정 폭 × 1.08 + 좌우 안쪽 여백의 합
- 예시: "디지털 전환 로드맵"은 한글 8자와 공백 2개라 8.6em이다. 글자 크기 24에서 206, 1.08배 후 223, 안쪽 여백 20씩 더하면 263 이상이 필요하다.
- 길이가 제각각인 텍스트가 들어가는 열은 가장 긴 문자열 기준으로 폭을 정한다. 단위가 붙는 값 라벨처럼 한 항목만 길어지는 경우에 넘침이 자주 생긴다.
- 줄바꿈은 `<tspan x="..." dy="1.35em">`로 직접 처리한다. 어절 경계에서 줄을 바꾸고 조사를 분리하지 않는다.
- 한글 라벨 한 줄은 14자 이하로 쓴다. (권장)
- 가운데 정렬은 `text-anchor="middle"`과 `dy="0.35em"`을 함께 쓴다. `dominant-baseline`은 일부 변환기에서 무시되어 이식성이 낮다.
- 라벨이 선이나 도형을 가로지르면 `paint-order="stroke"`와 흰색 stroke 3-4로 글자 주변을 비운다. paint-order를 지원하지 않는 렌더러(CairoSVG 등)는 흰 stroke로 글자를 덮어 글자가 보이지 않으므로 이 방식을 쓴 도해는 브라우저로 렌더링해 검증한다.
- 글자 크기는 1600×900 기준 최소 20으로 한다. 역할별로 핵심 수치 56-72, 요소 제목 28-32, 일반 라벨 22-24, 보조 라벨 20을 쓴다.
- 글꼴 지정은 `font-family="NanumGothic, 'Malgun Gothic', 'Apple SD Gothic Neo', sans-serif"`로 한다.
- 회전 텍스트는 세로축 라벨에만 쓰고 `rotate(-90)`만 쓴다. 세로쓰기는 쓰지 않는다.
- 도해 안에 도해 제목, 출처, 부연 설명, 작성 도구 정보를 넣지 않는다.

### 6단계 검증

- 렌더링 수단(브라우저, resvg, rsvg-convert, Inkscape, CairoSVG 등)이 있으면 PNG로 변환해 눈으로 확인한다. 결함이 있으면 코드를 고쳐 다시 렌더링하고 결함이 없으면 산출한다.
- 렌더링 수단이 없으면 산술 점검을 한다. 모든 텍스트의 추정 폭과 컨테이너 폭을 대조하고, 모든 요소의 좌표 최댓값이 viewBox 안에 있는지 확인하고, 같은 계층 요소의 x 좌표나 y 좌표가 일치하는지 확인한다.
- 검수 항목은 visual.md의 시각 검증 항목과 같다. 원본 수치와 도형 길이의 정합도 함께 확인한다.
- 필터를 지운 상태에서도 도해가 완결되는지 확인한다.

## 색 사용

visual.md의 색표를 SVG에서 아래처럼 쓴다.

| 값 | 용도 | 올릴 글자색 |
|----|------|-------------|
| #1A1A1A | 본문 텍스트, 주요 외곽선 | - |
| #2C466D | 가장 높은 강조 면 | 흰색 |
| #4369A3 | 높은 강조 면 | 흰색 |
| #6B8EC2 | 기본 면 | #1A1A1A |
| #9AB2D6 | 2차 면 | #1A1A1A |
| #C9D6E9 | 3차 면, 배경 영역 | #1A1A1A |
| #EDF1F8 | 가장 낮은 면, 영역 음영 | #1A1A1A |
| #595959 | 헤어라인, 축선, 보조선 | - |
| #C0392B | 강조 1곳 | 흰색 |

- #6B8EC2 위의 흰 글자는 대비가 3.35:1로 부족하다. 흰 글자는 #4369A3 이상 어두운 면에만 쓴다.
- 강조색은 도해 1개에 1곳만 쓴다.
- 네이비 계열과 강조색 외의 색이 필요하면 사용자에게 묻는다.
- 색은 범주에 1:1로 대응시키고 장식 목적의 색을 추가하지 않는다.
- 배경은 투명을 기본으로 하고 필요하면 `<rect fill="#FFFFFF">` 1개만 둔다.

## SVG 요소 사용법

### 출력 형식

- 루트는 `<svg xmlns="http://www.w3.org/2000/svg" viewBox="...">`로 쓰고 width와 height 속성은 생략한다. 장표에 넣을 때 컨테이너 크기에 맞춰 늘고 줄어야 하기 때문이다.
- `<foreignObject>`는 여러 변환기에서 내용이 사라지므로 쓰지 않는다.
- 외부 이미지 참조와 웹 글꼴 import를 쓰지 않고 파일 하나로 완결한다.
- 모든 `id`에 도해마다 고유한 접두어를 붙인다. 문서 하나에 SVG를 여러 개 넣으면 같은 id가 서로의 defs를 덮어써 도해가 깨진다.
- `<g>`에 `data-role` 속성으로 역할을 적어 디버깅할 때 추적할 수 있게 한다.

### marker(화살촉 통일)

- 화살표는 정보 흐름 전달에 꼭 필요한 곳에만 쓰고 방향이 분명한 좌우 배열에는 생략한다.
- 화살촉을 다각형으로 직접 그리지 않고 marker로 정의해 모든 화살표의 모양과 크기를 통일한다.
- `markerUnits="userSpaceOnUse"`로 선 굵기가 바뀌어도 화살촉 크기가 따라 변하지 않게 고정한다.
- `orient="auto-start-reverse"`로 반대 방향 화살표를 따로 정의하지 않고 처리한다.

### pattern(해칭으로 범주 구분)

단일 색 계열에서 범주를 늘리는 수단이다. 명도 단계를 다 쓴 뒤에 사용한다.

- 45도 대각선은 계획 상태, 미확정, 향후 도입을 뜻한다.
- 세로선은 외부 주체, 다른 기관 소관을 뜻한다.
- 점은 불확실, 검토 필요를 뜻한다.
- `patternUnits="userSpaceOnUse"`로 도형 크기가 바뀌어도 해칭 간격이 따라 변하지 않게 고정한다.
- 해칭의 의미는 별도 범례를 두지 않고 해당 요소나 그 계층에 직접 라벨로 적는다. 해칭은 훑어보기를, 직접 라벨은 의미 확정을 맡는다.
- 도해 1개에 해칭은 3종 이하로 쓴다. 넘으면 읽을 수 없다.

### clipPath와 mask

- clipPath는 축 절단, 부분 채움 게이지, 진척률 표현에 쓴다.
- mask는 테두리 밖으로 이어짐 표시, 절단된 축의 흐려짐 표현에 쓴다.
- 그라데이션은 mask 안에서 절단 표시 용도로만 쓰고 채움색으로 쓰지 않는다.

### symbol과 use

- 반복되는 도형은 `<symbol>`로 한 번 정의하고 `<use>`로 참조한다.
- `transform="scale()"`은 선 굵기까지 키워 선 굵기가 달라진다. `vector-effect="non-scaling-stroke"`를 지정하거나 scale을 쓰지 않는다.

### filter(허용 3종)

필터는 정보를 인코딩하거나 가독성 문제를 해결할 때만 쓴다. 아래 3종 외의 필터는 정보 근거를 밝힐 수 없으면 쓰지 않는다.

| 필터 | 표현하는 정보 |
|------|---------------|
| `feColorMatrix type="saturate" values="0"` | 범위 밖 요소, 논의 대상이 아님 |
| `feGaussianBlur stdDeviation="2-4"` | 경계 미확정, 범위가 정해지지 않음 |
| `feMorphology operator="dilate"`와 `feComposite operator="out"` | 떨어져 있는 요소들이 1개 단위임을 보이는 균일한 외곽 경계 |

- 필터 지원 범위는 렌더러마다 다르고 오피스 문서로 변환하면 무시되기도 한다. 필터를 지워도 도해가 완결되게 설계하고 정보 전달을 필터에 맡기지 않는다.
- `feDropShadow`, `feOffset`을 이용한 입체 표현, `feTurbulence`를 이용한 질감은 쓰지 않는다.
- 겹치는 영역은 필터 없이 `fill-opacity="0.5"` 중첩으로 표현한다. 겹친 부분이 자동으로 진해진다.

### 선과 형태

- 선 굵기는 헤어라인 `stroke-width="1.5"`, 기본 외곽선 `2`, 강조 외곽선 `3.5`, 그룹 경계 `6`을 쓴다.
- `rx` 기본값은 0이다. 둥근 모서리는 요소 종류를 구분하는 의미가 있을 때만 준다. 모든 요소에 같은 반경을 주지 않는다.
- 그림자, 그라데이션 채움, 3D, 입체감, 반사 하이라이트를 쓰지 않는다.
- 곡선은 순환 구조처럼 곡률이 의미를 가질 때만 쓰고 나머지는 직선으로 그린다.

## 추상 개념 작도

정량 데이터가 없는 추상 개념은 구조를 기하 관계로 옮겨 그린다. 은유 그림은 개념과 무관한 사물의 겉모습을 빌려 와 정보를 전달하지 못한다. 산 정상, 도로, 계단, 퍼즐 조각, 전구, 로켓, 톱니바퀴, 나무, 다리, 열쇠를 쓰지 않는다.

| 개념 구조 | 기하 표현 |
|-----------|-----------|
| 포함, 소속, 범위 | 중첩 경계 |
| 대립, 긴장, 상충 | 반대 방향 벡터, 대칭축 양 끝 배치 |
| 창발, 집적 | 작은 단위의 밀도 변화 뒤 경계 형성 |
| 임계, 문턱 | 축 위 절단선 1개와 양쪽 상태 차이 |
| 재귀, 자기참조 | 축소 반복 삽입 |
| 위상 변화 | 같은 요소의 배열 규칙 변경 |
| 불확정, 미정의 | 흐린 경계, 점선 |
| 순환 인과 | 닫힌 경로와 방향 표시 |
| 단절, 막힘 | 폭이 좁아지는 구간, 간극 |

- 라벨을 모두 지워도 구조가 읽히는지 확인한다. 읽히지 않으면 그 형태는 장식이므로 다른 표현을 찾는다.
- 도해 1개에 구조 1개만 담는다. 구조 2개 이상을 섞으면 콜라주가 된다.
- 복잡도는 관계 종류 수로 관리한다. 요소 30개에 관계 1종은 읽을 수 있고 요소 6개에 관계 5종은 읽기 어렵다.

## 컨설팅과 기획 장표 관례

- (계층 아키텍처) 계층 높이를 같게 하고 계층 이름은 왼쪽 여백에 둔다. 계층 사이 간격은 계층 안 간격의 2배로 한다.
- (현재 상태와 목표 상태) 두 패널의 좌표계와 척도를 같게 유지하고 차이만 형태로 드러낸다. 척도가 다르면 두 상태를 비교할 수 없다.
- (로드맵) 단계 열의 폭은 기간에 비례시키고 단계가 바뀌는 의사결정 시점은 세로 실선으로 표시한다. 산출물은 해당 열 안에 둔다.
- (기능 분해) 같은 수준의 박스는 폭을 같게 하고 하위 수준은 상위 박스 폭 안에 정렬한다.
- (매트릭스) 축 라벨에 판단 기준을 적는다. "낮음", "높음"만 따로 적지 않는다.
- (번호) 왼쪽 위에서 시작하는 읽기 순서와 번호 순서를 일치시킨다.
- 정량 수치는 산출 근거나 출처가 확인된 값만 적는다. 예시 수치를 실측값처럼 적지 않는다.

## 피할 패턴과 정보 잉크 검사

visual.md의 피할 패턴을 모두 적용하고 발견하면 지운 뒤 다시 그린다. 이어서 정보 잉크 검사로 마무리한다. 요소를 하나씩 지우며 메시지가 줄어드는지 확인하고, 줄지 않으면 그 요소는 정보 없이 잉크만 쓰고 있으므로 지운다.

## defs 예시

`PFX`를 도해 고유 접두어로 바꿔 쓰고 필요한 항목만 골라 넣는다.

```xml
<defs>
  <!-- 화살촉 통일: 선 굵기와 무관하게 크기 고정 -->
  <marker id="PFX-arrow" viewBox="0 0 12 12" refX="10" refY="6"
          markerWidth="12" markerHeight="12" markerUnits="userSpaceOnUse"
          orient="auto-start-reverse">
    <path d="M 0 1 L 11 6 L 0 11 z" fill="#1A1A1A"/>
  </marker>

  <!-- 해칭 1: 계획 상태, 미확정 -->
  <pattern id="PFX-hatch-plan" patternUnits="userSpaceOnUse"
           width="10" height="10" patternTransform="rotate(45)">
    <rect width="10" height="10" fill="#EDF1F8"/>
    <line x1="0" y1="0" x2="0" y2="10" stroke="#6B8EC2" stroke-width="2.5"/>
  </pattern>

  <!-- 해칭 2: 외부 주체 소관 -->
  <pattern id="PFX-hatch-external" patternUnits="userSpaceOnUse"
           width="9" height="9">
    <rect width="9" height="9" fill="#FFFFFF"/>
    <line x1="0" y1="0" x2="0" y2="9" stroke="#9AB2D6" stroke-width="2"/>
  </pattern>

  <!-- 해칭 3: 불확실, 검토 필요 -->
  <pattern id="PFX-dot-uncertain" patternUnits="userSpaceOnUse"
           width="10" height="10">
    <rect width="10" height="10" fill="#FFFFFF"/>
    <circle cx="5" cy="5" r="1.8" fill="#9AB2D6"/>
  </pattern>

  <!-- 필터 1: 범위 밖 요소 탈색 -->
  <filter id="PFX-out-of-scope" x="-5%" y="-5%" width="110%" height="110%">
    <feColorMatrix type="saturate" values="0"/>
  </filter>

  <!-- 필터 2: 경계 미확정 -->
  <filter id="PFX-undefined-edge" x="-10%" y="-10%" width="120%" height="120%">
    <feGaussianBlur stdDeviation="3"/>
  </filter>

  <!-- 필터 3: 떨어진 요소를 1개 단위로 묶는 균일 외곽 경계 -->
  <filter id="PFX-unify-boundary" x="-15%" y="-15%" width="130%" height="130%">
    <feMorphology operator="dilate" radius="8" in="SourceAlpha" result="grown"/>
    <feComposite in="grown" in2="SourceAlpha" operator="out" result="ring"/>
    <feFlood flood-color="#4369A3" result="ringColor"/>
    <feComposite in="ringColor" in2="ring" operator="in"/>
  </filter>
</defs>
```

라벨 주변 비우기 예시다.

```xml
<text x="800" y="450" font-family="NanumGothic, 'Malgun Gothic', sans-serif"
      font-size="24" font-weight="700" fill="#1A1A1A"
      text-anchor="middle" dy="0.35em"
      stroke="#FFFFFF" stroke-width="4" paint-order="stroke">
  의사결정 지연 구간
</text>
```

## 점검

- 메시지 1개를 정했고 도해가 그 메시지만 증명하는가
- 관계구조 1개를 판별했고 형태가 그 구조에서 나왔는가
- 정량값을 위치나 길이에 배정했는가
- 모든 텍스트의 추정 폭이 컨테이너 폭 안에 들어가는가
- 글자 크기가 20 이상이고 역할별 위계가 있는가
- 흰 글자를 #4369A3 이상 어두운 면에만 올렸는가
- 강조색을 1곳 이하로 썼는가
- 간격을 8, 16, 24, 40, 64 중에서만 골랐는가
- 모든 id에 고유 접두어를 붙였는가
- 필터를 지워도 도해가 완결되는가
- 피할 패턴에 해당하는 요소가 없는가
- 정보 잉크 검사 뒤 남은 요소가 모두 정보를 전달하는가
