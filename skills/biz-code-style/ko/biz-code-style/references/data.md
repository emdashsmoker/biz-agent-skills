# 데이터 분석

데이터의 형태와 품질을 먼저 확인하고 가설을 적은 뒤 계산한다. 모든 계산은 코드로 실행하고 다른 사람이 같은 결과를 얻을 수 있도록 코드와 실행 환경 정보를 남긴다. 예시는 pandas 기준이며 다른 도구에도 같은 원칙을 적용한다.

## 실행 환경 확인

- 작업을 시작하면 코드를 실행할 수 있는 수단을 다음 순서로 확인한다. 현재 세션의 내장 인터프리터, 연결된 외부 실행 도구(Python 실행 서버 등), 외부 코드 실행 API 순서다.
- 실행 수단이 있으면 Python과 주요 패키지(pandas 등)의 버전을 코드로 확인해 기록한다.
- 실행 수단이 없으면 코드만 작성한다. 실행하지 않은 결과를 표나 수치로 지어내지 않는다. 실행용 전체 코드를 제공하고 결과는 실행해야 확인된다고 밝힌다.
- 패키지 설치와 가상환경 규칙은 code.md를 따른다.

## 버전 호환

- 설치된 버전에서 동작하는 코드를 쓴다.
- 사용자가 웹 검색을 허용했으면 설치 버전의 릴리스 노트(pandas는 https://pandas.pydata.org/docs/whatsnew/)에서 추가된 기능, 폐기된 기능, 알려진 문제를 확인한다.
- 웹 검색을 쓰지 않을 때는 경고를 표시하는 설정(`python -W default` 등)으로 실행해 DeprecationWarning과 FutureWarning을 확인하고 대체 코드로 바꾼다.
- 사용자가 설치 버전에서 제거된 기능을 요청하면 대체 코드를 제시하고 실행 여부를 묻는다. 예를 들어 pandas 2.0에서 제거된 `DataFrame.append`는 `pd.concat`으로 바꾼다.
- 버전에 따라 동작이 달라지는 부분을 반영한다. pandas 3.0부터 Copy-on-Write가 기본 동작이 되어 연쇄 할당(`df[열][행] = 값`)은 원본을 바꾸지 않는다. 값을 바꿀 때는 `df.loc[행, 열] = 값`을 쓴다. 같은 버전부터 문자열 열의 기본 dtype이 `object`에서 `str`로 바뀌었다.
- pandas 1.0 이후 버전에 공통으로 있는 기본 API(read_csv, read_excel, read_json, head, tail, shape, columns, dtypes, info, describe, loc, iloc, drop, rename, fillna, dropna, replace, sort_values, groupby, agg, pivot_table, concat, merge, to_csv, to_excel, to_json)를 먼저 쓴다. (권장)

## 요청을 코드로 옮기기

- 요청이 불러오기, 저장, 보기, 필터, 정렬, 그룹 집계, 수정, 통계, 시각화 중 어느 작업인지 먼저 분류한다.
- 여러 작업이 이어진 요청은 단계로 나누고 메서드 체이닝으로 묶을 수 있다.
- 코드 위 주석에 원래 요청과 해석한 조건을 남긴다.
- 요청이 모호하면 확인 질문을 한다. 같은 이름으로 읽힐 열이 여러 개이거나 "높은 것"처럼 기준이 없는 경우가 해당한다. 질문에는 "상위 10개" 또는 "100 이상"처럼 고를 수 있는 기준을 함께 제시한다.

```python
# 요청: 나이 30 이상, 영업부만
# 해석: (나이 >= 30) AND (부서 == "영업")
result = df[(df["나이"] >= 30) & (df["부서"] == "영업")]
```

| 요청 | 해석 | 코드 |
|------|------|------|
| 나이 30 이상만 | 필터 | `df[df["나이"] >= 30]` |
| 부서별 급여 평균 | 그룹 집계 | `df.groupby("부서")["급여"].mean()` |
| 이름순으로 정렬 | 오름차순 정렬 | `df.sort_values("이름")` |
| 매출 높은 순으로 5개 | 내림차순 상위 N개 | `df.nlargest(5, "매출")` |
| 성별 열 삭제 | 열 삭제 | `df = df.drop(columns="성별")` |

## 불러오기와 저장

- 형식에 맞는 함수로 불러온다. csv는 `read_csv`, xlsx와 xls와 ods는 `read_excel`, tsv와 txt는 구분자를 지정한 `read_csv`, json은 `read_json`, parquet은 `read_parquet`을 쓴다.
- 이미지 속 표는 OCR 결과를, PDF와 docx 속 표는 추출 결과를 사용자에게 확인받은 뒤 쓴다.
- 엑셀 파일은 첫 시트를 불러오고 다른 시트가 있으면 시트 목록을 알린다.
- 불러온 직후 행 수, 열 수, 파일 크기, 상위 5행을 확인한다.
- 저장은 요청한 형식(csv, xlsx, json, md 등)으로 하고 파일명, 위치, 행과 열의 수를 알린다.

## 탐색과 품질 확인

- 분석 코드를 쓰기 전에 데이터의 형태(행과 열 수, 열별 타입)를 먼저 확인한다.
- 결측, 중복, 이상치 같은 품질 문제를 먼저 점검한다. 점검은 실제 데이터에 대해 실행되는 확인 코드(assert 등)로 하고 통과 여부를 기록한다.
- 계산 전에 가설을 먼저 적는다. 결과를 본 뒤 가설을 맞추지 않는다.
- 데이터 개요를 요청받으면 행과 열 수, 메모리 사용량, 열별 타입, 결측 수, 고유값 수, 최빈값, 수치형 열의 평균과 중앙값과 표준편차, 전체 결측률, 중복 행 수를 보여 준다.

## 결과 표시

- 사용자가 요청한 결과만 보여 준다. 기초 통계처럼 요청하지 않은 정보를 덧붙이지 않는다.
- 결과 표는 기본 10행까지 보여 주고 사용자가 행 수를 지정하면 그에 따른다.
- 100행을 넘는 전체 출력 요청에는 상위 100행 출력, 전체 출력, 파일 저장을 선택지로 제시한다.
- 긴 텍스트 열은 30자에서 줄여 표시한다. (권장)
- 마크다운을 렌더링하는 화면에서는 결과를 마크다운 표로 보여 주고 표를 코드 블록 안에 넣지 않는다. 마크다운을 렌더링하지 않는 터미널에서는 글자 폭을 맞춘 텍스트 표로 보여 준다.
- 응답은 현재 데이터 상태(데이터 이름, 행과 열 수), 실행 코드, 실행 결과, 처리 요약(예: 100행에서 2행으로 필터링) 순서로 짧게 구성한다.

## 데이터 변경과 보호

- 데이터를 바꾸는 작업 전에는 원본 복사본(`df.copy()`)을 남겨 되돌릴 수 있게 한다.
- 여러 열 삭제처럼 데이터가 크게 줄어드는 작업은 변경 전후 크기를 보여 주고 사용자 확인 후 실행한다.
- 주민등록번호처럼 개인을 식별할 수 있는 열이 보이면 마스킹(예: 앞 6자리만 남김)이나 열 삭제를 제안하고 확인을 받는다.
- 오류가 나면 원인, 발생 위치, 해결 방법을 알린다. 없는 열 이름이 원인이면 비슷한 열 이름과 현재 열 목록을 함께 보여 준다.

## 재현 코드

- 사용자가 요청하거나 실행 수단이 없는 경우 불러오기부터 저장까지 이어지는 실행용 전체 코드를 준다.
- 전체 코드의 머리 주석에 생성 일시와 실행 환경(Python, 주요 패키지 버전)을 적는다.
- 표본 추출, 데이터 분할, 모델 학습처럼 무작위성이 있는 처리는 난수 시드를 코드 상단의 상수로 선언하고 모든 무작위 함수에 전달한다.

## 통계 추론

- 상관관계를 인과관계로 단정하지 않는다.
- 표본 크기와 대표성을 고려하지 않고 일반화하지 않는다.
- 정보가 없다는 사실을 부정의 근거로 쓰지 않는다. 확인되지 않은 사항은 미확인으로 적는다.
- 확인된 사실과 추론을 구분하고 추론은 추론이라고 표시한다.

## 대용량 데이터

메모리에 한 번에 올리기 어려운 데이터는 적게 읽고, 효율적인 타입을 쓰고, 나눠서 처리한다.

- 필요한 열만 읽는다(csv는 `usecols`, parquet은 `columns`).
- 반복값이 많은 문자열 열은 `category` 타입으로, 수치 열은 `pd.to_numeric(..., downcast=...)`로 줄인다.
- 파일 단위나 청크 단위로 나눠 집계한 뒤 결과를 합친다.
- 규모가 더 크면 pandas와 호환되는 병렬 또는 분산 처리 라이브러리를 검토한다. (권장)
- 원자료 전체를 모델이 직접 읽지 않고 코드로 집계한 결과만 확인한다.

## 모델링과 머신러닝

평가 점수가 실제보다 좋게 나오는 누수를 막고 같은 실행이 같은 결과를 내게 한다.

- 데이터를 학습용과 평가용으로 먼저 나누고 전처리는 그 뒤에 한다.
- 결측 대체, 스케일링, 특성 선택 같은 전처리는 학습 데이터로만 학습(fit)하고 평가 데이터에는 변환(transform)만 적용한다.
- 전처리와 모델은 하나의 파이프라인으로 묶어 전처리 누락과 누수를 막는다.
- 평가 데이터로 학습하지 않는다.
- 개체 간 관계(1:1, 1:N, N:M)와 일종 관계, 부분 관계, 속성 관계의 구분은 structure.md를 따른다.

## 점검

- 모든 수치를 코드로 계산했는가
- 실행하지 않은 결과를 결과처럼 제시하지 않았는가
- 데이터 품질 확인 코드를 실행했는가
- 데이터를 바꾸기 전에 복사본을 남겼는가
- 개인 식별 정보를 확인했는가
- 난수 시드와 실행 환경 버전을 기록했는가
