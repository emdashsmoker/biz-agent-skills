# 시각화 공통

차트, 도해, 슬라이드용 그림, 포스터, HTML 시각 요소에 공통으로 적용한다. 무채색 바탕에 데이터와 강조만 색을 쓰고, 독자가 어디를 봐야 하는지 한눈에 알 수 있게 만든다. 유형별 규칙은 chart.md, svg.md, flowchart.md에 있다.

## 기획 순서

- 모든 시각화는 구현 전에 디자인 방향을 먼저 적는다. 파일을 만드는 작업이면 디자인 방향 문서(.md)로 적고, 응답 한 번으로 끝나는 작업이면 코드 앞에 3-5행으로 적는다.
- 순서는 메시지 확정, 디자인 방향 수립, 레이아웃 확정, 구현, 검증이다.
- (메시지 확정) 시각화가 전달할 메시지 1개를 판단문으로 정한다. 이 문장은 디자인 방향을 정하는 기준값이며 그림 안에 그대로 넣는 문구가 아니다.
- (디자인 방향 수립) 공간과 구조(정보 계층에 따른 공간 분할 방식), 색과 톤(메시지에 맞는 색 체계), 비례와 리듬(요소 간 크기 대비와 반복), 구성과 균형(시선 흐름과 시각적 무게 배분), 시각적 위계(정보 중요도의 시각 표현)를 정한다.
- (레이아웃 확정) 디자인 방향에 따라 공간 배치를 정한 뒤 코드로 구현한다.
- (검증) 구현 후 이 파일의 시각 검증을 수행한다.
- 사용자가 즉시 생성을 요청하지 않았다면 차트와 도해는 기획안(형태, 선택 근거, 표시 요소)을 먼저 보여 주고 확인을 받은 뒤 만든다.

## 제목과 메시지 위치

- 메시지 문장은 그림 바깥(슬라이드 헤드메시지, 문서 캡션, 응답 본문)에 둔다.
- 그림 안에는 제목, 부연 설명, 출처, 작성 도구 정보를 넣지 않는다.
- 사용자가 그림 안 제목을 요청하거나 그림을 단독으로 배포하면 제목을 넣는다. 제목은 "소재 부문이 전사 매출 성장분의 절반 이상을 창출"처럼 판단문으로 쓴다. "차트", "부문별 실적" 같은 주제 라벨은 쓰지 않는다.

## 색

| 용도 | 값 | 쓰임 |
|------|----|------|
| 배경 | #FFFFFF | 흰색 또는 투명 |
| 본문 글자 | #1A1A1A | 제목, 본문, 데이터 라벨 |
| 보조 글자와 선 | #595959 | 축 라벨, 단위, 주석, 축선, 보조선 |
| 데이터 기본 | #6B8EC2 | 파스텔 톤 네이비 블루, 단일 계열 데이터 |
| 범주 명도 단계 | #2C466D, #4369A3, #6B8EC2, #9AB2D6 | 다중 계열과 범주 구분, 어두운 순서 |
| 면 음영 | #C9D6E9, #EDF1F8 | 영역 음영, 도형 내부 배경 |
| 강조 | #C0392B | 독자가 가장 먼저 볼 요소 1곳 |

- 전체 구성은 무채색을 기본으로 하고 유채색은 데이터 표현과 강조에만 쓴다.
- 장식 목적의 색을 추가하지 않는다. 위 표에 없는 색(Tailwind 기본 indigo, purple 계열 포함)은 쓰지 않으며 다른 색 계열이 꼭 필요하면 사용자에게 묻는다.
- 색은 범주에 1:1로 대응시킨다.
- 범주는 명도 단계 4개를 어두운 순서로 써서 구분한다. 범주가 4개를 넘으면 해칭 무늬를 더한다(해칭 규칙은 svg.md).
- 강조색은 시각화 1개에 1곳만 쓴다. 여러 곳에 쓰면 강조 기능이 사라진다. 강조 대상은 원래 범주 색 대신 강조색으로 칠한다.
- 흰 배경 위 데이터 도형은 흰색과의 대비가 3:1 이상인 색으로 칠한다. #2C466D(9.5:1), #4369A3(5.5:1), #6B8EC2(3.4:1), #C0392B(5.4:1)가 해당한다.
- #9AB2D6처럼 흰색과의 대비가 3:1 미만인 색으로 칠한 데이터 도형에는 #4369A3 외곽선(1.5px)을 둘러 경계를 보이게 한다.
- 도형 안 글자색은 #1A1A1A와 #FFFFFF 중 채움색과 대비가 큰 쪽을 고른다. 그 결과 #2C466D, #4369A3, #C0392B 위에는 흰 글자를, #6B8EC2, #9AB2D6, #C9D6E9, #EDF1F8 위에는 #1A1A1A 글자를 쓴다.
- 대비비는 WCAG 2.x 상대 휘도 공식으로 코드를 실행해 계산한다.

## 글꼴

- 기본 글꼴은 NanumGothic Bold다. 한글과 라틴 문자를 모두 담고 있으며 Google Fonts와 운영체제 패키지(예: fonts-nanum)로 받을 수 있다.
- 작업 전에 운영체제에 글꼴이 설치되어 있는지 확인하고 없으면 먼저 설치한다.
- 차트 글자는 최소 12pt 이상 Bold로 쓰고 기본 크기는 16pt로 한다. SVG 글자 크기는 svg.md를 따른다.
- 글자는 가능한 한 크게 쓴다.
- Inter, Roboto, Arial, Open Sans처럼 AI 산출물에서 흔한 기본 글꼴을 쓰지 않는다.
- 시스템 대체 글꼴만으로 이루어진 글꼴 지정을 쓰지 않는다.
- 모든 요소에 같은 글자 크기를 쓰지 않는다. 크기와 굵기로 위계를 만든다.

## 형태

- 아이콘, 이모지, 클립아트, 일러스트를 쓰지 않는다.
- 사각형, 원, 직선 같은 단순한 기하 도형과 셰브론으로 구조를 표현한다.
- 단계와 흐름은 셰브론으로 표현한다. 셰브론은 도형 자체가 방향을 보여 주므로 화살표를 따로 붙이지 않는다.
- 관계는 직선이나 직교 연결선으로 표현한다.
- 비중과 규모는 면적으로 표현할 수 있다. 이때 수치 라벨을 함께 붙이고, 순위 비교가 필요한 값은 위치나 길이로 표현한다.
- 화살표는 정보 흐름 전달에 꼭 필요한 곳에만 쓴다.
- 그림자, 그라데이션, 3D, 입체감, 반투명 유리 효과가 없는 평면 구성으로 만든다.
- 모서리 둥글림은 쓰지 않거나 최소 반경으로 제한한다.

## 글자 배치

- 그림 안에는 독자가 확인해야 할 정보만 넣는다. 작성 과정, 사용 도구, 기술 스택처럼 독자가 궁금해하지 않는 정보는 넣지 않는다.
- 두 줄 이상인 글은 불릿으로 나눈다.
- 도형, 셰브론, 표 칸 안의 글자는 세로 가운데로 정렬한다.
- 정보 위계는 글자 크기, 굵기, 위치로 표현하고 색 장식으로 표현하지 않는다.
- 나열 항목의 분류 기준은 하나로 통일한다.
- 문구는 text.md와 wording.md를 따른다. "Build the future", "Your all-in-one platform", "미래를 설계", "End-to-End 혁신"처럼 어떤 제품이나 사업에도 넣을 수 있는 포부형 문구와 범용 설명은 쓰지 않는다.

## 레이아웃

- 캔버스 상하좌우 여백을 확보하고 네 방향 여백을 같게 유지한다. 슬라이드는 가장자리 여백을 0.5인치 이상 둔다.
- 요소를 그리드에 맞춰 정렬하고 같은 계층 요소 사이의 간격을 일정하게 유지한다.
- 요소 사이에 충분한 여백을 둔다.
- 빈 공간을 채우려고 요소를 추가하지 않는다.
- 메시지 전달에 필요한 최소 요소만 둔다. 요소를 하나 지워도 메시지가 남으면 그 요소를 지운다.
- 화면 공간은 겹치지 않게 나누고 나눈 영역이 합쳐서 화면 전체를 덮게 한다.
- 시각 요소의 위계는 정보 중요도 순서와 일치시킨다.
- 여러 시각화를 만들면 각각 고유한 정보 구조와 레이아웃을 갖게 한다. 미니멀 기조의 단조로움을 구조의 다양성으로 상쇄한다. 색과 형태 규칙은 전체에서 같게 유지한다.
- 사용자가 같은 템플릿의 반복을 요청하면 고유 구조 규칙을 적용하지 않는다.

## 피할 패턴

AI 도구가 통계적으로 수렴해 반복 산출하는 형태다. 부분적으로도 쓰지 않으며 초안에서 발견하면 다시 설계한다.

- (띠 장식) 카드나 박스 좌우 가장자리의 세로 색 띠, 캔버스나 박스 위아래 가장자리의 가로 색 띠, 전체 폭 장식 색 막대, 제목 아래 짧은 장식 밑줄, 제목 뒤 곡선 리본
- (코드 블록 흉내) 일반 텍스트를 담는 박스를 웹 문서의 코드 예제처럼 꾸민 구성. 왼쪽 세로 띠나 괄호 모양 곡선 옆에 글을 이어 쓰는 형태, 배경을 채운 사각형을 코드 블록처럼 쓰는 형태, 제목 표시줄과 복사 버튼과 창 조절 점으로 편집기 창을 흉내 낸 형태, 행 번호나 명령 프롬프트 기호를 붙인 형태, 어두운 둥근 사각형과 고정폭 글자와 왼쪽 위 세 색 원의 조합이 모두 해당한다.
- (반복 격자) 크기와 여백과 모서리 반경이 같은 카드의 기계적 격자 반복, 2x2나 3x3 벤토 카드 기본 배치, 아이콘과 제목과 설명을 3열로 반복하는 배치, 모든 요소를 가운데 정렬한 단조로운 대칭 배치
- (효과) 보라색에서 파란색으로 이어지는 그라데이션, 글자 그라데이션, 목적 없는 그라데이션, 반투명 유리 효과, 모든 상자에 넣은 그림자, 아이소메트릭 큐브와 3D 원형 차트 같은 입체 표현, 반사 하이라이트, 목적 없이 반복되는 등장 애니메이션
- (장식 배경) 점 격자, 하프톤, 등고선 무늬, 워터마크
- (내용 대체) 이모지나 일반 아이콘이 내용을 대신하는 구성, 가운데 큰 원 주변에 "AI", "Data", "Cloud" 같은 일반 명사를 작은 원으로 두른 구성, 사물 은유 그림(svg.md), 도형을 지워도 정보가 그대로 남는 텍스트 슬라이드
- (차트 기본값) matplotlib 기본 색 그대로 쓰기, 네 면 축선 유지, 전체 격자 유지, 범례만으로 데이터를 구분하게 하는 구성, 왜곡을 일으키는 3D 차트, 무늬나 질감 채움
- (연결선) 근거 없는 곡선 화살표, 방향 없는 점선 연결

## 시각 검증

- 모든 시각화는 만든 뒤 시각 검증을 한다.
- 순서는 렌더링(코드를 실행해 PNG, PDF, 스크린숏 같은 이미지로 변환), 렌더링 확인(이미지를 직접 보고 결함 탐지), 수정(결함이 있으면 코드를 고쳐 다시 렌더링), 완료(결함이 없으면 산출)다.
- 파일로 작업하는 환경에서는 PDF나 PNG로 변환해 확인하고, 화면에 바로 렌더링되는 환경에서는 렌더링된 결과를 직접 확인한다.
- 이미지로 확인할 수단이 없으면 svg.md의 산술 점검을 수행한다.

검수 항목은 다음과 같다.

- 텍스트 잘림이나 넘침
- 줄바꿈 때문에 단어나 문장이 잘림
- 요소 겹침
- 데이터 라벨 가독성(글자 크기와 색 대비)
- 여백 부족(슬라이드 가장자리 0.5인치 미만)
- 색 대비 부족(밝은 배경의 밝은 글자, 대비 3:1 미만 도형의 외곽선 누락 등)
- 같은 계층 요소의 수평 정렬과 수직 정렬 불일치
- 원본 데이터와 그림 속 수치의 불일치
- 디자인 통일성 위반
- 불필요한 구성 요소
- 요소 간 간격(지나치게 멀거나 가깝거나 일정하지 않음)
- 피할 패턴 해당 여부

## 점검

- 피할 패턴에 해당하는 요소가 없는가
- 시각화 1개가 메시지 1개만 전달하는가
- 데이터 라벨을 기준에 맞게 직접 표시했는가
- 글자가 12pt 이상 Bold인가
- 불필요한 시각 요소를 지웠는가
- 렌더링 결과를 확인했는가
- 여러 시각화가 서로 고유한 구조를 갖는가
- 강조색을 1곳에만 썼는가
