# 전문용어 최소화

이 스킬은 비전공 성인 독자가 뜻을 따로 찾아보지 않고 글을 끝까지 읽도록 어휘를 고친다. 쉬운 말로 바꿀 때도 정보의 정밀함과 어조의 격식은 유지한다.

## 실패 유형

어휘 수준을 조정할 때 실패는 과잉 전문성과 과잉 평이화로 나뉜다. 과잉 평이화는 모호한 추상화와 유치한 문체로 나타난다. 한쪽 실패를 피하려다 반대쪽 실패로 넘어가기 쉬우므로 세 유형을 항상 함께 점검한다.

- (과잉 전문성) 독자가 모르는 용어를 설명 없이 쓰는 실패
- (모호한 추상화) 쉽게 쓰려고 정밀한 용어를 두루뭉술한 말로 바꾸어 문장이 가리키는 대상이 사라지는 실패 (예: "통화스왑 체결"을 "돈 관련 약속 체결"로 바꾸기)
- (유치한 문체) 쉽게 쓰려고 어휘와 함께 어조까지 낮추는 실패 (예: 구어체 종결, 감탄, 독자에게 말 걸기, 본질을 왜곡하는 비유)

과잉 전문성은 전문용어 판별과 처리 순서로 다룬다. 모호한 추상화는 정밀성 보존에서 다루고 유치한 문체는 어조 보존에서 다룬다.

## 기준 독자

전문용어인지 판단할 때는 아래 독자를 기준으로 삼는다.

- 평균적인 비전공 성인
- 초중고 교과 내용을 배웠지만 세부 내용은 대부분 기억하지 못하는 사람 (교과 과정을 완벽하게 기억하는 독자는 상정하지 않는다)
- 특정 분야의 학부 전공 지식, 업계 관행, 조직 내부 약어를 모르는 사람

기준 독자는 어휘를 판별할 때만 쓴다. 독자가 비전문가라는 이유로 어조를 낮추지 않는다. 사용자가 독자를 따로 지정하면(예: "반도체 엔지니어 대상") 그 독자가 이미 아는 범위로 판별 기준을 옮긴다.

## 전문용어 판별

전문용어인지는 기준 독자가 그 단어를 정의 없이 이해하는지로 판별한다. 전문용어로 판별된 단어를 글에 남길지는 처리 순서에서 정한다.

- 기준 독자가 정의 없이 이해하는 단어는 일반어로 보고 그대로 쓴다
- 일상 대화와 생활 경험에서 익히는 단어는 일반어로 본다
- 특정 분야를 배우거나 그 분야에서 일해야 알게 되는 단어는 전문용어로 본다
- (위장 일반어) 일상어와 형태가 같지만 분야 안에서 다른 뜻으로 쓰는 단어는 전문용어로 본다 (예: 통계의 "유의하다", 법률의 "선의", 금융의 "노출")
- (약어) 영문 약어와 줄임말은 독자가 안다고 판단되어도 처음 1회 전체 명칭을 함께 적는다
- (익숙한 단어) 작성자는 자기 분야 단어일수록 전문용어인지 알아차리기 어려우므로 익숙한 단어를 먼저 의심한다

## 처리 순서

전문용어로 판별된 단어는 아래 표의 위에서부터 조건을 확인하고 처음 해당하는 처리를 적용한다. 정의를 붙일지 고민하기 전에 그 용어가 글에 필요한지부터 판단한다.

| 순서 | 조건 | 처리 |
|------|------|------|
| 1 | 글의 목적과 결론 전달에 기여하지 않는다 | 등장 제거 |
| 2 | 뜻을 잃지 않고 일반어로 바꿀 수 있다 | 평이어 대체 |
| 3 | 일반어로 바꾸면 뜻이 달라지거나 다른 대상과 구별되지 않는다 | 본문에 보존하고 설명 블록 추가 |

### 평이어 대체

뜻을 잃지 않고 일반어로 바꿀 수 있는 용어는 일반어로 바꾼다. 바꾼 문장이 정밀성 보존의 기준을 통과하지 못하면 설명 블록으로 처리한다.

| 바꾸기 전 | 바꾼 후 |
|-----------|---------|
| 마이그레이션 | 이전 |
| 온보딩 | 신규 인력의 업무 적응 |
| 거버넌스 체계 정립 | 의사결정 책임과 절차 마련 |
| 페인포인트 | 불편 사항 |
| 시너지 창출 | 결합 효과 확보 |

### 설명 블록

일반어로 바꾸면 뜻이 달라지거나 흐려지는 용어는 본문에 그대로 쓰고 설명 블록을 붙인다. 법령 용어, 기술 표준명, 제도명, 학술 개념처럼 정밀함이 뜻의 일부인 용어가 주로 여기에 해당한다. 형식은 인용 블록에 괄호 소제목을 붙인 한 줄이다.

```
> (용어) 한 문장 설명
```

- (위치) 용어가 처음 나온 항목 바로 뒤에 둔다. 항목은 불릿 하나 또는 문단 하나를 가리킨다.
- (재등장) 같은 용어가 다시 나오면 설명 없이 쓴다
- (여러 용어) 한 위치에 여러 용어의 블록이 필요하면 블록 사이를 빈 줄로 나눈다
- (용어집 미사용) 설명을 글 끝의 용어집이나 각주로 모으지 않는다. 독자가 용어와 설명 사이를 오가며 읽게 되기 때문이다.
- (괄호 정의 미사용) 본문 문장 안에 긴 괄호 정의를 끼워 쓰지 않는다. 문장이 길어져 읽기 어려워진다.

설명 문장은 아래 기준으로 쓴다.

- 설명은 한 문장의 단문으로 쓰고 주어, 대상, 방법 같은 요소가 문장 안에 각각 한 번만 나오게 한다
- 설명 안에 다른 전문용어를 쓰지 않는다
- 정의 대상 용어에서 전문적인 뜻을 담은 부분을 설명에 다시 쓰지 않는다
- 대상이 속한 일반 범주를 나타내는 단어(예: 암호, 예산, 채권, 금리)는 설명에 써도 된다
- (위반 예시) `> (전환사채) 주식으로 전환할 수 있는 사채`
- (올바른 예시) `> (전환사채) 회사가 돈을 빌리려고 발행하는 채권 가운데 정해진 조건에 따라 그 회사 주식으로 바꿀 수 있는 채권`

영문 약어는 본문에 처음 나올 때 전체 명칭을 괄호로 함께 적는다. 전체 명칭도 전문용어이면 설명 블록을 추가한다. 예를 들어 본문에 "PIM(Processing-In-Memory)"이라고 쓰고 바로 뒤에 `> (PIM) 데이터를 저장하는 장치 안에서 연산까지 처리하는 반도체 구조`를 둔다. 괄호 안에 전체 명칭을 적는 일은 표기에 해당하므로 정의 횟수에 세지 않는다.

### 정의 횟수

같은 용어의 정의는 본문과 설명 블록 가운데 한 곳에서 한 번만 한다. 같은 정보를 두 번 쓰면 읽는 흐름이 끊기고 글이 용어집처럼 된다.

- 설명 블록을 둔 용어는 본문 문장에서 다시 정의하거나 풀어 쓰지 않는다. 본문은 용어를 쓰기만 하고 정의는 블록이 맡는다.
- (위반 예시) 본문에 "금융회사끼리 하루 단위로 빌리는 자금에 적용되는 콜금리가 상승"이라고 쓰고 바로 뒤에 콜금리 설명 블록을 다시 둔다
- (올바른 예시) 본문에는 "콜금리가 상승"이라고만 쓰고 정의는 설명 블록에만 둔다
- 글의 목적이 그 개념을 설명하는 데 있으면 본문의 개념 설명이 곧 정의이다. 이때는 설명 블록을 붙이지 않는다.

## 정밀성 보존

모호한 추상화를 막는 규칙이다. 평이어로 바꾼 문장은 아래 기준을 모두 통과해야 한다. 하나라도 통과하지 못하면 원래 용어를 본문에 남기고 설명 블록을 붙인다.

- (구별 테스트) 바꾼 문장만 읽은 독자가 원래 용어가 가리키던 대상을 다른 대상과 구별할 수 있어야 한다
- (내장 정보) 용어 안에 수치, 조건, 범위가 들어 있으면 풀어 쓸 때 빠뜨리지 않는다
- (경계 정보) 이웃 개념과 구별하는 일이 용어의 존재 이유라면 그 구별 정보를 남긴다

"콜금리"를 "은행 금리"로 바꾸면 하루 단위 초단기 자금이라는 조건이 빠져 어떤 금리인지 구별할 수 없다. 이 경우 본문에 "콜금리"를 남기고 `> (콜금리) 금융회사끼리 하루 단위로 빌리고 빌려주는 초단기 자금에 적용되는 금리`를 붙인다.

"추경"을 "추가 예산"으로만 풀면 국회를 통과한 예산을 다시 국회 의결을 거쳐 고치는 절차라는 정보가 사라진다. 이 경우 본문에 정식 명칭 "추가경정예산"을 쓰고 설명 블록을 붙인다.

## 어조 보존

유치한 문체를 막는 규칙이다. 어휘와 설명은 쉽게 쓰고 어조는 성인 독자를 대하는 공식 문서 수준으로 유지한다.

- 격식 없는 표현, 구어체, 감탄, 이모지, 독자 호명("여러분")을 쓰지 않는다
- 난이도를 해설하는 표현("쉽게 말해", "간단히 말하면", "어렵게 들리겠지만")을 쓰지 않는다. 내용을 쉽게 쓰면 난이도를 해설할 필요가 없다.
- 비유는 개념의 구조를 정확히 옮길 때만 쓴다
- 비유가 개념의 일부 속성만 전하면서 전체를 대표하는 인상을 주면 쓰지 않는다
- 비유를 쓸 때도 실제 작동 방식을 함께 적는다
- 문장을 짧게 끊어 쉬워 보이게 만들지 않는다. 쉬움은 어휘와 논리에서 확보한다.

## 용어 밀도

- 한 문단에서 설명 블록 분량이 본문 분량을 넘으면 문단을 다시 설계한다. 이때 각 용어가 글의 목적에 필요한지부터 다시 판단하고 필요 없는 용어는 제거한다.
- 같은 개념을 가리키는 용어는 글 전체에서 하나로 통일한다 (예: 한 글에서 "마이그레이션", "이전", "전환"을 섞어 쓰지 않는다)

## 적용 방식

### 작성 모드

새 글을 쓸 때 전문용어 판별과 처리 순서를 적용한 결과만 내놓는다.

### 교정 모드

- 기존 글에서 전문용어를 찾아 처리 순서에 따라 고친다
- 원문의 사실 관계, 수치, 출처, 구조는 유지하고 어휘만 고친다
- 모호한 추상화를 고칠 때 원래 용어는 원문이나 원자료에서 찾아 복원한다. 찾을 수 없으면 새로 지어내지 않고 사용자에게 확인한다.
- 교정한 글 앞에 교정 대상 용어와 처리 방식을 짧게 요약한다

### 개입하지 않는 영역

이 스킬은 어휘만 다룬다. 아래 영역은 원문이나 다른 지침을 따른다. 어조의 격식은 어조 보존 규칙을 따른다.

- 문장 길이, 종결 형태(명사형 또는 동사형), 문체
- 글 전체 구조, 마크다운 계층, 분량
- 어휘 밖의 표현 습관

### 결과물 표기

- 결과물 본문에 용어를 바꾼 사실, 독자 수준에 대한 판단, 이 스킬의 존재를 적지 않는다
- "전문용어를 최소화하여 작성하면" 같은 자기 적용 선언을 쓰지 않는다
- 교정 모드의 요약은 교정한 글 바깥에 둔다

## 예외

- 인용 원문, 법령 조문 원문, 코드는 고치지 않고 앞뒤 설명 글에만 이 스킬을 적용한다
- 고유명사(기관명, 제품명, 정책명, 표준명)는 다른 말로 바꾸지 않는다. 독자 이해에 필요하면 설명 블록을 붙인다.
- 사용자가 유지하라고 지정한 용어는 처리 대상에서 제외한다

## 예시

### 과잉 전문성 교정

바꾸기 전

```
- 온프레미스 레거시 시스템의 클라우드 마이그레이션 시 리프트앤시프트 방식은 TCO 관점에서 차선책
- 리플랫포밍 또는 리아키텍팅을 통한 클라우드 네이티브 전환이 운영 효율 측면에서 우위
```

바꾼 후

```
- 사내 서버에서 운영해 온 기존 시스템을 설계 변경 없이 클라우드로 그대로 옮기는 방식은 도입과 운영에 드는 총비용 측면에서 불리
- 시스템 구조의 일부 또는 전체를 클라우드 환경에 맞게 고쳐서 옮기는 방식이 운영 효율 측면에서 유리
```

"온프레미스", "레거시", "마이그레이션", "리프트앤시프트", "TCO", "리플랫포밍", "리아키텍팅", "클라우드 네이티브"를 모두 일반어로 바꾸었다. "리플랫포밍"과 "리아키텍팅"의 차이는 "구조의 일부 또는 전체"로 남겼다. 평이어 대체만으로 뜻을 잃지 않는 사례이다.

### 설명 블록이 필요한 교정

바꾸기 전

```
- 중앙은행의 빅스텝 단행으로 콜금리 상승 및 RP 매각 확대
```

바꾼 후

```
- 중앙은행이 기준금리를 한 번에 0.5%포인트 인상
- 콜금리가 인상 폭을 반영하여 상승

> (콜금리) 금융회사끼리 하루 단위로 빌리고 빌려주는 초단기 자금에 적용되는 금리

- 중앙은행이 환매조건부채권 매각을 늘려 시중 자금 흡수

> (환매조건부채권) 일정 기간 뒤 되사는 조건을 붙여 파는 채권
```

"빅스텝"은 수치로 풀 수 있어 평이어로 바꾸었다. "콜금리"와 "RP"는 풀어 쓰면 다른 금리나 채권과 구별되지 않으므로 본문에 남기고 설명 블록을 붙였다. "RP"는 약어이므로 본문에 정식 명칭인 "환매조건부채권"을 적었다. 각 설명 블록은 용어가 처음 나온 항목 바로 뒤에 두었다.

### 모호한 추상화 교정

바꾸기 전

```
- 정부가 돈과 관련된 조치를 통해 시장에 영향을 주는 정책을 시행
- 이 조치로 경제 상황이 나아질 것으로 기대
```

바꾼 후

```
- 정부가 추가경정예산을 편성하여 소상공인 손실 보상 재원 확보

> (추가경정예산) 정부가 국회를 통과한 한 해 예산을 고치기 위해 다시 편성하여 국회 의결을 받는 예산

- 보상금 지급으로 소상공인의 단기 자금난 완화 기대
```

"돈과 관련된 조치"로는 어떤 정책인지 구별할 수 없다. 원자료에 있던 정책명과 지원 대상을 복원하고 정책명에는 설명 블록을 붙였다.

### 유치한 문체 교정

바꾸기 전

```
블록체인은 쉽게 말해 모두가 같이 쓰는 일기장이에요! 누가 한 번 쓰면 절대 지울 수 없답니다. 어렵게 들리겠지만 사실 우리 동네 반상회 회의록이랑 비슷해요.
```

바꾼 후

```
블록체인은 여러 참여자가 거래 기록을 같은 사본으로 나누어 보관하는 장부 기술이다. 한 참여자가 기록을 위조하면 다른 참여자의 사본과 맞춰 보는 과정에서 위조 사실이 드러난다. 이 구조 덕분에 중앙 관리자가 없어도 거래 당사자끼리 기록을 직접 검증할 수 있다.
```

구어체 종결, 감탄, 난이도 해설("쉽게 말해", "어렵게 들리겠지만"), 본질을 왜곡하는 비유를 없앴다. 일기장 비유는 한 사람이 쓰는 기록을 떠올리게 하므로 여러 참여자가 사본을 나누어 보관하는 구조를 전하지 못한다. 원문이 문단 형태이므로 교정 후에도 문단 형태를 유지했다. 글의 목적이 블록체인 설명이므로 본문이 정의를 맡고 설명 블록은 붙이지 않았다.

## 산출 전 점검

결과를 내기 전에 아래 항목을 확인하고 어긋난 부분은 고친 뒤 내놓는다.

- 기준 독자가 정의 없이 이해하지 못하는 단어를 설명 없이 쓰지 않았는가
- 글의 목적과 결론 전달에 기여하지 않는 전문용어가 남아 있지 않은가
- 위장 일반어를 설명 없이 쓰지 않았는가
- 영문 약어에 처음 1회 전체 명칭을 함께 적었는가
- 평이어로 바꾼 문장이 정밀성 보존 기준을 통과하는가
- 설명 블록이 용어가 처음 나온 항목 바로 뒤에 있는가
- 같은 용어의 정의가 본문과 설명 블록 가운데 한 곳에서 한 번만 이루어지는가
- 설명 블록에 다른 전문용어나 정의 대상 용어의 전문적인 부분이 들어 있지 않은가
- 본문 문장 안에 긴 괄호 정의가 없는가
- 같은 개념을 가리키는 용어가 글 전체에서 하나로 통일되어 있는가
- 격식 없는 표현, 구어체, 감탄, 난이도 해설 표현이 없는가
- 비유를 쓴 곳에 실제 작동 방식도 함께 적었는가
