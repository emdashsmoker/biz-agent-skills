# 초거대AI 활용 보안 점검 결과

AI를 쓰는 업무 6건 가운데 **1건은 보안 규정 위반이 확실합니다.** 설계팀이 설계 변경 보고서 초안을 외부 API 모델 C로 쓰고 있습니다. **1건은 지금 자료로는 판정할 수 없습니다.** 품질팀이 불량 원인 분석 보고서 초안에 쓰는 모델 B를 두고, 현황 자료는 사내 설치라고 하고 IT팀 자료는 외부 API라고 합니다. 관리 공백은 2건입니다. 모델 B의 설치 정보가 자료마다 다르고, 회의록 정리 업무를 맡은 부서가 없습니다. 나머지 3건은 규정에 맞습니다.

그림은 `ai_usage_map.png`(보기용)와 `ai_usage_map.svg`(확대·편집용)로 드립니다. 왼쪽부터 부서, 업무, 다루는 문서, 모델 순으로 이어지고 문서와 모델을 잇는 선의 색이 판정 결과입니다. 회색은 적합, 빨간색은 위반, 주황 점선은 확인 필요입니다.

## 업무별 점검표

판정 기준: 사내 문서를 다루는 업무는 사내 서버에 설치한 모델만 쓸 수 있습니다. 외부 공개 자료를 다루는 업무는 어느 모델을 써도 됩니다. 번호는 그림의 번호와 같습니다.

| # | 업무 | 부서 | 다루는 문서 | 모델 (설치 형태) | 판정 |
|---|---|---|---|---|---|
| 1 | 회의록 정리 | **미정** | 회의록 (사내) | A (사내 서버) | 규정상 적합, **관리 공백** |
| 2 | 과거 품질 문서 검색 | 품질팀 | 과거 품질 문서 (사내) | A (사내 서버) | 적합 |
| 3 | 불량 원인 분석 보고서 초안 작성 | 품질팀 | 불량 원인 분석 보고서 (사내) | B (자료마다 다름) | **확인 필요** |
| 4 | 공개 규격 문서 요약 | 설계팀 | 공개 규격 문서 (공개) | D (외부 API) | 적합 |
| 5 | 설계 변경 보고서 초안 작성 | 설계팀 | 설계 변경 보고서 (사내) | C (외부 API) | **위반** |
| 6 | 업계 동향 브리핑 | 기획팀 | 업계 동향 자료 (공개) | C (외부 API) | 적합 |

## 위반: 설계 변경 보고서 초안 작성 (설계팀, 모델 C)

설계 변경 보고서는 사내 문서인데 모델 C는 외부 업체 API입니다. 지금까지 쓴 초안만큼 사내 설계 정보가 외부 업체로 넘어갔다고 봐야 합니다.

1. 모델 C로 설계 변경 보고서 초안을 쓰는 일을 바로 멈춥니다.
2. 대신 모델 A를 씁니다. 두 자료가 모두 사내 설치로 보는 모델은 지금 A뿐입니다. B는 확인이 끝날 때까지 대안에서 뺍니다.
3. 지금까지 모델 C에 넣은 설계 변경 보고서의 기간, 건수, 내용을 파악합니다.
4. 외부 업체 계약에서 입력 데이터를 얼마나 보관하는지, 모델 학습에 쓰는지 확인하고 필요하면 삭제를 요청합니다. 사내에 보안 사고 보고 절차가 있으면 그 절차에 따라 보고합니다.

## 판정 보류: 불량 원인 분석 보고서 초안 작성 (품질팀, 모델 B)

불량 원인 분석 보고서는 사내 문서이므로 판정은 모델 B가 실제로 어디서 돌아가는지에 달려 있습니다.

| 실제 상황 | 판정 |
|---|---|
| 현황 자료가 맞음: B는 사내 서버에만 설치 | 적합 |
| IT팀 자료가 맞음: B는 외부 API로만 사용 | 위반 (설계팀 건과 같은 조치 필요) |
| 둘 다 맞음: 사내 설치본과 외부 API를 함께 사용 | 품질팀이 어느 쪽에 접속하는지에 따라 갈림 |

IT팀이 아래 세 가지를 보면 판정할 수 있습니다.
- 서버 자산 목록에 모델 B 설치 기록이 있는지
- 품질팀이 모델 B를 부를 때 접속하는 주소가 사내 주소인지 외부 업체 주소인지
- 모델 B 공급 업체와 맺은 API 계약이나 사용료 청구 내역이 있는지

확인이 끝날 때까지는 이 업무도 모델 A로 임시 전환하기를 권합니다. 위반으로 확인되면 설계팀 건의 3, 4번 조치를 똑같이 적용합니다.

## 관리 공백

**1. 모델 B 설치 정보가 자료마다 다름.** 위의 판정을 못 내리는 것보다 더 큰 문제가 있습니다. 어떤 모델이 회사 밖으로 데이터를 보내는지를 회사가 한 가지 기준으로 관리하지 못하고 있다는 점입니다. 모델별 설치 형태는 기준 자료를 하나로 정하고(IT팀 자산 목록 권장), 현황 자료를 포함한 다른 자료는 그 기준에 맞춰 고쳐야 합니다.

**2. 회의록 정리 업무에 담당 부서가 없음.** 지금은 사내 설치 모델 A를 쓰고 있어 규정 위반은 아닙니다. 하지만 누가 쓸 수 있는지, 어떤 회의록까지 넣어도 되는지, 결과물을 어디에 보관하는지 정할 주체가 없습니다. 나중에 누군가 이 업무를 외부 모델로 옮겨도 막을 사람이 없다는 뜻이기도 합니다. 회의록 원본을 관리하는 부서에 맡기는 게 가장 자연스럽습니다.

## 함께 볼 점

- **같은 모델 C가 기획팀 업무에서는 적합, 설계팀 업무에서는 위반입니다.** 규정의 기준이 모델이 아니라 업무가 다루는 문서이기 때문입니다. 그래서 "쓸 수 있는 모델 목록"만으로는 이번 같은 위반을 막지 못합니다. 업무마다 다루는 문서와 쓰는 모델을 등록하고 확인하는 대장이 필요하며, 위 점검표를 그 대장의 첫 판으로 쓰면 됩니다.
- **설계팀 사례로 보아 새 업무에 AI를 붙일 때 사전 확인 절차가 없거나 제대로 작동하지 않는 것으로 보입니다**(자료로 확인한 사실이 아니라 추정입니다).
- **사내 문서 업무가 모델 A로 몰릴 수 있습니다.** 사내 문서를 다루는 업무는 1, 2, 3, 5번 4건입니다. 모델 B가 외부 API로 확인되면 4건 모두 모델 A가 맡게 됩니다. A는 지금 검색과 회의록 정리에만 쓰이고 있으므로, 보고서 초안 품질과 처리 용량을 미리 확인해야 합니다.

## 조치 순서

| 순서 | 조치 | 담당 (제안) | 시점 |
|---|---|---|---|
| 1 | 설계 변경 보고서 초안에 모델 C 사용 중단, 모델 A로 전환 | 설계팀 | 즉시 |
| 2 | 불량 원인 분석 보고서 초안을 모델 A로 임시 전환 | 품질팀 | 즉시 |
| 3 | 모델 B 설치 형태 확인, 설치 정보 기준 자료 확정 | IT팀 | 1주 안 |
| 4 | 모델 C(B가 외부로 확인되면 B 포함)에 넘어간 사내 문서 범위 파악, 업체의 데이터 보관·학습 조건 확인 | 설계팀, 품질팀, IT팀 | 1주 안 |
| 5 | 모델 A의 처리 용량과 보고서 초안 품질 점검 | IT팀 | 2주 안 |
| 6 | 회의록 정리 담당 부서 지정 | AI 활용 총괄 책임자 | 2주 안 |
| 7 | 업무별 AI 사용 대장 운영, 새 업무는 등록·확인 뒤 사용 | 보안 담당, IT팀 | 1개월 안 |

## 전제와 확인하지 못한 것

- '적합' 판정은 각 업무가 표에 적힌 문서만 다룬다는 전제에서 나왔습니다. 예를 들어 업계 동향 브리핑에 사내 실적 자료를 함께 넣으면 그 순간 위반이 됩니다.
- 자료 차이는 모델 B만 언급되어 있어서, 모델 A는 IT팀 자료에도 사내 설치로 적혀 있다고 보고 판단했습니다. A도 다르게 적혀 있다면 1, 2번 판정과 대체 모델 권고를 다시 봐야 합니다.
- 외부 업체와의 계약 조건(입력 데이터 보관, 학습 활용)은 자료에 없어 판단하지 못했습니다.
