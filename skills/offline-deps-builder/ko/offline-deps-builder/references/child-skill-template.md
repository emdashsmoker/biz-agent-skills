# 의존성 스킬 양식

## 이름

의존성 스킬 이름은 `<부모 스킬 이름>-deps`로 짓는다. 여러 부모 스킬이 공유하는 런타임은 `<런타임 이름>-runtime`으로 짓는다. 이름은 소문자, 숫자, 하이픈만 쓰고 폴더 이름과 같게 맞춘다.

## 폴더 구성

```
<부모 스킬 이름>-deps/
├── SKILL.md
├── MANIFEST.md
├── scripts/          # 활성화 스크립트 (선택)
└── payload/
    ├── python/       # 휠, 또는 풀어서 다시 묶은 패키지 아카이브
    ├── node/         # node_modules 아카이브
    ├── bin/          # 실행 파일 (xz 압축)
    ├── runtime/      # 언어 런타임 아카이브
    ├── fonts/
    ├── data/         # 모델, 캐시, 템플릿
    └── licenses/     # 전문 동봉이 필요한 라이선스 파일
```

필요한 폴더만 만든다. 파일 수를 줄여야 하면 하위 폴더를 아카이브 하나로 묶는다.

활성화 스크립트는 Python 표준 라이브러리만 쓴다. zipfile, tarfile, lzma, shutil로 페이로드를 풀 수 있다. 환경 변수 설정은 스크립트 안에서 끝나지 않으므로 export 문을 출력하거나 env.sh 파일로 남긴다.

## SKILL.md 양식

꺾쇠 괄호 부분을 채우고, 해당하지 않는 줄은 지운다.

```markdown
---
name: <부모 스킬 이름>-deps
description: "<부모 스킬 이름> 스킬을 외부 통신이 막힌 환경에서 쓰기 위한 의존성 묶음. <부모 스킬 이름> 스킬을 사용할 때 함께 로드하고, 부모 스킬의 설치 단계 대신 이 스킬의 활성화 절차를 먼저 수행한다. 담은 항목과 출처는 MANIFEST.md에 있다."
---

# <부모 스킬 이름> 의존성

<부모 스킬 이름> 스킬에 필요한 <항목 요약>을 담는다. 대상 실행 환경은 <운영체제, 아키텍처, glibc, 언어 버전>이다.

## 활성화

1. 이미 쓸 수 있는지 확인한다: <확인 명령과 통과 조건>. 모두 통과하면 활성화를 건너뛴다
2. 작업 경로를 만든다: <예: /tmp/<부모 스킬 이름>-deps>
3. 페이로드를 푼다: <항목별 풀기 방법>
4. 실행 권한과 경로를 설정한다: <PATH, PYTHONPATH, NODE_PATH, 폰트, 캐시, 오프라인 모드 변수>
5. 작동을 확인한다: <명령과 기대 결과>
6. 부모 스킬에 알릴 값을 출력하고 <작업 경로>/env.sh에 export 문으로 저장한다: <경로나 옵션>

활성화 스크립트가 있으면 `python3 <이 스킬 폴더>/scripts/activate.py`로 위 절차를 한 번에 수행한다.

부모 스킬의 명령을 실행할 때는 `. <작업 경로>/env.sh &&`를 명령 앞에 붙인다. 명령마다 새 셸이 열리는 실행 환경에서는 한 번 설정한 환경 변수가 다음 명령에 남지 않는다.

## 부모 스킬과 함께 쓰기

- 부모 스킬의 설치 단계는 건너뛰고 활성화 결과를 쓴다
- <부모 스킬 옵션이나 환경 변수 연결 방법>

## 문제 대응

- 활성화가 실패하면 실패한 단계와 출력 메시지를 사용자에게 보여 준다
- 실행 환경이 MANIFEST.md의 대상 조건과 다르면 그 차이를 사용자에게 알리고, 맞는 조건으로 다시 조립하도록 안내한다
```

## MANIFEST.md 양식

```markdown
# <부모 스킬 이름> 의존성 목록

## 항목

| 항목 | 버전 | 형식 | 출처 주소 | 라이선스 | 대상 조건 | 받은 날짜 | 크기 | 쓰는 기능 |
|---|---|---|---|---|---|---|---|---|
| <이름> | <버전> | <휠, 실행 파일, 폰트 등> | <공식 주소> | <라이선스> | <cp312, manylinux_2_17_x86_64 등> | <YYYY-MM-DD> | <MB> | <부모 스킬 기능> |

## 제외한 구성 요소

- <구성 요소>: <제외 이유와 남긴 빈 폴더>

## 실행 환경 가정

- <확인하지 못하고 가정한 조건>

## 사전 설치에 기대는 항목

- <실행 환경에 이미 있다고 보고 제외한 항목>

## 검증 기록

- <날짜>, <환경>, <수행한 확인>, <결과>
- 미검증: <항목과 이유>
```
