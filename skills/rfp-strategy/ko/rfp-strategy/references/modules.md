# 수행 구조 설계

02_제안전략서.md의 7절(수행 구조)을 설계하는 규칙이다. 과업 유형은 01_RFP분석.md에서 판정하고 착수 질의에서 사용자가 확인한 유형을 쓴다. 과업 유형에 해당하는 절과 공통 표준 절을 읽는다.

## 적용 원칙

- RFP 과업 내용이 모듈 골격보다 우선한다. 골격은 설계의 출발점이다.
- 골격과 다른 구성을 허용한다. 순서 역전(전략 수립 뒤에 환경 분석)만 피한다.
- 여러 유형이 섞인 과업은 모듈 단위로 유형을 섞어 구성한다.
- RFP가 요구하지 않는 단계는 생략할 수 있다.
- 분석 절차는 사업 규모에 비례해 편성한다. 수억원 규모 과업에 대규모 재정사업급 분석 절차를 제시하면 실행 불가로 읽힌다.
- 방법론 이름은 RFP가 요구한 기법(SWOT, AHP(계층분석법), 델파이, 논리모형 등)만 표기한다. 그 외 기법은 이름 없이 수행 내용으로 서술한다.
- 전략과 과제는 상위 번호를 잇는다(1. 전략, 1-1. 전략과제, 1-1-1. 이행과제).
- 모든 요구항목은 1개 이상의 Task에 배치한다.
- 심사위원이 실무 이해를 가늠하는 증거는 조사 대상 기관명, 자료명, 조사 규모, 사전조사 결과다. 방법론 이름은 이 증거를 대신하지 못하므로 Task마다 대상과 규모를 실명과 수치로 적는다.
- 과제와 수요의 확보 경로는 수요조사, 인식조사, 전문가 참여, 직접 도출 중에서 RFP 요구에 맞춰 고른다. 고른 경로마다 Task를 편성한다. 직접 도출만 쓰면 자문이나 수요 확인 절차를 함께 편성한다.

골격의 지위는 트랙에 따라 다르다.

| 트랙 | 해당 유형 | 골격의 지위 |
|---|---|---|
| 제도 기반 | 성과분석평가형, 경영평가 대응형, 사업기획형 중 R&D 사업기획 | 제도가 골격과 워딩을 정하므로 유형별 골격을 기본값으로 적용 |
| 조건부 제도 | 정보화계획형, 사업기획형 중 비R&D 사업기획 | 제도 심사나 의무 대상이면 해당 지침의 구조를 적용. 그 외는 골격을 참고해 RFP 범위와 사업 규모에 맞게 구성 |
| 재량 | 전략기획형, 문제해결형, 지원사업 운영형 | 골격은 참고 예시. 모듈과 Task는 RFP 과업 내용과 핵심 이슈에서 도출. 예시 골격을 그대로 복제하면 경쟁사 제안과 구별되지 않음 |

## 사고 계통

유형 골격의 차이는 산출물 규격의 차이다. 생각의 순서는 두 계통으로 나뉜다. 계통은 모듈 순서를 정하는 근거이며 제안서 원고에는 드러내지 않는다.

| 계통 | 생각의 순서 | 해당 유형 |
|---|---|---|
| 목표 설정 | 목표 상태 정의 → 상위정책 정렬 → 목표 체계 수립 → 하향 전개 | 전략기획형, 정보화계획형, 사업기획형의 목표 체계 부분 |
| 갭 분석 | 현행 상태 규명 → 목표 대비 격차 도출 → 원인 구조화 → 대안 설계 | 문제해결형, 성과분석평가형, 경영평가 대응형, 지원사업 운영형, 사업기획형의 현황 진단 부분 |

사업기획형은 한 과업 안에서 두 계통이 겹친다. 예비타당성조사처럼 제도 심사를 받는 사업은 목표 체계와 상위정책 정렬의 비중을 크게 둔다.

## 전략기획형

M1 대내외 환경 분석 → M2 내부현황 및 사례 분석 → M3 비전 및 전략 도출 → M4 실행계획

| 모듈 | 내용 | 산출물 |
|---|---|---|
| M1 대내외 환경 분석 | 정책, 경제, 사회, 기술, 법제도 동향 중 주제에 맞는 항목만 선별. 해외 다음 국내 순 | 환경 변화 요인 목록 |
| M2 내부현황 및 사례 분석 | 대상 조직의 역량 진단, 국내외 선진사례 분석 | 진단 결과, 사례 시사점 |
| M3 비전 및 전략 도출 | 시사점 종합, 비전 체계, 분야별 전략과 전략과제 | 비전 체계도, 전략과제 목록 |
| M4 실행계획 | 이행과제 발굴, 우선순위, 로드맵, 재원과 추진체계, 성과지표, 기대효과 | 이행과제 카드, 로드맵, 지표표 |

- (흔한 실수) 환경 분석에 목표 모습을 섞는 구성, 시사점 없이 전략으로 넘어가는 구성
- (환경 분석) 사실 위주로 쓴다. 해석, 전망, 목표 모습, 해결 방안은 이 단계에 두지 않는다.
- (내부현황) 강점과 약점을 함께 진단한다. 환경 분석이 찾은 요건과 내부 현황의 격차를 드러낸다. 기관 소개성 현황(연혁, 조직, 예산)과 역량 진단을 나눠 쓴다.
- (시사점) 분석 결과를 전략으로 잇는 단계다. 시사점마다 근거 사실의 출처(외부, 내부, 사례)를 밝힌다.
- (SWOT 요인 출처) 내부현황 시사점은 강점과 약점에만 쓴다. 외부환경 시사점은 기회와 위협에만 쓴다. 사례 시사점은 네 구분 모두에 쓸 수 있다.
- (SWOT 교차 전략) SO 전략은 S와 O만 결합한다. ST, WO, WT도 해당 두 구분만 결합한다.
- (갭 분석) 현재 모습, 목표 모습, 격차, 해결 전략의 4열 표로 쓴다. 목표 모습의 근거는 사례 분석과 상위계획이다.
- (전략 체계 정렬) 비전, 미션, 전략, 전략과제, 이행과제, 성과지표를 번호를 이어 하나의 체계로 연결한다.
- (연결 점검) 상위 없는 하위와 하위 없는 상위를 만들지 않는다. 모든 시사점이 1개 이상의 과제로 이어지게 배치한다.
- (비전 도출) 상위계획과 국가정책의 방향(하향식)과 전략들의 공통 지향점(상향식)을 함께 반영한다. 하향식, 상향식, 최종의 3열 표로 제시한다.
- (우선순위) 평가 기준과 배점을 표로 제시하고 평가자와 절차를 적는다. 결과는 단기, 중기, 장기 로드맵으로 마감한다.
- (기대효과) RFP가 파급효과를 요구하면 M4에 편성한다. 산식은 사업기획형 절의 산업연관분석 표를 쓴다.
- (지역 산업 육성) M2에 산업 특화도(입지계수), 기업 수요조사, 앵커 기관과 수요처 접근성, 인력 공급 여건을 배치한다.
- (신사업 발굴) 업의 재정의 → 후보 목록 → 1차 선별(시장 매력성, 발주처 적합성, 재무 타당성) → 2차 선별 지표 → 신규사업 평가 → 세부 사업추진계획 순서로 후보를 좁힌다. 활성화 방안은 개발 전과 개발 후 시나리오로 나눈다.

우선순위 평가 기준 예시다. 배점은 과업에 맞게 조정한다.

| 기준 | 판단 내용 | 배점 | 근거 자료 |
|---|---|---|---|
| 정책 부합성 | 국정과제와 상위계획과의 연계 정도 | 30 | 국정과제, 상위계획 |
| 시급성 | 추진하지 않을 때 손실이 생기는 시점 | 20 | 환경 분석 결과 |
| 실현가능성 | 예산, 인력, 제도 여건 | 30 | 내부현황 진단 |
| 파급효과 | 수혜 범위와 연계 산업 | 20 | 사례 분석 |

평가자는 자문위원회나 분과위원회가 맡는 형태가 통상이다. 점수는 온라인 설문으로 모으고 가중치는 AHP로 도출한다.

### 경영전략 복합 과업

공공기관 중장기 경영전략은 경영전략, 조직진단, 경영효율화를 함께 다루는 형태가 많다.

- (경영전략) 환경 분석, 미션과 비전과 핵심가치 재설정, 발전전략, 전략과제와 실행과제의 부서 단위 전개, 우선순위와 추진 시기, 연도별 성과지표
- (조직진단과 재설계) 직무분석, 업무량 조사의 양적과 질적 분석, 적정 정원 산정과 배분, 조직구조 개편안, 위임전결 개선
- (경영효율화) 사업 포트폴리오, 경영평가 지표 개선, ESG, 정부의 공공기관 혁신 방향 반영. 경영평가 지표 개선의 워딩은 경영평가 대응형 절을 따른다
- (조직과 인사 과업) 직무분석 → 통솔범위 분석 → 유사기관 비교 → 재설계안 → 단계별 이행안
- (기관 내부 평가지표 개발) 대내외 평가제도 분석에서 제도 개선안까지 수행한다. 이해관계자 면담으로 지표 후보군을 도출하고 전문가 조사와 AHP 가중치로 타당성과 측정 가능성을 확인한다. 지표 정의서(정의, 산식, 가중치, 측정 방법)를 쓴 뒤 시범 적용과 제도 개선안을 제시한다. 산출 지표와 성과 지표를 나눠 배치한다.

경영평가 대응, 지표 개발, 조직진단에는 성과분석평가형 골격을 쓰지 않는다.

## 정보화계획형

M1 환경 분석 → M2 현황 분석 → M3 목표모델 설계 → M4 이행계획

| 모듈 | 내용 | 산출물 |
|---|---|---|
| M1 환경 분석 | 정책과 기술 동향, 상위계획 정렬, 유사기관 정보화 사례 | 환경 요인과 시사점 |
| M2 현황 분석 | 업무 현황, 정보시스템 현황(응용, 데이터, 인프라, 보안), 이용자 요구 | 현황 진단과 개선 요구 목록 |
| M3 목표모델 설계 | 업무 모델, 정보 모델, 응용 모델, 기술 모델, 보안 모델 | 목표 아키텍처 |
| M4 이행계획 | 이행과제 정의, 우선순위, 단계별 일정, 소요 예산, 기대효과 | 이행 로드맵, 과제 카드, 예산 산정표 |

- (흔한 실수) 의무 대상 여부 미판별, 의무 대상 밖 IT 기획에 ISP(정보화전략계획) 절차와 산출물 명칭 강제, 산정 근거 없는 예산 총액, 임의 분류 코드
- (의무 대상 판별) 중앙관서는 예산안 편성 지침에 따라 정보시스템 구축과 재구축 예산을 요구하기 전에 ISP나 ISMP(정보시스템 마스터플랜)를 수립한다. 수립 절차는 한국지능정보사회진흥원의 ISP·ISMP 수립 공통가이드를 따른다. RFP의 근거 지침, 사업 규모, 산출물 목록(정보화전략계획서, 제안요청서 초안)으로 의무 대상 여부를 판별한다. 불명확하면 착수 질의에서 확인한다.
- (의무 대상에서 제도가 정하는 부분) 4단계 골격(환경 분석, 현황 분석, 목표모델, 이행계획), 요구사항 분류 체계, 예산 산정 기준(소프트웨어사업 대가산정 가이드), 공공 정보화 보안 설계(국가 망 보안체계)
- (의무 대상에서도 재량인 부분) 모듈 명칭과 분할, Task 구성, 조사 설계, 목표모델의 상세 수준, 이행과제 우선순위 기준
- (의무 대상 밖 IT 기획) 시스템과 플랫폼 구축 기획, 데이터와 AI 도입 방안, 디지털 전환 계획, 차세대와 고도화 방안은 발주처가 요구한 범위로 모듈을 구성한다. 위 골격과 표준 산출물명은 참고 예시다. 간소한 IT 기획은 현황과 요구 분석 → 목표 시스템 설계 → 구축과 운영 계획으로 줄여 쓸 수 있다.
- (공공 계획) 지능정보사회계획 같은 공공 계획은 M3를 정책 과제 체계로 바꾸고 M4에 추진체계와 성과지표를 추가한다.
- (현황 분석) 이용자 요구는 설문과 인터뷰 규모를 수치로 적는다. 시스템 현황은 시스템명, 도입 연도, 운영 주체를 실명 표로 제시한다. 현재 모습과 목표 모습의 대비표로 격차를 명시한다.
- (요구사항) 기능과 비기능으로 나눈다. 분류 코드는 RFP가 지정한 코드만 쓴다. RFP에 코드가 없으면 분류명만 쓴다.
- (보안 설계) 공공 정보화의 보안 설계는 국가 망 보안체계(N2SF)의 절차(준비, C/S/O 등급 분류, 위협 식별, 보안대책 수립, 적절성 평가)와 등급별 대책의 워딩을 그대로 쓴다. C는 기밀, S는 민감, O는 공개 등급이다.
- (예산) 소요 예산은 산정 근거(인력 단가, 장비 견적 기준)와 함께 표로 제시한다. 대가산정 가이드는 적용 연도를 적는다.
- (이행계획) 이행과제 정의 → 로드맵 → 규모 산정과 예산 → 구축 사업계획(분리발주 검토, 제안요청서) 순서로 구성한다.
- (PoC, 개념 검증) 목표 설정 → 데이터 준비 → 모델 선택과 환경 → 시범 서비스와 성능 분석을 한 회차로 묶어 반복하는 구조로 구성한다. 성능 조건(동시 접속, 처리량)은 수치로 적는다.
- (표준 산출물명) 환경분석서, 현황분석서, 정보화 비전 및 전략 정의서, 업무 프로세스 설계서, 목표모델 설계서, 데이터관리체계 설계서, 운영체계 설계서, 이행계획서, 차년도 사업계획서, 제안요청서. RFP가 정한 명칭이 우선한다.
- (사업 이해도) 정보화 제안의 사업 이해도는 정책 환경, 발주처 데이터 현황, 발주처 제약(보안, 데이터, 의사결정 구조), 현재 모습과 목표 모습의 대비로 구성하는 형태가 관행이다.

## 사업기획형

M1 정책 및 환경 분석 → M2 유사사업 및 지적사항 분석 → M3 목표체계 및 논리모형 설계 → M4 타당성 확보 → M5 심사 및 보고 대응

| 모듈 | 내용 |
|---|---|
| M1 정책 및 환경 분석 | 상위계획 부합성, 정책과 기술 동향, 문제와 이슈 도출 |
| M2 유사사업 및 지적사항 분석 | 유사 사업 검토, 중복성과 차별성, 선행 기획의 심사 지적사항 항목별 해소 |
| M3 목표체계 및 논리모형 설계 | 목적, 전략목표, 성과목표, 지표, 세부활동, 정렬 점검 |
| M4 타당성 확보 | 추진체계, 재원 조달, 법제도 위험, 비용 추정과 경제성 분석 |
| M5 심사 및 보고 대응 | 기획보고서 작성, 대면회의와 질의 대응. RFP가 요구할 때만 편성 |

- (흔한 실수) 산출과 성과의 혼동, 폐지되거나 바뀐 제도의 현행 서술
- (사업 성격별 무게) 선도기술 확보 사업은 파급 논리, 산업 적용 사업은 시장 수요와 비용편익, 기반과 인력 조성 사업은 활용도와 비용효과에 분석의 무게를 둔다.
- (제도 확인) 국가연구개발사업 예비타당성조사는 2026년 법 개정으로 폐지되고 연구형과 구축형으로 나뉜 사전 점검 제도로 바뀌었다. 재정사업 예비타당성조사는 유지된다. 두 제도를 섞어 쓰지 않는다. 착수 시 현행 명칭, 대상 기준, 절차를 확인한다.
- (민간 서비스 기획) 시장과 사용자 조사 → 경쟁과 사례 분석 → 서비스 모델과 기능 정의 → 사업성과 실행계획 순서로 바꿔 쓴다.

### 논리모형

- 칸의 순서는 문제와 이슈 → 사업목표 → 투입 → 활동(세부활동) → 산출 → 성과 → 파급효과다.
- 인접한 두 칸의 연결을 각각 검증한다. 앞 칸이 없으면 뒤 칸이 성립하지 않는다.
- 활동 칸에는 세부활동(내역사업, 과제군)을 둔다. 산출 칸에는 활동의 직접 결과물을 둔다. 성과 칸에는 수혜자에게서 생기는 변화를 둔다.
- 산출과 성과를 섞으면 논리모형 전체의 신뢰가 떨어진다. 논문 건수는 산출이다. 국산화율 변화는 성과다.
- 수혜자를 특정하지 않은 성과 칸은 성립하지 않는다.

### 목표 체계 정렬

| 목표 체계 | 논리모형 대응 칸 | 정렬 점검 |
|---|---|---|
| 사업목적 | 파급효과 | 사업이 바꾸려는 상태와 일치하는가 |
| 전략목표 | 성과 | 수혜자 변화 수준에서 서술되었는가 |
| 성과목표 | 산출, 단기 성과 | 사업기간 안에 달성할 수 있는가 |
| 성과지표 | 측정 수단 | 성과목표와 1대1로 연결되는가. 산식이 객관적인가 |
| 세부활동 | 활동 | 어느 성과목표에 기여하는지 특정되는가 |

- 정렬 점검표를 실제로 채워 제시하면 설계가 끝났다는 증거가 된다.
- 지표는 대표성과 측정 가능성을 함께 갖춘다. 측정 산식과 근거 자료의 출처를 함께 적는다.

### 진단 도구 조합

| 변형 | 구성 | 적용 상황 |
|---|---|---|
| 완전형 | 이슈 진단 → 갭 분석 또는 SWOT → 목표 설정 → 논리모형 | 대규모 신규사업, 심사 대응, 목표 도출 근거를 요구받는 경우 |
| 논리모형 중심형 | 문제 정의와 목표 설정을 논리모형 안에서 처리 | 발주처가 논리모형 양식을 제시, 사업 범위가 명확 |
| 진단 도구형 | 논리모형 없이 갭 분석 또는 SWOT으로 목표와 과제 연결 | 소규모 사업, 기존 사업의 개편 기획 |

갭 분석과 SWOT을 중복 배치하지 않는다. 변형을 고른 근거를 1줄로 적는다.

### 비R&D 사업기획

| 트랙 | 분석 순서 |
|---|---|
| 건설과 시설 | 쟁점 파악 → 경제성(수요, 편익, 비용) → 정책성 → 지역균형 → 종합판단 |
| 복지와 소득이전 | 쟁점 파악 → 경제사회 환경 → 사업설계 적정성 → 비용효과성 → 종합판단 |
| 정보화 | 쟁점 파악 → 기술사회 환경 → 사업설계 적정성 → 비용효과성 → 종합판단 |

- 중소 규모 기획의 판정에 가장 크게 작용하는 항목은 사업설계 적정성이다. 세부 항목은 사업목표의 적절성과 시급성, 수혜대상의 적정성, 추진방법의 적정성, 전달체계의 적절성, 구현과 운영계획의 적정성이다.
- (시설 건립 기본계획과 타당성 조사) 현황 진단 → 건립 타당성 논리 → 기본방향과 추진전략 → 세부계획 → 총사업비와 재원조달, 연간 수익 예측 → 경제적 타당성과 파급효과 순서로 전개한다. 현황 진단은 관련 법령과 상위계획, 국내 시설 현황 통계, 국내외 사례, 지역 여건으로 구성한다. 세부계획은 시설 규모, 전시나 운영 프로그램, 건축 기본구상, 관리운영계획으로 구성한다. 중앙부처 공모 선정이 발주처의 목표이면 공모 심사 기준 대응과 사업계획서 작성 지원을 기대효과에 둔다. 제도 용어는 비R&D 제도 용어를 쓴다.

### 경제성 분석 규율

- 사업을 시행할 때와 시행하지 않을 때를 비교한다. 시행 전후 비교는 쓰지 않는다.
- 편익은 사업 목적과 직접 연관된 항목만 산입한다. 매몰비용은 제외하고 기회비용은 반영한다. 부가가치세는 제외한다.
- 초기 투자비와 함께 운영비, 재투자비, 잔존가치를 반영한다. 할인율과 분석 기간은 적용 값과 근거를 함께 적는다.
- 편익 계량화가 어려우면 비용효과 분석으로 대체하고 대체 근거를 밝힌다. 주요 변수의 민감도 분석을 수행한다.
- 계산은 코드로 하고 산식은 2열 표로 제시한다.

| 구분 | 산식 |
|---|---|
| 현재가치 | 미래가치 ÷ (1 + 할인율)^경과연수 |
| 순현재가치 | 편익 현재가치 합계 - 비용 현재가치 합계 |
| 편익비용비 | 편익 현재가치 합계 ÷ 비용 현재가치 합계 |
| 내부수익률 | 순현재가치를 0으로 만드는 할인율 |
| 비용효과비 | 효과 한 단위당 비용 |

산업연관분석 산식은 아래와 같다.

| 구분 | 산식 |
|---|---|
| 생산유발액 | Σ(상품군별 지출액 × 생산유발계수) |
| 부가가치유발액 | Σ(상품군별 지출액 × 부가가치유발계수) |
| 고용유발인원 | Σ(상품군별 지출액 × 고용유발계수), 단위 명/10억원 |

- 유발계수는 한국은행 산업연관표 값을 쓴다. 발표 연도와 상품군 분류 기준을 함께 적는다. 총사업비의 상품군별 배분 근거를 표로 제시한다.
- 유발효과를 경제성 분석의 편익으로 다시 계산하지 않는다. 두 값을 더하면 같은 효과를 두 번 세게 된다.

## 성과분석평가형

대상사업 현황 분석 → 분석 기준 수립 → 성과 조사 및 검증 → 투입, 산출, 효과 분석 → 대표성과 및 개선방안 → 보고서 및 점검 대응

- (흔한 실수) 비교군 없는 투입 대비 산출 제시, 해당 연도 지침의 발표 시점 무시
- 국가연구개발사업 성과평가 체계를 전제로 쓰였다. 비R&D 사업의 성과평가는 해당 제도의 평가 지침을 확인한 뒤 트랙 표와 성과유형을 바꿔 쓴다.
- 기관 경영평가 대응은 경영평가 대응형 절을 적용한다.

| R&D 제도 트랙 | 시점 | 핵심 산출물 |
|---|---|---|
| 전략계획서 수립 | 신규사업 착수 또는 계획 기간 종료 | 전략목표, 성과목표, 성과지표, 평가계획 |
| 중간평가 자체평가 | 사업 수행 중(주기는 해당 연도 지침 확인) | 자체평가보고서, 종합성과분석보고서, 대표성과 소개서 |
| 성과 관리와 활용 계획 | 사업 종료 뒤 | 성과 관리와 활용 계획서, 최종 목표 달성률 |
| 효과성 분석 | 사업 종료 뒤(시점은 해당 지침 확인) | 효과성 분석 보고서, 파급효과 추정 |

- 트랙마다 지침이 매년 공고된다. 지침 발표 전 기간은 전년도 지침 기준으로 준비하고 발표 뒤 대응을 갱신하는 순서를 제안서에 적는다.
- 대상사업이 여럿이면 사업별 개요(목적, 근거 법령, 기간, 규모, 성과목표와 지표 총괄표)를 먼저 제시한다.
- 트랙이 여럿이면 트랙 단위로 모듈을 나눈다.

| 단계 | 내용 |
|---|---|
| 1 대상사업 현황 분석 | 전략계획서, 연차보고서, 목적과 전략목표와 성과목표와 지표의 연계성 검토 |
| 2 분석 기준 수립 | 성과유형, 분석항목, 분석지표, 측정방안의 4열 표와 배점 |
| 3 성과 조사 및 검증 | 전문기관 자료, 연구책임자 설문, 수혜자 조사, 원자료 대조 |
| 4 투입 및 과정 분석 | 추진 목적과 정부 지원의 적절성, 추진체계, 예산 규모와 사업 구성 |
| 5 산출의 효율성 분석 | 투입 대비 산출을 비교군(전체 평균, 유사사업)과 함께 제시 |
| 6 성과의 효과성 분석 | 질적 우수성, 목표 달성도, 영향 요인, 파급효과 |
| 7 대표성과 도출 | 선정 기준 설정, 성과정보 수집, 소개서 작성(3-5개 이내) |
| 8 종합분석 및 개선방안 | 미흡 구간별 개선방안과 조치계획, 환류계획 |
| 9 보고서 및 점검 대응 | 보고서 작성, 자체점검위원회와 상위 점검 대응 |

- R&D 성과유형은 과학적, 기술적, 경제적, 사회적, 인프라 성과로 나눈다. 국가연구개발 표준성과지표를 참조하고 사업 고유 성과를 추가한다.
- 연구책임자 설문은 대상, 기간, 배포 방법, 독려 절차, 검증 방법을 적는다. 전문관리기관에 요청할 보유 자료 목록을 미리 열거한다. 비R&D 사업은 설문 대상을 사업 담당자와 수혜자로 바꾼다.
- 달성하지 못한 지표는 원인을 나눈다(투입 대비 산출 부족, 근거 자료 미비, 지표 설정 자체의 문제).
- 목표 달성률은 지표별 가중치와 달성률의 곱을 합산하는 산식으로 적는다.
- 성과 활용과 확산은 성공 요인과 실패 요인을 함께 분석한다. 실패 요인이 빠지면 점검 기준을 충족하지 못한다.
- (비R&D 지원사업 성과조사분석) 투입, 산출, 성과의 유형별 지표로 분석 기준을 구성한다. 성과 영향 요인은 회귀분석 같은 통계 기법으로 분석한다. 지역경제 파급효과는 산업연관분석으로 산출한다. 참여기업 만족도와 개선사항은 설문으로 조사한다. 용어는 성과분석, 성과지표, 발전방안 같은 일반 명칭을 쓴다.

## 경영평가 대응형

편람 지표 구조 분석 → 전년도 평가 결과 및 지적사항 분석 → 지표별 실적 논리 재구성 → 비계량 지표 서술 전략 수립 → 다른 기관 우수사례 대조 → 경영실적보고서 작성 지원

- (흔한 실수) 성과분석평가형 골격의 혼용, 편람 개정 시점 무시
- 공공기관 경영평가 편람과 지방공기업 경영평가가 골격과 워딩을 정하는 제도 기반 트랙이다.
- 핵심 산출물은 경영실적보고서 개선안, 지표별 대응 논리, 비계량 서술이다.
- 지표 명칭과 배점은 해당 연도 편람의 표기를 그대로 쓴다. 편람 개정 시점을 반영하는 계획을 적는다.
- 발주처의 목표는 평가 등급 상승인 경우가 많으므로 배경 서술은 압축한다.

## 문제해결형

문제 정의 → 이슈 분해 → 이슈 우선순위 → 작업계획 수립 → 핵심 분석(가설 검증) → 결과 종합 → 결론 전달과 실행 방안

이 순서는 통상 아래 3-4개 모듈로 압축한다.

M1 현황 진단 → M2 갭 분석 → M3 개선안 도출

| 모듈 | 내용 |
|---|---|
| M1 현황 진단 | 문제 정의와 원인 가설, 이슈 분해, 현행 상태 규명(문헌, 통계, 조사 중 과업에 맞는 수단) |
| M2 갭 분석 | 비교 기준 대비 격차 도출, 이해관계자 의견(FGI(표적집단면접), 설문), 원인 구조화 |
| M3 개선안 도출 | 대안 설정과 비교, 우선순위, 개선안과 시행 방안 |

- (흔한 실수) RFP 요약과 같은 수준의 문제 정의, 조사 규모 미특정
- (문제 정의) 발주 배경에서 발주처가 해결하려는 문제와 원인 가설을 도출한다. 제안사 고유의 문제 구조화를 1개 이상 포함한다.
- (이슈 분해) 하나의 기준으로 나누고 겹침과 빠짐을 점검한다. 모든 이슈의 처리 모듈을 대응표로 관리한다.
- (가설 검증) 조사와 분석은 가설 검증 관점으로 설계한다. 가설은 반증할 수 있는 형태로 쓴다. 어떤 결과로도 반증되지 않는 가설은 제외한다.
- (조사 중심 과업) 실태조사, 동향조사, 수요조사는 RFP 과업 항목을 모듈 구조로 그대로 쓴다. Task는 조사 설계(대상, 표본, 방법, 문항 구조) → 데이터 검증 → 종합 분석 순서로 구체화한다. 모집단, 표본 수, 조사 기간, 응답 독려 방법을 수치로 적는다.
- (제도 개선) 현행 제도 분석 → 문제점 유형화 → 해외 제도 비교 → 대안 설계 → 대안 비교표 → 추진 로드맵 순서로 구성한다.
- (개선 대상) 제도, 절차와 업무 프로세스, 조직과 인력 운영, 서비스와 프로그램, 시스템, 지침과 양식 중 RFP가 지정한 대상을 다룬다.
- (비교 기준) 갭 분석의 비교 기준은 개선 대상에 따라 고른다. 제도는 법령과 다른 기관 규정, 프로세스는 표준 절차와 선진 사례, 서비스는 이용자 경험과 경쟁 서비스를 기준으로 삼는다.
- (개선안) 변경 사항, 시행 주체, 단계별 적용 시점의 3열 표로 제시한다. 제도가 대상이면 개정 조문을 함께 적는다.

| 대안 | 개선 효과 | 소요 비용 | 법령 개정 | 수용성 | 종합 |
|---|---|---|---|---|---|
| 1안 현행 유지 보완 | 낮음 | 낮음 | 불필요 | 높음 | 단기 |
| 2안 제도 신설 | 높음 | 중간 | 시행령 개정 | 중간 | 중기 |

## 지원사업 운영형

M1 정책 및 사업 배경 → M2 수요자 현황 및 애로 → M3 프로그램 설계 → M4 성과관리 → M5 운영 및 집행

| 모듈 | 내용 | 산출물 |
|---|---|---|
| M1 정책 및 사업 배경 | 상위 정책과 근거 사업, 지역과 분야 여건, 사업 목적 | 사업 목적 정의 |
| M2 수요자 현황 및 애로 | 대상 기업과 대상자 현황 통계, 실태조사와 설문, 애로와 요청 사항 | 수요 집계표 |
| M3 프로그램 설계 | 진단과 선발, 교육, 컨설팅, 네트워킹, 판로와 투자 연계 | 프로그램 설계서 |
| M4 성과관리 | 성과목표 체계, 성과지표와 목표값, 증빙과 점검 방식 | 성과지표표 |
| M5 운영 및 집행 | 추진체계와 인력, 연간 일정, 사업비 편성과 집행계획 | 집행계획표 |

- (흔한 실수) 산출과 성과의 혼동, 프로그램 단계의 규모 미특정
- 수요자 애로에는 조사 대상 수, 응답률, 상위 응답 비율의 통계 근거를 함께 적는다.
- 프로그램은 단계별로 배치한다. 단계마다 대상, 방식, 횟수, 산출물을 적는다.
- 성과목표는 핵심 성과목표와 자율 성과목표로 나눈다. 성과지표 표의 열은 구분, 성과지표, 중간목표, 최종목표(누적), 증빙내역이다.
- 지표는 산출(건수, 개사)과 성과(매출, 투자유치, 고용)를 나눠 배치한다.
- 사업비는 항목별 편성표와 분기별 집행계획으로 제시한다.

## 공통 표준

### 모듈과 Task의 목적

목적은 그 단위의 산출물과 활동이 과업의 최종 결과물에 무엇을 공급하는지다. 협의체 운영, 의견수렴, 자문, 실증 지원 같은 활동도 단위의 결과에 해당한다.

| 단위 | 목적이 답하는 질문 |
|---|---|
| 과업 목표 | 과업이 끝나면 무엇이 확보되는가 |
| 모듈 목적 | 이 모듈의 산출물과 활동은 최종 결과물의 어느 부분이 되는가, 또는 어느 부분의 근거가 되는가 |
| Task 목적 | 이 Task의 산출물과 활동은 모듈 산출물의 어느 부분이 되는가, 또는 어느 판단의 근거가 되는가 |

- 목적 문장은 대상, 수행 행위, 산출물과 활동의 결과, 쓰임의 순서로 쓴다. 요소마다 1개씩 쓴다.
- (대상) 분석하거나 종합할 자료와 범위. 활동 성격의 단위는 참여 주체
- (수행 행위) 분석, 진단, 비교, 종합, 운영, 수렴 중 1개
- (결과) 산출물이 담는 내용(시사점, 요인, 기준, 논리, 후보 목록)이나 활동이 확보하는 결과(의견, 합의, 검토 결과)
- (쓰임) 결과가 쓰이는 과업 안의 후속 단계. 단계 이름이나 산출물 이름으로 쓴다
- 목적의 종결은 단위의 성격을 따른다. 분석 성격은 "OO의 근거 확보", "OO 도출"로 끝낸다. 수립 성격은 "OO 수립", "OO 설계", "OO 확정"으로 끝낸다. 활동 성격은 그 활동이 확보하는 결과("OO 의견 수렴", "OO 합의 확보")으로 끝낸다.
- 단위 1개에 목적 1개를 둔다. 목적이 둘로 갈리는 Task는 나눈다.
- 발주처가 얻는 성과는 배경, 추진전략, 기대효과에서 다룬다. 모듈과 Task마다 되풀이하지 않는다. 산출물이 발주처의 대외 설득이나 심의 대응에 직접 쓰이는 모듈은 그 쓰임까지 적는다.

목적 문장 예시다.

- (분석 성격 모듈) 국내외 정책, 산업, 기술 동향을 분석하여 전략 도출의 근거가 되는 기회 요인과 위협 요인을 도출
- (수립 성격 모듈) 환경 분석의 시사점과 수요조사 결과를 종합하여 비전, 목표, 추진전략을 수립
- (분석 중심 Task) 주요 기술 분야의 발전 단계를 분석하여 전략과제 발굴 시 기술 타당성 판단의 근거를 확보
- (도출 중심 Task) 후보 과제를 평가 기준으로 선별하여 전략별 세부과제를 확정
- (활동 성격 Task) 산학연 전문가 협의체를 운영하여 세부과제 우선순위 평가의 전문성을 확보

보완이 필요한 목적 문장의 형태다.

- 수행 행위만 있는 목적("국내외 동향을 조사 및 분석")은 결과와 쓰임을 보완한다.
- 문서 제출로 끝나는 목적("현황표를 작성하여 제출")은 결과와 쓰임으로 종결한다.
- 어느 과업에나 붙는 쓰임("전략 수립에 활용")은 전략 수립의 어느 판단에 쓰이는지 특정한다.

### Task 유형

Task 유형은 산출물의 성질로 나눈다. 산출물이 대상의 현재 상태(현황, 실태, 격차, 원인)이면 분석 중심이다. 산출물이 앞으로의 방향(시사점, 전략, 과제, 지표, 모델)이면 도출 중심이다. 유형 이름은 설계용 언어이므로 제안서 원고에는 쓰지 않는다.

| 유형 | 방법 | 적을 항목 | 함께 둘 표 |
|---|---|---|---|
| 분석 중심 | 문헌과 자료 조사, 인터뷰와 설문, 진단과 프로세스 분석, 데이터 분석 | 목적, 분석 대상, 분석 방법, 산출물 | 대상 실명 목록, 사전조사 결과, 질문 영역과 문항 구조, 진단 항목표, 현행 절차 단계표 |
| 도출 중심 | 분석 결과에서 시사점, 전략, 과제, 지표를 만듦 | 목적, 활용 자료, 기준, 수행 절차, 산출물 | 선정 기준표, 평가 기준(안), 산출물 시안 |

- 분석 중심 Task는 분석 대상(기관, 자료, 면담 대상 직급, 업무 절차)과 분석 방법을 실명으로 적는다. "관련 자료를 폭넓게 조사"는 대상을 특정하지 않은 서술이다.
- 건수가 실제로 정해지는 업무는 규모를 수치로 적는다.
- 도출 중심 Task는 판단 기준과 절차를 다른 사람이 따라 할 수 있게 적는다. "전문가 의견을 종합하여 도출"은 따라 할 수 없는 서술이다.
- 기준 항목의 이름은 Task의 행위에 맞춘다. 후보에서 고르는 Task는 선정 기준, 순위와 가중치를 매기는 Task는 평가 기준, 지표와 목표값을 정하는 Task는 설정 기준, 모델과 체계를 만드는 Task는 설계 기준으로 쓴다.
- 수행 절차는 후보 생성, 1차 선별, 정량 평가, 회의체 협의의 순서와 단계별 담당을 적는다.
- 산출물 칸에는 산출물 명칭만 적는다. 구성 항목, 판단 기준, 활용처는 그 아래 줄에 적는다. 제출 시점은 추진 일정에서 한 번만 제시한다.

### 회의체 설계

회의체 설계는 발주처가 제안사의 실무 이해를 가늠하는 신호다. 명칭, 구성, 회차, 안건, 결과 반영처를 적는다. RFP가 명칭을 정했으면 그 명칭을 쓴다.

| 회의체 | 구성 | 역할 | 통상 회차 |
|---|---|---|---|
| 자문위원회 | 산학연 외부 전문가 5-9명 | 단계별 결과물 검토와 방향 자문 | 3-4회(착수 뒤, 중간보고 전, 최종보고 전) |
| 분과위원회 | 분야별 전문가 3-5명 | 분야별 대상 후보 제시, 분류 체계와 지표의 적정성 검토, 시범 적용 결과 검토 | 분과별 2회와 수시 서면 |
| 실무협의회 | 발주처 담당자와 수행진 | 자료 요청, 현안 결정, 중간 산출물 확인 | 격주 또는 월 1회 |
| 보고회 | 발주처 결정권자와 수행진 | 착수보고, 중간보고, 최종보고 | 3회 |

- 위원 후보는 후보(안) 표로 제시한다. 열은 연번, 구분(산, 학, 연, 관), 소속, 직위, 성명이다. 표 아래에 "위원은 발주처와 협의하여 확정"을 적는다.
- 후보는 사용자가 제공한 명단에서 고른다. 후보군 규모는 15-20인 안팎이 관행이고 소규모 과업은 위원회 정원의 2배 수준이다. 명단이 없으면 분야와 인원만 적는다.
- 차수별 운영 표의 열은 회차, 시기, 안건, 결과 반영처(산출물 이름)다.

| 회차 | 시기 | 안건 | 결과 반영 |
|---|---|---|---|
| 1차 | 착수 후 3주 | 분석 기준과 조사 설계 검토 | Task 1-2 조사 문항 확정 |
| 2차 | 중간보고 전 | 시사점과 전략 방향 검토 | Task 3-1 전략 후보 수정 |
| 3차 | 최종보고 전 | 실행계획과 지표 검토 | 최종보고서 반영 |

### 의견수렴 도구

| 도구 | 적용 상황 | 적을 항목 |
|---|---|---|
| 설문조사 | 실태와 인식, 수요 파악 | 대상 집단과 모집단 규모, 표본 수, 영역별 문항 수, 배포 경로, 회수 목표율, 독려 절차 |
| 심층 인터뷰 | 원인 규명, 제도 운영 실태 | 대상 직급과 인원, 회차, 질문 영역 |
| FGI | 이해관계자 간 이견 확인 | 그룹 구성 기준, 그룹 수, 회당 인원 |
| 델파이 | 전문가 합의(지표, 기술 수준, 미래 전망) | 패널 규모, 라운드 수, 합의 판정 기준(변동계수, 사분위) |
| AHP | 우선순위와 가중치 | 계층 구조, 평가자 수, 일관성 비율 기준(통상 0.1 이하) |
| 수요조사 | 과제 발굴 | 제출 양식 항목, 배포 대상, 정제 기준(중복, 범위 이탈, 예산 과대) |

도구 이름만 나열하면 설계가 끝나지 않은 상태다. 규모와 절차의 수치가 설계의 증거다.
