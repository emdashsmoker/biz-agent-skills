# RFP 분석 양식

01_RFP분석.md를 작성하는 규칙과 양식이다. 분석 모드와 전략 모드 1단계에서 읽는다. 이 문서의 모든 항목은 RFP만으로 채운다.

## 작성 규칙

- 요구항목, 세부평가항목, 참가자격 문구, 작성 규정은 원문 표기 그대로 옮긴다. 요약하면 뒤 단계에서 제안서 워딩과 대조할 수 없다.
- 항목마다 원문 위치(쪽 번호 또는 조항 번호)를 적는다.
- RFP에 없는 항목은 "RFP 미기재"로 적는다.
- 탈락, 감점, 참여 제한으로 이어질 수 있는 조건은 굵게 표시한다.
- 과업 내용이 표로 제시된 RFP는 표의 행과 셀을 요구항목 행으로 옮긴다. 상위 항목 열에 소속 제목의 경로를 적어 배치 판단의 근거를 남긴다.
- 대항목 배점을 한 부분의 배점으로 읽지 않는다. "연구내용의 타당성 30점"처럼 묶인 배점은 세부평가항목 단위로 풀어서 적는다.
- RFP가 인용한 법령과 지침은 명칭과 조항 번호를 원문대로 적는다.

## 과업 유형 판정

과업 유형은 전략 모드의 모듈 골격을 고르는 기준이다. RFP의 과업명, 과업 목적, 산출물 목록에서 아래 판별 신호를 찾는다.

| 과업 유형 | 판별 신호 | 사고 계통 |
|---|---|---|
| 전략기획형 | 기본계획, 중장기 전략, 발전전략, 육성계획, 비전, 로드맵, 경영전략, 조직진단, 기관 내부 평가지표 개발, 신사업 발굴 | 목표 설정 |
| 정보화계획형 | 정보화전략계획(ISP), 정보시스템 마스터플랜(ISMP), 지능정보사회계획, 시스템과 플랫폼 구축 기획, 데이터와 AI 도입 방안, 디지털 전환 계획, 차세대 시스템과 고도화 방안 | 목표 설정 |
| 사업기획형 | 신규사업 기획, 사전기획, 상세기획, 타당성 검토, 기획보고서, 시설 건립 기본계획 | 목표 설정과 갭 분석 |
| 성과분석평가형 | 성과분석, 성과평가 대응, 자체평가, 성과관리, 효과성 분석 | 갭 분석 |
| 경영평가 대응형 | 경영평가 대응, 경영실적보고서, 편람 지표 | 갭 분석 |
| 문제해결형 | 실태조사, 동향조사, 수요조사, 제도 개선, 업무 프로세스 개선, 과제 발굴 | 갭 분석 |
| 지원사업 운영형 | 기업지원 프로그램 운영, 사업화 지원, 창업지원, 인력양성 운영기관 | 갭 분석 |

- 사고 계통은 과업이 요구하는 생각의 출발점이다. 목표 설정 계통은 목표 상태를 먼저 정하고 아래로 전개한다. 갭 분석 계통은 현재 상태를 먼저 밝히고 목표와의 차이를 좁힌다.
- 판별 신호에 걸리지 않는 과업은 사고 계통으로 판정한다. 목표 상태의 정의를 요구하면 전략기획형을 기본값으로 둔다. 현행 문제의 원인 규명을 요구하면 문제해결형을 기본값으로 둔다.
- 여러 유형이 섞인 과업은 주 유형과 부 유형을 함께 적는다. 모듈 단위의 혼합은 전략 모드에서 설계한다.
- 판정 결과에는 근거가 된 RFP 문구와 원문 위치를 붙인다.

## 핵심 워딩 사전

- RFP가 과업명, 산출물명, 단계명, 대상 명칭에 쓰는 표기를 5-15개 수록한다.
- 같은 대상을 가리키는 다른 표기가 RFP에 있으면 RFP가 더 자주 쓰는 표기를 표준으로 삼고 나머지를 변형 표기 열에 적는다.
- 발주처 기관명은 공식 명칭과 RFP나 기관 공문이 쓰는 약칭을 함께 수록한다.
- 제안서는 표준 표기만 쓴다. 심사위원은 RFP 워딩을 기준으로 채점표의 항목을 찾는다.

## RFP 해석

- (표면 니즈) 배경과 목적 문장 원문
- (해결하려는 문제) 배경 문장에서 부정적으로 서술된 현상과 RFP가 밝힌 원인
- (과업 유형) 주 유형, 부 유형, 판정 근거 문구와 원문 위치
- (필요 도메인 지식) 수행에 필요한 법제도, 산업, 기술 지식 5개 이내. 항목마다 관련 요구항목 ID를 붙인다

|---|---|---|

## 항목별 기준

- (계약 방법) 협상에 의한 계약, 적격심사, 2단계 경쟁 등 공고문 표기를 그대로 적는다. 평가와 협상 절차가 계약 방법에 따라 달라진다.
- (정량 여부) 신용등급, 실적 건수처럼 제출 서류로 점수가 정해지는 항목은 "정량"으로 적는다. 정량 항목의 점수는 제안서 서술로 높일 수 없다.
- (협상적격자 기준) 기술점수 하한이 있으면 굵게 표시한다. 하한에 못 미치면 가격과 관계없이 협상 대상에서 빠지므로 전 평가항목을 고르게 채우는 준비를 우선한다.
- (필요 도메인 지식) 요구항목을 수행할 때 모르면 결과물이 틀어지는 지식만 고른다. 과업명에서 바로 떠오르는 일반 지식은 제외한다.
- (확인 필요 사항) 배점 합계와 금액 환산은 코드로 확인한 결과만 적는다.
