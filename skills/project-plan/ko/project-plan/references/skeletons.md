# 과업 유형별 단계 골격

과업 유형은 최종 산출물의 성격 하나로 나눈다. 유형을 고른 뒤 그 골격을 출발점으로 삼고, 과업지시서의 과업 항목에 맞게 행을 더하거나 뺀다. 골격과 과업지시서가 다르면 과업지시서를 따른다.

| 유형 | 최종 산출물 | 해당 과업의 예 |
|---|---|---|
| 계획형 | 방향과 과제를 담은 문서 | 기본계획, 중장기 전략, 로드맵, 정보화 전략계획(ISP), 사업기획, 연구개발 사업기획, 사업화 전략, 제도 개선 방안 |
| 조사형 | 사실 확인과 분석 결과 | 실태조사, 동향조사, 수요조사, 성과분석, 평가 |
| 구축형 | 작동하는 결과물 | 정보시스템, 시제품, 실험과 시험 결과, 데이터베이스, 콘텐츠 |
| 운영형 | 서비스 제공 실적 | 교육 과정 운영, 행사 운영, 지원사업 운영기관 업무 |

발주처가 앞으로 추진할 연구개발을 기획하는 과업은 계획형이다. 실험과 시험은 우리 팀이 직접 수행하는 구축형 과업에서만 작업 행이 된다.

## 모든 유형의 공통 단계

- (첫 단계, 사업관리) 착수 준비, 착수보고회, 진도 및 위험 관리, 중간보고회, 최종보고회, 종료 정리를 둔다.
- (마지막 단계, 산출물 정리) 최종보고서 편집과 통합, 요약본, 계약서에 적힌 부속 산출물, 원자료와 통계표 인계를 둔다.
- (일정 여유) 마지막 작업과 계약 종료일 사이에 여유 행을 둔다.
- 원자료 인계는 정리에 1-2주가 들기 때문에 별도 행으로 둔다. 마지막에 몰아서 하면 납품이 밀린다.

## 계획형

기본 골격은 여건 분석, 방향 설정, 과제 도출, 성과관리, 의견 수렴 순서다. 진단 없이 과제를 먼저 정하면 심의나 검토에서 "왜 이 과제인가"라는 질문에 답하지 못한다.

| 단계 | 대표 행 | 대표 산출물 |
|---|---|---|
| 여건 분석 | 기존 계획 성과 분석, 외부 환경 분석, 내부 역량 진단, 벤치마킹, SWOT 및 시사점 도출 | 기존 계획 대조표, 환경 분석 결과, 진단 결과, SWOT 분석표 |
| 방향 설정 | 비전과 목표 체계 수립, 분야별 전략방향 설정, 목표와 전략과 기대성과 연결 | 비전-목표 체계도, 전략방향 설정표 |
| 과제 도출 | 전략과제 도출과 우선순위, 중복 과제 통폐합, 실행과제 정의서 작성, 필요 시 특성화 전략 | 전략과제 목록, 우선순위 판정표, 실행과제 정의서 |
| 성과관리 | 성과지표 설계, 지표별 관리카드, 환류 절차 설계 | 성과지표 체계표, 관리카드, 환류 절차서 |
| 의견 수렴 | 설문, 심층면담 또는 FGI, 자문회의, 공청회, 심의와 확정 | 결과보고서, 자문 의견 반영표, 확정본 |

선후 관계

- SWOT은 여건 분석의 다른 행이 모두 끝난 뒤에 시작한다. SWOT이 앞선 분석들을 종합하기 때문이다.
- 성과지표는 과제 목록이 나온 뒤에 설계한다. 지표는 과제에 붙는다.
- 의견 수렴은 방향 설정 초안이 나온 뒤에 시작한다. 수렴할 대상이 있어야 의견을 받을 수 있다.
- 전략방향 설정과 기대성과 연결은 동시에 시작해도 된다.
- 실행과제 정의서는 과제 수와 항목 수에 비례해 길어지므로 대부분 납기 직결 행이 된다. 서식 확정, 1차 작성, 검토와 보완 3행으로 나눈다.
- 심의나 위원회 확정이 필요하면 기관의 위원회 개최 주기를 확인하고 대기 행으로 둔다.

완료 기준 예시

| 산출물 | 완료 기준 |
|---|---|
| 기존 계획 대조표 | 대상 계획 전수를 실행과제 단위로 나누고 승계 판정(강화, 유지, 조정, 정리, 신설) 공란 0건 |
| SWOT 분석표 | 요인별 3건 이상, 요인 조합이 전략방향 후보와 1:1로 연결 |
| 비전-목표 체계도 | 목표마다 정량 목표치 보유 |
| 실행과제 정의서 | 전 과제에 소요예산, 재원, 연도별 투자계획, 성과지표 4항목 기재 |
| 성과지표 체계표 | 전체 지표, 전략방향별 지표, 실행과제별 지표의 3단 구성과 지표 간 중복 판정 완료 |
| 심의 결과 | 조건부 의결 이상, 조건 반영 계획 문서화 |

실행과제 정의서가 이 유형의 대표 산출물이다. 발주기관은 계획을 확정한 뒤 예산 요구와 공모 신청의 근거로 정의서를 그대로 쓴다.

작은 과업에서 줄이는 순서

- 벤치마킹, 공청회, 실행과제 정의서의 항목 수(4항목에서 예산과 성과지표 2항목으로)를 먼저 줄인다.
- SWOT은 방향 설정의 입력이므로 남긴다.

### 연구개발 사업기획

계획형 골격의 여건 분석에 기술동향, 특허와 논문 분석, 유사사업 중복성 검토를 더하고, 과제 도출 단계에 아래 행을 더한다.

| 행 | 대표 산출물 |
|---|---|
| 핵심기술 도출 | 핵심기술 목록, 기술트리 |
| 기술수준 진단과 목표 설정 | 기술수준(TRL) 진단표 (현재 수준, 목표 수준, 판단 근거) |
| 성능 목표값 설정 | 성능지표 정의서 (지표, 현재 수준, 목표값, 측정 방법) |
| 기술 확보 방식 판단 | 자체 개발, 도입, 협력의 판정표 |
| 세부과제와 연차별 계획 | 세부과제 구성표, 연차별 로드맵 |
| 소요예산 산정 | 비목별 단가 근거가 있는 예산 내역서 |
| 추진체계 설계 | 추진체계도, 역할분담표 |
| 성과와 활용 계획 | 성과지표 체계표, 활용과 확산 계획서 |
| 타당성 분석 | 경제성과 정책성 판정 |

- 경제성 분석은 예산 산정 뒤에 둔다. 사업비가 경제성 분석의 입력이기 때문이다.
- 기술수준 진단 직후에 자문 1회를 둔다. 현재 수준에 대한 판단이 전문가마다 갈리기 때문이다.
- 특허와 논문 분석은 유료 데이터베이스 접근에 의존하는 경우가 많다. 비고에 "특정 인력 의존"을 적고, 공개 데이터베이스와 표본 축소를 대체 경로로 둔다.
- 성능지표 정의서에 측정 방법이 빠지면 뒤따르는 과제 공고의 목표를 검증할 수 없게 된다.
- 특허 분석은 검색식, 데이터베이스, 검색 기간, 건수와 유효특허 선별 기준을 문서로 남기면 완료된다. 유사사업 비교표는 전 사업에 중복, 보완, 신규 판정을 붙이면 완료된다.

### 사업화 전략

기술 사업화, 신사업 기획, 투자 유치 준비 과업은 아래 순서로 행을 둔다. 보유 기술을 모른 채 시장부터 보면 우리 기술로 갈 수 없는 시장을 설계하게 된다.

| 단계 | 대표 행 |
|---|---|
| 기술과 지식재산 진단 | 보유기술 분석, 지식재산 현황, 기술성숙도 판정, 경쟁기술 비교, 권리 안정성 검토 |
| 시장과 사업성 | 시장 규모 추정, 고객과 수요 분석, 경쟁과 대체재 분석, 수익성 분석 |
| 사업화 경로 | 사업 모델, 시장 진입 전략, 인허가와 규제 대응, 협력사와 공급망, 지식재산 전략 |
| 실행과 재원 | 단계별 실행 로드맵, 소요자금 산정, 투자와 지원사업 연계, 조직과 인력 계획 |

- 권리 안정성 검토는 지식재산 전략보다 먼저 끝낸다. 결과는 "검토 결과"로 표기한다.
- 인허가 소요 기간이 시장 진입 시점을 정한다. 그래서 인허가 검토는 진입 전략과 동시에 시작하거나 먼저 시작한다. 기간은 소관기관의 공표 처리 기간을 쓰고, 없으면 `[확인 필요]`로 적는다.
- 수익성 분석("팔면 남는가")과 소요자금 산정("시작하려면 얼마가 드는가")은 별도 행으로 둔다. 수익성 분석의 가정이 자금 계획의 입력이 된다.
- 고객 검증 결과가 사업 모델을 바꿀 수 있으므로 고객 검증 뒤에 사업 모델 재검토 행을 둔다. 수요기업 섭외는 대기 행으로 둔다.
- 투자 유치와 지원사업 연계는 공모와 심사 일정에 맞춰 대기 행으로 둔다.
- 지식재산 진단은 특허 데이터베이스나 변리사 검토에 의존한다. 비고에 "특정 인력 의존"과 대체 경로(공개 데이터베이스, 범위 축소)를 적는다.
- 시장 규모 추정표는 전체 시장, 접근 가능 시장, 획득 가능 시장의 3단과 각 단계의 산출 근거를 갖춘다.
- 작은 과업에서도 권리 안정성 검토는 핵심 청구항 1건 수준으로 줄여서 남긴다.

## 조사형

기본 골격은 조사 설계, 자료 수집, 분석, 해석과 제언 순서다. 수집이 설계보다 먼저 시작되면 모은 자료가 분석 틀에 들어가지 않는다.

| 단계 | 대표 행 | 대표 산출물 |
|---|---|---|
| 조사 설계 | 조사 틀 설계, 모집단과 표본 설계, 조사도구 개발, 사전검증, 승인 절차 | 조사 설계서, 표본 설계서, 설문지와 면담 가이드 |
| 자료 수집 | 2차 자료 수집 계획, 협조 요청, 회신 대기, 정제, 설문, 심층면담 또는 FGI, 현장조사 | 자료원 목록, 정제 데이터, 설문 원자료, 녹취 요약 |
| 분석 | 기초 통계, 교차와 심층 분석, 정성 분석, 결과 통합 | 통계표, 분석 결과, 주제별 정리표 |
| 해석과 제언 | 시사점 도출, 제언 작성, 활용 방안 | 근거-제언 연결표, 활용 방안서 |

선후 관계

- 설문, 설문 기초 분석, FGI 주제 확정, FGI 순서로 둔다. FGI는 설문에서 드러난 결과의 이유를 묻는 자리이므로 설문 결과가 먼저 있어야 한다.
- 설문 문항을 만들기 위한 탐색용 FGI는 설문 앞에 별도 행으로 두고 이름을 다르게 적는다.
- 연구윤리 심의나 통계 작성 승인이 필요한 조사는 승인을 받은 뒤에 시작한다. 승인 전에 모은 자료는 쓸 수 없다.
- 정성 분석은 면담 직후에 시작하고 결과 통합 단계에서 정량 분석과 합친다. 결과 통합 행은 정량과 정성 자료가 모두 있을 때만 둔다.
- 성과분석과 평가 과업은 조사 설계 단계에 평가 틀 설계(지표, 비교 기준, 자료원)를 둔다.
- 사전검증 뒤의 문항 수정 1회를 미리 행으로 둔다.
- 교차와 심층 분석이 통계 전문 인력에 의존하면 비고에 "특정 인력 의존"과 대체 인력을 적는다.

완료 기준 예시

| 산출물 | 완료 기준 |
|---|---|
| 조사 설계서 | 조사 대상, 분석 단위, 비교 기준 명시, 발주처 승인 |
| 표본 설계서 | 모집단 규모, 목표 표본수, 추출 방법, 허용오차 명시 |
| 설문지 | 조사 항목 전건을 문항으로 포함, 문항과 분석 항목 대응표 공란 0건 |
| 사전검증 | 응답 소요 시간과 오해 문항 확인 뒤 수정본 확정 |
| 정제 데이터 | 결측과 이상치 처리 규칙 문서화, 원자료 건수와 대조 완료 |
| 설문 원자료 | 유효 응답이 목표 표본의 80% 이상 |
| 면담 결과 | 계획 건수 완료, 녹취 정리, 동의서 확보 |
| 제언 목록 | 전 항목이 분석 결과와 1:1로 연결, 발주처 검토 완료 |

근거-제언 연결표가 이 유형의 대표 산출물이다. 제언이 분석 결과와 이어지지 않으면 검토 의견이 대부분 이 지점에서 나온다.

작은 과업에서 줄이는 순서

- 사전검증 규모(전문가 검토로 대체)와 분석 범위(기초 통계와 주요 교차 분석)를 먼저 줄인다.
- 승인 절차는 기관 일정에 맞춰 줄어들지 않으므로 그대로 둔다.

## 구축형

기본 골격은 선행 조사와 설계, 구현, 시험과 검증, 적용, 성과 정리 순서다.

| 단계 | 대표 행 | 대표 산출물 |
|---|---|---|
| 선행 조사와 설계 | 선행 기술 조사, 요구사항 정의, 상세 설계 | 조사 보고서, 요구사항 정의서, 설계서 |
| 구현 | 장비와 재료와 개발 환경 확보, 모듈 개발, 통합 | 구매 내역, 모듈 결과물, 통합 결과물 |
| 시험과 검증 | 시험 계획, 자체 시험, 공인시험 또는 사용자 검수, 목표 대비 판정 | 시험계획서, 시험 결과보고서, 성적서, 달성도 판정표 |
| 적용 | 실증 또는 시범 운영 환경 구축, 실증, 개선 | 실증 결과보고서, 개선 조치 결과 |
| 성과 정리 | 지식재산 출원, 성과 확산, 운영 인계와 사용자 교육 | 출원 목록, 인계 문서 |

선후 관계

- 장비, 재료, 개발 환경을 확보한 뒤에 개발을 시작한다. 조달은 요청, 대기, 입고 3행으로 나누고, 수입 품목은 공급사 납기를 확인한다.
- 공인시험은 예약에 몇 주가 걸리는 경우가 있으므로 시험 계획을 세울 때 예약을 요청한다.
- 요구사항 정의서는 발주처 검토 사이클(초안, 내부 검토, 제출, 검토 대기, 반영)을 거친 뒤 설계로 넘어간다.
- 실험과 시험 행은 성공을 전제하지 않는다. 재시험 가능성이 1회면 기본 행 기간의 30%, 2회 이상이면 50%를 재시험 행으로 둔다. 비율을 고른 이유를 비고에 한 줄 남긴다.

완료 기준 예시

| 산출물 | 완료 기준 |
|---|---|
| 요구사항 정의서 | 전 요구사항에 식별 번호와 검증 방법 기재, 발주처 확인 |
| 시험 결과보고서 | 전 지표에 목표값과 실측값 병기, PM 승인 |
| 공인시험 성적서 | 원본 수령, 목표 충족 여부 판정 완료 |

## 운영형

기본 골격은 운영 준비, 모집과 선정, 운영, 성과 관리 순서다.

| 단계 | 대표 행 | 대표 산출물 |
|---|---|---|
| 운영 준비 | 운영 계획 수립, 선정 기준 마련, 모집 공고 준비 | 운영 계획서, 선정 기준표 |
| 모집과 선정 | 공고 게시, 접수 대기, 서류와 발표 평가, 선정 통보 | 접수 목록, 평가 결과표 |
| 운영 | 회차별 운영, 참여자 지원, 만족도 조사 | 회차별 운영 결과표, 만족도 결과 |
| 성과 관리 | 실적 집계, 성과 분석, 결과 보고 | 실적 집계표, 결과보고서 |

- 접수 기간은 신청자가 끝을 정하므로 대기 행으로 둔다. 접수 인원이 목표에 못 미칠 때를 대비해 추가 모집 행을 보완 행으로 둔다.
- 같은 형식의 회차는 회차 묶음 1행으로 두고 비고에 회차 수와 날짜를 적는다.
- 만족도 조사가 설문이면 `survey.md`의 회수 기준을 적용한다.

## 복합 과업

두 유형에 걸친 과업은 최종 산출물을 기준으로 주 골격 1개를 고르고, 다른 유형의 단계를 치환하거나 삽입한다. 치환과 삽입 중 무엇을 할지 먼저 정한다. 같은 일이 두 단계에 들어가면 과업 범위 대조가 깨진다.

| 조합 | 합치는 방법 |
|---|---|
| 계획형과 조사형 | 계획형의 여건 분석을 조사형의 조사 설계, 자료 수집, 분석으로 치환한다 |
| 계획형 과제 일부가 기술개발 과제 | 과제 도출 단계에 연구개발 사업기획의 기술 목표 행을 삽입한다. 기술개발 과제만 기술수준과 성능 목표값을 가진다 |
| 계획형 과제 일부가 사업화 과제 | 성과관리 단계 앞에 사업화 전략의 시장과 사업성 단계를 삽입한다 |
| 조사형과 사업화 전략 | 조사형의 해석과 제언을 시장과 사업성 단계로 치환한다 |
| 계획형과 구축형 | 기획 중 일부를 실증하는 과업은 계획형에 시험과 검증 단계를 삽입한다 |

- 사업관리 단계는 1개만 둔다.
- 합친 뒤에는 `plan.py check`를 다시 실행한다. 합치면 대부분 일정이 길어지는 쪽으로 바뀐다.
