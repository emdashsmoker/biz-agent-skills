# 초거대AI 시범 도입 TF 협업 구조 진단

**결론:** 지금 TF는 **정보A 한 사람**과 **팀별 창구 1명**에 매달린 구조입니다. 13명 중 5명이 빠지면 TF가 끊깁니다. 연결 **2개**(기획B–정보C, 품질B–설계C)만 새로 이으면 이런 사람이 0명이 되고, 정보A를 거쳐야 하는 경로 비중도 67%에서 37%로 줄어듭니다.

![현재 구조와 개선안 비교](tf_network_compare.png)

그림 파일은 `tf_network_compare.png`입니다. 왼쪽이 현재 구조, 오른쪽이 개선안입니다. 빨간 테두리는 빠지면 TF가 끊기는 사람, 초록 점선은 새로 이어야 할 연결입니다.

## 1. 현재 구조의 문제

### ① TF 전체가 정보A를 거쳐야 이어짐
- 정보A가 빠지면 TF가 **3조각**(품질+기획 6명 / 설계 4명 / 정보B·C 2명)으로 갈라집니다.
- 정보A를 뺀 12명 사이의 66쌍 가운데 **44쌍(67%)은 정보A를 거치지 않으면 닿을 길이 없습니다.** 업무 병목이 생기고 정보A에게 부담이 몰리기 쉬운 구조입니다.

### ② 팀마다 바깥 창구가 1명뿐
- **설계팀**은 TF와 이어진 연결이 *설계B–정보A* 하나뿐입니다. TF 인원의 31%인 4명이 이 연결 하나에 달려 있습니다.
- **품질팀**은 바깥 연결이 2개 있지만 둘 다 품질A를 통합니다.
- 팀 내부는 탄탄합니다. 품질팀과 설계팀은 각각 가능한 6쌍 중 5쌍이 협의했습니다. 문제는 팀과 팀 사이입니다.

### ③ 팀 사이에 직접 연결이 없는 곳이 2곳
- 4개 팀이 이룰 수 있는 6개 팀 쌍 가운데 **품질–설계**, **기획–설계**는 직접 협의가 한 번도 없었습니다.
- 그래서 품질D가 설계A·C·D에게 닿으려면 5단계를 거쳐야 합니다.

### ④ 협의 상대가 1명뿐인 사람
- 정보C는 정보B하고만, 기획B는 기획A하고만 협의했습니다. 그 한 사람이 빠지면 고립됩니다.

### 빠지면 TF가 끊기는 사람 (5명)

| 사람 | 빠지면 떨어져 나가는 사람 | 비고 |
|---|---|---|
| **정보A** | 설계 4명, 정보B·C (TF 3분할) | 가장 심각. 전체 연결의 중심 |
| **설계B** | 설계A·C·D | 설계팀 유일 창구 |
| **품질A** | 품질B·C·D | 품질팀 유일 창구 |
| **정보B** | 정보C | |
| **기획A** | 기획B | |

## 2. 개선안: 연결 2개 추가

| 구분 | 새 연결 | 해결되는 문제 |
|---|---|---|
| 신규 1 | **기획B – 정보C** | 정보B·기획A가 빠져도 끊기지 않음. 기획·정보 실무자 사이에 직접 통로가 생김 |
| 신규 2 | **품질B – 설계C** (품질C도 효과 동일) | 비어 있던 품질–설계 직접 연결이 생김. 품질A·설계B가 빠져도 끊기지 않고, 정보A가 빠져도 TF가 이어짐 |

**이 두 개를 고른 이유**
- **2개가 최소입니다.** 정보A가 빠지면 3조각이 나므로 1개로는 해결할 수 없습니다.
- 연결 2개로 끊기는 사람을 모두 없애는 조합은 18가지가 있습니다. 그중 평균 거리와 정보A 경유 비중이 가장 많이 줄어드는 조합을 골랐습니다.
- 새 연결은 기존 창구(정보A·품질A·설계B·기획A)가 아니라 **창구가 아닌 사람끼리** 잇습니다. 창구에 일을 더 얹지 않고 부담을 나누는 방향입니다.
- 아무 데나 2개를 이으면 안 됩니다. 예를 들어 *기획B–품질D*와 *설계C–정보C*를 이어도 정보A가 빠지면 TF는 여전히 갈라집니다.

### 전후 비교

| 지표 | 현재 | 개선안 |
|---|---|---|
| 빠지면 TF가 끊기는 사람 | 5명 | **0명** |
| 대체 경로가 없는 연결 | 4개 | **0개** |
| 정보A를 거치는 최단 경로 비중 | 67% | **37%** |
| 두 사람 사이 평균 거리 | 2.68단계 | **2.35단계** |
| 정보A가 빠졌을 때 | 3조각으로 분리 | 연결 유지 (평균 3.09단계) |
| 직접 연결이 없는 팀 쌍 | 품질–설계, 기획–설계 | 기획–설계 |

## 3. 실행 제안

1. **새 연결은 공동 과제로 만드세요.** "서로 연락하라"는 지시만으로는 유지되지 않습니다. 두 사람이 함께 내야 하는 산출물을 하나씩 배정하는 편이 효과적입니다. 예를 들면 기획B–정보C에는 시범 적용 업무의 요건과 데이터 확인을, 품질B–설계C에는 AI 적용 결과물의 품질 기준 검토를 맡길 수 있습니다. 실제 역할에 맞게 조정하세요.
2. **정보A의 부담을 계속 살펴보세요.** 개선 후에도 정보A가 가장 많이 거치는 사람(37%)입니다. 또 정보A와 기획A가 동시에 빠지면 기획B·정보B·정보C가 떨어져 나갑니다. 휴가나 출장이 겹치지 않게 일정을 조율하는 것이 좋습니다.
3. **(선택) 기획–설계 직접 연결.** 기획팀이 설계팀 요구를 직접 들어야 하는 단계라면 *기획B–설계C*를 하나 더 잇는 방안을 검토해 보세요. 평균 거리는 2.13단계, 정보A 경유 비중은 22%까지 내려가고, 가장 먼 거리도 5단계에서 4단계로 줄어듭니다. 다만 기획B와 설계C에 일이 몰리는 점은 감안해야 합니다.
4. **한 달 뒤 같은 방식으로 다시 측정**해서 새 연결이 실제로 생겼는지 확인하세요.

## 4. 해석할 때 주의할 점
- 협의 **횟수와 중요도가 없는 자료**입니다. 1회 협의도 연결 하나로 셌기 때문에, 형식적인 협의와 핵심 협의가 구분되지 않습니다.
- 기록 밖의 소통(메신저, 비공식 대화 등)은 빠져 있을 수 있습니다.
- 정보C와 기획B가 보조 역할이라 팀 선임을 통해서만 협의하는 것이 의도된 구조일 수도 있습니다. 그렇더라도 TF가 이어지려면 대체 통로가 하나는 있어야 합니다.
- 추천한 연결 상대는 **구조만 보고** 고른 것입니다. 역할이 맞지 않으면 품질B 대신 품질C를 써도 효과가 같습니다. 설계C 대신 설계A·D를 써도 끊기는 사람은 똑같이 없어지고, 개선 폭만 조금 작아집니다(평균 2.39단계, 정보A 경유 38%).

**확인하고 싶은 점:** 각 사람의 역할이나 직급, 또는 협의 횟수 자료가 있으면 알려 주세요. 연결 상대를 실무에 더 맞게 다시 고르고, 횟수를 반영해 다시 분석해 드리겠습니다.

공유가 필요하시면 이 내용을 팀원에게 보낼 수 있는 웹 페이지로도 만들어 드릴 수 있습니다.
