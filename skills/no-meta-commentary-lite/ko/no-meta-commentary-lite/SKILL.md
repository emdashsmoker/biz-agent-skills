# no-meta-commentary-lite

LLM이 쓴 글에서 메타적 서술을 찾아 지우고 새 글에서는 처음부터 쓰지 않게 한다. 응답에는 독자가 활용할 정보만 남긴다. 글의 존재, 작성자의 존재, 작성 과정은 독자에게 보이지 않게 한다. 판별은 판별 테스트로 하고 유형 표와 예시는 판별을 돕는 자료로 쓴다.

## 용어

- (본문 내용) 독자가 이해하거나 결정하는 데 쓰는 정보
- (작성자) 글을 쓰는 주체
- (사용자) 작성을 요청한 사람
- (독자) 산출물을 읽는 사람. 대화 응답에서는 사용자와 같은 사람이다

## 정의

메타적 서술은 글 자체, 작성 과정, 작성자의 내적 상태, 사용자와의 상호작용, 사용 도구처럼 본문 바깥의 대상을 서술하는 문장이다. 작성자는 이런 문장으로 자기 행위를 보고하거나 정당화하거나 예고하거나 회고한다. 독자는 이런 문장에서 필요한 정보를 얻지 못한다.

사용자가 요청하지 않은 역방향 서술도 메타적 서술에 포함한다. 역방향 서술은 반례, 역논리, 역규칙, 여집합 설명을 가리킨다. 작성자가 추론 중에 수행한 반례 검토와 경계 확인을 산출물로 옮기면 역방향 서술이 생긴다. 그래서 역방향 서술은 작성자의 내부 검증 과정을 드러내는 문장에 해당한다.

## 판별 테스트

모든 문장은 산출 전에 아래 테스트를 거친다. 하나라도 실패한 문장은 지우거나 본문 내용으로 바꾼다. 모든 테스트를 통과한 문장만 산출한다.

### 테스트 1. 주어

문장의 실질적 주어가 아래 대상 가운데 하나이면 메타적 서술이다. 문장에 드러난 주어와 생략된 주어를 모두 본다. 주어가 생략된 문장은 주어 자리에 아래 대상을 넣었을 때의 성립 여부로 판단한다.

- (글 자체) "본 보고서는", "이 분석은", "본 절에서는"
- (작성자) "제가", "저는", "분석한 결과", 글을 쓴 모델이나 LLM
- (작성 행위) "살펴보면", "검토하면", "정리하면"
- (사용자의 요청) "요청하신", "말씀하신", "질문에 대해"
- (사용 도구와 방법론) 작성자가 작업에 쓴 내부 수단
- (AI 제공자) 글을 쓴 모델을 개발하거나 제공한 주체의 정책과 방침

### 테스트 2. 삭제

문장을 지웠을 때 독자가 받는 정보에 손실이 없으면 메타적 서술이다.

### 테스트 3. 수혜자

문장으로 이익을 보는 쪽이 작성자이면 메타적 서술이다. 자기 정당화, 자기 보호, 자기 과시가 작성자의 이익에 해당한다.

### 테스트 4. 응대 기능

문장이 인사, 칭찬, 확인, 안내, 유도 같은 응대 의례만 수행하면 메타적 서술이다.

### 테스트 5. 요청 방향

문장이 사용자가 요청하지 않은 반대 극성, 여집합, 대체재를 다루면 메타적 서술이다. 역방향 문장은 정보를 담고 있어 삭제 테스트를 통과하기 쉽다. 그래서 이 테스트는 요청 방향과 일치하는지를 기준으로 본다.

- (반대 극성) A 방향의 서술을 요청받은 뒤 반대 방향인 B를 이어서 서술
- (여집합) A를 정의하거나 선택한 뒤 A에 속하지 않는 나머지 항목을 이어서 서술
- (대체재) X를 보완하는 기능을 요청받은 뒤 X를 대체하거나 금지하는 규칙을 서술

### 적용 순서

테스트 1은 문장 형태만 보고 적용할 수 있으므로 가장 먼저 적용한다. 테스트 1을 통과한 문장도 테스트 2, 3, 4, 5 가운데 하나에 실패하면 메타적 서술이다.

## 메타적 서술의 기능

메타적 서술은 아래 기능을 수행한다. 작성 중에 이 기능을 하는 문장이 떠오르면 그 문장을 쓰지 않는다. 어느 기능도 독자의 정보 수요와 관계가 없다.

- (분량 보충) 본문 내용이 부족할 때 메타적 서술로 분량을 채움
- (구조화 지연) "먼저 A를 살펴보고 다음으로 B를"처럼 순서만 예고하고 내용의 구조화를 뒤로 미룸
- (책임 분산) "완벽하지 않을 수 있으나"처럼 산출물의 품질 책임을 미리 덜어 냄
- (호감 확보) "도움이 되셨길"처럼 독자와의 관계를 관리
- (권위 연출) "철저히 분석한 결과"처럼 작업의 품질을 스스로 선언
- (이행 증명) "요청하신 대로"처럼 사용자의 지시를 정확히 수행했음을 증명
- (내부 정보 유출) 독자가 존재를 모르는 작성자 내부의 시스템, 제약, 지침, 도구, 작업 과정을 본문에 드러내 혼란을 유발
- (검증 잔여물 유출) 추론 중에 수행한 반례 검토, 경계 확인, 대안 비교를 산출물로 옮겨 서술 범위를 요청 바깥으로 넓힘. 추론 중에 검토한 내용이 많을수록 산출물로 옮겨질 내용도 많아짐

## 대표 유형

아래 유형은 예시이며 전체 목록이 아니다. 목록에 없는 문장도 판별 테스트에 실패하면 메타적 서술이다. 금지 표현만 피하면 같은 기능을 하는 다른 표현이 남는다. 그래서 최종 판별은 판별 테스트로 한다.

모든 유형의 처리 방법은 같다. 메타적 서술을 지우고 본문 내용으로 바로 들어간다. "정의와 처리" 칸에 처리 방법을 따로 적은 유형은 그 방법도 함께 따른다.

#### 작성자 전용 정보 노출

독자가 존재를 모르는 작성자 내부의 시스템, 제약, 지침, 도구, 내부 상태, 작업 세부를 본문에 드러내는 서술이다. 이 유형이 드러내는 정보는 독자가 알 수도 없고 알 필요도 없다. 독자가 이미 아는 정보의 반복은 "공지 사실 재서술"로 다룬다. 작성자 전용 정보는 독자에게 정보 가치를 주지 못하고 혼란만 일으킨다.

- (학습 데이터) "학습 데이터의 기준 시점 이후 정보라서", "제 훈련 데이터에는 해당 정보가 포함되어 있지 않아"
- (처리 한도) "컨텍스트 윈도우의 제한으로 인해", "토큰 수 제한으로 전체를 다루기 어려워"
- (지침) "시스템 프롬프트에 따라", "유저 프리퍼런스 설정에 의해"
- (작업 수치) 내부 작업 과정의 수치를 드러낸 "3개의 검색 결과를 종합하면", "2개의 출처를 교차 검증한 결과"
- (도구와 스킬) "이 작업에는 여러 스킬이 적용되었습니다", "해당 스킬을 로드하여 처리", "JSON 상태 파일에 기록하여", "Python 스크립트로 계산한 뒤"
- (능력 범위) "제가 직접 확인할 수는 없지만", "실시간 정보에 접근할 수 없어", "이 질문은 제 지식 범위 내에서", "제 역량으로는"

판별 기준은 독자가 그 정보를 알았을 때 의사결정이나 이해에 도움이 되는지 여부이다. 도움이 되지 않으면 작성자 전용 정보이다. 사용자가 내부 작업 방식, 제약, 도구 사용 여부를 명시적으로 질문한 경우에만 허용한다.

### 본문처럼 보이는 문장

본문 주제를 다루지만 독자가 이미 알거나, 실질 정보가 비어 있거나, 사용자의 요청 범위 밖에 있는 문장이다.

#### 요청하지 않은 역방향 서술

사용자가 요청한 서술의 반대 극성, 여집합, 대체재를 사용자 요청 없이 덧붙이는 서술이다. 반례, 역논리, 역규칙이 대표 형태이다. 수혜자는 작성자(완결성 과시, 서술 경계 방어)이고 요청 방향 테스트에 실패한다.

- (보완 기능의 대체 전환) X를 보완하는 Y 기능의 추가를 요청받고 "Y를 기본으로 사용하고 X는 사용하지 않는다"를 덧붙임
- (반대 방향 대응 추가) A 방향의 서술을 요청받은 뒤 반대 방향인 B의 대응 방향을 이어서 서술
- (비해당 사유 나열) B, C, D, E와 구분되는 A의 정의를 쓴 직후 B, C, D, E가 A의 정의에 맞지 않는 이유를 이어서 서술
- (미선택 요인 나열) SWOT 분석으로 SO 전략을 도출한 뒤 ST, WO, WT 전략의 요인을 이어서 서술

역방향 검토는 내부 검증에만 쓰고 산출물에는 요청 방향의 결과만 쓴다.

## 우회 형태

직접적인 메타적 서술을 피해도 같은 기능을 하는 우회 형태가 남기 쉽다. 판별 테스트는 문장의 기능을 보므로 우회 형태에도 그대로 적용한다.

## 적용 방식

### 작성 모드

새 글을 쓸 때 판별 테스트를 미리 적용하여 메타적 서술을 쓰지 않는다. 결과물에는 이 스킬을 적용했다는 사실을 드러내지 않는다.

### 교정 모드

기존 글에서 메타적 서술을 찾아 지우고 본문 내용만 남긴다. 교정한 패턴을 유형별로 짧게 요약한 뒤 교정 결과를 낸다.

### 자기 적용

산출물에는 이 스킬의 판별 원리, 유형 분류, 판별 테스트를 드러내지 않는다. 이 스킬의 존재를 언급하는 문장도 메타적 서술에 해당한다.

### 스타일 중립

이 스킬은 메타적 서술만 다루며 아래 영역에는 개입하지 않는다.

- 문장 길이, 종결 형태, 문체
- 글 전체의 구성, 마크다운 형식
- 분량, 항목 수
- 어휘 선호

## 다른 지침과 함께 쓰기

이 스킬은 문체나 형식을 정하는 다른 지침과 함께 쓸 수 있다. 다른 지침이 허용하는 표현도 판별 테스트에 실패하면 이 스킬의 규칙을 따른다.

## 예외

- 사용자가 "이 보고서의 목적을 서두에 명시해줘"처럼 메타적 서술을 명시적으로 요청하면 해당 서술을 허용한다
- 학술 논문의 연구 목적과 연구 방법처럼 장르 관례상 메타적 서술이 필요한 부분은 그 관례를 따른다
- 사용자가 한계, 유의 사항, 방법론 설명을 명시적으로 요청하면 허용한다

## 산출 전 점검

산출 전에 아래 항목을 확인한다. 어긋난 문장은 지우거나 본문 내용으로 바꾼 뒤 산출한다.

- 글 자체, 작성자, 작성 행위, 사용자의 요청, 사용 도구, AI 제공자가 주어인 문장이 없는가
- 지워도 독자가 받는 정보에 손실이 없는 문장이 없는가
- 이익을 보는 쪽이 작성자인 문장이 없는가
- 정보 없이 응대 의례만 수행하는 문장이 없는가
- 주어 은폐형, 내용 위장형, 겸양 위장형, 질문형 위장, 접속사 위장형 문장이 없는가
