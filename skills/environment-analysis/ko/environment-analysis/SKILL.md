# 환경분석

주체를 둘러싼 외부 환경과 주체의 내부 상태를 근거 자료로 정리한다. 결과물은 출처가 붙은 팩트, 팩트에서 귀납한 시사점, 개조식 보고서다. 분석은 시사점에서 멈춘다. SWOT 분류와 전략, 과제, 목표치 같은 처방은 후속 단계에서 다루며 이 스킬은 후속 단계가 바로 받아 쓸 수 있는 형태로 팩트와 시사점을 넘긴다.

환경분석은 매번 전체 과정을 거칠 필요가 없다. 정책동향만, 경쟁구조만, 내부역량 진단만 필요한 경우를 위해 모든 모듈은 따로 실행할 수 있다.

## 핵심 원칙

- (근거) 사실 진술은 사용자 제출 자료, 이번 작업에서 직접 확인한 웹 페이지, 연결 시스템(사내 시스템, 공공 데이터 API 등)에서 조회한 자료에만 기댄다. 모델이 기억하는 지식으로 사실을 채우지 않고 자료에 없는 내용은 확인되지 않았다고 적는다
- (사실과 해석 분리) 모듈 본문은 확인된 현상과 추세로 채운다. 5-Forces 경쟁강도, VRIO 결과, 핵심 성공 요인처럼 절차가 정한 판정은 근거 팩트와 짝을 지어 쓰되 팩트와 한 문장에 섞지 않는다. 주체에게 주는 의미의 해석은 시사점 절에 모은다
- (처방 제외) To-be, 해결 방안, 지원 필요 영역, 투자 타당성 판단은 쓰지 않는다. 이런 판단은 SWOT이나 갭분석처럼 뒤에 오는 단계에서 다룬다
- (추적 가능성) 모든 팩트에 ID, 출처, 기준 시점을 붙이고 시사점에는 근거 팩트의 ID를 단다. 제3자가 같은 자료로 같은 절차를 밟으면 같은 결론에 도달해야 한다
- (코드 계산) 합계, 비중, 증감률, 환산은 코드로 계산하고 출처에 적힌 수치도 코드로 검산한다. 코드 실행이 불가능한 환경이면 계산식과 입력값을 함께 적고 검산 필요로 표시한다
- (요청 범위) 요청한 모듈과 범주만 실행한다. 팩트는 풍부하게 모으고 해석은 간결하게 쓴다

## 용어 정의

| 용어 | 정의 |
|---|---|
| 주체 | 분석의 중심에 두는 조직, 지역, 산업 기술 영역 |
| 주제 | 분석이 다루는 산업, 기술, 제품, 서비스, 정책 분야 |
| 거시환경 | 주체가 통제할 수 없고 직접 주고받는 관계도 없는 넓은 변화. 정책, 경제, 사회, 기술, 환경, 법제도가 해당 |
| 미시환경 | 주체가 거래, 경쟁, 협력으로 상호작용하는 대상. 시장, 산업, 경쟁자, 고객, 공급자, 투자 재원이 해당 |
| 내부현황 | 주체가 직접 통제하는 자원, 역량, 운영 상태 |
| 벤치마킹 | 비교할 수 있는 다른 주체의 사례와 주체와의 차이 |
| 팩트 | 출처와 기준 시점이 확인된 단일 사실 진술 |
| 판정 | 5-Forces, VRIO처럼 정해진 기준으로 팩트를 평가한 결과. 근거 팩트를 함께 적는다 |
| 시사점 | 하나 이상의 팩트나 판정을 귀납하여 주체에게 주는 의미를 한 문장으로 압축한 진술 |
| 산업 가치사슬 | 한 산업에서 원료와 부품 공급 단계(후방)부터 최종 수요 단계(전방)까지 이어지는 시장 단계의 연결. 단계마다 여러 기업이 경쟁하는 시장이 있다. Porter(1985)가 공급자, 기업, 유통, 구매자의 가치사슬을 이은 전체로 설명한 가치 시스템(value system)에 대응한다. 미시환경과 5-Forces의 분석 단위다 |
| 조직 가치사슬 | 한 조직 안에서 가치를 만드는 활동의 연결. Porter(1985)는 본원적 활동(구매 물류, 운영, 출하 물류, 마케팅과 판매, 서비스)과 지원 활동(기업 인프라, 인적자원관리, 기술개발, 조달)으로 나눴다. 주체가 통제하는 활동이므로 내부현황에 속한다 |
| 자료 경로 | 웹검색, 사용자 제출 파일, 연결 시스템(MCP, API, DB) |
| 검증 강도 | 출처 확인 절차의 엄격도. 1단계부터 3단계까지 있으며 references/sources.md에 정의 |

거시, 미시, 내부의 구분은 주체의 통제 가능성과 상호작용 가능성이라는 하나의 기준으로 판단한다. 같은 대상도 주체가 바뀌면 분류가 바뀐다. 지역 산업정책은 지역 안의 기업이 주체일 때 거시환경이고 그 지역이나 지방자치단체가 주체일 때 내부현황이다. 정부 연구개발 사업의 정책 방향 문서는 거시환경이다. 주체가 지원하거나 경쟁하는 개별 사업과 과제의 자금 흐름은 미시환경의 투자 범주다. 주체가 이미 수주해 수행 중인 사업은 주체가 통제하는 자원이므로 내부현황이다.

산업 가치사슬과 조직 가치사슬은 다루는 단위가 다르다. 산업 가치사슬의 단위는 시장이고 조직 가치사슬의 단위는 한 조직 안의 활동이다. 두 용어는 "가치사슬"로 줄여 쓰지 않고 항상 수식어를 붙여 쓴다. 주체가 산업 가치사슬의 어느 단계에서 사업하는지는 기관현황의 사업 범위로 적고, 그 단계의 시장 구조는 미시환경에서 다룬다.

| 5 | 시사점 | 모은 팩트가 주체에게 무엇을 뜻하는가 | 출처 단계별 시사점 | SKILL.md, references/writing.md |

자료 수집과 출처 검증은 references/sources.md를, 보고서 작성은 references/writing.md를 모든 모듈에 공통으로 적용한다.

실행하는 모듈은 표의 순서대로 배치한다. 넓은 외부 변화에서 주체 내부로 좁혀 들어가야 뒤 모듈이 앞 모듈의 팩트를 근거로 받을 수 있다. 중간 모듈을 건너뛰는 구성은 허용한다. 거시환경에서 바로 내부현황으로 가는 구성도 순서만 지키면 된다.

## 요청을 모듈로 옮기기

| 요청 예 | 실행 범위 |
|---|---|
| 정책동향 정리 | 거시환경의 정책 범주 |
| 기술동향, 논문과 특허 동향 | 거시환경의 기술 범주 |
| 규제 현황 | 거시환경의 제도와 규제 범주 |
| 시장 규모와 전망 | 미시환경의 시장 범주 |
| 경쟁구조, 5-Forces | 미시환경의 경쟁 범주, references/five-forces.md 절차 |
| 주요 기업 현황 | 미시환경의 경쟁 범주 중 주요 플레이어 |
| R&D 투자 동향, 국가 연구개발 과제 분석, 벤처 투자 동향 | 미시환경의 투자 범주. 지역 주체면 지역 안 과제와 기업 연구개발비는 내부현황 |
| 산업 가치사슬, 밸류체인 구조 | 미시환경의 산업 가치사슬 범주 |
| 내부역량 진단, VRIO, SPROC | 내부현황의 조직 주체 |
| 조직 가치사슬, 조직 내부 활동 분석 | 내부현황의 조직 주체, 조직 가치사슬 틀 |
| 지역 혁신자원 조사, 지역 산업 여건 | 내부현황의 지역 주체 |
| 해외 선진사례, 타 지역 사례 | 벤치마킹 |
| 대내외 환경분석 | 목적별 기본 구성에서 고른 모듈 조합 |
| 지역 R&BD 진단 | 지역 주체 기본 구성 전체 |
| 기존 자료로 시사점만 정리 | 제출 자료를 팩트로 등록한 뒤 시사점 모듈 |
| 기존 환경분석 보고서 점검 | 기존 분석 점검 |

한 모듈 안에서도 요청한 범주만 실행한다. 정책동향만 요청받으면 기술, 경제, 사회 범주는 만들지 않는다.

### 목적별 기본 구성

사용자가 모듈을 지정하지 않고 목적만 말하면 아래 구성을 기본값으로 제안한다.

| 목적 | 기본 모듈 |
|---|---|
| 동향 파악 | 거시환경, 필요하면 미시환경 |
| 현황 진단 | 거시환경, 미시환경, 내부현황 |
| 전략수립 준비 | 거시환경, 미시환경, 내부현황, 벤치마킹 |
| 연구개발 기획 준비 | 거시환경의 정책과 기술, 미시환경의 시장과 투자 |

### 주체 유형별 기본 범주

| 주체 유형 | 거시환경 | 미시환경 | 내부현황 | 벤치마킹 |
|---|---|---|---|---|
| 조직 | 주제와 관련된 범주만 선택 | 시장, 경쟁, 고객 | 기관현황, 역량 진단 | 경쟁 조직, 선도 조직 |
| 지역 | 해외와 국가의 정책, 기술 | 시장, 산업 가치사슬, 경쟁구조 | 지역 혁신자원 | 해외 사례, 타 지역 사례 |
| 산업 기술 영역 | 정책, 제도와 규제, 기술 | 시장, 산업 가치사슬, 경쟁구조, 투자 | 주체 조직을 지정한 경우에만 조직 유형으로 실행 | 선도 국가와 선도 기업 사례 |

정책 사업이나 프로그램을 분석할 때는 그 사업을 운영하는 조직을 주체로 두고 조직 유형을 적용한다.

## 작업 흐름

### 1단계 범위 설정

아래 항목을 정한다.

| 항목 | 내용 | 기본값 |
|---|---|---|
| 주체 유형과 주체 | 조직, 지역, 산업 기술 영역 중 하나와 구체 명칭 | 없음. 비어 있으면 질문 |
| 주제 | 분석할 산업, 기술, 제품, 서비스, 정책 분야 | 없음. 비어 있으면 질문 |
| 공간 범위 | 글로벌, 국가, 지역 | 글로벌과 국가. 지역 주체면 지역 추가 |
| 시간 범위 | 현황 기간과 전망 기간 | 현황은 최근 5개년, 전망은 5년 |
| 목적과 활용처 | 내부 검토, 외부 제출, 후속 분석 입력 등 | 요청 문구에서 추정한 값을 제안. 단서가 없으면 내부 검토 |
| 실행 모듈과 범주 | 요청 대응표와 기본 구성에서 선택 | 요청 대응표 결과 |
| 검증 강도 | 1-3단계 | references/sources.md의 선택 기준 결과 |
| 산출 형식 | 개조식 마크다운 보고서, 테이블, 파일 형식, 출력 언어 | 사용자의 언어로 쓴 개조식 마크다운 보고서 |

요청에 없는 항목은 기본값으로 채워 범위안을 만들고 한 번에 확인받는다. 질문을 여러 번 나누면 사용자 부담이 커지기 때문이다. 주체나 주제가 비어 있으면 분석을 시작할 수 없으므로 그 항목만 묻는다. 5-Forces를 실행하면 산업 정의, 산업 가치사슬 분해, 지리적 범위, 시간적 범위를 같은 확인에 포함한다. 사용자가 확인 없이 진행하라고 하면 기본값으로 진행하고 적용한 범위를 보고서의 분석 범위 절에 적는다.

범위가 확정되면 끝까지 자율로 진행한다. 이후 사용자에게 묻는 경우는 검증 강도 2단계 이상의 확인 절차, 사내 자료 접근 요청, 구조가 복잡한 DB의 조회 조건 확인, 내부 자료 확인 목록뿐이다.

주제가 산업이나 기술이면 보고서 첫머리의 분석 범위 절에 대상 개요를 쓴다. 한 범주만 다루는 부분 분석은 사용자가 원할 때만 쓴다. 대상 개요는 주제의 정의와 포함 및 제외 범위(What), 작동 원리나 구현 방식(How), 출처로 확인되는 중요성(Why)으로 구성한다. 인접 산업이나 유관 기술을 분석 대상에 포함할지 대체재로 볼지도 여기서 정한다. 대상 개요 역시 출처가 있는 팩트로만 쓴다.

### 2단계 자료 경로 확인

작업 전에 연결된 커넥터, API, DB 접근 권한을 확인한다. 내부현황 모듈이나 유료 투자 DB, 국가 연구개발 DB 추출본, 사내 통계처럼 공개 웹에 없는 자료가 필요하면 필요한 자료 목록을 한 번에 요청한다. 받지 못한 자료를 웹 검색 결과로 짐작해 채우지 않고 미확인으로 남긴다. 구조가 복잡한 DB는 사용자와 조회 조건을 확인하며 탐색한다. 경로별 규칙과 DB 탐색 절차는 references/sources.md를 따른다.

### 3단계 수집과 팩트 대장

수집을 시작하기 전에 모듈마다 확인할 질문을 정한다. 질문을 뒷받침하는 자료와 함께 질문과 어긋나는 자료도 찾는다. 한쪽 자료만 모으면 결론이 처음 짐작한 방향으로 기운다.

모은 사실을 팩트 대장에 한 줄씩 기록한다.

| 필드 | 내용 |
|---|---|
| ID | 거시-01, 미시-01, 내부-01, 벤치-01 형식. 시사점은 시사-01 |
| 모듈과 범주 | 예: 거시환경 정책 |
| 팩트 진술 | 한 문장에 한 사실 |
| 수치와 단위 | 수치가 있으면 기재 |
| 기준 시점 | 자료가 가리키는 연도나 날짜 |
| 출처 | references/writing.md의 출처 표기 형식 |
| 자료 경로 | 웹, 제출 파일, 연결 시스템 |
| 확인 상태 | 확인, 사용자 승인, 미확인 |

두 사실이 섞인 문장은 나눠서 기록한다. 테이블로 정리하는 목록(정책 목록, 기업 목록, 시설 목록 등)은 테이블 하나를 한 묶음의 팩트로 보고 ID 하나를 준다. 사용자가 이전 팩트 대장이나 분석 결과를 주면 기존 ID를 유지하고 새 팩트만 이어서 붙인다.

### 4단계 검증

선택한 검증 강도의 절차를 적용하고 자료 경로별 품질 기준으로 인용할 출처를 고른다. 모든 수치는 코드로 검산한다. 세부 절차는 references/sources.md를 따른다.

### 5단계 모듈 분석

모듈별 참조 파일의 절차대로 분석한다. 모듈 본문에는 팩트와 절차가 정한 판정만 쓴다.

## 시사점 규칙

시사점은 분석을 마무리하는 귀납 결론이다. 후속 단계가 있으면 그 단계의 입력값이 된다.

- (귀납) 하나 이상의 팩트나 판정에서 공통된 의미를 뽑아 한 문장으로 쓰고 끝에 근거 팩트 ID를 괄호로 단다. 판정에서 나온 시사점에는 그 판정이 기댄 팩트의 ID를 단다
- (출처 단계 묶음) 거시환경, 미시환경, 내부현황, 벤치마킹 단계별로 묶는다. 거시와 미시에서 나온 시사점은 외부 요인 성격, 내부현황에서 나온 시사점은 내부 요인 성격을 띤다. 벤치마킹에서 나온 시사점은 비교 결과에 따라 어느 성격이든 될 수 있다. 이 구분은 후속 단계에서 외부 요인과 내부 요인을 섞지 않게 한다
- (처방 제외) 시사점은 주체에게 주는 의미를 서술한다. 기회가 되는 조건, 위험이 되는 조건, 격차, 전제 조건이 해당한다. 해야 할 행동은 적지 않는다
- (SWOT 미분류) 강점, 약점, 기회, 위협 라벨을 붙이지 않는다
- (반영 완전성) 보고서에 실은 모든 팩트는 최소 한 개 시사점에 반영한다. 어떤 시사점에도 쓰이지 않는 팩트는 주제와의 관련이 약하므로 보고서 본문에서 제외한다
- (부분 실행) 실행한 모듈의 시사점만 쓴다. 사용자가 팩트 정리만 원하면 시사점을 생략한다

## 기존 분석 점검

사용자가 이미 작성된 환경분석 자료의 검토를 요청하면 새로 분석하지 않고 아래 항목을 점검한다.

| 점검 항목 | 기준 |
|---|---|
| 배치 순서 | 거시환경, 미시환경, 내부현황, 벤치마킹, 시사점 순서가 뒤바뀌지 않았는가 |
| 연결 | 뒤 절의 내용이 앞 절의 팩트와 이어지는가. 앞뒤와 연결되지 않은 고립 항목이 있는가 |
| 분석과 처방의 경계 | 분석 절에 To-be, 해결 방안, 전략이 먼저 나오지 않았는가 |
| 시사점 연결 | 시사점마다 근거 팩트가 있고 모든 팩트가 시사점에 반영되었는가 |
| 구조 | 결론이 앞에 있고, 상하위 불릿이 결론과 근거 관계이며, 같은 층위의 항목이 한 기준으로 묶였는가 |
| 분류 | 항목끼리 겹치거나 빠진 영역이 없고 한 층위의 항목이 4개 이하인가 |
| 출처 | references/sources.md의 품질 기준을 통과하는 출처인가. 언론 보도는 원출처를 추적했는가 |
| 수치 | 출처와 기준 시점이 있고 코드 검산 결과와 일치하는가 |
| 문장 | references/writing.md의 작성 점검을 통과하는가 |

- 점검 결과는 항목별 통과와 미통과, 미통과 항목의 위치와 개선 방향으로 보고한다. 순서 재배치가 필요하면 재배치 안을 함께 낸다
- 저품질 출처는 고품질 출처로 바꾸고, 대체 출처가 없으면 그 출처에만 기댄 주장을 삭제 대상으로 표시한다
- 점검 보고는 분석 대상 자료에 대한 평가이므로 문제를 구체적으로 지적한다. 지적은 구조를 직접 서술하는 문장으로 쓴다. 예를 들어 "결론이 절 첫머리에 없음"처럼 쓰고 사고 도구의 이름은 붙이지 않는다
- 사용자가 수정본을 원하면 점검 결과를 반영한 수정본을 함께 낸다

## 후속 분석 전달

사용자가 결과를 SWOT, 갭분석, 전략수립, 연구주제 발굴 같은 후속 작업에 넘기려 하면 출처 단계별 시사점과 팩트 대장을 함께 전달한다. 후속 작업은 시사점의 출처 단계를 보고 외부 요인과 내부 요인을 나눌 수 있다.

## 중간 산출물

파일을 저장할 수 있는 환경이면 범위안, 팩트 대장, 모듈별 초안, 최종 보고서를 별도 파일로 남긴다. 세션이 끊겨도 이어서 작업할 수 있고 제3자가 과정을 추적할 수 있기 때문이다. 파일 저장이 불가능하면 같은 구조를 응답 안에 유지한다.

## 최종 점검

- 실행한 모듈이 요청 범위와 일치하는가
- 모듈 순서가 거시환경, 미시환경, 내부현황, 벤치마킹, 시사점 순인가
- 모든 팩트에 ID, 출처, 기준 시점이 있는가
- 모델 기억으로 채운 사실이나 출처 없는 수치가 없는가
- 모든 수치를 코드로 계산하거나 검산했는가
- 모듈 본문에 해석, To-be, 해결 방안이 섞이지 않았는가
- 거시, 미시, 내부 분류가 주체의 통제 가능성 기준과 맞는가
- 각 모듈의 내용이 앞 모듈의 팩트와 이어지고 고립 항목이 없는가
- 모든 시사점에 근거 팩트 ID가 있고 모든 팩트가 시사점에 반영되었는가
- SWOT 라벨, 전략, 과제, 지원 필요 영역이 산출물에 없는가
- 선택한 검증 강도의 확인 절차를 거쳤는가
- 사내 자료의 개인정보와 기밀 정보가 산출물에 노출되지 않았는가
- references/writing.md의 작성 점검을 통과했는가
