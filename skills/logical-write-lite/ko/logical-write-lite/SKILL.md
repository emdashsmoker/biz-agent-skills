# logical-write-lite

마크다운 계위로 한국어 개조식 글을 쓰고 고치는 스킬이다. 결론을 먼저 세우고, 근거를 한 가지 기준으로 묶고, 한 문장에 메시지 하나만 담는다. 보고서, 기획서, 제안서, 분석 메모처럼 독자가 읽고 판단을 내려야 하는 글에 쓴다.

## 1. 작동 방식

### 작업 유형
| 유형 | 요청 예 | 산출 |
|------|---------|------|
| 작성 | 새 글을 써 달라는 요청 | 완성된 글만 출력 |
| 교정 | 기존 글을 고쳐 달라는 요청 | 고친 글을 먼저 출력하고 그 아래에 고친 유형과 대표 위치를 3줄 안팎으로 요약. "교정했습니다" 같은 완료 보고 문장은 쓰지 않음 |
| 진단 | 구조나 논리를 검토해 달라는 요청 | 17장 점검표 항목별 통과 여부, 문제 위치, 개선 방향 (고친 글은 요청할 때만) |

### 단문 모드와 흐름 모드
두 모드는 연결어와 종속절을 허용하는지만 다르다. 나머지 규칙은 모두 같다.
- 기본값은 단문 모드다. 절을 연결어로 잇지 않고 문장을 나눈다 (8장).
- 사용자가 "흐름 있게", "서사적으로", "연결되게", "스토리라인 있게", "이야기처럼 풀어서"처럼 흐름을 요청하면 흐름 모드로 쓴다 (9장).
- 사용자가 "단문으로", "끊어서", "엄격한 개조식으로"를 요청하면 단문 모드로 돌아간다.
- 정해진 모드는 사용자가 바꾸라고 할 때까지 같은 대화에서 유지한다. 모드를 따로 묻지 않는다.

### 우선순위와 비노출
- 사용자가 직접 지정한 형식, 골격, 분류 기준, 순서, 용어는 이 스킬보다 우선한다. 지정 내용에 구조 결함이 보이면 지정을 따르되 결함을 한 줄로 알린다.
- 이 스킬의 규칙은 글을 쓰는 동안 안에서만 작동한다. 산출물에는 규칙 이름, 프레임워크 이름(SCQA, MECE, 5W1H 등), 규칙을 적용했다는 사실, 자기 글에 대한 평가를 쓰지 않는다.
- 진단 보고에서도 프레임워크 이름 대신 현상을 적는다. 예: "결론이 글 첫머리에 없음"

## 2. 용어
| 용어 | 이 스킬에서의 뜻 |
|------|-----------------|
| 단위 | 독자가 한 번에 보고 소화하는 구획. 문단 1개, 불렛 묶음 1개, 표 1개, 슬라이드 1장, 차트 1개 |
| 메시지 | 단위에서 독자가 기억해야 할 판단문 1개. 주어와 서술을 갖춘 주장 |
| 계위 | 마크다운 기호로 표시하는 글의 층. 제목(#), 섹션(##), 불렛(-), 하위 불렛(+) |
| 그룹 | 같은 상위 항목 아래 같은 층에 놓인 항목 묶음 |
| 소제목 | 불렛 문장 앞에 괄호로 붙이는 짧은 이름. 예: (투자 구조 개편) |
| 연결어 | 두 절이나 두 문장을 잇는 말. 그리고, 그러나, 이는, -으며 등 |
| 종속절 | 핵심 절에 붙어 원인, 조건, 범위, 수단을 더하는 절 |
| 5W1H 요소 | 누가, 언제, 어디서, 무엇을, 왜, 어떻게 |
| 근거 | 주장이 맞다고 볼 이유가 되는 사실, 자료, 추론 |
| 정량 데이터 | 수치, 비율, 금액, 건수처럼 숫자로 표현한 사실 |

## 3. 쓰기 전 사고 순서
문장을 쓰기 전에 아래 순서로 생각한다. 큰 단위에서 작은 단위로 내려간다.
1. (요청 이유) 사용자가 이 글을 왜 요청했는지, 독자는 누구이고 글을 읽은 뒤 어떤 판단을 내려야 하는지 추론한다. 요청 문장의 글자 그대로에 머물지 않는다.
2. (정의, 기준, 범위) 핵심 용어의 정의, 판단 기준, 다룰 범위를 정한다. 한 번 정한 정의와 기준은 글 끝까지 바꾸거나 섞지 않는다.
3. (전제 의심) 제1원칙 사고로 접근한다. 사용자 요청, 자기 지식, 통념, 권위, 유명 프레임워크, 유행어를 그대로 받아들이지 않고 사실인지 확인한다. 문제는 "왜"를 반복해 더 거슬러 올라갈 수 없는 원인까지 추적한다.
4. (결론) 글 전체의 결론을 한 문장으로 정한다.
5. (골격과 헤더) 4장에서 골격을 고르고 헤더명을 먼저 짓는다. 헤더만 읽어도 흐름이 보여야 한다.
6. (단위와 요소) 단위마다 메시지 1개를 정하고 메시지를 받치는 요소를 고른다 (5장).
7. (문장) 6장부터 16장까지의 규칙으로 쓴다.
8. (점검) 17장 점검표로 확인하고 헤더명을 한 번 더 살핀다.

생각하는 동안 아래 사고를 피한다.
- 현장 사실과 동떨어진 기계적 사고. 검증되지 않은 가정 위에 형식만 정교하게 쌓은 모형, 선도 사례의 겉모양만 옮긴 모방, 성과보다 형식 갖추기에 머무는 방어 논리가 여기에 든다.
- 비용 숫자만 세는 관점과 과장된 홍보 관점.
- 뜻 없는 말장난. 제3자가 읽고 타당하다고 납득하도록 설명할 수 있어야 글이 의미를 가진다.

## 4. 글 전체 골격

### 결론을 먼저 둔다
- 글 전체의 결론은 문서 제목이나 첫 섹션에 압축해 둔다. 첫 섹션을 주제 소개나 자료 안내로 채우지 않는다.
- 상황 서술로 시작하는 골격(SCQA, SCR)은 결론을 문서 제목에 명제로 둔다. 예: `# 공급망 거점 분산 필요`
- 각 섹션의 첫 문장에 그 섹션의 결론을 둔다. 결론을 끝까지 미뤄 독자에게 추론을 맡기지 않는다.

### 골격을 하나 고른다
글의 목적에 맞는 골격 하나를 고르고 한 글 안에서 섞지 않는다. 사용자가 골격을 지정하면 그대로 따르고, 요청과 자료로 목적을 추론할 수 없을 때만 사용자에게 목적을 묻는다.

| 골격 | 흐름 | 맞는 글 |
|------|------|---------|
| SCQA | 상황, 전개(상황을 흔든 변화), 질문, 답 | 의사결정자에게 답을 주는 분석 보고 |
| WWH | 왜 필요한가, 무엇을 하는가, 어떻게 하는가 | 행동을 요청하는 제안과 권고 |
| SCR | 상황, 문제 또는 변화, 해결 방향 | 진단 후 개선안, 환경분석이나 내부진단 후 시사점과 전망 |

### 환경분석에서 전략까지 다루는 글
외부 환경에서 출발해 조직 내부로 좁혀 들어간 뒤 전략과 실행으로 나아가는 순서로 섹션을 놓는다. SCR 골격을 구체화한 형태로 본다. 분석 단계와 시사점이 상황과 문제를 맡고 전략과 이행계획이 해결을 맡는다.

| 순서 | 단계 | 다루는 내용 |
|------|------|-------------|
| 1 | 거시환경 | 대상 조직이 통제할 수 없는 외부 변화와 추세. 정책, 경제, 사회, 기술, 환경, 법제도 중 주제에 필요한 항목 |
| 2 | 미시환경 | 대상 조직과 서로 영향을 주고받는 산업, 시장, 경쟁, 고객, 공급망 |
| 3 | 내부현황 | 대상 조직의 역량, 자원, 운영 상태 |
| 4 | 벤치마킹 | 유사 조직과 선행 사례의 경험 |
| 5 | 전략수립 | 방향, 목표, 전략 대안 |
| 6 | 이행계획 | 과제, 일정, 자원 배분 |

- 단계는 목적에 맞게 고른다. 동향 파악은 1단계(필요하면 2단계 추가), 현황 진단은 1-3단계, 방향 제시는 1-3단계와 5단계, 전략 수립은 1-6단계 전부를 쓴다.
- 고른 단계는 표의 순서를 지킨다. 중간 단계를 건너뛰는 구성은 괜찮고 순서를 뒤집는 구성은 쓰지 않는다.
- 분석 단계(1-4)는 사실만 쓴다. 해석과 전망은 시사점에, 해결책과 지향하는 모습은 전략 단계에 쓴다. 전략 단계에서는 분석을 다시 늘어놓지 않는다.
- 대상 조직이 영향을 줄 수 없는 환경은 거시, 서로 영향을 주고받는 환경은 미시로 나눈다. 분류 항목과 배치 순서는 주제에 맞게 고르고 틀을 채우려고 무관한 항목을 나열하지 않는다. 틀마다 순서도 다르다 (PEST는 정치, 경제, 사회, 기술 순, STEEP는 사회, 기술, 경제, 환경, 정치 순).
- 내부현황은 강점과 약점을 함께 쓰고 미시환경에서 찾은 산업 요건과 내부 역량의 차이가 드러나게 쓴다. 연혁, 조직도, 예산, 인력 같은 조직 소개는 환경분석 앞에 둘 수 있고 역량 진단은 환경분석 뒤에 둔다.
- 벤치마킹은 대상을 고른 이유, 대상 조직과의 유사점과 차이점, 성공 요인과 실패 요인을 함께 쓰고 앞 단계 진단과 이어지는 시사점을 낸다.
- 전략의 근거는 앞 단계 분석에서만 가져오고 도출 도구는 목적에 맞게 고른다. 이행 과제는 전략에서 파생하며 전략과 무관한 과제는 넣지 않는다.
- 시사점은 분석한 사실을 귀납해 뜻을 압축한 문장이다. 단계마다 끝에 두거나 분석 뒤에 한 섹션으로 모은다. 시사점 없이 분석에서 전략으로 건너뛰지 않는다. 전략 단계가 없는 글에서는 시사점이 결론이다. 거시와 미시에서 나온 시사점은 외부 요인(기회, 위협)으로, 내부현황에서 나온 시사점은 내부 요인(강점, 약점)으로 다룬다.
- 각 단계의 분석은 다음 단계의 초점을 좁힌다. 이행 과제에서 전략, 전략에서 분석, 내부에서 미시, 미시에서 거시로 거슬러 올라가도 근거가 보여야 한다. 근거가 보이지 않는 요소는 근거를 보충하거나 지운다.
- 모든 사실은 시사점 1개 이상에, 전략 단계가 있으면 모든 시사점은 전략 1개 이상에 반영한다. 반영되지 않는 항목은 지운다.
- 해외와 국내를 함께 다루면 분류 항목(예: 정책동향)마다 해외 동향을 먼저 쓰고 국내 동향을 이어 쓴 뒤 둘의 관계(영향, 대응, 격차)를 드러낸다. 섹션 제목에는 "거시환경", "내부현황" 같은 단계 이름 대신 내용을 담은 키워드를 쓴다.

## 5. 단위와 불렛

### 마크다운 계위
```
# 문서 제목
## 섹션 제목
- 주장 (들여쓰기 없음)
    + 주장의 근거나 부연 (4칸 들여쓰기)
> (자료명) 근거 데이터 설명 또는 출처
```

- `+`는 하위 불렛 표시 전용이다. `>`는 데이터, 출처, 용어 설명에만 쓴다.
- 문서가 단독 문서인지 상위 문서의 일부인지에 따라 #, ##, ### 단계는 달라질 수 있다. 층 사이의 상대 관계를 지킨다.
- 위층에서 아래층으로 갈수록 추상도는 낮아지고 구체성은 높아진다.

### 헤더
- 헤더명을 가장 먼저 짓고 헤더 사이의 흐름을 정한다. 산출 직전에 한 번 더 점검한다. 헤더만 읽어도 아래 내용을 알 수 있게 짓는다.
- 헤더 하나에는 주제 하나만 둔다. "정책동향 및 기술동향", "A와 B", "A/B"처럼 두 주제를 묶지 않고 헤더를 나눈다.
- 키워드형(예: 정책동향)과 문장형(예: 공급망 거점 분산 필요) 중 하나를 골라 한 글 안에서 통일한다.
- "개요", "배경", "현황", "결론"처럼 내용과 무관한 일반 라벨을 기계적으로 반복하지 않는다. 사용자가 양식을 지정하면 양식을 따른다.
- 형제 헤더는 같은 패턴으로 짓고 분량과 정보 밀도도 비슷하게 맞춘다. 예: "글로벌 시장 동향"과 "지역별 시장 동향"
- 키워드형 헤더는 대상을 예고하고 첫 문장이 판단을 담는다. 문장형 헤더는 헤더가 메시지를 담고 첫 문장은 근거로 들어간다. 헤더와 첫 문장이 가리키는 대상이 어긋나면 헤더를 고치거나 내용을 옮긴다.

### 단위당 메시지 하나
- 단위마다 메시지는 1개다. 메시지가 2개 이상이면 단위를 나눈다.
- 메시지는 판단문이다. "시장 현황", "추진 배경" 같은 주제 라벨은 메시지로 보지 않는다.
- 판별 질문은 "이 단위를 본 독자가 기억할 한 문장은 무엇인가"이다. 답이 없으면 메시지가 없는 상태이고 독립 주장 2개가 이어지면 메시지가 넘치는 상태다.
- 메시지는 단위의 머리에 둔다. 불렛 묶음은 상위 불렛, 문단은 첫 문장, 표와 차트는 제목, 슬라이드는 헤드메시지가 메시지를 맡는다.
- 단위 안은 메시지, 지지 요소, 세부의 3층으로 비중을 나누고 강조 지점은 1곳으로 정한다. 모든 요소가 같은 비중이면 다시 배치한다. 차트와 슬라이드는 강조 대상 1개만 크기, 위치, 색으로 부각하고 데이터 레이블은 메시지와 관련된 지점에만 붙인다.

### 요소 고르기
- 메시지를 받치는 요소는 단위당 3-4개 이하를 기본으로 한다. 요소끼리 겹치지 않고 메시지의 다른 부분을 나눠 맡는다. 사람이 한 번에 붙잡아 두는 정보 덩어리는 대략 3-5개로 보고되며 3-4개 기본값은 이 범위 안에 머물기 위한 기준이다.
- 2개로 충분하면 2개로 둔다. 개수를 채우려고 늘리지 않는다. 4분면, 5단계처럼 개수가 정해진 틀은 그 개수를 따른다.
- 5개 이상이 필요해 보이면 메시지가 섞였는지 보고 단위를 나눈다. 그다음 상위 범주 3-4개로 묶어 세부를 아래층으로 내린다. 그래도 남으면 메시지를 받치지 않는 항목을 지운다.
- 압축은 요소를 골라 버리는 방식으로 한다. 요소 수를 그대로 두고 문장만 줄이면 읽는 부담이 그대로 남는다. 남긴 요소는 충분한 분량으로 쓴다.
- 지우는 순서는 메시지와 무관한 정보, 독자가 이미 아는 배경, 같은 결론을 반복해 받치는 근거, 판단에 기여하지 않는 장식성 수치와 사례 순이다.
- 탈락한 내용은 지우는 쪽이 기본이다. 독립 메시지 가치가 있으면 새 단위로 나누고 참고 가치만 있으면 부록이나 별첨으로 옮긴다. 본문에 이름만 언급하고 설명을 생략하는 처리는 하지 않는다.
- 같은 층 병렬 항목 5개 이상, 한 문단 안 독립 주장 2개 이상, 주제 라벨에 머문 제목, 강조 지점 부재, 원인과 결과나 현상과 대책처럼 성격이 다른 요소의 혼재 중 하나라도 보이면 다시 구성한다.

### 층 사이의 관계
- 상위 메시지는 하위 메시지의 결론이고 하위 메시지는 상위 메시지의 근거다.
- 위에서 아래로는 "왜 그렇게 말할 수 있는가"에, 아래에서 위로는 "그래서 무엇을 뜻하는가"에 답이 되어야 한다. 한쪽으로라도 이어지지 않는 메시지는 옮기거나 지운다.
- 같은 층 메시지는 묶는 방식 하나만 쓴다. 같은 종류의 사실을 모아 공통 결론을 끌어내는 귀납 묶음과 대전제와 소전제로 결론을 끌어내는 연역 묶음을 한 그룹에 섞지 않는다.
- 인접한 문장과 불렛은 앞 내용에 대해 부연, 근거, 사례, 대비, 결론 중 하나의 역할을 한다. 관계없이 사실만 덧붙이는 나열은 쓰지 않는다.

### 하위 불렛과 소제목
- 하위 불렛은 대등한 항목이 2개 이상일 때만 쓴다. 1개만 남으면 상위 문장에 합치거나 별도 상위 불렛으로 올린다. 상위 불렛이 고유 명칭이나 프레임워크이고 하위 불렛 1줄이 그 정의나 범위를 적는 경우는 1개도 괜찮다.
- 하위 불렛 수는 3-4개를 권장한다. 불렛마다 개수가 너무 적거나 많아 리듬이 깨지지 않게 한다.
- 소제목은 괄호로 감싼다. `- (투자 구조 개편) 기초연구 비중 단계적 확대`처럼 쓰고 `소제목 : 내용`, `소제목 - 내용`은 쓰지 않는다.
- 소제목은 내용을 담아 짓는다. (설명), (이유), (주장), (근거), (섹션1) 같은 빈 라벨과 같은 소제목의 반복은 쓰지 않는다.
- 같은 그룹 안 소제목은 같은 분류 기준을 따른다. (정책), (책임 체계), (모니터링)은 모두 정비 분야라서 맞는다. (정책 공백), (검증 체계 부재), (부서 의견 수렴)은 한계, 기반, 활동이 섞여 맞지 않는다.
- 같은 그룹 안에서는 모든 항목에 소제목을 붙이거나 모두 붙이지 않는다. 그룹이 다르면 달라도 된다. 소제목은 필요한 그룹에만 붙인다.

### 표와 구성
- 표는 글 전체에서 3개 이하로 쓴다. 표가 많으면 어느 표가 중요한지 흐려진다. 글이 길어지면 표로 요지를 정리한다.
- 주장 뒤에 표를 둔다. 표 바로 뒤에 표를 두지 않는다. 주장, 표, 주장, 표의 교차 배치는 괜찮다.
- 표를 `>` 블록이나 코드 블록 안에 넣지 않는다. 행, 열, 셀 문구는 한 가지 기준으로 나눠 겹침과 빠짐이 없게 한다.
- 섹션은 따로 떼어도 읽히고 다른 섹션과 붙여도 어긋나지 않게 쓴다. 수정과 삭제가 쉬운 구조를 우선하고 문단 수는 겹침 없이 최소로 한다.

## 6. 분류
분류, 묶기, 목차 짜기에 모두 적용한다. 순위나 목록처럼 단순 나열을 요청받은 경우는 이 장을 강제하지 않는다.
- 분류 전에 다음 질문에 답한다. 이 분류로 어떤 판단을 내리는가, 대상 범위는 어디까지인가, 기준이 한 차원인가, 범위 안 모든 사례가 빠짐없이 들어가는가.
- 한 분류의 기준은 한 차원이다. 기술별, 산업별, 시급성별 항목을 같은 층에 섞지 않는다. 기준이 여럿이면 1차 분류와 2차 분류로 나눈다. 축은 시간, 절차, 구조, 인과 중 목적에 맞는 하나를 고른다.
- 한 사례가 두 항목에 동시에 들어가는지 반례를 찾아본다. 겹치면 경계를 다시 긋거나 상위 범주로 합친다. 겹침이 불가피하면 분류 대신 속성(태그)으로 다루고 그렇게 밝힌다.
- 어느 항목에도 들지 않는 사례가 있는지 찾아본다. "기타"를 쓰면 기타의 비중이 주요 항목보다 작아야 하고 크면 기준을 다시 짠다.
- 같은 층 항목은 3-4개를 권장하고 5개 이상이면 중간 층이 빠졌는지 본다. 2개면 두 선택지로 나누는 방식이 맞는지(거짓 양자택일) 확인한다. 생물 분류, 산업분류 코드, 법령 조항처럼 체계가 정해진 분류는 항목이 많아도 결함으로 보지 않는다.
- 상하 관계는 종류를 구별해 한 층에 섞지 않는다. 일종 관계(전기차는 자동차의 일종), 부분 관계(배터리는 전기차의 부분), 속성 관계(예산은 프로젝트의 속성)다. 일종 관계라면 상위 개념의 속성이 하위 개념에서도 성립해야 한다.
- 계층은 3층 이내를 권장하고 4층 이상이면 중간 층이 정말 필요한지 다시 본다. 행정구역처럼 원래 깊은 체계는 예외다.
- 다른 항목과 아무 관계가 없는 항목은 소속을 다시 본다. 신규 영역이나 예외처럼 고립이 정당하면 사유를 밝힌다. 사례가 하나도 없는 범주는 지우고 앞으로 채워질 근거가 있으면 근거를 적는다.
- 기존 분류에 항목을 더할 때는 기존 항목과의 관계(상위, 하위, 병렬, 의존, 선후)를 밝힌다. 단기, 중기, 장기 분류에 "긴급"을 더하는 경우처럼 새 항목이 다른 축에 속하면 별도 축으로 나누거나 기존 항목의 속성으로 붙인다.
- 차트 그리기 편하다거나 특정 틀에 넣기 쉽다는 이유로 현실의 분류를 바꾸지 않는다. 현실 구조를 먼저 파악한 뒤 표현 방식을 정하고 사실과 판단을 한 분류에 섞지 않는다.

## 7. 문장 공통 규칙
아래 규칙은 단문 모드와 흐름 모드에 똑같이 적용한다.

### 한 문장 한 메시지
- 한 문장에는 메시지 1개만 담는다. 독립된 내용 2개는 두 문장이나 두 불렛으로 나눈다.
- 한 문장 안에서 5W1H 각 요소는 1번만 나온다. 같은 요소가 2번 나오면 메시지 2개가 섞였다는 신호다. 문장에는 되도록 왜, 무엇을, 어떻게가 모두 들어가게 한다.
- 판정은 이 순서로 한다. 문장의 5W1H 요소를 찾는다. 같은 요소가 2번 이상 나오는지 본다. 2번 이상이면 요소 경계에서 문장을 나눈다. 나눈 문장마다 왜, 무엇을, 어떻게가 있는지 다시 본다.
- 문장을 나누더라도 각 문장에 필요한 5W1H 정보는 빠뜨리지 않는다. 단어 두세 개로 끝나는 조각 문장은 쓰지 않는다.

```
(고치기 전) 정부는 연구개발 예산을 확대하고 평가 제도를 개편하여 연구 환경을 개선하고 성과를 높임
(고친 뒤)
- 정부는 연구개발 예산을 단계적으로 확대하여 연구 환경 개선 추진
- 정부는 성과 평가 제도를 개편하여 연구 성과 제고 도모
```

### 종결과 표기
- 문장은 명사형으로 끝낸다. 예: -임, -함, -필요, -전망, -예정, -확인, -추진
- 동사형 종결(-한다, -된다)과 존댓말(-합니다, -입니다)은 쓰지 않는다. 인용문, 법령 원문, 정의 원문은 원래 형태를 유지한다.
- 명사형 종결은 자연스럽게 쓴다. "달성할 필요", "접근할 필요", "내장시킬 필요"처럼 관형형을 남기지 않고 "달성 필요", "접근 필요", "내장 필요"로 쓴다. "목차명에는 키워드 기반 재구성으로 반영"처럼 뭉친 문장은 "목차명은 키워드 기반으로 재구성"처럼 푼다. "삭제할 파일"처럼 동사가 대상을 한정하는 관형형은 남긴다.
- "구조", "우선", "결론", "-것", "-곳"처럼 문장 끝을 어색하게 봉합하는 말로 끝내지 않는다.
- 명사만 이어 붙인 문장을 쓰지 않는다. "디지털 산업 집적 지표"는 "디지털 산업의 집적도"로, "온전 세트"는 "온전한 세트"로 조사와 어미를 살려 쓴다.
- 조사 탈락, 주어와 서술어의 호응 깨짐, 수식 대상이 모호한 비문을 쓰지 않는다.
- 문장 끝 마침표는 쓰지 않는다. 명사로 끝나는 문장의 마침표는 한글 맞춤법 문장 부호 규정에서 생략을 허용한다.
- 물결표(`~`)는 마크다운에서 취소선으로 렌더링될 수 있어 쓰지 않는다. 범위는 하이픈으로 적는다. 예: 3-5년
- 숫자에는 천 단위 쉼표와 단위를 붙인다. 예: 1,000,000 또는 100만. 기호는 한글 자판으로 입력할 수 있는 범위에서 쓴다.

### 리듬
- 소리 내어 읽었을 때 어색하지 않게 쓴다. 문장 길이, 하위 불렛 수, 주어, 서술어, 종결어가 기계적으로 반복되지 않게 하고 인접한 문장 3개 이상이 같은 구조면 하나를 바꾼다.

## 8. 단문 모드
기본 모드다. 연결어는 한 문장에 5W1H 요소를 두 번 넣는 통로가 되기 쉬워서 쓰지 않고 문장을 나눈다.
- 그리고, 그러나, 그래서, 그렇기 때문에, 이는, -으며, -있으며, -이며 같은 연결어는 쓰지 않는다. 문장을 나누거나 명사형으로 다시 짠다.
- 수단이나 원인을 나타내는 "-하여", "-으로"는 한 문장 안에서 어떻게나 왜가 1번만 나오는 범위에서 쓸 수 있다.
- 쉼표는 같은 범주 3개 이상을 나열할 때만 쓴다. 대등한 명사 2개는 쉼표나 '와', '과' 대신 "A 및 B"로 잇는다(예: "예산과 인력 확보"는 "예산 및 인력 확보"). 비교 대상이나 협력 상대를 나타내는 '와', '과'는 그대로 둔다. 문장 연결, 삽입구, 부연을 위한 쉼표는 쓰지 않는다.
- 쉼표를 지우기만 하고 문장을 그대로 두지 않는다. "정부는 예산을 확대하였고, 이에 따라 연구 환경이 개선됨"은 "정부는 연구개발 예산을 단계적으로 확대"와 "예산 확대에 따른 연구 환경 개선 기대"로 나눈다.
- 3개 이상 나열의 쉼표는 반드시 남긴다. "공공 산업 연구 부문"처럼 띄어쓰기로만 나열하지 않고 "공공, 산업, 연구 부문"으로 쓴다.

## 9. 흐름 모드
사용자가 흐름 있는 서술을 요청할 때 쓴다. 단문 모드의 연결어 제한만 풀고 다른 규칙은 그대로 지킨다. 흐름은 연결어의 양보다 불렛 배치 순서와 인과 논리에서 생긴다.
- 종속절은 핵심 메시지를 보강하는 역할로만 쓴다. 인과(원인이나 결과), 조건(성립 조건), 구체화(범위나 사례), 수단(달성 방식)이 여기에 든다.
- 한 문장의 주어와 서술어 골격은 1개다. 종속절은 이 골격에 매달린다. 절을 붙여도 핵심 주어와 서술어가 흐려지지 않아야 하고 한 호흡에 읽혀야 한다.
- 종속절이 핵심 메시지에 이미 있는 5W1H 요소를 한 번 더 들여오지 않게 한다. 같은 요소가 둘 필요하면 원인 사슬로 하나로 만들거나 문장을 나눈다. 두 사실이 단순 병렬이면 나눈다.
- 한 문장에 -며, -고, -면서, -으나를 쌓지 않는다. 같은 연결어를 반복하지 않는다. 흐름이 자연스러우면 연결어 없이 끝낸다.
- 쓸 수 있는 연결어는 인과(이에 따라, 따라서, 이를 통해), 부연(또한, 동시에, 아울러), 대비(그러나, 반면, 이와 달리), 시간(최근, 향후, 이후, 기존에는), 지시(이러한, 해당)다. 종속 어미는 -으며, -으나, -함에 따라, -함으로써, -할 경우를 쓸 수 있다.
- 문단 흐름은 목적에 맞게 하나를 고른다. 변화 흐름(기존 상태, 변화 동인, 새 양상, 시사점), 문제 흐름(현황, 한계, 대안, 기대 효과), 확산 흐름(등장, 확산, 적용 사례, 전망)이다.
- 모든 문장을 짧게 끊는 글, 연결어를 모두 지워 인과가 끊긴 글, 독립 메시지 여러 개를 종속절로 묶은 만연체, 서사를 살린다며 쓰는 구어체는 이 모드에서 쓰지 않는다.

```
(원인 2개 병렬) 예산 제약과 인력 공백으로 도입 시점 지연
(원인 사슬로 하나로) 예산 제약으로 인력 확보가 늦어지면서 도입 시점 지연
```

## 10. 논리와 근거

### 주장과 근거
- 모든 주장은 결론과 근거가 짝을 이룬다. 근거 없는 결론 선언과 결론 없는 근거 나열은 쓰지 않는다.
- 근거는 겉으로 드러난 이유에서 멈추지 않고 "왜"를 거듭 물어 근본 원인까지 내려간다.
- 결론의 범위는 근거의 범위를 넘지 않는다. 결론이 너무 좁아 판단에 쓸 수 없으면 근거를 보강한다.
- 입증 책임은 주장하는 쪽에 있다. 주장은 반증할 수 있는 형태로 쓴다. 가설은 자료 수집 전에 세우고 반증 자료가 나오면 고친다.
- 권위를 근거 대신 쓰지 않는다. 기관이나 전문가 이름은 출처 표시일 뿐이고 근거는 그 자료의 내용이다. 인용하는 권위가 해당 분야의 전문성을 가졌는지 확인한다.
- 사실과 판단을 한 문장에 섞지 않는다. 모르는 정보는 모른다고 쓴다.
- 정보가 없다는 사실을 "없다"는 근거로 쓰지 않는다. "확인되지 않음"과 "존재하지 않음"을 구별한다. 대상 전체를 빠짐없이 조사한 범위에서만 "없음"이라고 쓰고 조사 범위를 밝힌다.
- 관계는 유형과 방향을 밝힌다. 인과는 선후와 작동 경로를 확인하고, 상관은 인과로 단정하지 않고, 의존은 어느 쪽이 없으면 다른 쪽이 성립하지 않는지 밝히고, 연관은 관계의 성격을 구체적으로 적는다. "관련이 있다"로 뭉뚱그리지 않는다. 양방향 관계는 방향마다 근거를 따로 들고 필요하면 1:1, 1:N, N:M 여부와 필수 여부도 밝힌다.
- 정의문에 정의 대상 단어를 다시 쓰지 않는다. 상위 개념, 구성요소, 목적, 속성으로 정의한다. "디지털 전환은 디지털 기술로 전환하는 활동"은 순환 정의이고 "기존 업무 절차를 소프트웨어 기반으로 다시 설계해 운영 효율을 높이는 활동"은 순환이 없다.
- 동어반복(개선이 필요하므로 개선 필요), 목적의 정의 반복(예산은 집행하기 위해 편성), 내용 없는 당위(검토가 필요하다고 판단)는 쓰지 않는다. 구체적 근거, 용도, 실행 방안으로 바꾼다.

## 11. 결론 내리기
분석은 방향이 있는 결론으로 끝낸다. 양쪽을 똑같이 늘어놓는 글은 틀릴 위험이나 반대편 독자의 반감을 피하려는 작성자 보호 장치일 뿐 독자의 판단을 돕지 못한다. "양쪽 모두 일리가 있다"는 결론이 비어 있는 상태다. 사용자가 양쪽 입장 정리나 중립 정리를 요청한 경우는 이 장의 결론 강제를 적용하지 않는다.
- 근거의 비중은 질로 판단한다. 근거의 개수, 분량, 인용 횟수, 동의한 사람 수, 권위자 수는 비중을 따질 때 세지 않는다.
- 질은 아래 순서로 평가한다. 위 기준에서 우열이 갈리면 아래 기준의 결과와 관계없이 위 기준을 따른다.

| 순서 | 기준 | 질문 |
|------|------|------|
| 1 | 논리적 건전성 | 전제에서 결론까지 추론에 오류가 없는가 (10장 오류 점검) |
| 2 | 인과 설명력 | 왜 그런지 작동 경로를 구체적으로 설명하는가 |
| 3 | 반례 저항력 | 알려진 반례에 견디는가, 반례를 예외로 치우거나 유리한 사례만 고르지 않았는가 |
| 4 | 방법론 엄밀성 | 표본 설계, 대표성, 기저율 고려가 적절한가 |
| 5 | 범위 적합성 | 근거가 논의 대상의 범위에 맞는가 |

- 반론은 가장 강한 형태로 다시 세운 뒤 평가한다. 핵심 논거를 뺀 약한 반론을 이긴 결론은 믿을 수 없다. 결론을 내린다는 요구가 반론을 줄여도 된다는 허가는 되지 않는다.
- 반론은 결론 아래에 둔다. 반론을 결론과 같은 층에 두면 결론이 흐려진다.

```
- 직원 100명 미만 기업의 신규 업무 시스템은 클라우드 방식이 적합
    + 초기 설비 투자가 작아 자본 여력이 적은 기업의 재무 부담 경감
    + 자체 운영 인력이 부족한 여건에서 운영 위탁이 현실적 대안
    + 데이터 통제 우려는 국내 데이터센터를 쓰는 인증 서비스 선택으로 완화 가능
    + 데이터 보관 위치가 법으로 제한되는 업종은 사내 설비를 함께 쓰는 혼합 구성 검토 필요
```

- 조건부 결론은 결론이다. "현재 근거로는 A가 적합하나 X 조건이 바뀌면 재검토 필요"처럼 쓴다. 방향 없는 유보("상황을 보고 판단")는 쓰지 않는다.
- 근거가 한쪽으로 기울면 서술 분량도 기울어도 된다. 약한 쪽 분량을 억지로 채우지 않는다.
- 결론 자리에 아래 표현을 쓰지 않는다. 결론을 먼저 제시한 뒤 부수 조건으로 쓰는 경우는 괜찮다.
- (부분 동의형) 절반은 맞다, 일리가 있다, 틀린 말은 아니다, 부분적으로 타당하다
- (양쪽 인정형) 각각 장단점이 있다, 양날의 검, 기회이자 위기, 동전의 양면
- (판단 유보형) 상황에 따라 다르다, 단정하기 어렵다, 속단하기 이르다
- (가짜 절충형) 균형 잡힌 접근이 필요, 양쪽 장점을 결합해야, 적절한 균형점
- (마무리 회피형) 종합적 판단 필요, 신중한 접근 필요, 지속적 모니터링 필요, 추가 연구 필요
- (책임 전가형) 독자의 판단에 맡긴다, 각자 상황에 맞게 판단
- 두 입장의 분량과 수식 강도를 일부러 똑같이 맞추거나, 유보 표현을 2번 이상 쓰거나, 근거 없이 두 입장의 중간값을 결론으로 내세우면 결론을 피한 글로 본다.
- 유보는 다음 조건을 모두 갖출 때만 쓴다. 양쪽 근거가 함께 부족함, 어떤 근거가 확보되면 결론이 가능한지 구체적으로 밝힘, 현재 근거가 기운 방향을 제시함.
- 판례가 확립되지 않은 법적 쟁점은 "현행법상 해석이 확립되지 않음"으로 유보할 수 있다. 이때도 다수설과 소수설을 구분해 경향을 밝힌다.
- 선택지 비교를 요청한 사람이 의사결정권자면 권고안을 제시하고 최종 선택은 그 사람에게 있다고 밝힌다.
- 중립은 사실을 중립적으로 인식한다는 뜻이다. 중간 입장을 대변하거나, 허수아비를 세우거나, 비약하고 공격적으로 단정하지 않으면서 결론은 분명히 낸다.

## 12. 정량 데이터와 출처
- 정량 데이터는 조사 주체, 시점, 방법, 산출 근거가 분명할 때만 쓴다. 제3자가 근거를 물으면 5W1H로 답할 수 있어야 한다.

```
- (쓰지 않음) AI 응용 서비스 시장은 연평균 N% 성장 전망
- (씀) A리서치의 2025년 조사에 따르면 AI 응용 서비스 시장은 2024년 B원에서 2030년 C원으로 연평균 약 N% 성장 전망 (기업 매출 합산 방식 추정)
```

- 합계, 비율, 연평균 성장률 같은 계산은 코드나 계산 도구로 하고 원문 수치도 다시 계산해 확인한다. 모델이 암산한 숫자를 쓰지 않는다.
- 핵심 정량 데이터는 글 전체에서 3개 이하로 쓴다. 숫자가 많으면 어느 숫자가 판단에 중요한지 흐려진다.
- 되도록 3-5년 이상의 시계열 자료를 쓰고 연평균 성장률과 전체 대비 비중을 함께 적는다. 통계를 근거로 쓸 때는 표본 크기, 추출 방법, 대표성을 밝힌다.
- 출처는 `> 기관명 또는 저자명(연도), 자료명(링크)` 형식으로 적는다. 출처가 여럿이면 `>` 블록 사이에 빈 줄을 둔다.
- 정량 데이터가 있는 문장 바로 아래나 데이터 묶음 바로 뒤에 출처를 1번 적는다. 정성 인용의 출처는 문단이나 섹션 끝에 둘 수 있다.
- 링크는 자료에 바로 닿는 전체 주소로 적고 도메인만 남기지 않는다.
- 기관명, 자료명, 정책명, 사업명, 제품명, 인명은 원문의 공식 전체 이름을 쓴다. 임의로 줄이거나 바꾸지 않는다. 존재하지 않는 출처를 만들지 않는다.
- 문헌을 소개할 때는 독자가 원문을 따로 찾지 않아도 되도록 요지를 빠뜨리지 않고 담는다.
- 편집과 검증 절차가 있는 1차 자료를 우선 인용한다. 정부와 공공기관 발간물, 공공 연구기관 보고서, 동료평가 논문, 국제기구 통계, 금융기관과 전문 조사기관의 공식 자료가 여기에 든다. 개인 블로그, 위키 본문, 익명 커뮤니티, 출처 없는 집계 사이트, 자동 생성 콘텐츠는 인용하지 않는다. 언론 보도는 보도가 인용한 원출처를 찾아 원출처를 인용한다.

## 13. 어휘

### 전문용어
- 기준 독자는 해당 분야를 전공하지 않은 성인 실무자다. 학교에서 배운 내용의 세부는 대부분 기억하지 못하는 수준으로 본다. 사용자가 독자를 정하면 그 독자에 맞춘다.
- 먼저 기준 독자가 정의 없이 이해하는지 묻는다. 분야를 배워야 아는 말, 일상어와 모양은 같지만 분야에서 다른 뜻인 말(통계의 "유의하다", 금융의 "노출"), 영문 약어는 전문용어로 본다. 쓰는 사람에게 익숙한 말일수록 먼저 의심한다.
- 전문용어는 다음 순서로 처리한다. 결론 전달에 필요 없으면 지운다. 쉬운 말로 바꿔도 뜻이 같으면 바꾼다(마이그레이션은 이전, 페인포인트는 불편 사항). 바꾸면 뜻이 달라지거나 다른 대상과 구별되지 않으면 본문에 그대로 두고 설명 블록을 붙인다.
- 설명 블록은 용어가 처음 나온 항목 바로 뒤에 `> (콜금리) 은행 사이에 하루 단위로 빌려주는 초단기 자금에 붙는 금리`처럼 1줄로 쓴다. 설명 안에 다른 전문용어나 정의 대상 단어를 쓰지 않는다. 블록이 여럿이면 사이에 빈 줄을 둔다. 글 끝 용어집이나 각주로 미루거나 본문 괄호 안에 긴 정의를 끼우지 않는다.
- 정의는 본문과 설명 블록 중 한 곳에서 1번만 한다. 개념 설명 자체가 글의 목적이면 본문이 정의를 맡고 블록을 두지 않는다.
- 영문 약어는 처음 나올 때 전체 이름을 함께 적고 전체 이름도 어려우면 설명 블록을 더한다. 과한 약어, 한국어로 바꿀 수 있는 외래어, 어려운 한자어는 풀어 쓴다.
- 쉬운 말로 바꿀 때 정보를 잃지 않는다. 바꾼 말로 원래 대상을 다른 대상과 구별할 수 있는지 확인한다. "콜금리"를 "은행 금리"로 바꾸면 구별이 안 되므로 설명 블록을 쓴다. 용어에 담긴 수치, 조건, 범위를 빠뜨리지 않는다.
- 쉽게 쓴다는 이유로 어조를 낮추지 않는다. 구어체, 감탄, 이모지, "여러분" 같은 호명, "쉽게 말해" 같은 난이도 해설을 쓰지 않는다. 비유는 개념 구조를 정확히 옮길 때만 쓰고 실제 작동 방식 서술을 함께 둔다.
- 설명 블록이 본문보다 많아지면 용어가 정말 필요한지 다시 본다. 같은 개념은 글 전체에서 한 용어로 통일한다. 고유명사(기관명, 제품명, 정책명, 표준명)는 바꾸지 않고 필요하면 설명 블록으로 처리한다.

### 어휘 선택
어휘는 뜻의 옳고 그름보다 독자가 받아들이기 쉬운지, AI가 쓴 글처럼 보이는지, 격식 문서에 어울리는지로 고른다. 뜻이 같아도 어감이 다르면 다르게 다룬다. 아래 예는 닫힌 목록이 아니며 같은 성격의 말에 같은 기준을 적용한다.

| 구분 | 기준 | 예 |
|------|------|----|
| 선호 | 수용성이 높고 격식 문서에 자연스러움 | 연계, 수립, 확보, 도입, 증대, 도출, 조성, 전환, 설정, 확장, 부합, 개방, 기여, 협력, 보완, 개선, 마련, 반영, 추진, 단계적, 점진적, 단기, 중장기, 전주기, 시사점 |
| 비선호 | AI 글의 표지가 되는 말, 지워도 뜻이 같은 말, 공격적인 말, 단정적인 말, 과장된 말, 직역된 말 | 맥락, 담론, 지형, 함의, 층위, 축, 패러다임, 게임체인저, 인사이트, 딥다이브, 획기적, 혁신적, 압도적, 폭발적, 전례 없는, 진정한, 궁극적, 매우, 상당히, 사실상, 절대, 오직, 유일, 무조건, 즉시, 맞춤형, 차단, 배제, 도태, 선점, 정립, 결, 틀, 매핑, 나아가, 더불어, 뿐만 아니라, 다시 말해, 추가적으로, 갈래, 뽑기(뽑다의 활용형 포함), 통독 |
| 신중 사용 | 쓸 수는 있으나 반복하면 힘이 빠지는 말. 한 문단에 2번 이상 쓰지 않음 | 핵심, 본질, 근본, 체계, 구조, 구축, 고도화, 역량, 리스크, 과제, 영향, 결과, 판단, 검증, 강화, 특히, 즉, 전략적, 효과적, 적극적, 지속적, 생태계, 플랫폼, 로드맵, 시너지, 조사 -으로 |

- "넣다", "빼다", "박다" 같은 구어 동사는 원치 않는 어감을 부를 수 있어 포함, 추가, 제외, 삭제, 명시, 고정으로 바꾼다. "빼앗다", "빼어나다"처럼 원형이 다른 말은 해당하지 않는다.
- 영어권 AI 글에서 흔한 말의 직역도 피한다. 깊이 파고들다(delve), 지형(landscape), 레버리지(leverage), 헤쳐 나가다(navigate), 강조하다(underscore), 다면적(multifaceted), 끊임없이 진화하는(ever-evolving), 총체적(holistic)이 여기에 든다.
- "언어", "번역", "통역"은 실제 언어를 가리킬 때만 쓰고 비유로 쓰지 않는다. AI 기술 자체를 설명할 때 필요한 "맥락" 같은 말은 쓸 수 있으나 빈도를 최소로 한다.
- 인용문, 고유명사, 법률 용어, 기술 표준 명칭, 사용자가 지정한 말은 이 기준에서 뺀다.

### 번역투
| 표현 | 바꾸는 방법 |
|------|------------|
| -에 있어서, -에 대하여, -을 통하여, -로 인하여 | -에서, -에 대해, -을 통해, -로 인해로 줄이거나 원인과 대상을 직접 서술 |
| -의 경우 | 주어를 직접 밝힘 |
| -라고 하는 Y | "-인 Y"로 어순 정리 |
| -인 셈이다, -것은 아닐까, -하는 듯 | 직접 명제로 서술하거나 "-으로 추정" |
| -하지 않으면 안 된다, -할 수밖에 없다 | -필요, -불가피 |
| -적(的), -화(化)의 반복 | 한 문단에 -적 3회, 한 문장에 -화 2회가 넘으면 풀어 씀 |
| 두 축, 세 각, n중 구조, n층 체계 | 분류사를 쓰지 않고 내용을 직접 나열 |

## 14. 표현 패턴
아래 패턴은 지워도 뜻이 그대로이거나 AI가 쓴 글처럼 보이게 한다. 판별 기준은 "지웠을 때 독자가 얻는 정보가 줄어드는가"이다. 목록에 없는 변형도 같은 기준으로 판단한다.

| 패턴 | 예 | 처리 |
|------|----|------|
| 접착제 표현 | 이러한 맥락에서, 이러한 관점에서 볼 때, 시사하는 바가 크다 | 지우고 내용으로 바로 들어감. 시사점은 구체적으로 적음 |
| 상투적 도입 | 필요성이 대두되고 있다, 관심이 높아지고 있다, 시대가 도래하였다 | 구체적 사실로 시작함 |
| 중요성 선언 | 중요한 것은, 주목할 점은, 여기서 핵심은 | 지움 |
| 과잉 수식 | 매우, 탁월한, 획기적인, 폭발적인, 부정할 수 없다, 자명하다 | 지우거나 구체적 근거, 수치, 비교 대상으로 바꿈 |
| 헷지 누적 | 어느 정도 다소 긍정적인 것으로 보임 | 불확실성은 1번만 밝힘 |
| 추상적 재포장 | 비용 절감이라는 목표 하에, 혁신 수단으로서의 AI | "X라는 Y", "X로서의 Y"를 풀고 X를 직접 씀 |
| 선언형 정의 나열 | 본질은 다음 단어 예측, 구조는 트랜스포머 | 독자가 아는 정의는 지우고 분석이나 판단으로 채움 |
| 대비 강조 | 단순한 A가 아니라 B, A가 아닌 진정한 B, A를 넘어 B로 | B를 바로 씀. 이 구문은 쓰지 않음 |
| 자문자답 | 왜 이런 일이 생겼는가? 그것은 | 질문을 지우고 답을 씀 |
| 단편 극적 표현 | 혁신. 바로 그것이다. 빠르다. 정확하다. | 완결된 문장으로 합침 |
| 과대 일반화 | 산업 전체의 패러다임 전환을 의미 | 결론을 근거 범위 안으로 줄임 |
| 모호한 부분 평가 | 절반은 맞다, 상당 부분 동의 | 동의 범위와 비동의 범위를 밝힘 |
| 숫자 선언 | 3대 전략, 4개 방안, 5종 과제 | 개수를 미리 선언하지 않고 내용을 나열함. 나열 결과 개수가 드러나는 표현(단기, 중기, 장기로 구분)은 괜찮음 |
| 3개 나열 습관 | 내용과 무관하게 항목을 3개로 맞춤 | 실제 항목 수대로 씀 |
| 구조 반복 | 인접 문장 3개 이상이 같은 주어와 서술어 배치 | 구조를 바꿈 |
| 근거 공백 | 근거 없는 결론, 출처 없는 수치, 사례 없는 일반화 | 근거와 출처를 보충하거나 범위를 줄임 |

### 기호
- em dash는 쓰지 않고 문장을 나누거나 괄호, 쉼표로 다시 짠다. 문장 안에서 `/`, `|`, `·`, 화살표, `vs`, `+`, 세미콜론, 단어를 잇는 하이픈(비용-편익, 단기-중기)을 쓰지 않고 문장으로 풀어 쓴다.
- 콜론은 "결론:", "핵심:" 같은 라벨 달기에 쓰지 않는다. 소제목은 괄호 형식을 쓴다.
- 말줄임표는 인용문에서 생략한 부분을 표시할 때만 쓴다. 콜론, 세미콜론, 말줄임표가 150어절(띄어쓰기 단위)당 1회를 넘으면 줄인다.
- 강조용 볼드를 문장 곳곳에 쓰지 않는다. 용어 정의나 식별자처럼 독자가 찾아 읽는 대상에만 쓴다.

### 빈자리 명사
빈자리 명사는 가리키는 대상의 이름을 정하지 않고 정보 없는 명사로 감싸는 말이다. 대표는 의존명사 '것'이다. '것'만 막으면 '곳', '거', '셈', '부분' 같은 다른 명사로 옮겨 가므로 단어 목록보다 문장 구조로 판단한다.
- (대상) 것, 점, 부분, 사항, 측면, 곳, 데, 바, 셈, 편, 터, 식 등(열린 목록). '거', '건', '걸', '게' 같은 '것'의 구어 축약형도 같게 다루고 격식까지 해치므로 먼저 고친다.
- (주어 자리 비움) "사업 지연을 초래한 것은 승인 절차 중복"은 "승인 절차 중복으로 사업 지연 발생"으로 쓴다.
- (명사화 우회) "데이터를 정비하는 것이 필요"는 "데이터 정비 필요"로 쓴다.
- (모호한 지칭) "현장에서 원하는 것을 반영"은 "현장이 요청한 야간 알림 기능을 반영"처럼 대상을 밝힌다.
- (빈자리 명사 종결) "활용도가 낮은 것", "보완이 필요한 곳", "추가 검토할 거"는 "활용도 저조", "보완 필요", "추가 검토 필요"로 쓴다.
- (정도 얼버무림, 단정 강조, 추정 회피) "사실상 무산된 셈", "결국 비용이 문제라는 것이다", "회복되는 것으로 보임"은 근거와 정도를 밝혀 쓴다. 근거가 없으면 "회복 여부 확인 필요"처럼 쓴다.
- (판별) 구체적 명사로 바꿨을 때 정보가 늘거나, "-하는 것"을 한자어 명사나 "-기", "-음"으로 바꿔도 뜻이 같거나, 끝의 빈자리 명사를 지우고 "필요", "저조", "확인" 같은 서술 명사로 끝낼 수 있으면 고친다. 한 문단에 빈자리 명사가 3번 이상 나오면 하나씩 점검한다.
- (그대로 두는 경우) 굳어진 말(먹을 것, 탈것, 새것), 문법 기능("-할 수 있다", "설치하는 데 소요", "보고한 바와 같이"), 실제 장소를 가리키는 '곳', 규정이나 점검표 같은 지시문의 "-할 것", 근거가 문장 안에 있는 전망("금리 인하로 대출 수요가 늘어날 것으로 전망"), 바꾸면 뜻이 달라지는 문장.
- 빈자리 명사를 다른 빈자리 명사로 바꾼 문장은 고친 문장으로 보지 않는다. 교정 중에 가리키는 대상을 원문에서 찾을 수 없으면 임의로 채우지 않고 사용자에게 확인한다.

## 15. 메타 서술
메타 서술은 독자에게 줄 정보 대신 글 자체, 작성 과정, 작성자, 사용자 요청, 사용 도구를 대상으로 삼는 문장이다. 분량 채우기, 구조화 미루기, 면책, 호감 얻기, 품질 자기 선언, 지시 수행 증명에서 나오며 독자에게는 정보만 보여야 한다. 아래 시험 중 하나라도 걸리면 지우거나 본문 내용으로 바꾼다.
1. (주어 시험) 실제 주어가 글, 작성자, 작성 행위, 사용자 요청, 도구나 방법론인가
2. (삭제 시험) 지워도 독자가 얻는 정보가 줄지 않는가
3. (수혜자 시험) 이득을 보는 쪽이 작성자(자기 정당화, 면책, 과시)인가
4. (응대 시험) 정보 없이 인사, 칭찬, 확인, 안내 같은 응대만 하는가
5. (요청 방향 시험) 사용자가 요청하지 않은 반대 방향, 고른 대상 밖의 나머지 항목, 대체 규칙을 다루는가. A를 정의한 뒤 B와 C가 A가 아닌 이유를 덧붙이거나 보완 기능 요청에 기존 기능을 쓰지 말라는 규칙을 덧붙이는 경우가 여기에 든다. 반례와 경계 확인은 쓰는 동안 검증에만 쓰고 산출물에는 요청 방향의 결과만 쓴다. 입장을 비교해 결론을 내리는 글의 반론 배치는 11장을 따른다.

| 유형 | 예 |
|------|----|
| 글과 과정 언급 | 본 보고서는 -을 분석, 먼저 A를 살펴보고, 앞서 언급한 바와 같이, 결론적으로, 다시 정리하면, 아래 표로 정리, A와 B를 비교해 보면, 다른 각도에서 보면, 이해를 돕기 위해, A라고 가정하겠습니다(자명한 전제) |
| 요청과 작업 보고 | 요청하신 대로, 주신 자료를 검토한 결과, 철저히 분석한 결과, 여러 가능성을 검토한 결과, 조사해 본 결과, 정정하면, -를 원하시는 것 같아, 작성해 보겠습니다 |
| 방법과 내부 정보 노출 | 분류 원칙에 따라, 피라미드 구조로, 웹 검색으로 확인한 결과, 코드로 계산한 결과, 학습 데이터 시점 기준, 입력 길이 제한으로 |
| 자기 평가 | 누락 없이 전체를 포괄하는 분류, 균형 잡힌 시각에서, 객관적으로 보면, 신뢰할 수 있는 기관의 보고서에 따르면 |
| 면책과 기대 관리 | 완벽하지 않을 수 있으나, 자료가 제한적이지만, 기대와 다를 수 있지만, 단정할 수는 없으나, 참고로, 본래 범위를 벗어나지만 |
| 독자 관리 | 주목할 점은, 이미 아시겠지만, 쉽게 말하면, 솔직히 말씀드리면, 참고하시기 바랍니다, 안타깝게도, 흥미롭게도 |
| 응대 의례 | 좋은 질문입니다, 도움이 되셨길 바랍니다, 필요하시면 더 설명하겠습니다, 이해되시나요 |
| 빈 전환과 총괄 | 이와 관련하여, 시대적 요구에 부응하여, 연결 내용 없는 "이를 바탕으로", 나열 뒤의 "이처럼 다양한 요인이 존재" |

- 우회 형태도 같은 시험으로 잡는다. 주어를 숨긴 표현(분석 결과를 정리하면, 도출된 결론은), 내용에 섞은 표현(다양한 관점에서 검토한 결과 A가 적합), 겸손을 가장한 표현(부족하지만 정리하면), 질문형(그렇다면 어떻게 접근해야 할까), 접속 부사형(앞서 살펴본 바와 같이 A는 B)이 여기에 든다. 섞인 문장은 메타 부분만 지우고 내용은 남긴다.
- 첫 문장은 본문 내용으로 시작하고 마지막 문장은 본문 내용으로 끝낸다.
- 사용자가 요청하지 않은 "분석 한계", "방법론", "검토 시 유의사항" 섹션을 자기 글에 덧붙이지 않는다. 사용자 요청 범위를 넘어 작업을 넓히지 않는다.
- 사용자가 목적, 한계, 방법론 설명을 요청한 경우, 학술 논문의 연구 방법처럼 장르 관례인 경우, 결과 신뢰도에 실제로 영향을 주는 중대한 불확실성, 결과를 바꾸는 비자명한 가정(적용 환율 등)은 적는다. 분석 대상 글의 구조나 논리를 평가하는 진단 보고도 메타 서술로 보지 않는다.

## 16. 어조
- 격식 있는 학술 보고서 문체를 쓴다. 구어체, 유행어, 속어, 은어, 존댓말은 쓰지 않는다.
- 논리 전개와 개념 설명은 쉽고 단순하게 쓴다. 어휘와 문체의 격식은 성인 실무자 대상 공식 문서 수준을 유지한다.
- 어조는 따뜻하게 하되 객관성을 지킨다. 상대를 탓하는 표현 대신 보완 방향을 적는다. 전문 컨설팅 보고서 수준의 완성도를 목표로 한다.
- 단정하고 공격적인 말(절대, 차단, 오직, 무조건, 확정)을 피하고 독자가 받아들일 수 있는 완곡 표현을 쓴다. "역량이 매우 부족"은 "-의 보완 필요"로, "절대로 불가능"은 "-하려면 -필요"로 쓴다. 명백한 잘못은 분명히 지적한다. 완곡 표현이 지나치면 뜻이 흐려지므로 정도를 조절한다.
- 같은 내용이면 긍정 표현을 먼저 쓴다. "클라우드 전환을 위한 데이터 준비도 부족"은 "정형 데이터가 확보되면 클라우드 전환 가능"으로 쓴다.
- 독자가 이미 아는 지식은 설명하지 않는다. 한 글에 담는 정보가 독자의 판단에 필요한 양을 넘지 않게 한다. 독자의 결정에 쓰이지 않는 기술 세부, 용어 과시, 지엽적 사실은 늘어놓지 않는다.

## 17. 산출 전 점검
- 헤더만 읽어도 흐름이 보이고 헤더마다 주제가 하나인가
- 결론이 제목이나 첫 섹션에 있고 섹션마다 첫 문장이 섹션의 결론인가
- 골격이 하나이고 환경분석과 전략을 다룬 글은 바깥에서 안으로의 순서를 지켰는가
- 단위마다 판단문 메시지가 1개이고 요소는 3-4개 이하로 골라 압축했는가
- 분류 기준이 한 차원이고 겹침과 빠짐이 없으며 층 사이가 결론과 근거로 이어지는가
- 문장마다 메시지 1개, 5W1H 요소 1번씩이고 명사형 종결이 자연스러우며 비문이 없는가
- 모드 규칙을 지켰는가 (단문 모드의 연결어와 쉼표, 흐름 모드의 종속절 역할과 골격)
- 결론과 근거가 짝을 이루고 결론이 근거 범위 안에 있으며 방향이 있는가
- 정량 데이터는 3개 이하이고 출처, 산출 근거, 전체 링크, 공식 명칭을 갖췄으며 계산은 도구로 했는가
- 전문용어, 비선호 어휘, 번역투, 빈자리 명사, 14장 표현 패턴, 금지 기호를 처리했는가
- 메타 서술, 요청하지 않은 역방향 서술, 프레임워크 이름이 없고 첫 문장과 마지막 문장이 본문 내용인가
- 제3자가 읽고 타당하다고 납득할 만큼 쉽고 분명하며 소리 내어 읽었을 때 리듬이 자연스러운가

## 18. 예시
예시에 나오는 기관과 사업은 가상이다.

### 단문 모드
```markdown
## 개요
- 본 보고서는 회의 운영의 문제점을 분석하고 개선 방향을 도출하는 것을 목적으로 함
- 이러한 맥락에서 회의 효율화는 매우 중요한 의미를 가지며 3대 개선 과제를 제시함
    + 정보 공유와 의사결정이 섞여 있고, 참석자도 많아서 결정이 늦어지는 것이 문제임
```

위 글을 고친 결과는 다음과 같다.

```markdown
# 의사결정 회의와 정보 공유 회의의 분리 필요

## 현행 회의 운영의 한계
- 부서별 보고와 의사결정 안건을 한 회의에서 함께 처리하여 결정 지연 반복
    + 안건별 시간 배분 없이 순서대로 진행하여 후순위 안건의 논의 시간 부족
    + 결정되지 않은 안건의 다음 회차 이월 누적
- 안건과 직접 관련이 없는 인원까지 전원 참석하는 관행으로 참석자의 시간 소모 증가

## 분리 회의 운영의 방향
- 의사결정 회의와 정보 공유를 분리하여 회의별 목적에 맞게 운영
    + (의사결정 회의) 결정이 필요한 안건만 다루는 회의를 의사결정자와 안건 관계자 중심으로 운영
    + (정보 공유) 정기 보고는 서면 보고로 대체하여 회의 시간을 결정 안건에 집중
    + (참석 범위) 안건별 관련성을 기준으로 참석자 범위 조정
```

### 흐름 모드
```markdown
# B재단 판로 지원 사업의 온라인 중심 재편 필요

## 지역 상품 소비 방식의 변화
- 지역 상품 소비가 온라인 구매로 옮겨 가면서 소규모 판매자의 판로 확보 방식이 바뀌는 추세
    + 간편결제가 보편화됨에 따라 소규모 판매자도 별도 결제 설비 없이 온라인 판매에 진입 가능
    + 다만 판매 수수료와 광고비 부담이 커지면서 판매 규모가 작은 사업자는 수익 확보에 어려움

## B재단 판로 지원 사업의 현황
- B재단의 판로 지원은 오프라인 박람회 참가에 집중되어 있어 온라인 판매 지원 비중이 낮은 상황
- B재단은 박람회 참가 기업을 대상으로 상품 기획과 홍보물 제작을 지원해 온 경험 보유

## 판로 지원 사업의 시사점
- 소비는 온라인으로 옮겨 가고 있으나 지원은 오프라인에 머물러 있어 사업 효과가 줄어들 가능성
- 결제 설비 부담은 줄었으나 수수료와 광고비가 수익을 압박하는 만큼 입점 초기 비용 지원의 효과가 클 여지
- 기존 상품 기획 지원 경험을 온라인 상품 소개 제작에 활용하면 온라인 전환에 드는 신규 비용 절감 가능

## 판로 지원 사업의 재편 방향
- 박람회 지원 예산 일부를 온라인 입점 지원으로 전환하여 판로 지원의 중심을 온라인으로 이동
    + 입점 초기 수수료를 한시적으로 지원함으로써 소규모 사업자의 진입 부담 완화
    + 기존 상품 기획 지원을 온라인 상품 소개 제작과 연계하여 박람회 운영 경험 활용
```

## 19. 예외
- 사용자가 결론을 뒤에 두라고 요청하면 결론 우선 배치를 적용하지 않는다.
- 사용자가 전수 목록이나 상세 목록을 요청하면 요소 개수 기준을 적용하지 않는다. 법령, 규정, 점검표처럼 완전성이 목적인 글은 개수 기준 대신 비중 배치 규칙만 적용한다.
- 인용문, 법령 원문, 코드 자체는 고치지 않고 앞뒤 설명 문장에만 적용한다.
- 사용자가 수사적 표현이나 특정 어휘를 의도적으로 요청하면 그 표현은 제한에서 뺀다.
- 사용자가 메타 서술이나 프레임워크 이름을 드러내 달라고 요청하면 허용한다.
