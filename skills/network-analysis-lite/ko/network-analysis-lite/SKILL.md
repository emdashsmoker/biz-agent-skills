# 소셜 네트워크 분석

사람, 부서, 기관, 기업, 국가 사이의 관계 데이터를 NetworkX로 계산하고 입력 매트릭스, 결과 표, 그림을 한 묶음으로 보고한다. 계산과 그림 함수는 `scripts/sna_toolkit.py`에 모여 있다.

## 기본 원칙

- 보고하는 모든 수치는 `sna_toolkit.py` 또는 NetworkX 실행 결과에서 가져온다. 중심성, 등위성, 집중도는 손계산에서 틀리기 쉽고 코드로 계산해야 제3자가 같은 결과를 재현할 수 있다.
- 분석 결과에는 입력 매트릭스 표, 결과 표, 그림 파일을 함께 제공한다. 그림만 있으면 독자가 원자료와 수치를 대조할 수 없다.
- 그림은 PNG 파일로 저장하고 실행 환경의 파일 전달 기능으로 전달한다. 본문에 `![](경로.png)` 형태로 로컬 경로를 적으면 대부분의 채팅 화면에서 깨진 이미지로 남는다.
- 그림 함수는 파일이 실제로 생성되었는지 확인하고 실패하면 오류를 낸다. 오류가 나면 해당 그림에 대한 언급을 본문에서 삭제한다.
- 사용자가 파일을 주면 파일을 직접 읽는다. 데이터를 파이썬 리스트로 바꿔 달라고 사용자에게 요청하지 않는다.
- 데이터 없이 개념만 물으면 노드 5-10개의 가상 네트워크로 시연하고 가상 데이터임을 결과에 밝힌다.

## 실행 준비

필수 패키지는 networkx, numpy, pandas, scipy, matplotlib이다. Excel 입력에는 openpyxl, 라벨 겹침 조정에는 adjustText가 추가로 쓰인다. 동작을 확인한 버전은 NetworkX 3.6, pandas 3.0, numpy 2.4, scipy 1.17, matplotlib 3.10이다.

```bash
pip install networkx numpy pandas scipy matplotlib openpyxl adjustText
```

시스템 파이썬을 보호하는 환경에서는 가상환경을 쓰거나 `--break-system-packages` 옵션을 붙인다.

한글 라벨을 그리려면 NanumGothic이나 Noto Sans CJK 계열 글꼴이 설치되어 있어야 한다. 스크립트는 설치된 글꼴을 찾아 쓰기만 하고 글꼴을 설치하지 않는다. 글꼴 설치에는 관리자 권한이 필요하기 때문이다. 맞는 글꼴이 없으면 경고를 내고 기본 글꼴로 그리며 이때 한글이 네모로 보일 수 있다.

```python
import sys
sys.path.insert(0, "<스킬 폴더>/scripts")

```

## 작업 순서

요청 하나를 아래 순서로 처리한다.

1. 입력을 읽어 그래프를 만든다
2. 방향과 가중치를 정한다
3. 규모에 맞는 처리 방식을 고른다
4. 질문에 맞는 함수로 계산한다
5. 매트릭스 그림과 네트워크 그림을 만든다
6. 보고 형식에 맞춰 답한다

### 입력 읽기

| 입력 | 함수 | 참고 |
|---|---|---|
| 파이썬 행렬 | `from_matrix(matrix, labels, directed, weighted)` | 대각선(자기 관계)은 무시 |
| 엣지 목록 | `from_edges(edges, directed, weighted)` | `(u, v)` 또는 `(u, v, 가중치)` |
| 사람과 활동의 소속 | `from_incidence(df 또는 dict)` | 이분 그래프와 두 투영 그래프 반환 |
| CSV, TSV, Excel | `load_table(path, fmt, directed, weighted)` | `fmt` 생략 시 자동 판별 |
| UCINET DL | `read_ucinet_dl(path)`, `write_ucinet_dl(G, path)` | FULLMATRIX, EDGELIST1 |
| Pajek, GEXF, GraphML | `nx.read_pajek`, `nx.read_gexf`, `nx.read_graphml` | 저장은 `nx.write_*` |
| 결과 표 저장 | `export_table(G, path, fmt)` | 엣지 목록 또는 매트릭스 CSV |

- 자동 판별은 열이 3개 이하이면 엣지 목록, 행과 열 수가 같거나 첫 열이 라벨이면 인접 매트릭스, 나머지는 사건 매트릭스로 본다.
- Excel에서 저장한 한글 CSV가 깨지면 `encoding="utf-8-sig"` 또는 `encoding="cp949"`를 지정한다. `export_table`은 utf-8-sig로 저장하므로 Excel에서 한글이 그대로 보인다.
- Pajek, GEXF, GraphML로 저장하면 Gephi 같은 외부 도구에서 이어서 작업할 수 있다.

### 방향과 가중치 판단

- 사용자가 방향을 밝히지 않았으면 매트릭스가 대칭일 때 무방향, 비대칭일 때 방향 그래프로 읽는다.
- 셀 값이 0과 1뿐이면 이진 그래프, 다른 값이 있으면 가중 그래프로 읽는다.
- 판단 결과는 읽기 함수의 `directed`, `weighted` 인자로 넘기고 분석 개요에 한 줄로 적는다.

### 규모별 처리

`recommend_strategy(G)`가 노드 수에 따라 아래 표의 방식을 돌려준다. 30개 기준은 매트릭스 셀 글자를 읽을 수 있는 한계에서 정한 기본값이다.

| 노드 수 | 방식 | 본문 매트릭스 | 결과 표 | 그림 |
|---|---|---|---|---|
| 30 이하 | full | 전체 매트릭스 | 전체 | 매트릭스 그림, 네트워크 그림 |
| 31-100 | filtered | 연결정도 상위 30개 발췌 | 상위 10개, 전체는 CSV | 네트워크 그림 |
| 101-500 | aggregated | 블록 간 밀도 표 | 상위 10개, 전체는 CSV | 블록 축소 그래프 |
| 501 이상 | summary_only | 블록 간 밀도 표 | 요약 통계 | 연결정도 분포 |

- 31-100개 구간에서 블록모델링을 했다면 발췌 매트릭스를 블록 순서로 재정렬해 보여 줄 수 있다.
- 101개 이상은 `louvain`이나 `blockmodel`로 블록을 먼저 나누고 `block_density`로 블록 간 밀도 표를, `reduce_to_blocks`로 축소 그래프를 만든다.
- 501개 이상은 `describe`, `degree_stats` 요약 표와 `plot_degree_histogram` 분포 그림으로 보고한다. 이 규모에서는 노드와 선이 겹쳐 개별 노드를 읽을 수 없다.
- REGE와 계층 군집은 노드 수의 제곱 이상으로 계산량이 늘어나므로 100개를 넘으면 실행 시간을 사용자에게 먼저 알린다.

## 측정 정의

아래 식에서 $g$는 노드 수, $L$은 선의 수, $d_i$는 노드 $i$의 연결정도, $d_{ij}$는 두 노드 사이 최단 거리다.

### 그래프 기본 요소

| 개념 | 정의 |
|---|---|
| 궤적(walk) | 노드와 선을 반복해서 지날 수 있는 이동 |
| 경로(path) | 노드를 한 번씩만 지나는 이동 |
| 사이클(cycle) | 출발 노드로 돌아오는 경로이며 무방향 그래프에서는 노드 3개 이상 |
| 거리 | 두 노드를 잇는 최단 경로의 선 수 |
| 직경 | 모든 거리 가운데 최댓값이며 1에서 $g-1$ 사이 |
| 편심도 | 한 노드에서 가장 먼 노드까지의 거리 |
| 반경 | 모든 노드의 편심도 가운데 최솟값 |
| 양자(dyad) | 노드 두 개의 쌍이며 가능한 쌍의 수는 $g(g-1)/2$ |

- `cycles`의 길이 상한은 기본 4이다. 길이가 길어지면 사이클 수가 급격히 늘어 해석이 어려워진다.
- 연결되지 않은 그래프의 직경과 반경은 무한대로 보고하고 평균 거리는 서로 도달 가능한 쌍만으로 계산한다.
- 무방향 그래프의 연결정도 평균은 $2L/g$, 분산은 $\sum_i (d_i - \bar d)^2 / g$이다. 방향 그래프는 인디그리와 아웃디그리의 평균이 모두 $L/g$이고 분산은 각각 계산한다.
- 방향 그래프에서 인디그리는 받는 관계 수로 인기도를, 아웃디그리는 보내는 관계 수로 관계 범위를 나타낸다. 매트릭스의 행 합이 아웃디그리, 열 합이 인디그리다.
- `directed_node_types`는 인디그리와 아웃디그리가 모두 0이면 고립, 인디그리만 0이면 전달자, 아웃디그리만 0이면 수신자, 둘 다 있으면 매개자로 분류한다.
- 매트릭스의 행과 열을 블록 순서로 재배열(치환)하면 숨은 패턴이 드러나며 그림과 표 함수의 `groups` 인자로 처리한다. 방향을 뒤집은 관점(전치)은 `G.reverse()`로 만든다.

### 밀도

| 대상 | 식 | 함수 |
|---|---|---|
| 무방향 이진 | $L / \{g(g-1)/2\}$ | `nx.density` |
| 방향 이진 | $L / \{g(g-1)\}$ | `nx.density` |
| 가중치 무시 | 이진 밀도와 같음 | `nx.density` |
| 가중 평균 | 선 값의 합 / 가능한 관계 수 | `valued_density(G)` |
| 다중 관계 | 선 값의 합 / (관계 종류 수 × 가능한 관계 수) | `valued_density(G, max_value=관계 종류 수)` |

- 포괄성(inclusiveness)은 고립점을 제외한 노드 수를 전체 노드 수로 나눈 값이며 `describe`가 함께 계산한다. 포괄성이 같아도 연결 수가 다를 수 있으므로 밀도와 함께 본다.
- 밀도가 높은 네트워크는 정보가 빨리 공유되고 결속이 강한 반면 외부 정보가 들어올 경로는 적다. 밀도가 낮으면 협력과 정보 공유가 저절로 일어나기 어렵다.

### 중심성

| 지표 | 상대값 식 | 의미 |
|---|---|---|
| 연결정도 | $d_i / (g-1)$ | 직접 연결된 노드 수, 국지적 영향력 |
| 근접 | $(g-1) / \sum_j d_{ij}$ | 다른 노드에 빨리 도달하는 정도, 전체 네트워크 기준 |
| 매개 | $\sum_{j<k} \frac{g_{jk}(i)}{g_{jk}} \Big/ \frac{(g-1)(g-2)}{2}$ | 다른 노드 사이 최단 경로를 중개하는 정도 |
| 내향, 외향 | 인디그리, 아웃디그리 $/(g-1)$ | 방향 그래프의 받는 관계와 보내는 관계 |
| 아이겐벡터 | 인접 행렬의 주 고유벡터 | 중요한 노드와 연결될수록 높음 |
| PageRank | 무작위 이동과 순간 이동을 섞은 정상 확률 | 방향 그래프의 영향력 순위 |
| Katz | 길이에 따라 감쇠하는 모든 궤적의 합 | 직접과 간접 연결을 함께 반영 |
| HITS | `nx.hits(G)` | 방향 그래프의 허브 점수와 권위 점수 |

- $g_{jk}$는 $j$와 $k$ 사이 최단 경로 수, $g_{jk}(i)$는 그중 $i$를 지나는 경로 수다.
- `centralities`는 상대값을 돌려주고 매개 중심성 순으로 정렬한다. `extended_centralities`는 수렴하지 않은 지표를 빈칸으로 두고 경고를 낸다.
- 근접 중심성은 NetworkX 기본값을 따라 도달 가능한 노드만으로 계산하고 도달 가능한 비율을 곱한다.
- 스타형에서는 중심 노드의 상대 매개 중심성이 1, 나머지는 0이다. 원형에서는 모든 노드가 같고 일렬형에서는 가운데 노드가 가장 높다.
- 연결정도는 직접 교류량, 근접은 정보 도달 속도, 매개는 정보 흐름 통제력을 읽는 지표다. 매개 중심성이 높은 노드가 빠지면 집단 사이 소통이 끊길 수 있다.

### 집중도

집중도(centralization)는 네트워크 전체가 한 노드에 쏠린 정도이며 Freeman(1979)의 식 $\sum_i (C^* - C_i) / \max\sum$을 쓴다. $C^*$는 최댓값이고 분모는 스타형 그래프에서 나오는 최대 차이 합이다. 0은 모든 노드가 같은 상태, 1은 스타형이다.

| 그래프 | 지표 | 계산 기준 | 분모 |
|---|---|---|---|
| 무방향 | 연결정도 | 연결정도 원값 | $(g-1)(g-2)$ |
| 무방향 | 매개 | 매개 원값(순서 없는 쌍) | $(g-1)^2(g-2)/2$ |
| 무방향 | 근접 | 상대 근접 중심성 | $(g-1)(g-2)/(2g-3)$ |
| 방향 | 인디그리, 아웃디그리 | 원값 | $(g-1)^2$ |
| 방향 | 매개 | 매개 원값(순서 있는 쌍) | $(g-1)^2(g-2)$ |

- 근접 집중도는 연결된 무방향 그래프에서만 계산하고 나머지는 빈칸으로 둔다. Freeman의 분모가 그 조건에서 유도되었기 때문이다.
- 밀도는 연결이 평균적으로 얼마나 많은지, 집중도는 연결이 얼마나 한쪽에 쏠렸는지를 본다. 집중도가 1에 가까우면 중심 노드가 빠질 때 네트워크가 흩어질 위험이 크다.

### 구조적 틈새

구조적 틈새는 서로 연결되지 않은 이웃들 사이를 한 노드가 잇고 있는 상태다(Burt 1992). 그 노드는 중복되지 않는 정보를 먼저 얻고 흐름을 조정할 수 있다.

| 지표 | 식 | 해석 |
|---|---|---|
| 중복(redundancy) | $2t/n$ | 이웃끼리 서로 연결된 정도 |
| 유효 규모(effective size) | $n - 2t/n$ | 중복을 뺀 이웃 수 |
| 효율성(efficiency) | 유효 규모 $/ n$ | 이웃 가운데 비중복 이웃의 비율 |
| 제약(constraint) | $\sum_j (p_{ij} + \sum_{q \ne i,j} p_{iq} p_{qj})^2$ | 낮을수록 틈새를 잇는 위치 |

- $n$은 에고의 이웃 수, $t$는 에고를 뺀 이웃 사이 관계 수다. 유효 규모 식은 무방향 이진 그래프에서 Burt의 일반식을 줄인 형태이며(Borgatti 1997), 가중 또는 방향 그래프는 `structural_holes(G, weight="weight")`가 NetworkX의 일반식으로 계산한다.
- $p_{ij}$는 $i$의 전체 관계 가운데 $j$에 쓴 비율이다. 제약은 네트워크 규모가 작을수록, 밀도가 높을수록, 관계가 한 이웃에 몰릴수록 커진다.
- 이웃이 없는 노드는 계산할 수 없으므로 빈칸으로 둔다.
- 밀도가 높을수록 틈새가 생길 여지가 줄고 모든 구성원이 서로 연결된 파당에는 틈새가 없다.
- `openness(G, groups)`는 집단 구성원의 관계 가운데 집단 밖으로 이어진 비율이다. 0은 폐쇄적, 1은 개방적 집단이며 방향 그래프는 나가는 관계를 센다.

### 하위집단

| 개념 | 정의 | 함수 |
|---|---|---|
| 컴퍼넌트 | 끊김 없이 이어진 노드 집합, 방향 그래프는 방향을 무시한 약한 컴퍼넌트와 방향을 따라 서로 도달하는 강한 컴퍼넌트로 나눔 | `components` |
| 고립점 | 어떤 노드와도 연결되지 않은 노드 | `components` |
| 연결점(cut-point) | 제거하면 컴퍼넌트 수가 늘어나는 노드 | `cutpoints` |
| 브릿지 | 제거하면 컴퍼넌트 수가 늘어나는 선 | `cutpoints` |
| 노트(knot) | 연결점을 기준으로 나뉘는 덩어리(바이컴퍼넌트) | `cutpoints` |
| 사이클 컴퍼넌트 | 모든 브릿지를 제거한 뒤 남는 노드 3개 이상의 연결 집합 | `cycle_components` |
| k-core | 모든 구성원이 집합 안에서 $k$개 이상과 연결된 최대 집합(Seidman 1983) | `k_cores` |
| m-slice | 다중성 $m$ 이상인 관계만 남겼을 때의 연결 집합 | `m_slices` |
| 파당(clique) | 노드 3개 이상이 모두 서로 직접 연결된 최대 집합 | `cliques` |
| n-파당(n-clique) | 전체 그래프에서 서로 거리 $n$ 이하인 최대 집합 | `n_cliques` |
| n-클랜(n-clan) | n-파당 중 집합 안의 경로만으로 직경이 $n$ 이하인 집합 | `n_clans` |
| n-클럽(n-club) | 집합 안의 직경이 $n$ 이하인 최대 집합 | `n_clubs` |

- 컴퍼넌트는 연결된 영역을, 파당 계열은 촘촘하게 연결된 노드 묶음을 찾는다.
- `k_cores`는 노드별 코어 번호와 $k$별 구성원, 잔류점, 잔류점 비율을 표로 돌려준다. 잔류점은 $k$를 올릴 때 빠지는 노드이고 잔류점 비율은 잔류점 수를 전체 노드 수로 나눈 값이다. $k$가 높은 코어일수록 응집이 강한 핵심 집단이다. 코어 번호로 노드 색을 칠하면 응집 수준별 동심 구조(네스팅)를 볼 수 있다.
- `m_slices`는 가중 그래프의 선 가중치를 다중성으로 쓴다. 이진 그래프에서는 두 끝 노드의 공유 이웃 수를 다중성으로 쓴다.
- n-파당은 집합 밖의 노드를 거쳐 거리를 채울 수 있다. n-클랜은 이를 막은 개념이며 모든 n-클랜은 n-파당이면서 n-클럽이다(Wasserman and Faust 1994).
- $n$은 기본 2를 쓴다. 3 이상이면 집합이 커져 응집 집단으로 해석하기 어렵다.
- `n_clubs`는 n-클랜과 반경 $n$ 이웃 집합을 후보로 삼아 직경을 확인하는 방식이다. 모든 n-클럽을 찾는 계산은 노드 수에 따라 급격히 무거워지므로 이 함수는 후보 가운데 극대 집합만 돌려준다.
- `clique_membership`에서 여러 파당에 동시에 속한 노드는 파당 사이를 잇는 연결자로 읽는다.

### 구조적 등위성과 블록모델링

두 노드가 서로 모르더라도 제3자들과 맺는 관계 패턴이 같으면 같은 위치(position)에 있다고 보고 이를 구조적 등위라 한다. 같은 위치의 행위자는 관계망 안에서 서로 대체할 수 있다. 지위는 관계 패턴이 비슷한 행위자 집합이고 역할은 그 지위에 결부된 관계 패턴이다.

| 함수 | 계산 | 읽는 법 |
|---|---|---|
| `se_distance` | $\sqrt{\sum_{k \ne i,j} [(x_{ik}-x_{jk})^2 + (x_{ki}-x_{kj})^2]}$ | 0에 가까울수록 등위, 이진 단일 관계의 최댓값은 $\sqrt{2(g-2)}$ |
| `se_correlation` | 같은 행과 열 프로필의 피어슨 상관 | +1에 가까울수록 등위 |
| `rege_similarity` | 이웃끼리의 유사도를 반복해서 짝지은 정규 등위 유사도 | 1에 가까울수록 같은 역할 |

- 상관계수는 프로필의 모양이 같으면 +1이 되지만 거리는 값의 수준과 폭까지 같아야 0이 된다. 그래서 같은 데이터에서도 두 방법의 묶음이 다를 수 있으며 관계의 동일성을 보려면 거리, 패턴의 유사성을 보려면 상관을 쓴다.
- 분산이 0인 프로필(고립점 등)의 상관은 정의되지 않으므로 0으로 둔다.
- 정규 등위는 완전히 같은 상대가 아니어도 비슷한 유형의 상대와 관계를 맺으면 같은 역할로 본다(White and Reitz 1983). 예를 들어 각기 다른 부하를 둔 두 관리자는 정규 등위다.
- `rege_similarity`는 모든 쌍을 1에서 시작한다. 매 반복에서 두 노드의 나가는 이웃과 들어오는 이웃을 따로 짝지어 가장 비슷한 상대의 점수를 평균하고 한쪽에만 이웃이 있는 방향에서는 점수가 깎인다. 변화가 1e-4 미만이거나 20회에 이르면 멈춘다. 무방향 이진 그래프에서는 고립점을 뺀 모든 쌍이 1로 수렴하므로 방향 그래프에 쓴다.

`blockmodel(G, n_blocks, method)`는 노드를 블록으로 나눈다.

| method | 방식 |
|---|---|
| `euclidean` | `se_distance`를 평균 연결 계층 군집으로 묶음 |
| `concor` | CONCOR로 반복 분할 |
| `structure` | 최단 거리 행렬에 `se_distance`와 같은 거리를 적용해 간접 관계까지 반영(Burt 1976), 도달할 수 없는 쌍의 거리는 $g+1$ |
| `rege` | $1 -$ `rege_similarity`를 평균 연결 계층 군집으로 묶음 |

- CONCOR(Breiger, Boorman and Arabie 1975)는 `se_correlation` 행렬의 상관을 다시 구하는 과정을 모든 값이 +1 또는 -1이 될 때까지 반복한 뒤 부호로 둘로 나눈다. 원하는 블록 수가 될 때까지 가장 큰 블록을 같은 방식으로 다시 나눈다. 한 번에 둘씩만 나뉘므로 블록 수는 분석자가 정한다.
- CONCOR는 직접 관계 패턴의 상관을, structure는 간접 관계를 포함한 거리를 기준으로 묶는다.
- 사용자가 블록 수를 정하지 않으면 함수 기본값(`blockmodel` 3개, `concor` 2개)을 쓰고 사용한 블록 수를 분석 개요에 적는다.

블록 사이에 관계가 있는지는 `image_matrix(G, blocks, criterion)`로 판정한다. 블록 밀도는 블록 사이 실제 관계 수를 가능한 관계 수로 나눈 값이며 같은 블록 안에서는 자기 자신과의 관계를 뺀다.

| criterion | 1로 판정하는 조건 | 쓰임 |
|---|---|---|
| `alpha` | 블록 밀도가 α 이상, α 기본값은 전체 네트워크 밀도 | 일반적인 경우 |
| `zero` | 블록 안에 관계가 하나라도 있음 | 밀도가 낮은 네트워크 |
| `one` | 블록 안의 모든 관계가 있음 | 밀도가 높은 네트워크 |
| `perfect` | 모두 있으면 1, 모두 없으면 0, 섞여 있으면 빈칸 | 블록모델의 적합도 확인 |

블록모델링 결과는 원자료 매트릭스, 블록 순서로 재정렬한 매트릭스(`plot_matrix(G, path, groups=blocks)`), 이미지 매트릭스, 축소 그래프(`reduce_to_blocks` 후 `plot_network`) 순서로 보여 준다.

### 대규모 네트워크

- `top_k_subgraph(G, k, by)`는 매개, 연결정도, 근접, PageRank 가운데 하나로 상위 $k$개 노드를 골라 부분 그래프를 만든다.
- `core_subgraph(G, min_degree=3)`는 연결정도가 기준 미만인 노드를 한 번 걸러 주변부를 덜어 낸다.
- `louvain(G)`는 모듈성을 높이는 방향으로 커뮤니티를 찾는다. Louvain은 노드 순서를 무작위로 섞기 때문에 seed를 42로 고정해 같은 결과를 재현한다.
- 커뮤니티는 서로 촘촘히 연결된 노드 묶음이고 등위 블록은 관계 패턴이 같은 노드 묶음이다. 응집을 묻는 질문에는 Louvain을, 위치와 역할을 묻는 질문에는 블록모델링을 쓴다.
- 501개 이상에서는 `nx.community.label_propagation_communities`도 대안으로 쓸 수 있다.

### 이분 네트워크

- `from_incidence`는 사람과 활동의 소속 자료를 이분 그래프로 만들고 사람 투영 그래프와 활동 투영 그래프를 함께 돌려준다.
- 사람 투영 그래프의 선 가중치는 함께 참여한 활동 수, 활동 투영 그래프의 선 가중치는 함께 참여한 사람 수다.
- `plot_bipartite`는 사람을 왼쪽 원, 활동을 오른쪽 사각형으로 그린다.

## 이론 개념

개념을 설명할 때는 아래 정의와 출처를 쓰고 가능한 경우 측정 지표와 연결해 가상 네트워크로 시연한다.

| 개념 | 내용 | 연결되는 분석 | 출처 |
|---|---|---|---|
| 관계 유형 | 거래, 의사소통, 경계 침투, 도구적, 감정, 권위와 권력, 친족 관계로 나눔. 분석 전에 어떤 관계를 선으로 볼지 먼저 정함 | 데이터 정의 | Knoke and Kuklinski (1982) |
| 분석 범위 | 한 행위자와 그 이웃(에고), 두 행위자의 쌍(양자), 경계 안의 모든 행위자(전체 네트워크) | `ego_network`, `describe` | Wasserman and Faust (1994) |
| 연결의 강도 | 함께 보낸 시간, 정서적 강도, 친밀성, 상호 도움의 조합. 약한 연결은 서로 다른 집단을 이어 새로운 정보를 전하고 강한 연결은 결속과 지원을 제공 | 가중치, 브릿지, 매개 중심성 | Granovetter (1973) |
| 구조적 틈새 | 끊어진 집단 사이를 잇는 위치가 비중복 정보와 중개 기회를 얻음 | `structural_holes` | Burt (1992) |
| 사회적 자본 | 촘촘하게 닫힌 관계가 신뢰와 규범을 만든다는 폐쇄 관점과 틈새를 잇는 위치가 정보 우위를 준다는 중개 관점 | 밀도, 제약 | Coleman (1988), Burt (1992) |
| 배태성 | 경제 행위는 지속되는 사회관계 안에서 일어나며 과소사회화 관점과 과잉사회화 관점을 모두 비판 | 관계 지속성, 반복 거래 | Granovetter (1985) |
| 배태성의 역설 | 배태된 관계는 신뢰, 세밀한 정보 이전, 공동 문제 해결로 성과를 높이지만 임계점을 넘으면 외부 충격과 외부 정보에 취약해져 성과를 떨어뜨림 | `plot_uzzi_concept` | Uzzi (1997) |
| 네트워크 조직 | 네트워크를 시장, 위계와 구별되는 경제 활동 조정 형태로 규정 | 조직 간 관계 설계 | Powell (1990) |
| 중심 위치의 효과 | 중심 위치와 영향력, 혁신 참여, 팀 성과, 관리자 승진 사이의 관계가 보고됨 | 중심성, 제약 | Brass (1984), Ibarra (1993), Baldwin, Bedell and Johnson (1997), Burt (1992) |

|---|---|---|
| 중심 연결자(central connector) | 집단 안의 많은 동료와 연결되어 정보를 모으고 퍼뜨림 | 높은 연결정도 |
| 경계 연결자(boundary spanner) | 집단 밖이나 다른 부서와의 관계를 유지함 | 소속 집단 밖으로 이어진 관계 수 |
| 정보 중개자(information broker) | 서로 떨어진 하위 집단을 이어 줌 | 높은 매개 중심성, 낮은 제약 |
| 주변 전문가(peripheral specialist) | 연결은 적지만 특정 분야의 전문 지식을 제공함 | 낮은 연결정도와 전문성 속성 자료 |

## 보고 형식

요청 유형에 맞는 형식을 고르고 필요 없는 절은 삭제한다. 모든 분석 응답에는 입력 매트릭스 표, 결과 표, 그림 파일이 들어간다.

분석 요청에서는 `matrix_and_network`가 매트릭스 마크다운과 두 PNG 경로를 한 번에 만든다.

```python
cent = centralities(G)
out = matrix_and_network(G, "outputs/org", title="조직 소통망",
                         values=cent["betweenness"])
print(out["markdown"])      # 입력 매트릭스 표
print(df_markdown(cent))    # 결과 표
# out["matrix_png"], out["network_png"]를 파일로 전달
```

블록이나 파당 소속을 보여 줄 때는 `groups=blocks`를 넘긴다. 그러면 매트릭스가 블록 순서로 재정렬되고 블록 경계선이 그려진다.

### 표기 규칙

- 스크립트의 열 이름은 영어다. 표를 보고할 때는 사용자 언어로 열 이름을 바꾼다. 예를 들어 `degree`는 연결정도 중심성, `betweenness`는 매개 중심성으로 적는다.
- 소수는 셋째 자리까지 표시한다.
- 그림 제목과 라벨도 사용자 언어로 넘긴다. `plot_centrality_bars`에는 열 이름을 바꾼 표와 그 이름을 담은 `columns`를, `plot_degree_histogram`에는 `xlabel`, `ylabel`을, `plot_uzzi_concept`에는 `labels`를 넘긴다.
- UCINET이나 Pajek 사용법을 물으면 같은 분석을 NetworkX로 수행하는 코드를 보여 주고 결과 파일을 해당 도구 형식으로 저장해 준다.

## 제출 전 점검

- 모든 수치가 코드 실행 결과에서 나왔는가
- 입력 매트릭스 표와 결과 표가 본문에 있는가
- 그림 파일이 실제로 생성되었고 파일 전달 기능으로 전달했는가
- 본문에 로컬 경로 이미지 마크다운이 없는가
- 규모별 처리 표의 기준을 지켰는가
- 방향, 가중치, 가상 데이터 여부를 분석 개요에 적었는가
- 표의 열 이름과 그림 라벨을 사용자 언어로 바꿨는가
