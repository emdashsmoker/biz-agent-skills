# 구조 렌즈

분류, 묶음, 계층, 관계가 맞게 짜였는지 점검한다. 온톨로지 설계 원칙을 사고 규칙으로 옮겨 쓴다. 온톨로지 모델을 만들거나 추론기를 돌리는 작업은 이 렌즈의 범위 밖이다.

## 배경

아래 출처의 원칙을 사고 규칙으로 바꿨다.

- 상호배제와 전체포괄(MECE): 바바라 민토(Barbara Minto)의 피라미드 원칙에서 널리 쓰는 분류 기준
- 온톨로지 설계 기준: 토마스 그루버(Thomas Gruber, 1995)의 명확성, 일관성, 확장성, 최소 표현 편향 등
- 역량 질문: 그뤼닝거와 폭스(Grüninger & Fox, 1995)가 제안한 "이 구조가 답해야 할 질문"을 먼저 모으는 방식
- 흔한 설계 결함: 온톨로지 점검 도구 OOPS!의 결함 목록(고립 요소, 계층 순환, 한 범주에 두 개념 혼합, "기타" 범주 등)

## 원칙 요약

| 원칙 | 원래 뜻 | 사고 규칙으로 옮긴 형태 |
|---|---|---|
| 상호배제 | 분류 항목끼리 겹치지 않음 | 한 사례가 두 항목에 동시에 들어가면 분류 기준을 다시 짠다 |
| 전체포괄 | 분류 항목을 합치면 논의 대상 전체가 됨 | 어느 항목에도 들어가지 않는 사례가 있으면 분류가 불완전하다 |
| 단일 분류 기준 | 한 분류 체계는 한 가지 기준으로 나눔 | 기준이 다른 항목을 한 분류에 섞지 않는다 |
| 일종 관계 | 하위 개념은 상위 개념의 속성을 모두 물려받음 | "X는 Y의 일종인가"를 통과해야 상하위로 둔다 |
| 부분 관계 | 부분은 전체를 이루지만 전체의 일종은 아님 | "일종인가"와 "부분인가"를 섞지 않는다 |
| 배타 선언 | 동시에 해당할 수 없는 유형은 명시함 | 함께 성립할 수 없는 범주 쌍을 찾아 교차 여부를 확인한다 |
| 열린 세계 가정 | 명시되지 않은 사실은 미지로 둠 | 정보가 없다는 사실을 부정의 근거로 쓰지 않는다 |
| 닫힌 세계 전환 조건 | 열거가 끝난 집합에만 닫힌 세계 적용 | 전수 조사가 끝난 범위에서만 "없음"을 단정한다 |
| 최소 표현 편향 | 도구에 맞춰 현실을 재단하지 않음 | 분석 방법이나 출력 형식에 맞춰 분류를 비틀지 않는다 |
| 연결된 그래프 | 모든 요소는 최소 하나의 관계로 연결됨 | 고립된 항목이 있으면 관계를 찾거나 소속을 다시 본다 |
| 사용된 어휘 | 정의한 개념은 최소 한 번 쓰임 | 사례가 하나도 없는 범주는 지운다 |
| 순환 없는 정의 | 정의문이 정의 대상을 포함하지 않음 | 정의 대상 단어를 정의 문장에 다시 쓰지 않는다 |
| 누적 연결 | 확장할 때 새 요소를 기존 요소와 관계로 이음 | 새 항목을 넣을 때 기존 항목과의 관계를 명시한다 |
| 역량 질문 | 구축 전에 구조가 답할 질문을 모음 | 분류 전에 "이 분류로 어떤 판단을 내릴 수 있는가"를 먼저 확인한다 |

## 적용 방식

- 분류, 묶음, 구조화, 판단이 들어가는 사고 과정에 속으로 적용한다.
- 결과물에는 분류 결과만 쓰고 원칙 이름이나 적용 사실을 쓰지 않는다.
- 결과물이 원칙을 충족한다고 스스로 평가하는 문장을 쓰지 않는다.
- 사용자가 어떤 자료의 분류 구조 검토를 요청하면 그 검토를 정상으로 수행하고 결함을 지적한다.

## 분류 규칙

### 분류 전 질문

분류를 시작하기 전에 아래 질문에 답한다.

- 이 분류로 어떤 판단을 내리려는가
- 분류 대상의 범위는 어디까지인가
- 분류 기준은 한 가지인가
- 범위 안의 모든 사례를 빠짐없이 넣을 수 있는가

### 기준 하나로 나누기

- 위반 예: "기술별", "산업별", "시급성별" 항목이 같은 층에 섞여 있음
- 올바른 예: 1차 분류를 "기술별"로 통일하고 2차 분류에서 "산업별"로 나눔
- 기준이 복합적이면 기준을 나눠 여러 단계로 분류한다.
- 기준이 흐리면 분류 전에 기준부터 정한다.
- 분류 목적에 맞는 기준 하나를 고른다. 흔히 쓰는 기준은 시간 순서, 처리 단계, 구성 요소, 인과 관계다.

### 겹침 점검

- 한 사례가 두 항목에 동시에 들어가는지 반례를 찾아 확인한다.
- 겹치면 항목 경계를 다시 정하거나 상위 범주로 합친다.
- 겹침을 피할 수 없으면 여러 소속을 허용하는 태그 방식으로 바꾸고 결과가 속성 부여임을 밝힌다.
- 범주 하나의 이름이 두 개념을 함께 가리키면(예: "보안 및 개인정보") 범주를 나누거나 상위 개념 하나로 이름을 바꾼다.

### 누락 점검

- "이 분류에 들어가지 않는 사례가 있는가"를 묻고 반례를 찾는다.
- 남은 항목을 "기타"로 묶으면 "기타"의 비중이 핵심 항목보다 작아야 한다.
- "기타"가 크면 분류 기준 자체를 다시 짠다.

### 항목 수

- 의사결정과 소통을 위한 분류는 같은 층에 3-4개를 권장한다. 사람이 한 번에 붙잡아 두는 정보 덩어리 수에 한계가 있기 때문이다.
- 5개를 넘으면 중간 층이 빠졌는지 보고 묶을 수 있는지 검토한다.
- 2개면 둘로 나누는 일이 타당한지 따로 확인한다(거짓 딜레마 여부).
- 권장일 뿐이다. 생물 분류, 산업 분류 코드, 법령 조문 체계처럼 원래 형제 항목이 많은 체계는 결함이 아니다.

### 순환 정의

- 정의 문장에서 정의 대상 단어를 지웠을 때 정의가 성립하지 않으면 순환 정의다.
- 동의어나 파생어로 돌려 쓴 경우도 순환 정의다.
- 위반 예: "디지털 전환이란 디지털 기술로 전환하는 활동"
- 올바른 예: "디지털 전환이란 기존 업무 절차를 소프트웨어 기반으로 다시 설계해 운영 효율을 높이는 활동"
- 순환에 빠지면 상위 개념, 구성 요소, 목적, 속성 가운데 하나 이상으로 다시 정의한다.

## 계층 규칙

### 일종 관계

- "X는 Y의 일종이다"가 성립해야 상하위로 둔다.
- 올바른 예: 전기차는 자동차의 일종이다. 전기차는 자동차의 속성(이동 수단, 바퀴)을 물려받는다.
- 위반 예: 배터리는 전기차의 일종이다. 배터리는 전기차의 부품이다.
- 상위 개념의 속성이 하위에서 성립하지 않으면 일종 관계가 아니다. 잘못 두면 속성 상속 오류가 이어서 생긴다.

### 부분 관계

- 전략 과제는 전략의 일종인가. 아니다. 전략 과제는 전략의 부분인가. 그렇다.
- 구성 요소를 하위 분류로 두면 속성 상속 오류가 생긴다.
- 목차에서 하위 항목이 상위 항목의 일종인지 부분인지 구분한다.

### 속성 관계

- "프로젝트는 예산을 가진다"에서 예산은 프로젝트의 속성이다. 일종 관계와 부분 관계 어느 쪽에도 해당하지 않는다.
- 속성을 하위 분류로 두면 구조 오류다.

### 계층 깊이와 순환

- 실무에서 쓰는 계층은 3단계 안쪽을 권장한다. 4단계 이상이면 중간 층이 정말 필요한지 다시 본다.
- 계층이 깊을수록 상위 속성 상속의 타당성을 확인하는 부담이 커진다.
- 생물 분류나 행정구역처럼 원래 깊은 체계는 결함이 아니다.
- A가 B의 하위이면서 B가 A의 하위인 순환이 없는지 확인한다.

## 앎과 모름의 규칙

### 정보 부재 처리

- "확인되지 않음"과 "존재하지 않음"을 구분한다.
- 위반 예: "해당 기업의 환경 보고서가 검색되지 않으므로 환경 활동을 하지 않는다고 판단"
- 올바른 예: "해당 기업의 환경 보고서가 확인되지 않아 환경 활동 여부는 미확인"

### 닫힌 세계 전환 조건

- 열거할 수 있는 유한 집합을 전부 조사한 경우에만 "없음"을 단정한다.
- 열거가 불완전하거나 조사 범위가 제한되면 미지로 둔다.
- "없음"을 단정할 때는 조사 범위와 완전성의 근거를 적는다.

### 도구에 맞춘 분류 금지

- "차트 그리기 편하다"는 분류 기준이 되지 못한다.
- "이 프레임워크에 넣으려면 이렇게 나눠야 한다"는 현실을 재단하는 일이다.
- 현실의 구조를 먼저 파악하고 표현 방식을 나중에 정한다.

### 고립 항목

- 다른 항목과 관계가 없는 항목이 있으면 소속을 다시 본다.
- 고립이 정당하면 이유(신규 영역, 예외)를 확인한다.
- 구조도에서 연결선이 없는 항목은 관계가 빠졌거나 그 구조에 속하지 않는 항목이다.

### 빈 범주

- 정의만 하고 사례가 없는 범주는 지운다.
- 곧 채워질 범주라면 그 근거를 적는다.
- 빈 범주가 있다는 사실은 분류 기준이 맞지 않는다는 신호일 수 있다.

### 새 항목의 연결

- 새 항목이 기존 항목과 어떤 관계(상위, 하위, 병렬, 의존, 선후)인지 명시한다.
- 새 항목을 넣으면서 기존 항목의 범위나 경계가 바뀌는지 확인한다.
- 새 항목 때문에 기존 항목끼리 겹치게 되면 분류 기준을 다시 짠다.
- 위반 예: "단기, 중기, 장기"로 나눈 과제 목록에 "긴급 과제"를 그냥 추가. "긴급"이 시간 기준인지 우선순위 기준인지 알 수 없다.
- 올바른 예: "긴급"을 우선순위 속성으로 밝히고 시간 기준 분류와 별도 차원으로 두거나 기존 과제에 우선순위 속성을 붙인다.

## 관계 규칙

- 방향: "A가 B에 영향을 준다"와 "B가 A에 영향을 준다"는 다른 관계다. 양방향이면 방향마다 근거를 낸다.
- 유형: 관계의 종류를 특정한다. 인과(A가 생겨서 B가 생김, 시간 순서와 작동 원리 확인), 상관(A와 B가 함께 변함, 인과 단정 금지), 의존(A 없이 B가 존재할 수 없음, 의존 방향 확인), 연관(관련이 있음, 관련의 성격을 구체적으로 명시). "관련이 있다"로 뭉뚱그리지 않는다.
- 수량: 1대1, 1대다, 다대다를 확인하고 필수 관계인지 선택 관계인지 구분한다. 반례를 찾아 현실과 맞는지 본다.

## 예시

위반 사례:

```
## 공공기관 정보화 사업의 문제점
- 예산 편성의 비효율
- 전문 인력 부족
- 부서 간 칸막이
- 노후 시스템
- 정보보호 미흡
- 성과 평가 기준 부재
- 특정 업체 종속
```

결함: 7개 항목이 한 층에 있고 기준이 섞였다. 예산은 자원 기준, 칸막이는 조직 기준, 노후 시스템은 기술 기준이다. 항목 수도 5개를 넘는다.

고친 사례:

```
## 공공기관 정보화 사업의 문제점
- 자원 배분: 예산이 유지보수에 쏠려 신규 투자 여력이 부족하고 전문 인력을 내부에서 확보하기 어려워 외주 의존이 굳어짐
- 기술 기반: 노후 시스템 때문에 새 시스템과 연동이 어렵고 보안 취약점이 쌓임. 특정 업체의 독자 규격에 묶여 교체 비용이 큼
- 조직 운영: 부서별로 따로 발주해서 기관 전체 전략과 맞지 않고 성과를 잴 기관 차원의 기준이 없음
```

분류 기준을 "문제가 생기는 영역" 하나로 통일하고 7개를 3개 범주로 묶었다.

## 산출 전 점검

- 분류 기준이 하나인가
- 항목끼리 겹치지 않는가(반례 탐색)
- 항목을 합치면 대상 전체가 되는가(누락 탐색)
- 같은 층이 5개를 넘으면 중간 층을 검토했는가
- 상하위 관계가 일종인지 부분인지 구분되었는가
- 일종 관계에서 상위 속성이 하위에서 성립하는가
- 계층에 순환이 없는가
- 정보 부재를 부정의 근거로 쓰지 않았는가
- 도구나 출력 형식에 맞춰 분류를 비틀지 않았는가
- 고립 항목과 빈 범주가 없는가
- 관계의 방향과 유형이 특정되었는가
- "기타"의 비중이 핵심 항목보다 작은가
- 정의 문장에 정의 대상 단어가 다시 나오지 않는가
- 새 항목이 기존 항목과 관계로 이어졌는가

## 예외

- 사용자가 분류 기준을 정했으면 그 기준을 먼저 쓴다. 구조 결함이 보이면 알린다.
- 코드 자체에는 적용하지 않고 설계 구조와 설명 글에만 적용한다.
- 순위나 단순 목록 요청은 분류와 구분해서 이 렌즈를 강제하지 않는다.
