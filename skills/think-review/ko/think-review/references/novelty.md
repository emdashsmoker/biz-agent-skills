# 새로움 렌즈

결론이 통념을 되풀이하는지, 기존 대안을 복제하는지, 요인을 고르게 나열하는지, 결정을 미루는지를 점검한다. 사업 기획에 한정하지 않고 분석, 기획, 글쓰기, 설계, 의사결정의 사고 과정에 모두 쓴다.

## 배경

피터 틸(Peter Thiel)과 블레이크 매스터스(Blake Masters)의 책 "Zero to One"(2014)에 나오는 생각을 사고 점검용 질문으로 옮겼다. 원래 창업 맥락의 생각이므로 사업 밖에 쓸 때는 "시장"을 "대상 영역"으로, "경쟁자"를 "기존 대안"으로 읽는다.

## 원리

### 1. 통념 검증

다수가 합의했다는 사실은 진실의 근거가 되지 못한다. 합의된 결론을 다시 쓰면 새 정보가 생기지 않는다. 어느 분야에나 아직 발견되지 않은 사실이 남아 있다.

| 판별 질문 | 위반 패턴 | 처리 |
|---|---|---|
| 이 결론 가운데 다수가 동의하지 않을 부분은 무엇인가 | 통념을 근거 없이 결론으로 채택 | 통념을 가설로 낮춘 뒤 근거 확인 |
| 통념과 같은 결론이라면 통념의 근거는 무엇인가 | 다수 의견을 진위의 근거로 사용 | 다수 의견을 지우고 사실 근거만 남김 |
| 이 분야의 탐구가 끝났다는 전제의 근거는 무엇인가 | 남은 사실이 없다는 전제로 탐색 종료 | 다수가 보지 않는 곳에서 근거 탐색 |

- 다수가 보지 않는 곳은 아무도 묻지 않는 질문, 말하기 꺼려지는 사실, 방치된 문제에 있다.
- 통념과 다른 결론에는 통념보다 강한 근거를 붙인다.
- 통념의 반대를 고르는 일 자체를 목적으로 삼지 않는다.

### 2. 수직 진보 판별

작동하는 대안을 복제하는 활동은 수평 진보다. 대안이 없던 곳에서 새 결론을 만드는 활동은 수직 진보다. 경쟁 대상을 기준점으로 삼으면 사고가 작은 개선으로 수렴한다.

| 판별 질문 | 위반 패턴 | 처리 |
|---|---|---|
| 이 결론은 기존 최선의 대안과 무엇이 다른가 | 선도 사례의 복제를 새 결론으로 제시 | 기존 대안을 먼저 적고 차이를 서술 |
| 차이가 기존 대안을 필요 없게 만들 만큼 큰가 | 경쟁 대상을 기준점으로 삼은 작은 개선 | 문제 자체를 기준점으로 다시 설정 |
| 기존 대안이 있는데도 이 결론을 고를 이유가 있는가 | 구조는 같고 이름만 바꿈 | 차이가 작으면 복제라고 표기하고 복제의 근거를 서술 |

- 복제 자체는 허용한다. 복제인지 창조인지를 구별해 표기하게 한다.
- 원서는 기존 대안보다 한 자릿수 이상(10배 수준) 나은 차이를 기준으로 든다. 차이를 수치로 잴 수 없으면 기존 대안을 대체할 수 있는지를 정성 기준으로 쓴다.

### 3. 멱법칙 집중

소수의 변수가 결과의 대부분을 정한다. 요인에 같은 무게를 주면 결과가 왜곡된다. 지배할 수 있는 가장 작은 범위에서 시작해 넓혀 가는 경로가 넓게 흩어진 작은 개선보다 낫다.

| 판별 질문 | 위반 패턴 | 처리 |
|---|---|---|
| 결과의 대부분을 정하는 변수 하나는 무엇인가 | 요인의 균등 나열 | 지배 변수를 첫 문장에 배치 |
| 나열한 요인의 비중이 실제로 같은가 | 우선순위 없는 대안 목록 | 나머지 요인을 지배 변수와의 관계로 서술 |
| 결론의 적용 범위를 지배할 수 있는 최소 단위로 좁혔는가 | 넓은 범위에 작은 개선을 흩뿌림 | 범위를 줄인 뒤 확장 경로를 명시 |

- 지배 변수를 고른 근거를 정량 또는 정성 자료로 제시한다.
- 여러 변수의 비중이 실제로 같으면 고르게 서술해도 된다.

### 4. 확정적 설계

구체적인 미래 상태를 특정하는 계획이 선택지 나열보다 낫다. 시작할 때 정한 정의, 범위, 기준이 이후 모든 결론을 결정한다. 오래 유지되는 결론이 먼저 들어가는 결론보다 낫다. 결론이 누구에게 어떻게 전달되는지도 결론의 일부다.

| 판별 질문 | 위반 패턴 | 처리 |
|---|---|---|
| 이 결론은 누가 무엇을 언제 달성하는지 특정하는가 | 선택지를 나열하고 결정을 미룸 | 가설 하나를 확정하고 성립 조건을 명시 |
| 시작할 때 정의, 범위, 기준이 고정되어 있는가 | 기초 정의 없이 상세 서술 진행 | 정의, 범위, 기준을 앞에 고정 |
| 지금이 적절한 시점인가 | 시점 근거 없이 착수 | 지금 해야 하는 근거와 늦출 때의 비용을 서술 |
| 이 결론이 오래 유효한가 | 먼저 들어간 일 자체를 성과로 봄 | 지속성의 근거를 서술 |
| 결론이 수요자에게 닿는 경로가 설계되어 있는가 | 가설 없는 실험 반복으로 설계를 대신함 | 전달 경로를 결론의 일부로 포함 |

- 가설을 세운 실험은 확정적 설계를 검증하는 수단으로 허용한다.
- 결정을 미뤄야 하면 미루는 조건과 결정할 시점을 쓴다.

## 사고 절차

| 단계 | 할 일 | 산출 |
|---|---|---|
| 기초 고정 | 정의, 범위, 기준을 정함 | 고정된 전제 |
| 통념 식별 | 대상 영역의 통념과 그 근거를 적음 | 검증할 가설 목록 |
| 격차 측정 | 기존 최선의 대안과의 차이를 잼 | 창조 또는 복제 표기 |
| 변수 확정 | 결과를 지배하는 변수 하나를 찾음 | 지배 변수와 근거 |
| 확정 서술 | 가설 하나, 성립 조건, 시점, 지속성, 전달 경로를 씀 | 결론 |

## 진단 결과 형식

아이디어, 기획안, 논증을 받아 진단을 요청받으면 아래 형식을 쓴다. 헤더는 원리 이름 대신 대상의 내용을 담은 말로 바꿀 수 있다.

```
# (대상 키워드) 진단
## 통념과 다른 점
- 진단 결과와 근거
## 기존 대안과의 격차
- 진단 결과와 근거
## 지배 변수
- 진단 결과와 근거
## 확정성
- 진단 결과와 근거
## 개선 방향
- 충족하지 못한 항목별 개선 방향과 근거
```

- 충족한 항목에는 충족 근거를 쓴다.
- 충족하지 못한 항목에는 위반 패턴 이름 대신 그 대상에서 실제로 빠진 내용을 쓴다.

## 반영할 때

- 요청받은 산출물을 평소 형식으로 쓰고 위 원리는 결론을 만드는 과정에만 적용한다.
- 결과물에 원리 이름, 저자 이름, 책 이름을 쓰지 않는다.
- 결과물이 원리를 충족한다고 스스로 평가하는 문장을 쓰지 않는다.

## 산출 전 점검

- 결론 가운데 통념과 다른 부분이 있는가
- 통념과 다른 결론에 통념보다 강한 근거가 붙어 있는가
- 기존 최선의 대안이 적혀 있는가
- 창조 또는 복제 표기가 격차의 크기와 맞는가
- 지배 변수 하나가 첫 문장에 있는가
- 요인에 같은 무게를 주지 않았는가
- 정의, 범위, 기준이 앞에 고정되어 있는가
- 결론이 누가 무엇을 언제 달성하는지 특정하는가
- 시점의 근거, 지속성, 전달 경로가 결론에 들어 있는가

## 예외

- 사용자가 기존 대안의 복제를 요청하면 복제 표기 없이 복제한다.
- 통념이 확인된 사실이면 통념을 결론으로 써도 된다.
- 사용자가 선택지 나열을 요청하면 결정을 미뤄도 된다.
- 단순 사실 조회에는 사고 절차의 기초 고정 단계만 적용한다.
- 인용 원문과 코드 자체에는 적용하지 않는다.
