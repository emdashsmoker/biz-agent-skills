# 기획 렌즈

기획이 답해야 할 질문에 빠짐없이 답하는지 점검한다. 질문 목록은 미국 방위고등연구계획국(DARPA)의 하일마이어 문답(Heilmeier Catechism)을 따른다.

## 배경

1975년부터 1977년까지 DARPA 국장을 지낸 조지 하일마이어(George H. Heilmeier)가 연구개발 과제를 판단하려고 만든 질문 목록이다. DARPA가 공개한 질문 목록은 아래와 같다(https://www.darpa.mil/about/heilmeier-catechism). 원래 연구개발 과제용이지만 이 렌즈는 인프라, 산업 진흥, 인사 전략, 정책, 조직 전략 같은 모든 기획에 쓴다.

## 질문 목록

각 질문 아래에는 점검할 내용을 적었다.

### 질문 1. 무엇을 하려는가? 전문용어 없이 목표를 말하라

- 이 기획으로 무엇을 이루려는지 일반인도 이해할 말로 설명하는가
- 왜 중요한지 쓰는가

### 질문 2. 지금은 어떻게 하고 있고 현재 방식의 한계는 무엇인가

- 현재 기술, 시장, 정책의 수준과 한계를 쓰는가
- 국내외 동향을 반영하는가
- 최신 수준을 알고 있고 가능한 선택지를 두루 검토했는가
- 지금 전략적으로 지원할 필요성과 시급성이 있는가

### 질문 3. 새로운 점은 무엇이고 왜 성공하리라 보는가

- 기존 방식과 새 방식의 차이를 쓰는가
- 성공할 이유를 근거와 함께 쓰는가

### 질문 4. 누가 관심을 갖는가? 성공하면 무엇이 달라지는가

- 이 기획의 수요자는 누구인가
- 성공했을 때의 차이와 파급 효과를 쓰는가
- 질문 1보다 측정 가능한 형태로 현재 상태와 바뀐 상태를 쓰는가(예: 처리 시간을 현재 수준에서 목표 수준으로 단축)

### 질문 5. 위험은 무엇인가

- 실패할 수 있는 지점(기술, 수요, 실행, 제도, 일정)을 쓰는가
- 성공했을 때 생기는 부작용(운영 부담, 추가 비용, 주변 시스템에 미치는 영향)을 쓰는가
- 위험마다 대응이나 완화 방안이 있는가

### 질문 6. 비용은 얼마인가

- 예산 규모가 목표와 범위에 맞는가
- 과제 성격(하향식, 상향식), 수행 주체, 추진 단계(기술성숙도 등)를 반영하는가

### 질문 7. 기간은 얼마나 걸리는가

- 추진 기간이 목표와 추진 단계에 맞는가

### 질문 8. 성공을 확인할 중간 시험과 최종 시험은 무엇인가

- 중간 점검과 최종 점검의 대상과 지표를 정했는가
- 지표가 측정 가능하고 목표와 이어지는가

## 연구개발 외 기획에 쓸 때

연구개발 용어를 해당 분야 용어로 바꿔서 쓴다. 진단 결과 첫머리에 어떤 용어를 어떻게 바꿨는지 적는다.

| 원래 표현 | 인프라 구축 | 인사 전략 | 산업 진흥 전략 |
|---|---|---|---|
| 이 연구개발로 이루려는 것 | 이 인프라로 이루려는 것 | 이 인사 전략으로 이루려는 것 | 이 진흥 전략으로 이루려는 것 |
| 현재 기술 수준 | 현재 인프라 현황 | 현재 인사제도 운영 현황 | 현재 산업 생태계 현황 |
| 최신 기술 인지 | 국내외 유사 인프라 사례 인지 | 국내외 인사관리 사례 인지 | 국내외 산업 정책 사례 인지 |
| 기존 방식과의 차이 | 기존 시설 운영 방식과의 차이 | 현행 제도와의 차이 | 기존 진흥 정책과의 차이 |
| 연구 수행 주체 | 발주처, 시공사, 운영기관 | 인사 부서, 현업 부서, 외부 전문가 | 중앙부처, 지자체, 유관기관, 민간 |
| 연구 단계 | 기본구상, 타당성 조사, 설계, 시공 | 현황 진단, 제도 설계, 시범 적용, 전면 시행 | 의제 설정, 정책 설계, 시범 사업, 본 사업 |
| 중간 시험과 최종 시험 | 공정률 점검과 준공 검사 | 시범 적용 평가와 시행 후 성과 측정 | 시범 사업 평가와 사업 종료 후 정책 평가 |

교육, 국방, 환경, 문화처럼 표에 없는 분야도 같은 방식으로 바꾼다.

## 진단 절차

### 1. 기획안 확인

기획안을 텍스트나 파일로 받는다. 기획안 없이 호출되면 기획안을 요청한다.

### 2. 개선안 깊이 질문

기획안을 요약하거나 분석하기 전에 먼저 개선안의 깊이를 묻는다.

- A: 질문별 핵심 개선 포인트만(현재 상태와 개선 방향)
- B: A에 개선 근거 추가
- C: B에 다시 쓴 문장 예시 추가

### 3. 분야 판별

연구개발 과제면 질문을 그대로 쓴다. 다른 분야면 위 표의 방식으로 용어를 바꾼다.

### 4. 등급 평가

| 등급 | 기준 |
|---|---|
| 상 | 질문에 대한 답이 논리적으로 완결되어 있고 구체적 근거와 데이터가 충분함 |
| 중 | 답은 있으나 구체성이 부족하거나 논리의 비약이 있음 |
| 하 | 답이 없거나 논리에 심각한 결함이 있음 |

- 기획안에 쓰여 있지 않은 항목은 "기획안에 해당 내용 없음"으로 적는다. 이 판정 자체가 쓸모 있는 피드백이다.
- 근거 없는 추론이나 가정으로 빈칸을 채우지 않는다.
- 너그럽게 평가하지 않는다.
- 등급의 근거는 기획안 본문에서 인용해 보여 준다.

### 5. 출력

아래 순서로 쓴다.

1. 개요: 기획안 핵심을 2-3문장으로 요약한다. 용어를 바꿨으면 여기에 적는다.
2. 등급 요약표: 질문, 등급, 핵심 판단 근거 한 줄
3. 질문별 상세: 각 질문마다 현재 상태와 개선 방향을 표로 쓰고 선택한 깊이에 따라 개선 근거와 다시 쓴 문장을 붙인다.
4. 종합 평가: 질문별 결과를 나열하지 않고 질문 사이의 논리 연결을 본다. 예를 들어 질문 4의 파급 효과가 질문 8의 지표로 측정되는지, 질문 5의 위험이 질문 6과 7의 비용과 기간에 반영됐는지 본다. 선택한 깊이에 맞춰 현재 상태와 보완 방향을 쓴다.

개선안은 바로 실행할 수 있을 만큼 구체적으로 쓴다.

## 반영할 때

사용자가 "하일마이어 기준으로 기획서 써줘"처럼 요청하면 요청한 산출물의 형식을 그대로 따른다.

- 질문 번호, 등급표, 현재 상태와 개선 방향 표를 쓰지 않는다.
- 결과물 안에 아래 요소가 자연스럽게 들어가게 쓴다. 쉬운 말로 쓴 목적, 현황과 한계, 근거가 있는 차별점, 수요자와 측정 가능한 파급 효과, 위험과 대응, 자원과 일정의 적정성, 중간 점검과 최종 점검 지표.

## 예외

- 사용자가 검토, 평가, 진단, 개선을 요청하지 않았으면 등급 평가나 개선안 표를 임의로 내지 않는다.
- 결과는 대화창에 바로 쓰고 파일은 사용자가 요청할 때만 만든다.
- 웹 검색은 사용자가 요청한 경우에만 한다.
