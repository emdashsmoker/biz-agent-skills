# 출처 확인

이 스킬은 답변에 들어가는 사실의 근거를 사용자가 제출한 자료와 웹검색 결과로 한정한다. 언어 모델은 존재하지 않는 문헌, 틀린 발행 연도, 틀린 수치를 그럴듯하게 만들어 내는 경향이 있다. 이런 오류는 읽는 사람이 원문을 찾아보기 전까지 드러나지 않는다. 이 스킬은 근거의 범위를 좁히고, 출처의 품질을 선별하고, 오류의 피해가 큰 작업일수록 사용자가 증거를 직접 보고 승인하게 하는 방식으로 이 문제를 줄인다.

작업은 아래 순서로 진행한다.

1. 확인 레벨을 정하고 사용자에게 알린다
2. 기본 규칙을 적용한다
3. 수집한 출처의 품질을 선별한다
4. 레벨 2 이상이면 사용자 승인 절차를 수행한다
5. 승인된 내용만으로 답변을 작성하고 결과물을 점검한다

## 확인 레벨

레벨은 누적 구조다. 상위 레벨은 하위 레벨의 규칙을 모두 포함한다.

| 레벨 | 적용 내용 |
|---|---|
| 레벨 1 | 기본 규칙, 출처 품질 선별 |
| 레벨 2 | 레벨 1에 더해 정량 데이터를 본문에 넣기 전 사용자 승인 |
| 레벨 3 | 레벨 1에 더해 모든 출처와 인용 내용의 증거를 모아 사용자 승인 (정량 데이터 포함) |

이 스킬이 호출되었다는 사실은 사용자가 출처 확인을 원한다는 뜻이다. 그래서 레벨 1보다 낮은 선택지는 두지 않는다.

### 레벨 정하는 방법

사용자가 레벨을 지정하면 그 레벨을 그대로 쓴다. 지정이 없으면 결과물에 대해 아래 두 가지를 판단한다.

| 판단 항목 | 구분 | 기준 | 예시 |
|---|---|---|---|
| 수정 가능성 | 수정 가능 | 작성자 본인이나 내부 팀만 보고 폐기할 수 있는 결과물 | 개인 조사 메모, 아이디어 초안, 팀 내부 검토용 초안, 정기 현황 브리핑 |
| 수정 가능성 | 수정 제한 | 외부에 이미 전달했거나 전달할 예정이라 정정 기회가 적은 결과물 | 거래처 발송 보고서, 입찰 제안서, 감사 증빙, 게재 논문, 공식 고시, 법원 제출 자료, 최종 보고서 |
| 정량 데이터 | 미포함 | 정성 분석만으로 구성되고 수치 데이터가 없는 결과물 | 개념 정리, 사례 비교 |
| 정량 데이터 | 포함 | 시장 규모, 성장률, 예산, 통계 같은 수치가 1건 이상 들어가는 결과물 | 시장 분석, 예산 검토 |

두 판단 결과를 아래 표에 대입해 레벨을 고른다.

| 수정 가능성 | 정량 데이터 미포함 | 정량 데이터 포함 |
|---|---|---|
| 수정 가능 | 레벨 1 | 레벨 2 |
| 수정 제한 | 레벨 3 | 레벨 3 |

수정 제한 결과물은 정량 데이터가 없어도 레벨 3을 쓴다. 외부로 나간 결과물에서는 틀린 수치, 사실과 다른 서술, 존재하지 않는 출처가 모두 피해를 낳는다. 세 가지를 모두 확인하는 절차는 레벨 3에만 있다. 정량 데이터가 없으면 레벨 3의 정량 데이터 표를 비워 두고 넘어가므로 확인 부담이 불필요하게 늘지 않는다.

### 레벨 알림

레벨을 정하면 작업을 시작하기 전에 한 줄로 알린다. 사용자가 지금 적용 중인 레벨을 알아야 조정을 요청할 수 있다.

```
출처 확인 레벨: 레벨 2 (정량 데이터 승인) | 판단 근거: 팀 내부 검토용 초안에 시장 규모 수치 포함
```

- 알림은 한 줄로 쓰고 판단 과정을 길게 설명하지 않는다
- 알림 없이 레벨을 적용하지 않는다

### 레벨 조정

사용자는 알림을 본 뒤 언제든 레벨을 바꿀 수 있다.

- "레벨 올려줘", "더 엄격하게" 같은 요청에는 한 단계 올린다
- "레벨 내려줘", "이 정도면 돼" 같은 요청에는 한 단계 내린다
- 사용자가 레벨을 직접 지정하면 판단 표를 거치지 않고 그 레벨을 바로 적용한다
- 판단 표에 없는 보정 규칙을 임의로 만들지 않는다. 표의 결과를 바꾸는 방법은 사용자 조정뿐이다

## 기본 규칙

모든 레벨에 적용한다. 근거의 범위를 좁히면 모델이 기억에 기대어 만든 사실이 답변에 섞이지 않는다.

- 사실의 근거는 사용자가 제출한 자료와 이번 작업에서 수행한 웹검색 결과로 한정한다
- 두 곳에서 확인되지 않는 사실은 모델이 학습으로 기억하는 지식으로 채우지 않는다. 여기서 사실은 수치, 날짜, 인명, 기관명, 사건, 인용문, 문헌 정보처럼 참과 거짓을 가릴 수 있는 진술을 말한다
- 확인되지 않는 사실은 "제출 자료와 검색 결과에서 확인되지 않음"으로 남긴다
- 모든 숫자 계산은 코드로 수행한다. 모델이 코드 없이 계산한 값은 쓰지 않는다
- 제출 자료와 검색 결과에 실린 수치도 코드로 확인한다. 합계, 비율, 증감률처럼 다른 수치로부터 계산된 값은 원래 수치로 다시 계산해 일치 여부를 본다
- 코드를 실행할 수 없는 환경에서는 계산 결과를 적지 않는다. 계산식과 입력값을 적어 사용자가 직접 계산할 수 있게 한다
- 웹검색 결과를 근거로 쓸 때는 해당 정보가 실린 페이지의 전체 URL을 경로까지 적는다. 사이트 첫 화면 주소만 적지 않는다
- 출처 표기에는 발행 주체, 발행 연도, 자료명, 전체 URL을 모두 넣는다

```
> 발행 주체(발행 연도), 자료명(전체 URL)
```

## 출처 품질 선별

모든 레벨에 적용한다. 검색 결과에는 편집 절차가 없는 글, 홍보용 글, 자동 생성된 글이 섞여 있다. 이런 글을 근거로 쓰면 출처를 적어 두어도 사실 오류가 그대로 남는다. 그래서 수집한 모든 출처를 인용하기 전에 고품질, 한계적, 저품질 세 등급으로 나누고 등급별로 다르게 처리한다.

사용자가 이미 쓴 글의 출처 점검을 요청하면 글에 인용된 출처에 같은 기준을 적용한다. 저품질 출처는 고품질 출처로 교체하고, 교체할 출처가 없으면 그 출처에만 기대는 서술을 삭제한다.

### 판단 기준

출처의 품질은 아래 구조적 속성으로 판단한다.

| 기준 | 고품질 신호 | 저품질 신호 |
|---|---|---|
| 편집과 사실 확인 절차 | 편집진과 사실 확인 절차가 명시된 발행 | 편집진이 없고 확인 절차 없이 스스로 발행 |
| 발행 주체의 독립성 | 다루는 대상과 이해관계가 없는 제3자 발행 | 홍보, 광고, 자기 홍보 목적의 당사자 발행 |
| 자료 유형 | 원자료를 직접 생산한 1차 자료 | 출처가 불분명한 2차 가공이나 재인용 |
| 확인 가능성 | 원문, 방법론, 표본, 산출 근거를 추적 가능 | 근거를 추적할 수 없고 단정적 주장만 제시 |
| 전문성과 동료평가 | 동료평가를 거친 자료 또는 전문기관의 공식 발간물 | 익명 작성이거나 작성자 전문성을 확인할 수 없음 |
| 작성 주체 | 사람 저자와 편집 책임이 확인되는 콘텐츠 | 언어 모델이 자동 생성한 것으로 추정되고 확인할 수 없는 콘텐츠 |

- 기준을 많이 충족할수록 고품질, 많이 어길수록 저품질로 본다
- 근거를 추적할 수 없거나 AI 자동 생성으로 추정되는 출처는 다른 기준을 충족하더라도 저품질로 처리한다
- 발행 주체는 사이트의 소개 페이지, 편집진 안내, 연락처로 확인한다. 사이트 밖에서 발행 주체를 따로 검색해 실체도 확인한다
- 매체의 정치 성향이나 브랜드 인지도로 등급을 매기지 않는다. 황색 매체 여부는 사실 확인 절차의 부재와 선정성 같은 속성으로 판단한다
- 진영이 서로 다른 두 매체에는 같은 기준을 같은 방식으로 적용한다

### 등급별 처리

| 등급 | 해당 출처 | 처리 |
|---|---|---|
| 고품질 | 판단 기준을 대부분 충족하는 출처 | 우선 인용 대상으로 직접 활용 |
| 한계적 | 상황에 따라 조건부로 쓸 수 있는 출처 | 원출처를 추적하거나 교차 확인을 거친 뒤 조건부로 인용 |
| 저품질 | 확인할 수 없거나 결격 사유가 뚜렷한 출처 | 인용하지 않고 없는 것으로 취급. 이 출처에만 기대는 주장은 쓰지 않음 |

### 고품질 출처 유형

아래는 고품질로 분류되는 유형의 예시다. 목록에 없는 출처가 곧 저품질이라는 뜻은 아니며 목록에 없는 출처는 판단 기준으로 하나씩 평가한다.

- (정부와 공공기관) 중앙정부, 지방자치단체, 소속기관의 공식 발간물과 보도자료
- (공식 통계) 국가 공식 통계와 통계 기관의 공식 발간물
- (법령) 법령과 행정규칙 원문
- (의회와 감사기관) 의회 소속 조사, 예산, 입법 연구기관의 보고서와 감사기관의 감사 결과 보고서, 의회의 예산 결산 심사 보고서
- (공공 연구기관) 정부 출연 연구기관, 과학기술과 정보통신 분야 공공 전문기관, 기술 수준 평가기관의 발간 보고서
- (학술 자료) 동료평가를 거친 학술지 논문과 학위논문. 논문은 학술 검색 서비스나 출판사 페이지에서 원문을 직접 확인해 인용한다
- (특허와 표준) 각국 특허청 공보와 특허문헌, 국제 지식재산 기구 자료, 국내외 표준화 기구의 표준 문서
- (국제기구) 국제기구와 산하 기구의 보고서와 통계, 국제 연구기관이 정기 발간하는 공개 지표 보고서
- (금융 기관) 각국 중앙은행, 증권거래소, 국제 금융 기구의 공식 통계와 발간물
- (전문 리서치) 컨설팅 기관과 산업 리서치 기관의 공식 발간 보고서
- (통계 집계 서비스) 통계 집계 서비스와 시장 보고서 판매 서비스는 2차 자료이므로 원출처를 찾아 원출처를 인용한다
- (기술 문서) 기술 주제에 한해 대형 오픈소스 프로젝트의 공식 문서와 공식 저장소, 표준 라이브러리와 프레임워크의 공식 문서

### 저품질 출처 유형

아래 유형은 저품질로 분류해 인용하지 않는다. 공통 신호는 편집과 사실 확인 절차의 부재, 발행 주체 미상, 확인 불가, AI 자동 생성이다. 목록에 없더라도 이 신호에 해당하면 같게 처리한다.

- (AI 자동 생성 콘텐츠) 확인할 수 없는 언어 모델 생성 글을 대량으로 발행하는 사이트와 AI 생성 백과사전. 저자와 편집진이 없음, 해시 문자열 같은 자동 생성 URL, 원출처 없는 요약, 내용을 직접 확인하라는 면책 문구가 대표 신호
- (사용자 생성 콘텐츠) 위키 본문, 질의응답 서비스, 사용자 리뷰처럼 불특정 다수가 쓰는 콘텐츠. 위키는 본문에 달린 원출처를 찾아 원출처를 인용
- (개인 게시물) 개인 블로그, 블로그 플랫폼의 개인 글, 개인 SNS 게시물
- (익명 커뮤니티) 익명 게시판, 포럼, 댓글처럼 작성자 전문성을 확인할 수 없는 공간
- (황색 매체) 선정성 위주이고 사실 확인 절차가 없는 매체
- (출처 없는 모음 사이트) 출처를 밝히지 않는 뉴스 모음, 카드뉴스, 데이터 수집 서비스, 제휴 링크 위주의 리뷰 사이트
- (홍보성 콘텐츠) 스폰서 콘텐츠, 광고성 기사, 보도자료를 그대로 옮긴 기사
- (국가 선전 매체) 편집 독립성이 없는 국가 통제 매체
- (정체 불명 사이트) 발행 주체와 편집 책임을 확인할 수 없는 도메인

### 한계적 출처 처리

아래 유형은 조건을 지킬 때만 인용한다.

- (일반 언론 보도) 보도가 인용한 원출처를 찾아 원출처를 우선 인용한다. 원출처를 찾을 수 없으면 보도를 단독 근거로 쓰지 않는다
- (기업 자체 발표) 이해관계가 있으므로 해당 기업의 주장으로 범위를 한정해 인용한다
- (사전공개 논문) arXiv 같은 사전공개 논문은 동료평가를 거치지 않은 자료로 보고 제한적으로 인용한다
- (단일 출처 주장) 한 출처만 제기하는 주장은 독립된 다른 출처로 교차 확인한 뒤 인용한다
- (의견 글) 신뢰할 만한 매체의 글이라도 사설과 칼럼은 사실 보도와 구분해 필자의 견해로 한정해 인용한다
- (협회와 옹호 단체) 특정 입장을 대변하는 단체의 발간물은 이해상충 가능성을 고려해 인용한다

### 출처가 모두 저품질일 때

- 수집한 출처가 모두 저품질이면 그 출처들을 없는 것으로 본다
- 저품질 출처에만 기대는 주장은 쓰지 않는다
- 해당 지점은 정보가 없는 상태로 남긴다. 정보가 없다는 사실을 그 주장이 거짓이라는 근거로 쓰지 않는다
- 고품질 출처가 필요하면 검색 대상을 고품질 출처 유형으로 좁혀 다시 찾는다

### 등급 비공개

- 결과물에 출처 등급, 제외한 출처, 판단 기준과 판단 과정을 적지 않는다
- 결과물에는 선별을 통과한 출처만 일반 인용 형식으로 나온다

### 선별 예시

아래 예시의 기관명, 자료명, URL은 설명용 가상 값이다.

(예시 1) 자동 생성 리포트를 1차 조사 자료로 교체

```
before
- 국내 OO 업계의 최대 애로사항은 인력 부족으로 분석됨
> 자동 생성 리포트 사이트(2025), OO 산업 분석 리포트(https://reports.example.com/r/9f3a1c7e)

after
- 국내 OO 업계 기업 중 N%가 사업 운영상 애로사항으로 인력 부족을 꼽음
> OO 공공연구기관(2025), 2024년 OO 산업 실태조사(https://www.example.org/stat/2025/oo-survey)
```

자동 생성 리포트는 확인할 수 없으므로 제외하고 공공연구기관이 직접 조사한 1차 자료로 교체한다.

(예시 2) 언론 보도 대신 보도가 인용한 원출처를 인용

```
before
- 소비자물가 상승률이 둔화된 것으로 보도됨
> OO일보(2025), "물가 상승률 둔화"(https://news.example.com/article/123)

after
- 연간 소비자물가 상승률이 전년 대비 둔화
> OO 통계기관(2025), 2024년 연간 소비자물가동향(https://www.example.org/cpi/2024-annual)
```

보도가 근거로 삼은 통계기관의 공식 발표를 찾아 직접 인용한다.

(예시 3) 저품질 출처만 있는 주장은 삭제

```
before
- 해당 신기술의 글로벌 시장 규모는 향후 폭발적으로 성장할 전망
> 개인 블로그(2025), 신기술 전망(https://blog.example.com/post/1)
> 익명 커뮤니티 게시글(2025)

after
(해당 주장을 삭제하고 대체 서술을 추가하지 않음)
```

시장 전망이 개인 블로그와 익명 게시글에만 기대고 있고 고품질 대체 출처가 없으므로 주장 자체를 삭제한다.

## 레벨 2: 정량 데이터 승인

레벨 2에서 적용한다. 레벨 3은 이 승인을 레벨 3 승인 요청의 정량 데이터 표로 대신한다. 수치 오류는 문장 속에서 눈에 잘 띄지 않고 한번 인용되면 계속 퍼진다. 그래서 수치를 본문에 넣기 전에 사용자에게 목록을 보여 주고 승인을 받는다.

### 승인 대상

- 수치, 통계, 비율, 백분율, 금액, 성장률, 순위, 건수, 규모처럼 숫자로 표현되는 모든 정보
- 사용자 제출 자료에서 가져온 수치와 웹검색 결과에서 가져온 수치 모두

### 승인 절차

1. (수집) 제출 자료와 검색 결과에서 정량 데이터를 찾고 출처의 발행 주체, 연도, 자료명, URL을 함께 기록한다
2. (승인 요청) 본문을 쓰기 전에 아래 형식으로 목록을 보여 준다
3. (반영) 승인된 데이터만 본문에 쓴다. 수정 요청을 받은 데이터는 사용자가 제시한 수치로 바꿔 쓴다. 거부된 데이터는 답변에서 모두 제외한다

```
정량 데이터 승인 요청

아래 정량 데이터를 답변에 사용할 예정입니다. 확인 후 승인해 주세요.

| 번호 | 데이터 항목 | 수치 | 출처 |
|---|---|---|---|
| 1 | (항목 설명) | (수치) | (발행 주체(연도), 자료명) |
| 2 | (항목 설명) | (수치) | (발행 주체(연도), 자료명) |

- 승인: 전체 승인 또는 번호 지정 승인 (예: "1, 3번 승인")
- 수정: 수정할 번호와 올바른 수치 제시 (예: "2번은 42%로 수정")
- 거부: 해당 데이터 미사용
```

### 하지 않는 행동

- 승인받지 않은 정량 데이터를 본문에 넣지 않는다
- "약", "대략", "추정" 같은 표현으로 돌려서 승인받지 않은 수치를 넣지 않는다
- 승인을 기다리는 동안 해당 수치를 확정된 사실처럼 서술하지 않는다

## 레벨 3: 모든 인용의 증거 확인

레벨 3에서 적용한다. 언어 모델은 실제로 없는 문헌을 만들어 내기도 하고, 실재하는 문헌의 발행 연도나 권호를 틀리게 적기도 한다. 레벨 3은 인용할 모든 출처와 내용에 대해 증거를 모아 사용자에게 보여 주고, 사용자가 직접 확인해 승인한 항목만 쓴다.

### 승인 대상

- 답변에 인용할 모든 출처와 각 출처에서 인용할 모든 내용. 건수와 중요도와 관계없이 전부 포함한다
- 정성 내용(정의, 주장, 사실 진술)과 정량 데이터(수치, 통계, 비율, 백분율, 금액, 성장률, 순위, 건수, 규모, 날짜)를 모두 포함한다
- 사용자 제출 자료에서 인용하는 내용도 포함한다
- 정량 데이터는 승인과 별도로 기본 규칙에 따라 코드로 수치를 확인한다

### 승인 절차

1. (인용 항목 정리) 답변에 쓸 모든 출처를 찾고 출처마다 발행 주체, 자료명, 발행 연도, URL, 인용할 내용을 기록한다
2. (증거 수집) 출처마다 아래 표의 증거를 모은다. 검색 결과가 없거나 페이지 접근에 실패하면 그 사실을 있는 그대로 적는다
3. (일괄 제시) 본문을 쓰기 전에 모든 출처의 증거와 인용 예정 내용을 한 번에 보여 준다. 출처 표와 정량 데이터 표는 나누어 제시한다
4. (반영) 승인된 항목만 본문에 쓴다. 수정 요청은 사용자가 제시한 내용으로 바꿔 쓴다. 승인되지 않은 항목은 쓰지 않는다. 교체 요청을 받으면 대체 출처를 찾아 같은 증거 수집을 다시 수행한다

| 출처 유형 | 증거 | 수집 방법 |
|---|---|---|
| 웹검색 | 실재성 | "발행 주체 + 자료명"으로 검색한 결과의 스니펫 원문 |
| 웹검색 | 날짜 | 검색 결과나 페이지에서 확인한 발행 날짜 원문 |
| 웹검색 | URL 접근 | 페이지를 여는 도구로 URL을 연 결과(성공 여부와 페이지 제목) |
| 웹검색 | 내용 | 인용할 내용이 담긴 문단의 원문 발췌 |
| 사용자 제출 | 날짜 | 문서에 적힌 발행일, 작성일, 기준일 원문 |
| 사용자 제출 | 내용 | 인용할 내용이 담긴 문단의 원문 발췌 |
| 사용자 제출 | 정합성 | 문서 제목, 작성 기관, 기준 연도가 인용하려는 쓰임과 맞는지 보여 주는 원문 |

사용자 제출 자료는 파일을 직접 읽어서 증거를 모은다.

```
인용 항목 승인 요청

[출처와 인용 내용]

| 번호 | 출처 유형 | 출처명 | 발행 연도 | 인용 예정 내용 |
|---|---|---|---|---|
| 1 | 웹검색 | (발행 주체, 자료명) | (연도) | (인용할 내용 요약) |
| 2 | 사용자 제출 | (발행 주체, 자료명) | (연도) | (인용할 내용 요약) |

[1번 출처 증거 (웹검색)]
- 실재성: "발행 주체 자료명" 검색 결과 (스니펫 원문 또는 "검색 결과 없음")
- 날짜: 검색 결과에서 확인된 날짜 (원문 또는 "날짜 정보 미확인")
- URL 접근: (URL) 접근 결과 (페이지 제목 또는 "접근 실패")
- 내용: 페이지 내 관련 문단 발췌 (원문 또는 "해당 내용 미발견")

[2번 출처 증거 (사용자 제출)]
- 날짜: 문서에 적힌 날짜 (원문 또는 "날짜 표기 없음")
- 내용: 문서 내 관련 문단 발췌 (원문)
- 정합성: 문서 제목, 작성 기관, 기준 연도 (원문)

[정량 데이터]

| 기호 | 출처 번호 | 출처명 | 발행 연도 | 데이터 항목 | 수치 |
|---|---|---|---|---|---|
| A | 1번 | (발행 주체, 자료명) | (연도) | (항목 설명) | (수치) |
| B | 2번 | (발행 주체, 자료명) | (연도) | (항목 설명) | (수치) |

- 승인: 전체 승인 또는 번호와 기호 지정 승인 (예: "1, 2번 승인, A 승인")
- 수정: 수정할 번호나 기호와 올바른 내용 제시 (예: "B는 42%로 수정")
- 교체: 해당 출처 대신 대체 출처 탐색 요청 (예: "2번 대체 출처 찾아줘")
- 거부: 해당 항목 미사용
```

### 하지 않는 행동

- 증거를 모으지 않은 출처를 답변에 넣지 않는다
- 승인받지 않은 인용 내용을 본문에 넣지 않는다. 정성 내용과 정량 데이터 모두 해당한다
- 인용할 내용을 승인 요청 표에서 빠뜨리지 않는다. 건수와 중요도와 관계없이 전부 적는다
- "약", "대략", "추정" 같은 표현으로 돌려서 승인받지 않은 데이터를 넣지 않는다
- 승인을 기다리는 동안 인용 내용을 확정된 사실처럼 서술하지 않는다
- URL을 만들어 내거나 추측해서 적지 않는다
- 발행 연도를 추측해서 적지 않는다. 증거에서 확인된 연도만 적는다
- 증거는 원문 그대로 보여 준다. 요약하거나 가공하지 않는다

## 승인 절차 공통 예외

레벨 2와 레벨 3의 승인 절차에 적용한다.

- 사용자가 대화 중 직접 제시한 정보(예: "매출이 100억 원인데")는 사용자 본인이 제시한 정보이므로 승인 대상에서 제외한다
- 사용자가 "승인 생략", "컨펌 생략", "바로 써도 돼"처럼 명시적으로 허락하면 그 턴에 한해 승인 절차를 생략한다
- 다음 턴부터는 승인 절차를 다시 적용한다

## 출처 선별 예외

- 사용자가 특정 출처의 인용을 직접 지시하면 그 출처는 저품질이라도 인용한다
- 분석 대상 자체가 저품질 출처이면 분석 목적의 인용을 허용한다 (예: 허위정보 확산 사례 분석)
- 당사자가 무엇을 발표했는지 자체를 전할 때는 당사자 발표를 자기 진술 범위로 인용한다
- 사용자가 등급 공개를 명시적으로 요청하면 등급 비공개 규칙을 적용하지 않는다

## 결과물 점검

답변을 내보내기 전에 아래 항목을 점검하고 어긋난 부분은 고친 뒤 내보낸다.

- 작업 시작 전에 확인 레벨을 한 줄로 알렸는가
- 모든 사실 진술의 근거가 제출 자료나 이번 작업의 검색 결과에 있는가
- 모든 계산 값을 코드로 계산했는가. 코드를 실행할 수 없는 환경이면 계산식과 입력값만 적었는가
- 인용 링크가 정보가 실린 페이지의 전체 URL인가
